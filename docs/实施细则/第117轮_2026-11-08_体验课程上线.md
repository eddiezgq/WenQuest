# 实施细则 · 第 117 轮：体验课程上线（2 门课程包 + 9 本教材各建一门体验课）

日期：2026-11-08
起因：Eddie 11-08 12:02（美东）：“国内问渠科技没有课程，把课程上线，不是要培训，是给老师学习企业体验的。”国内学习平台的课程目录是空的：体验单位的老师、企业的人登录进来没有课可看。
Eddie 选定：**2 门现成课程包 + 9 本教材各建一门体验课**；**登录的人都能免费加入**；国内、美国两边都有。
状态：**待 Eddie 确认第三节“每门体验课里有什么”**

## 一、现状

| 内容 | 状态 |
|---|---|
| 课程包《数字工厂实训》（12 讲，第 3、6、10 讲完整，其余为大纲）、《缝纫机设计与制造》（31 讲，三批） | 两台服务器上都有，管理员在“管理 → 课程包”按批点“发布”才建成课程；国内一直没点 |
| 9 本教材（机器人学、PLC 原理及实践、机械设计、机械制造技术、人工智能、线性代数、微积分、大学物理、数字集成电路设计） | 平台“教材”页能看网页版、PDF、互动课件、虚拟实验；**不是课程**，不在课程目录里 |

## 二、决定

| 编号 | 决定 |
|---|---|
| D-1 | 两门课程包在国内、美国都发布全部各批；课程包页加“全部发布”按钮（一次把所有课程包的所有批次发完，不用逐批点）。 |
| D-2 | 9 本教材各自生成一个“体验课”课程包（`教材名 · 体验课`），和现有课程包走同一套发布：每章一节。 |
| D-3 | 体验课都标“免费”，进课程目录；登录的人（体验单位老师、自动开通的企业、以后手机号注册的个人）都能点“加入”。 |
| D-4 | 体验课不是正式课程：不设作业、考试，不计成绩；课程说明里写清“供体验，内容随教材持续更新”。 |
| D-5 | 教材改了，体验课跟着更新：部署时重新生成，课程包页的“更新”按钮（已有）把改动的节换新。 |

## 三、每门体验课里有什么（待确认）

- **课程说明**（第 0 节）：本书简介（`book.yaml` 的介绍）、适用专业、全书章目、怎么用（网页版、互动课件、虚拟实验、AI 助教）、“供体验、不计成绩”。
- **每章一节**，节里依次放：
  1. **本章导读**（页面）：本章各节标题；还在写的节标“编写中”。
  2. **网页版教材 · 第 N 章**（链接，打开平台教材页这一章）。
  3. **互动课件 · 第 N 章**（链接；这一章有课件才放）。
  4. **虚拟实验**（链接，每个实验一条；这一章有实验才放）。
  5. **本章 PDF**（链接）。
- 本轮不做每章测验（教材习题还没有标准答案库）；以后有了再加。

## 四、交付物

1. `textbook/tools/bookcourse.py`：读一本书的构建产物（`web/index.json`、课件、实验），写 `textbook/build/<书>/course/manifest.json`（课程包格式，`course_pack.py` 直接认）。教材构建（`build.py`）末尾调用。
2. 网关 `course_pack.py`：`POST /api/v1/admin/course-packs/publish-all`（依次发布每个课程包的每一批，已发布的跳过）；体验课发布后在目录里标“免费”（已有）。
3. 学习平台“管理 → 课程包”：“全部发布”按钮；体验课显示在课程包列表里。
4. 测试：`bookcourse.py` 对一本小书的产物生成清单并校验结构；网关 publish-all 用假 Moodle 走一遍。
5. 帮助《体验课程》（管理员怎么一键发布、老师和企业怎么加入）。

## 五、施工顺序与验收

`bookcourse.py` 与测试 → 网关 publish-all → 管理页按钮 → 本机完整环境：生成一本书的体验课、点“全部发布”、学生账号在课程目录里看到并加入、点开各链接 → 推送、部署（按增量）→ Eddie 在国内、美国各点一次“全部发布” → 国内用体验单位账号看课程目录验收。
