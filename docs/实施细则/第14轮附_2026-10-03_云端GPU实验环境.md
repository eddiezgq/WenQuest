## 一、要解决的两件事

1. **学生实验**：学生在问渠的实验页点“打开 GPU 实验”，几十秒内进入一个装好 CUDA 工具包、PyTorch、Triton、Nsight 命令行工具的 JupyterLab；做完实验，测出的结果自动回填实验报告；用完自动关机、按秒计费；老师能看到每人用了多少时长、花了多少钱。
2. **书中数字的实测**：第 4 章起正文里的耗时、带宽、利用率由程序在云端 GPU 上实际测出，记录 GPU 型号、驱动、CUDA 版本、时间戳和程序的指纹，存为 `code/runs/*.json`；构建时核对程序没有改过（第 14 轮细则 2.4 节“实测记录”）。

两件事用**同一个容器镜像**，保证学生跑出来的和书里写的是同一套环境。

## 四、设计

### 4.1 总体结构

```
问渠实验页 ──“打开 GPU 实验”──▶ 网关 GPU 调度服务（新） ──开放接口──▶ 平台适配器（AutoDL / 阿里云 / Lambda / 学校服务器）
     ▲                                  │ 额度、计时、自动关机、费用台账                    │
     └──────── 结果回填实验报告 ◀────── 结果回传（带签名）◀──── 容器里的 wqgpu 工具 ◀────┘
```

- **统一镜像** `wenquest/cuda-lab`：Ubuntu + CUDA 12.x 工具包、PyTorch、Triton、Nsight Systems / Compute 命令行、JupyterLab、本书各章的实验笔记本，以及小工具 `wqgpu`（记录 GPU 型号/驱动/CUDA 版本、运行实验、把结果带签名回传问渠）。镜像放国内与国际两个镜像仓库。
- **平台适配器**：每个平台一个适配器，统一四个动作：开机（指定显卡、镜像、令牌）、查状态、关机、查费用。换平台或加学校服务器只加一个适配器，课程与实验不用改。
- **调度服务**放在网关里（不新增服务器）：
  - 额度：每门课、每名学生的 GPU 小时上限，由老师设定；超额需老师批准；
  - 计时：空闲 15 分钟提醒、30 分钟自动关机，单次最长 3 小时；
  - 安全：每个容器一次性令牌，只能访问自己的 JupyterLab；学生不接触平台账号与密钥；
  - 台账：每次开机的平台、显卡、时长、费用，老师和管理员可看。
- **结果回填**：实验笔记本最后一格调用 `wqgpu submit`，把测得的数（耗时、带宽、利用率、正确性检查）回传，问渠把它们填进该生的实验报告表格。

### 4.2 合规

- 国内部署的学生实验只用国内平台，数据不出境；第 9 章需要大模型的实验只在租来的 GPU 上运行开源模型（如 DeepSeek、通义千问），不调用境外模型接口。
- 美国课程用国际平台；作者实测的记录注明平台与地区。

### 4.3 施工前细化的设计（2026-10-03，确认后写定）

查阅两家平台的开放接口后，把 4.1 节的做法细化如下：

1. **“统一环境”的做法**：不强制每家平台都用问渠自建的镜像，而是**平台的官方基础镜像（CUDA 12 + PyTorch）+ 问渠的配置步骤**。原因：AutoDL 的容器只能从它自己的基础镜像或保存的私有镜像启动，Lambda 的虚拟机自带 Lambda Stack（CUDA、PyTorch）。开机后，调度服务通过 JupyterLab 的文件接口把本次实验的笔记本、`wqgpu` 工具和本次会话的回传凭证放进去；笔记本第一格运行环境检查，缺什么补装什么，并记下环境指纹（GPU 型号、驱动、CUDA、PyTorch 版本），回传时一并带上。问渠自建的 Docker 镜像（`deploy/gpu-lab/Dockerfile`）用于学校服务器（方案 C）和以后的其他平台。
2. **两家平台的接口**（据官方文档）：
   - AutoDL 容器实例 Pro：创建（指定 GPU 规格、镜像、CUDA 最低版本、开机命令）、查状态、查详情（返回 JupyterLab 地址与令牌、每小时价格）、关机、释放；按量计费，需实名认证；
   - Lambda：开机（实例类型、地区、SSH 公钥）、查实例（状态 booting / active / terminated，返回 JupyterLab 地址与令牌）、终止。
3. **额度模型**：
   - 每名学生的 GPU 小时额度 = 他所在课程中老师给出的额度的最大值，再加管理员单独给的额度；
   - 默认额度为 0；没有额度的学生能看到 GPU 实验，但“打开”按钮提示联系老师；
   - 每次开机前检查剩余额度，同时只能开一台；单次最长 3 小时，空闲 30 分钟（JupyterLab 的“最近活动”时间）自动关机。
4. **在教材中的写法**：新增指令 `::: GPU实验 4.1`（`src:` 笔记本，`显卡:` 需要的显卡档次，`说明:`），构建时把笔记本和它的指导书、报告模板打包，网页中显示“打开 GPU 实验”框；构建检查笔记本的格式、最后一格有回传、指导书表格引用的结果名在笔记本里都有。
5. **结果回填**：回传的结果按 `结果名 → 数值` 保存；学生下载的实验报告中，表格里写了 `{{结果名}}` 的格子填上自己测得的数，其余照模板。
6. **作者实测**：先接 Lambda（SSH 执行），国内实测在阿里云适配器接上后补。由 GitHub 上的手动工作流触发，密钥放在加密变量中。

### 4.4 书中实测的流程

1. 每章需要实测的程序放在 `code/runs/` 下，各带一个 `run.yaml`（要什么显卡、重复几次、取中位数）。
2. 运行工具 `textbook/tools/gpurun.py` 通过适配器开一台机器，跑完把结果写回 `code/runs/*.json`，关机。由 Eddie 在 GitHub 上手动触发（平台密钥存在 GitHub 的加密变量里），或我在会话里提交触发。
3. 构建时检查：正文引用的实测数都有记录；记录里的程序指纹与当前程序一致，不一致就报错，提示重测。
4. 在实测之前，正文可以先写，引用的实测数显示为“〔待实测〕”，状态不能超过“草稿”。
