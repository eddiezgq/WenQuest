## 二、决定

1. **逐条找根因、修根因**，不靠加长等待时间“糊过去”。只有查实就是慢（例如 GitHub 机器忙）才放宽时限，并在第八节写明证据。
2. **先修两个已经确定的真毛病**：
   - 巡检规则 Q3 的时间相减：统一成带时区的时间；加一条单元测试（不带时区的数据进来不报错）。
   - 作业卡时间重叠：报工时同一工位的时间记录按先后接上、不重叠；加单元测试。
3. **其余几条先补诊断**：失败时把原因打全（例如收货单查不到时，打出 ERPNext 里有没有这张单、报错是什么），再按日志定根因修。
4. **验收**：修完连续跑 3 次“服务器演练”全部一次通过（每次约 45 分钟用量，共约 2.5 小时）。3 次里再出新的偶发，记下来，能当场修的修，修不了的单列给 Eddie。
