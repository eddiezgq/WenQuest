## 八、Eddie 补充：同时完善校情中枢（2026-11-05 04:28）

现状：评价程序包里只有“问渠 ⇄ 校情中枢”的**数据契约 v1**（JSON Schema：问渠推送达成度、增值、评教主题、学业预警；校情中枢回发改进任务）和推送、任务的样例；**校情中枢本身还没有**——仓库里没有它的方案和程序。

建议照厂情中枢（`docs/方案/厂情中枢架构与方案.md`，已建成）的路子做“学校版”，复用同一套地基（对象浏览器、规则、追因、动作、AI 提醒、报告）：

| 层 | 校情中枢里是什么 |
|---|---|
| 本体（对象） | 学校 → 学院 → 专业 → 培养方案 → 毕业要求 / 指标点 → 课程 → 开课班 → 教师、学生；评估项目（审核评估、专业认证、校内评估）及其指标 |
| 数据接入 | 问渠按数据契约推送（课程达成度、增值、评教、预警）；教务系统（学籍、选课、成绩）先用导入表格，以后接口 |
| 规则（发现问题） | 课程目标未达成、毕业要求指标点低于阈值、某课连续两学期评教最低题不变、学业预警人数上升、证据材料缺失 |
| 追因 | 指标点 → 支撑课程 → 课程目标 → 考核项 → 题目 / 实验（契约样例里已有这条链） |
| 动作 | 给课程负责人发**改进任务**（契约已定义）、跟踪完成、下学期复核——“评价—反馈—改进”闭环，认证最看重的就是这个 |
| 报告 | 毕业要求达成情况评价报告、专业自评报告的数据章节、本科教学质量报告的数据部分、审核评估的数据与佐证清单；网页 + Word |

分期建议：
1. **第一期（随本轮做）**：《校情中枢架构与方案》初稿写进 `docs/方案/`；V0 演示：收问渠推送并按契约校验 → 毕业要求汇总 → 学校 / 学院 / 专业三级看板 → 规则亮灯 → 一键发改进任务 → 生成毕业要求达成报告。全部用模拟数据，和本轮的评价演示页连成一条线（课程层 → 专业层 → 学校层）。
2. 第二期：教务数据导入、评估项目与佐证材料管理、专业自评报告整本生成。
3. 第三期：AI 代理（周报、风险提醒、自评报告起草）、真实学校试点。
