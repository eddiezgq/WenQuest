## 二、决定（建议）

| 编号 | 决定 | 理由 |
|---|---|---|
| J-1 | **已装机台账**：机器人厂每发出一台 WQ-CR5（订单做完开票），在客户现场建一份档：序列号、客户、6 个关节各用了哪一批谐波减速器、出厂背隙、标定后绝对定位误差、跑合力矩。另有 8 台“情景开始前已经在用”的（示例），三个客户各有几台 | 售后能一路追到车间和供应商——这是数字工厂“质量追溯”的最后一环 |
| J-2 | **现场模拟器**（教学模式，1 分钟 = 1 个现场日）：每台每天一条运行摘要——运行小时、每个关节的温度峰值、电流均方根、碰撞次数、背隙估计。关节按 `twin/robot.py` 的寿命模型磨损；**用了问题批次减速器的关节背隙涨得快**（实验 25 的“批次问题”在现场显出来） | 寿命公式现成；批次问题把车间、来料和售后串成一条线 |
| J-3 | **预警与诊断**：背隙接近上限、关节过热、碰撞次数突增，平台出预警（AI 巡检规则），说明是哪台、哪个关节、可能原因（批次 / 润滑 / 撞过） | 和减速器厂“振动超限预警”同一个做法 |
| J-4 | **投诉与服务工单**：客户投诉（如“定位不准”“J2 异响”）同时开 ERPNext Issue；服务方案三种：远程重新标定、上门更换关节模组（用成品库的 WQJ-L / M / S 当备件，出库进 ERPNext）、上门补润滑脂；4 位服务工程师（示例）排班；做完回访打满意度 | 售后的三种典型处理，备件就是本厂的产品 |
| J-5 | 页面：机器人厂的“客户与服务”是一页新的（已装机器人、远程监测、投诉与工单、回访），减速器厂的原页不动。线索（CRM）两厂共用 | 不改减速器厂 |
| J-6 | 帮助机器人厂加一章“客户与服务”；CI 演练 `--domains` 加：发出的 WQ-CR5 建了档、现场有摘要、投诉开了 ERPNext Issue | 与前两轮同一套 |
| J-7 | 实验不新增；以后可以做“实验 29：一台机器人的售后追溯”（现场预警 → 追到减速器批次 → 召回同批） | 先跑通 |
