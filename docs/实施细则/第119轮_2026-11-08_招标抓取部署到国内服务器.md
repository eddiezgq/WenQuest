# 实施细则 · 第 119 轮：招标抓取部署到国内服务器

- 日期：2026-11-08
- 起因：Eddie 要求每天自动抓取国内公开招标公告，供每日招标判断任务（“每日招标搜寻”）使用；并要求“国内也是这边部署的”，由我们直接装到国内阿里云服务器，不让他手动操作。
- 状态：施工中

## 一、决定

| 编号 | 决定 |
| --- | --- |
| D-1 | 程序放在本仓库 `ops/tender-crawler/`（版本 1.0.1），与问渠平台代码分开；不进平台镜像，不影响学习平台。 |
| D-2 | 服务器上以 `deploy` 用户安装到 `~/tender-crawler`，不用 sudo：借用平台已有的网关镜像（Python 3.12）在容器里运行，额外依赖（requests、lxml）走阿里云 PyPI 镜像装到 `~/tender-crawler/pylib`。容器限 512 MB 内存、半个 CPU。 |
| D-3 | 定时用 `deploy` 用户自己的 crontab：每小时检查一次，北京时间 06 点那一档运行，一天一次（与服务器时区无关）。 |
| D-4 | 安装、立即运行、查看状态、取回结果，全部由新工作流 `.github/workflows/tender-crawler.yml` 通过 SSH 完成，复用部署国内服务器的同一组密钥（`CN_DEPLOY_*`）。 |
| D-5 | 取回结果：每天北京时间 07:10 工作流把 `latest.json / latest.md` 取回，存为工作流附件 `tender-feed`（保留 7 天），并把摘要写在运行页面上。每日招标判断任务从这里读。数据只是公开公告，不含个人信息。 |
| D-6 | 规矩写死在程序里：只访问公开页面；每个网站两次请求间隔 ≥4 秒并遵守 robots.txt；遇 403/412/429/验证码当天停止该网站、不重试、不绕过；不登录、不报名、不发邮件；只用规则提取，大模型开关打开会被拒绝（以后若用，只能用国内已备案模型）。 |
| D-8 | （施工中发现，2026-11-08 补记）首次运行两个来源都不通：政府采购网**检索页**对服务器第一次访问就返回“频繁访问”（对云服务器 IP 的拦截），按规矩不绕过、关闭；改读政府采购网**公告列表页**（www.ccgp.gov.cn/cggg，静态页，访问正常）。交易平台旧域名 deal.ggzy.gov.cn 已停用，改用新版接口 www.ggzy.gov.cn/information/pubTradingInfo/getTradList；接口要求验证码（code 829）时当天停止。程序升到 1.0.2，服务器旧配置自动备份后迁移。 |
| D-9 | 新增只读诊断 `probe`（工作流选项），每个网址只访问一次、间隔 5 秒，用于网站改版后排查。 |
| D-7 | `ops/**` 和新工作流加入 `deploy.yml` 的 paths-ignore：改抓取程序不触发平台上线。 |

## 二、交付物

1. `ops/tender-crawler/`：程序、配置、测试（6 项）、`server-install.sh`（无 sudo 安装）、`cron.sh`（定时入口）。原 systemd 版 `install.sh` 保留，供以后有 root 的机器使用。
2. `.github/workflows/tender-crawler.yml`：手动运行可选 install / run / status / fetch；每天定时 fetch。
3. `docs/帮助/招标抓取.md`：怎么看结果、怎么改关键词、出问题怎么办。

## 三、施工顺序与验收

1. 本地测试 6 项全过。
2. 推送 main 后运行 install：服务器上 `check` 通过，crontab 有一行 `tender-crawler/cron.sh`。
3. 运行 run：生成 `latest.md`，每个来源状态为 ok / partial / blocked / error 之一（blocked 说明对方拦截，按规矩停止，不算程序故障）。
4. 运行 fetch：附件 `tender-feed` 可下载，运行页面显示摘要。
5. 更新“每日招标搜寻”任务，让它读取附件。
