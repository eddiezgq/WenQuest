# 实施细则 · 第 169 轮：国内零件库补上

日期：2026-11-14　状态：已完成（先做后补记：Eddie 11-14 “零件库也打不开”，紧接着第 168 轮补国内教材）

## 一、起因

国内数字工厂 `factory.wenquestech.online/library/latest.json` 返回 404（“零件库里没有这个文件”），所以国内“零件与机器人库”打不开。美国 `factory.wenquestrobotics.com` 正常，最新版本是 2026.11.21。

原因：零件库发布流程 `library.yml` 只把网页包解到美国服务器（`DEPLOY_HOST`），国内服务器从来没有收到过零件库文件。数字工厂本身（`factory.yml`）是两边都部署的。

## 二、决定与改动

1. `library.yml` 加一个任务“传到国内数字工厂”：
   - 从 GitHub Releases 取最新一版 `library-web-*.tar.gz`；
   - 用国内服务器的钥匙（`CN_DEPLOY_*`）传过去，用美国那边同一个 `factory/deploy/library.sh` 解包；
   - 解包后检查网址。
   以后每次发布零件库，美国、国内两边都会更新。
2. 手动运行时多一个选项 `cn_only=yes`：不重新生成零件库，只把最新一版传到国内。
3. `library.sh`：先 `mkdir -p library`。国内第一次传的时候还没有这个文件夹。

## 三、验收

- 这次推送改了 `library.yml`，会自动跑一次完整发布：生成新版本，再传美国和国内。
- 验收标准：国内 `https://factory.wenquestech.online/library/latest.json` 显示的版本号与发布的版本一致；Eddie 在国内数字工厂“资源 → 零件与机器人库”能打开，并能看到三维模型。
- 结果：通过。发布运行 43610526740：“生成与发布”成功，出了 2026.11.22 版；“传到国内数字工厂”成功，用时约 3 分钟。国内 `factory.wenquestech.online/library/latest.json` 显示 2026.11.22，与美国一致；`index.json`（1.1 MB）能打开。没有遇到目录归 root 的问题。待 Eddie 在页面上看一遍。

## 四、注意

- 网页包约 145 MB。跨境慢的时候可能要传很久，所以这个任务的时限给了 90 分钟。
- 如果国内服务器上 `/opt/wenquest/factory/library` 是由容器启动时自动建出来的，它会归 root 所有，deploy 用户就写不进去。遇到这种情况，请 Eddie 在服务器上执行 `chown -R deploy:deploy /opt/wenquest/factory/library`，然后用 `cn_only=yes` 重跑一次。
