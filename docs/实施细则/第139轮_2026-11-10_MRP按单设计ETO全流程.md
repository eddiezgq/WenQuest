按单设计（Engineer-to-Order，ETO）：客户拿着要求或图纸来，产品是这一单专门设计的，接单时还没有物料清单和工艺。
非标设备、工装夹具、定制减速器、机器人工作站都是这类。

## 一、现在有什么、缺什么

数字工厂的 MRP（`factory/digital/hub/mrp.py` 等）现在按“产品事先定好”工作：按库存生产，或在配置器里选参数下单。

| 环节 | 现在 | ETO 缺的 |
|---|---|---|
| 估算 | 配置器只对 3 个参数模板报价（标准成本 × 1.3）；客户模块有商机、报价单 | 没有模板的非标件：按客户要求逐项估（材料、外购件、各工位工时、外协、设计工时、风险预留），数量阶梯，报价改版留底 |
| 工单 | 订单 → 工单；物料、BOM、工艺事先就有 | 每单一个**作业号**，把报价、订单、设计、采购、工单、检验、发票串起来；这一单专用的物料、BOM、工艺在接单后由设计产生，**设计发布前不能下工单** |
| 物料 | 净需求按全厂库存、在途、占用算 | **专料专用**：请购单、采购单挂作业号，到货只给这一单用；长周期件可在设计冻结前先买（人批准）；外协工序走采购 |
| 计划 | 从开工日加工时推完工日 | 从交期**倒排**：设计 → 采购 → 加工 → 装配 → 检验 → 发货；看各工位已有负荷；报价时就回答“这个交期做不做得到” |
| 车间执行 | 工单、作业卡、报工、仿真车间 | 作业卡带作业号和**批准的图纸版本**（作业单）；工时、领料实际记到作业号上 |
| 质量 | 来料检验、工序在线检验、不合格品 | 每个作业按它自己图纸的关键尺寸生成检验计划（首件、终检）；**终检合格才能发货**；出合格证 |
| 开票 | 一张订单开一张发票 | 按**里程碑分期开票**（例如订金、设计确认、发货、验收），到了里程碑才起草；作业成本：**估算 vs 实际**、毛利 |

## 二、决定

1. **放在哪**：做在数字工厂的 MRP 里（两边共有的代码，问渠这边和 freecad-ai-parts 那边都能用），新增“作业（ETO）”页。演示放在减速器厂（演示工厂），演示数据标明虚构。
2. **ERPNext 只用自带单据、不改源码**：作业号 = Project；报价单 Quotation；销售订单 Sales Order（付款计划 Payment Schedule 写里程碑）；
   这一单专用的物料 / BOM（编号带作业号）；请购单、采购单、工单、作业卡都挂 Project；设计工时记 Timesheet；检验记 Quality Inspection；发票 Sales Invoice 按付款计划逐期开。
3. **AI 起草，代码定数，人签字**：
   - AI 读询价（文字、图纸 PDF / 图片）起草估算行、设计说明、检验项；
   - 合计金额、工时、交期倒排、净需求、发票金额都由确定性代码算；
   - 单价、费率、交期缺的标“未知”，**有未知项不能发报价**（不估、不填 0）。
4. **关口（人在界面上确认，留记录）**：发报价、接单、设计发布（冻结这一单的 BOM 和工艺，存内容指纹）、长周期件提前采购、首件判定、终检放行、每一期发票。
5. **设计变更**：发布后要改只能出新版本；已下的工单、采购单里受影响的列出来，让人逐条处理（取消、改量、照用）。
6. **企业之间不同的东西是配置数据**（写进工厂清单）：作业号前缀、里程碑和比例、风险预留比例、各工位费率。演示值标“示例”。
7. **不动现有流程**：按库存生产、配置器下单、已有演练和测试不改不放宽。

## 八、施工记录

### 139a 作业号与估算（PR #71，11-10 合并）

1. **作业与估算**（`factory/digital/hub/eto.py`、`eto_api.py`，新表 `eto_job`、`eto_estimate`）：
   - 一张询价一个作业号（`JOB-年份-序号`，前缀是配置）；估算行五类：材料、外购件、工序、外协、设计。
   - 计算（纯函数 `compute`）：材料 / 外购件 / 外协 = 每件 × 数量；工序 = (调整 + 单件 × 数量) / 60 × 工位费率（工作站的折旧 + 人工 + 能耗，和标准成本同一来源）；
     设计 = 工时 × 设计费率（一次性）；成本 = 小计 × (1 + 风险预留)；报价 = 成本 × (1 + 加价率)。最多 5 档数量阶梯。
   - **缺什么标“未知”、不能报价**：单价、调整时间、单件工时、设计工时、费率、风险预留、加价率任何一项缺都算不出那一档，不估、不填 0。
   - **改版留底**：报价发出后那一版冻结；再改存成新版本，旧版原样留着。
2. **起草**：AI 只给结构、用量、工时，**AI 给的价格一律丢掉**（价格只取物料主数据，或由估算员填）；工序名不在本厂工序表里的标错。
   没有模型时，要求里写了现有产品编号（如 WQR-105）就照它的多级物料清单和工艺起草；照产品起草时装配、加工中心等工位没有标准调整时间，标“未知”让估算员补。
3. **报价**：“生成报价提议”→ 预览（数量阶梯、合计）→ 人确认 → 桥接（新文件 `bridge/lib/erp_eto.js`）在 ERPNext 建
   Project（作业号）、物料（编号 = 作业号）、报价单（自定义字段 `wq_job`；报价单上报客户要的数量，其余数量阶梯和付款条件写进条款）。
   再执行一次不重建 Project 和物料。执行完作业记为“已报价”。
4. **配置数据**：工厂清单新增可选的 `eto` 一节（`factory/plant.py` 校验：前缀、比例范围、各期加起来 100、开票时点四选一），
   Excel 模板加“按单设计”“分期开票”两张表（可不填）；演示减速器厂的值写在 `factory/data.py`（示例值，页面上注明），
   `plants/wenquest-gearbox.yaml` 重新导出；企业帮助“工厂清单”一章加两行。企业清单没写这一节时，页面提示“本厂还没有配置”。
5. **页面**：新页“按单设计（ETO）”（`/eto`，导航在“从订单到回款”）：作业列表、新询价、估算表（可编辑）、报价与数量阶梯、未知项清单、估算版本；
   提议弹窗加了报价的预览。中英两套文字（英文表 56 条），i18n 检查 0 缺口。
6. **演练**：服务器演练（真 ERPNext）加第 13b 段：建作业 → 手填估算（2 件报价与手算一致）→ 报价提议 → 确认 → 查 ERPNext 里的项目和带作业号的报价单。
7. **测试**：`tests/test_eto.py` 9 条——手算对照、未知项挡报价、错误行、照产品起草、AI 不带价格、改版与冻结、接口全流程、
   清单校验、桥接 → 模拟 ERPNext（建 Project、物料、报价单，重复执行不重建）。
8. **偏差**：
   - 第四节“每段两边同步比对 0 差异”做不到：两边现在已有 174 处差异（别的轮次积下的）。按单设计的新文件先只在这边，
     等 139h 时一起同步到 freecad-ai-parts（那边改工厂清单格式要按那边规矩写 ADR）。

### 139b 接单与设计发布（PR #72，11-10 合并）

1. **接单**：作业“已报价”后，“客户接受报价”→ 接单提议 → 人确认 → ERPNext 建销售订单：单价按报出去的那一版，挂项目（作业号），
   引用报价单，付款计划按里程碑（订金的计划日期 = 下单日，其余 = 交期；金额最后一期补零头，加起来等于订单金额）。
2. **设计**（新文件 `hub/eto_design.py`，新表 `eto_design`）：这一单的物料清单和工艺，按版本存。
   - “照估算起草”：估算是照现有产品起草的，就取那个产品的顶层物料清单和工艺；否则估算的材料、外购件当子件、工序当工艺，没编号的成单新物料。外协行另记，139c 转采购。
   - “复制为新件”：把要改的现有自制件（例如输出轴组件 SA-300）复制成本单新件（编号 = 作业号-后缀），物料清单和工艺照抄，父件改用新件，再改它的工艺和子件。
   - 检查（纯函数）：新物料编号以作业号开头、不重复；类别、名称、单位必填；工序在本厂工序表、每件分钟大于 0；子件在主数据或本单新物料里、用量大于 0；
     自制件要有物料清单、外购件和原材料不能有；没有循环。外购件没写单价、供应商只提醒（算料标“待确认”），不挡。
3. **设计发布**：检查通过、已接单 → 发布提议（新物料、物料清单、指纹）→ 人确认 → 桥接在 ERPNext 建新物料、物料清单（带工序，子件先建）并设为默认，
   物料清单上记指纹（自定义字段 `wq_fingerprint`）；同一指纹已建过不重建。发布的那一版冻结（存指纹和确认人），再改出新版本；
   发布后并入工厂主数据（枢纽重启时从库里并回），算料、排产照原样用。
4. **设计没发布不能算料、下工单**：`mrp.plan_order` 对还没发布设计的作业报错。
5. **改版影响**：挂在作业上、还没完的工单、请购单、采购单列出来（桥接读回的单据补了“项目”字段）；139c 起才会有这些单据。
6. **页面**：作业页加“设计（物料清单与工艺）”页签；报价栏加“客户接受报价”；提议弹窗加接单（付款计划）和设计发布的预览。中英文 45 条。
7. **演练**：服务器演练第 13b 段接着做：接单 → 查 ERPNext 销售订单挂项目 → 照估算起草设计 → 发布 → 查 ERPNext 物料清单带指纹。
8. **测试**：`tests/test_eto_design.py` 5 条（设计检查、指纹与先后、照估算起草与复制为新件、接单—设计—发布全流程含“没发布不能算料”和改版、
   桥接 → 模拟 ERPNext 建销售订单（付款计划）与物料清单、重复执行不重建）。模拟 ERPNext 补了“物料清单提交后可改默认”（真 ERPNext 就是这样）。
9. **偏差**：第三节写“复用网页设计台”：这一段没接网页设计台（出图、校核），设计是在作业页上改物料清单和工艺；客户图纸附件同上，放到 139f。

### 139c 物料（PR #73，11-10 合并）

1. **作业算料**（新文件 `hub/eto_mrp.py`）：设计发布后，从作业逐层往下算（按低层码：一个件所有父件算完才算它）。
   - 本单专用件（编号以作业号开头）：不用库存，只认已挂在这个作业上的工单、请购单、采购单；
   - 通用件：先用自由库存（实有 − 安全库存 − 其他在手订单占用），再认挂在本作业上的在途；本作业自己的订单、工单不算“别的占用”；
   - 自制件净需求下工单（挂作业号），**只按净需求往下展开子件**（例如输入轴组件库存有 1 个，只做 1 个，它的子件也只算 1 套）；
   - 外购件、原材料净需求下请购（挂作业号；通用件按批量取整，专用件按实需）；没有供应商或提前期的标“交期待确认”，晚于交期的提醒；
   - 设计里的外协：按作业件数请购外协服务（不进库存的服务物料，编号 = 作业号-OS序号）。
   通用算料（`mrp.plan_order`）里“在途、占用”的算法抽成 `supply_demand()` 两边共用，原来的行为不变（原有测试全过）。
2. **提议**：“生成算料提议”→ 预览（逐层算料表、工单、请购）→ 人确认 → 桥接在 ERPNext 建工单（挂项目；作业本身的工单关联销售订单）和请购单（每行挂项目），
   外协服务物料不存在就先建。再算一次时，已挂在作业上的工单、请购不重复下。
3. **长周期件提前采购**：设计发布前，从当前设计草稿里挑提前期 ≥ 门槛的外购件、原材料先请购（单独的提议、人确认，请购单写明“设计第 N 版，未发布”）；
   门槛是配置 `eto.long_lead_days`（Excel“长周期件（天）”，不填按 15 天）；自制件、设计里没用到的、提前期不够的不能提前买；设计发布后改用作业算料。
4. **页面**：作业页加“物料”页签（接单后出现）：逐层算料表（专用件标“专用”）、提醒、生成算料提议；发布前显示长周期件勾选。
5. **演练**：13b 段加“作业算料 → 查 ERPNext 里挂作业号的工单”。

### 139d 计划（PR #74，11-10 合并）

1. **从交期倒排**（新文件 `hub/eto_plan.py`，纯函数 `schedule_tree`）：交期 → 发货预留（缺省 1 个工作日，配置 `eto.ship_days`）→ 作业本身的工序 →
   下一层自制件（父件开工前一天做完）→ …；外购件、原材料的“最晚到货” = 用它的件开工前一天。每件工期 = 单件分钟 × 件数 ÷ 480（一天 8 小时、串行），只算周一到周五。
2. **最早能交与松紧**：从今天往后排（采购按供应商提前期，各件按工期，子件齐了父件才开工），比出富余或晚几个工作日；晚了顺着最晚就绪的子件找关键路径，
   说出卡在哪（例如“晚 11 个工作日，关键路径：采购 RM-HT200-COVER（提前期 15 个工作日）；加工 HSG-002→SA-000→WQR-105”）。交期不明的采购件按 0 天算并列出来。
3. **工位负荷**：本作业按倒排的日子、其他在制工单按计划开工到完工的工作日平均摊开，每周每个工作站对能力（同时开工数 × 480 × 5），超了标红。
4. **报价时能否按期**（`feasibility`，还没设计时按估算粗算）：设计工时 ÷ 8 + 最长采购提前期 + 全部工序串行 + 发货预留 → 最早交期，和客户要的交期比；
   周期不明的外协、新物料列出来，有不明的不算“赶得上”。显示在报价栏。
5. **算料用倒排的日期**：工单计划开工 = 倒排的最晚开工（不早于今天，已经晚了的提醒），请购需求日 = 最晚到货日（来不及就按最早能到的日子并提醒）。
6. **页面**：作业页加“计划”页签：交期 / 最早能交 / 松紧，自制件倒排表（关键件加粗、已晚标红），采购件最晚到货表，工位负荷表；报价栏加粗算一行。
7. **演练**：13b 段加“查倒排结果”。
8. **测试**：`tests/test_eto_plan.py` 3 条（倒排与顺排手算对照、晚 3 天卡在采购、件数加倍工期加倍、交期落周末；报价粗算手算对照、周期不明不算赶得上；
   车床那周排满时本作业标超；算料工单日期 = 倒排最晚开工）。
9. **限制**：不排到具体某台设备、不算节假日（只去掉周末）、设计按一个人算；这些是粗排，够回答“能不能按期、卡在哪”。

### 139e0 作业卡时间重叠（PR 待合并）

1. **根因**（第 134 轮第八节第 2 条查实的）：教学情景重载时工厂时钟回到情景起点，新工单在某工位报的工时，和上一次情景里同一工位作业卡的工时落在同一段时间；
   ERPNext 按“工位同时开工数”判重叠（417），拒收这条工时。上一次情景的作业卡（含已提交的）一直在 ERPNext 里，所以每次重载后都会碰上。
2. **改法**（`bridge/lib/erp.js` 的 `onCycleEnd`）：ERPNext 报“重叠”时，从提示里取出冲突的那张作业卡，把这条工时顺延到那张卡最后一条工时之后（时长不变），
   再写；还冲突就再顺延，最多 6 次。别的错误（例如超过工单数量）照旧报出来。只改 ERPNext 里记的时段；总线上的事件（节拍、成本）照旧按仿真时间，
   所以作业的实际工时、成本不受影响。没选“工厂时钟不回退”：那会改动整个教学情景的日期，影响面太大。
3. **模拟 ERPNext**：重叠的提示改成和真 ERPNext 一样带出冲突的作业卡号（“… is overlapping with PO-JOB00005”）。
4. **测试**：`tests/test_jobcard_overlap.py`（上一次情景的工时 09:00–10:00，新情景 09:10–09:20 → 记成 10:00:01–10:10:01；不重叠的原样记；
   超过工单数量的照旧报错）；夏令时那条老测试照过。
5. **验收**：上线后看服务器演练日志里还有没有 417 重叠（第 134 轮第一节说 7 次日志里都有）。
