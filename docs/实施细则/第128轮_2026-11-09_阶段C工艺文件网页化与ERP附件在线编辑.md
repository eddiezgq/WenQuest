## 二、决定（建议，待确认）

| 编号 | 决定 |
|---|---|
| D-1 | **分两块做，先做本仓库的“工艺文件网页化”（C1），再做 ERP 附件在线编辑（C2）。** C1 全在本仓库，见效快；C2 主要在 `wenquest-ops` 仓库（质量 ERP），要单独开一轮，在那个仓库的会话里做。 |
| D-2 | **C1 工艺卡**：工艺规程的数据仍是唯一来源（审批、核算、ERP 工艺路线都靠它），网页上改的是**数据**，不是卡片排版：在数字工厂“工艺规程”页加“在页面上改工艺卡”——工序、工步、设备、夹具、切削参数、检验项按卡片的格子直接改，改完重新核算（`cards.check`）、AI 工艺评审照旧。导出 Word / PDF 用现有卡片版式；PDF 改走 OnlyOffice 转换（服务器上不用浏览器出 PDF）。 |
| D-3 | **C1 调机卡、计算书**：由设计计算出来，不让手改数字（改了就和计算对不上）。做法：缝纫机设计软件里“导出”之外加 **“存为网页文档”**——生成一份网页文档（第 126 轮格式），数字和红绿灯照计算结果，工程师可以加说明、改措辞、加照片，AI 可写“设计说明”初稿；每份记下是哪一版设计算出来的，设计改了提示“重新生成”。导出 Word / PDF。 |
| D-4 | **C1 的文档放在哪**：调机卡、计算书存在企业自己的工作区（缝纫机软件已按企业开通）；工艺卡随工艺规程存数字工厂。都不出境（国内、美国各一套）。 |
| D-5 | **C2 ERP 附件在线编辑**（后一轮）：在质量 ERP 里装一个小应用：附件是 docx / xlsx / pptx 时多一个“在线编辑”按钮，用本服务器的 OnlyOffice 打开，多人同时改，保存后新文件存回该附件（ERPNext 留旧版本）。每家试点企业的 ERP 都装；OnlyOffice 共用一套，按企业分开 JWT。数字工厂的 ERPNext（教学用）只读打开，不改。 |
| D-6 | **AI**：工艺卡由 AI 工艺评审员把关（已有），网页上改完自动再审；调机卡、计算书的“设计说明”AI 起草、人改；数字由计算核心给，AI 不改数字（第 121 轮 D-9）。国内只用 DeepSeek。 |

## 三、界面（定稿前的样子）

## 五、施工顺序与验收

施工顺序：工艺卡格子编辑（后端 → 前端）→ 卡片 PDF → 计算书 / 调机卡网页文档 → 帮助、方案 → 本地走一遍 → 上线 → 服务器上导出 PDF 实测。

验收：
1. 学生 / 工程师在数字工厂工艺规程页改一道工序的切削参数和检验项，卡片当场更新，核算和 AI 评审重跑；导出 Word、PDF 与改后一致。
2. 改坏的数据（缺设备、尺寸链不闭合等）在页面上标红，不能提交。
3. 平缝机设计“存为网页文档”得到计算书和调机卡两份，数字与 Word 导出一致；加一段说明、一张照片，导出 Word / PDF 都在；改设计后文档提示“重新生成”。
4. 国内服务器：文档存在国内，AI 走 DeepSeek，PDF 走国内 OnlyOffice。
5. 测试全绿（网关、数字工厂、教材第 50 章构建不变）。

## 六、要 Eddie 确认

1. **先后**：建议**本轮只做 C1（工艺卡、调机卡、计算书网页化）**，ERP 附件在线编辑（C2）放下一轮、在 `wenquest-ops` 仓库做。另一种是本轮两块一起做——要同时动两个仓库，周期长一倍。
2. **工艺卡怎么改**：建议**改数据、卡片照版式重排**（核算、审批、ERP 工艺路线都跟着走）；另一种是把卡片当普通文档随便改，灵活但和工艺规程脱节。
3. **调机卡、计算书的数字**：建议**数字不能手改**，只能加说明、照片；要改数字回设计里改再重新生成。
4. **C2 范围**：建议只做**质量 ERP（每家试点企业）**的附件在线编辑；教学用的数字工厂 ERPNext 只读打开。

## 七、施工记录

11-09 施工，偏差如下：

1. **工艺卡**：数字工厂新页面“在页面上改工艺卡”（`web/src/pages/ProcessEdit.vue`，地址 `/process/edit/<零件>`）；枢纽加 `GET/PUT/DELETE /api/process/drafts/<零件>`（每人每个零件一份草稿，表 `process_draft`）、`POST /api/process/live`（`cards.check` + AI 预检，不记录）。工序简图、定位夹紧符号等不在页面上改（保留原数据，新加的工序没有简图时卡片照常生成）。
2. **卡片 PDF**：枢纽把 Word 交给学习平台网关的内部接口 `POST /api/v1/internal/docx-to-pdf`（网关在 factory-edge 网络上加别名 `wq-gateway`，钥匙用两边都有的 `WQ_FACTORY_READ_KEY`），网关走第 122 轮的 OnlyOffice 转换。主工厂和演示工厂配了 `WQ_PDF_URL`；**班级工厂暂时只能导出 Word**（页面提示）。
3. **计算书、调机卡**：不另写一套块生成，而是把“导出”的同一份 Word 按顺序拆成块（`production/docx_blocks.py`），所以数字一定和 Word 一致；这些块标 `lock`，保存时服务器以生成的为准（改了数字、删掉都会还原；不能伪造“计算生成”的块）。新模块 `engdocs_api.py`，表 `edocs`（同一个 `webdocs.db`），按单位共享；页面用第 126 轮的文档页（`/pages/doc/doc?eng=<编号>`，不显示发布、版本、AI 初稿）。
4. **重新生成**：自己加的块按所在的计算小节（标题）放回该节末尾；开头的仍在开头、末尾的仍在末尾。
5. **AI**：计算书的“设计说明”沿用第 49 轮缝纫机 AI 助手（导出页勾“计算书带上设计说明”，存网页文档时一样带上）；工程文档页不另开 AI 改写。
6. C2 的交接草稿：`docs/方案/阶段C2_问渠ERP附件在线编辑_交接草稿.md`。
