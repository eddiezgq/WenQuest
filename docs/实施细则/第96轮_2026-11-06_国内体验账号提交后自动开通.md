# 实施细则 · 第 96 轮：国内版“注册”提交后自动开通体验账号

日期：2026-11-06
起因：Eddie 11-05 22:19：“我觉得提交后自动比较好。”（背景：第 91 轮给国内版顶栏加了“注册”，进预约表单并勾选“申请在线体验账号”；第 50 轮定的是管理员在“体验单位”页手工开通。）
状态：**待 Eddie 确认**（第六节）

## 一、现在的样子

- 官网表单提交 → 存进申请表 → 管理员在学习平台“管理 → 体验单位”点一下带入 → “开通体验” → 再给每个人“添加账号”，平台生成 12 位初始密码（只显示一次），管理员复制发给对方。
- 国内服务器**没有配发信**（SMTP 空着），平台发不了邮件。
- 国内生成式 AI 的网信办登记还没办（`WQ_AI_REG` 空）。第 50、87 轮正是因为这个，才定“按单位开通、不对公众开放”。

## 二、决定（建议）

| 编号 | 决定 | 理由 |
|---|---|---|
| D-1 | 表单勾了“申请在线体验账号”且信息齐全 → **当场自动开通**：建一家体验单位（体验期 90 天，账号数按申请，最多 5 个），并给**填表人自己**建 1 个账号 | Eddie 要提交后自动 |
| D-2 | **账号和初始密码直接显示在提交成功的页面上**（只显示这一次，提醒对方马上记下、登录后修改）。勾体验时“邮箱”改为必填（学习平台账号要邮箱，也用来“忘记密码”自己改密码） | 国内服务器发不了信；等阿里云邮件推送配好，再加一份发到邮箱 |
| D-3 | **同事的账号**：填表人登录后在“我的单位”里自己添加，不超过申请的账号数；管理员仍可在“体验单位”页加减、延长、停用 | 不用每个账号都找管理员 |
| D-4 | **防滥用**：同一手机号、同一邮箱、同一单位名只能自动开通一次；每个网络地址每小时最多 2 次；每天最多自动开通 20 家（`WQ_CN_AUTO_DAILY`）；总数仍受体验单位上限（`WQ_CN_MAX_ORGS`，现为 100）限制。超出的不报错，转为“已收到，人工审核后开通”，和现在一样 | 公开入口要防刷 |
| D-5 | **合规**：网信办登记办好之前，**自动开通的账号不开 AI 功能**（AI 建课、AI 助手等按钮显示“AI 功能在登记完成后开放”，可以浏览课程、教材、虚拟实验、数字工厂）；管理员人工开通、审核过的单位照旧可用 AI。`.env` 填了 `WQ_AI_REG` 后，自动开通的账号也自动开 AI | 自动开通等于对公众开放；生成式 AI 对公众提供要先登记 |
| D-6 | 管理员能看到：“体验单位”页标出“自动开通”，有一个开关可以随时**关掉自动开通**（关掉后回到人工审核） | 出问题能马上停 |

## 三、交付物

1. 网关 `demo_request.py` 提交时调用 `orgs.py` 的开通逻辑（共用一套，不另写）；`orgs.py` 加“自动开通”标记、填表人自助加同事、AI 开关（按单位）；配置 `WQ_CN_AUTO`（开关，默认开）、`WQ_CN_AUTO_DAILY`（默认 20）。
2. 官网表单：勾体验时邮箱必填；成功页显示账号、初始密码、登录入口；超限时显示“人工审核”。
3. 学习平台：“我的单位”（填表人加同事）；AI 功能入口按单位开关；管理页标“自动开通”、自动开通开关。
4. 测试：自动开通成功、重复手机号 / 邮箱 / 单位转人工、每日上限、AI 关闭与登记后打开、关掉开关后转人工。
5. 帮助：《国内体验账号（自动开通）》；隐私政策里“账号”一段补一句“申请体验时自动为你建立账号”。

## 四、施工顺序与验收

网关 → 测试 → 官网表单 → 学习平台页面 → 本机模拟国内服务器（`WQ_REGION=cn`）走一遍：填表 → 拿到账号 → 登录 → AI 按钮显示“登记后开放” → 加一位同事 → 管理员看到“自动开通” → 关开关后再提交转人工。推送、部署、写验收。
