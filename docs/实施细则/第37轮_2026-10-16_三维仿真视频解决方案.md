## 一、定位：一句话要一段工程级三维仿真视频

- **用户**：老师（课件、讲课视频），学生（实验报告、毕业设计展示），企业（产品展示、方案汇报、投标演示、操作培训、售后说明）。
- **用户做的事**：说一句要什么（“六轴臂从料台抓件放上传送带，透视电机，标关节角”），或者从平台里已有的东西一键出发：一个零件或装配、一次多体动力学仿真、一次有限元或流体结果、一个 CAM 刀路、一台数字孪生设备。
- **平台做的事**：AI 写场景脚本 → 运动由我们的求解器算（逆运动学、MuJoCo 多体动力学、刀路、流场）→ Blender 渲染 → 叠中英标注和读数 → 出 MP4 / WebM。几分钟先看低清小样，满意再出高清。
- **和别家的区别**：
  - **动作是算出来的**，不是动画师手调的，读数可信，可以写进报告和课件；
  - **和平台数据贯通**：设计、仿真、工艺、孪生的结果直接变成视频，不用导出再找人做；
  - **不装软件**，浏览器里下单，云上渲染。

## 二、在平台里长什么样

1. **入口**（三处，同一个功能）：
   - 数字工厂里每个结果页（多体、有限元、流体、CAM、孪生）上的 **“出三维视频”** 按钮；
   - AI 建课和白板课的 **“插入三维视频”**；
   - 独立的 **“三维视频”** 菜单：写一句要求，选模型（零件库、上传 STEP 或 glTF、程序生成的机械臂和机构）。
2. **小样**：先出 960×540、每秒 15 帧的低清版，约几分钟；网页上直接看，可以逐条提意见（“镜头再近一点”“第 3 步慢一点”“加剖面”），AI 改脚本重出。
3. **高清出片**：1920×1080，30 帧，MP4 和 WebM，中英标注，可选配音（平台 AI 声音）。
4. **风格**：
   - 工程图风格（默认，便宜快）；
   - 写实风格（产品宣传、投标，用 GPU）；
   - 透视、剖面、慢放、读数面板、轨迹线、力和力矩箭头，都是可选的“镜头效果”。
5. **交付**：进用户的素材库，可插进课件、白板课、报告；企业版可以下载原文件，可以加自己的标志。

## 三、技术路线

| 部分 | 做法 |
| --- | --- |
| 场景脚本 | 第 36 轮的 `scene.py` 改成通用格式：模型、运动来源、镜头、效果、标注都用数据描述（YAML），AI 只写数据，不写代码 |
| 运动来源 | 逆运动学路线（样片 A 那套）；数字工厂多体动力学（MuJoCo）结果；CAM 刀路回放；有限元变形和云图；流体流线；孪生的运行记录 |
| 模型来源 | 零件库（`library/`，含机械臂、腿式机器人等，只用许可证允许商用的）；教材 glTF；用户上传 STEP（转 glTF）；程序生成的参数化机构 |
| 渲染 | Blender（GPL，作为服务器上的独立程序调用，不分发，平台代码不用公开）。工程图风格用 CPU；写实风格用 GPU |
| 出片速度 | 帧切成多份并行渲染。开发和内部出片用 GitHub 免费构建机；平台上给用户出片用自己的渲染机：CPU 机器并行，写实走租用 GPU（照 `gpu-run.yml`，用完关机） |
| 检查 | 程序自动查：模型在画面内、不穿模、字不出框、读数与计算一致、每段动作在镜头里完整 |
| AI | 国内用 DeepSeek，美国用 Claude（照合规规定）；AI 只负责写场景数据和解释，不负责算运动 |

## 七之二、AI 只在已有模型上做（Eddie 22:34 确认）

- **AI 负责：** 挑模型、摆位置、填尺寸参数、编动作（算法算运动）、定镜头和标注。几何形状不让 AI 凭空生成。
- **模型来源（按顺序）：**
  - 零件与机器人库 `library/catalog`，共 270 条：标准件 20、机器人 167、机构 10（皮带、凸轮、齿轮系、槽轮等）、器件 12（关节模组、相机、夹爪、力传感器）、工装和机床附件 61；
  - 教材里的 glTF 模型；
  - 参数化生成器：AI 只填参数，例如齿数、杆长；
  - 用户上传的 STEP 或 FreeCAD 模型。
- **库里没有的东西：** 先用参数化生成器或用户上传补上，再收进库里，下次直接用。
- **AI 文字生成三维：** 精度不够、尺寸不可信，最多只用于背景小道具，不用于讲课的零件和机构。
- **品牌机器人：** 库里不少条目是真实品牌机型。对外视频按条目里记的许可使用；许可不清或用于商业宣传时，换成我们自己的通用机型，不仿品牌外观。

## 七之三、与 SolidWorks 等工具的关系（Eddie 22:36 问，23:12 同意写入；对外统一这个说法）

- **一句话：** “SolidWorks 负责设计和算，问渠负责讲出来、教出去。”同样适用于 FreeCAD、ADAMS、机器人仿真软件（RoboDK、Gazebo、Isaac Sim 等）。
- **不和它们比：** 不比求解精度，不比建模功能，不比实时交互仿真。
- **它们的局限：**
  - 要会用的工程师；
  - 授权贵，SolidWorks 每个座位几万元，Simulation、Visualize、Composer 另购；
  - 出来的是动画本身，讲解字幕、中英标注、读数面板、配音还要另外做；
  - 一段一段手工调，没法给一门课批量出。
- **我们补的就是这一段：**
  - 不会这些软件的人（老师、学生、销售）一句话就能出片；
  - 小样几分钟、高清约 10 分钟；
  - 自带步骤拆解、透视、剖面、慢放、中英标注、读数、配音；
  - 可以批量出；
  - 直接插进课件、白板课、实验指导书。
- **接住，不替代：**
  - 数字工厂已支持从 SolidWorks、FreeCAD 桌面提交模型；
  - 企业的装配导出 STEP 上传就能出片；
  - 以后可以读入它们的运动结果（关节角、位置随时间的表格）直接出片。
- **对学校：** 学生用不起、也学不会商业软件全套，要的是“看懂机构为什么这样动”。这正是三维仿真视频做的事。

### 第 2 步：通用场景格式 + 样片 B（2026-10-17，已完成）

- **场景格式：** 一段视频 = `scene.yaml`，只写数据；格式见 `tools/blender/场景格式.md`。渲染器是 `tools/blender/render.py`，工作流 `video3d.yml` 改为调用它。
- **能用的模型：**
  - 程序生成：`gen:arm6`（六轴臂加逆运动学）、`gen:conveyor`；
  - 简单形体：`box`、`cyl`；
  - 被搬运的小物件：`item`；
  - 已有虚拟实验的整机：`weblab:`。
- **运动来源：** 逐帧向已有虚拟实验要数（`tools/blender/weblab.py`）。在无界面浏览器里打开实验页，调用页面的 `__api.dump(主轴转角)`，取每个零件的位置、线的路径和读数。视频和学生在网页上操作的是同一套机构计算。平缝机虚拟样机页（`proto-lockstitch.html`，中英两页）只加了 `dump` 和 `mesh` 两个只读接口，页面行为不变。

  - 透视：两层合成，外壳半透明，关键零件和线清楚地叠在上面；

  - 底部字幕条；
  - 读数面板，加一圈 0–360° 的曲线和当前位置光标。

### 插入：旋梭钩线讲解片（Eddie 13:15“旋梭勾线不清楚细腻，这个很难理解，即便是看实物”；13:16“好”）

**决定：** 单独做一段约 1 分半的“旋梭钩线”讲解片，把这一步讲透。先出第 3 步“线环套过梭壳”的小样，确认看懂了再做完整的四步。

1. **线环按三维算**（`tools/blender/hookloop.py`）：
   - 线的一头在针眼，一头在布面针孔，中间挂在梭尖上；
   - 梭尖随旋梭转（主轴的 2 倍），线环被拉大，一股贴着梭壳前面，一股绕到梭壳后面，整个梭壳被套在线环里（里面是底线）；
   - 旋梭转过 270° 后脱线，转到 360° 时线环被挑线杆收完。
   - 尺寸取自虚拟样机：旋梭半径 13.5、梭尖 13.75、梭壳半径 10.6、机针 x = −17。
   - 画面上注明“示意：线径放大”。
   - 以后可以补进网页虚拟样机，学生在网上也能看到。
2. **分四步讲：**
   - ① 线环形成：针回升约 2 mm；
   - ② 梭尖钩入：约 206°，时间窗口约 0.3 ms；
   - ③ 拉大、套过梭壳：慢放，从两个角度看；
   - ④ 脱线、收紧、和底线交锁：用布料剖面小图表现。
   - 每步结尾定格，最后连贯播一遍。
3. **看得清的手段：**
   - 旋梭、梭壳半透明，梭尖用红点标出，红色弧形箭头表示旋梭转向；
   - 面线蓝、底线橙，线加粗；
   - 角落放同步的平面示意小图（第二版加）。
4. **风格：** 讲解用工程图画法（出片快，可反复改）；定稿后再出写实精华版。
5. **小样：** `video3d/旋梭钩线_套过梭壳/scene.yaml`，20 秒。正面看，转到斜上方，再看收线。
