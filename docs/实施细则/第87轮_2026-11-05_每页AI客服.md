## 一、现在的样子

- 平台里已有几处 AI：学习平台的 AI 助教、AI 建课（课程负责人）、缝纫机 / 凸轮 / 轴承软件里的 AI 助手；都只懂自己那一块。
- 官网、数字工厂、各软件页面上**没有**能回答“问渠是什么、某个模块怎么用、怎么开通”的客服。
- 能当知识的资料都在仓库里：`docs/帮助/`（50 多篇使用说明）、`docs/方案/`、`tools/site_home/catalog.yaml`（首页 37 项的名称、一句话、网址）、各书 `book.yaml`、国内版官网文字稿。

## 二、决定（建议）

| 编号 | 决定 | 理由 |
|---|---|---|
| D-1 | **一个客服，挂在所有页面**：官网（美国、国内）、学习平台、数字工厂、缝纫机 / 凸轮 / 轴承软件、评价与校情演示页，右下角一个“问问问渠”按钮，点开是对话框 | Eddie 要“每页” |
| D-2 | **答得对，靠“只按资料回答”**：客服的知识库由仓库里的帮助文件、方案、首页清单、国内版文字稿**自动生成**（每次部署重建，资料改了客服跟着改）；回答时先检索相关段落，只依据这些段落作答，**每个回答附出处链接**；资料里没有的，直接说“这个我不确定”，并给“联系我们 / 预约演示” | 大模型自己编最危险；有出处才能“正确回答” |
| D-3 | **知道你在哪一页**：页面把自己是哪个模块告诉客服，先按这个模块的资料答（例如在“数控编程”页问“怎么出 G 代码”） | 回答更准 |
| D-4 | **模型**：美国站用 Claude，国内站只用已备案的 DeepSeek（合规规则）；同一套知识库，中英文都能问 | 第 34、48 轮的合规规定 |
| D-5 | **不能做的**：不报价（只说“请预约演示”）、不承诺功能（计划中的写“计划中”）、不收集身份证等敏感信息；不替用户登录或操作；每条回答标“AI 生成” | 合规、不夸大 |
| D-6 | **防滥用与成本**：不登录也能问，按 IP 限流（如每小时 20 问）；单次回答长度上限；每天费用上限，超了提示“稍后再问”；对话记录保存 30 天，用于改进资料，不用于别的 | 公开入口要防刷 |
| D-7 | **答不上来的问题收集起来**：后台列出“客服答不上 / 用户点了没帮助”的问题，定期补进帮助文件——帮助文件越写越全，客服越来越准 | 闭环 |
| D-8 | **验收用一套考题**：先写 60 道常见问题（每个模块几道，中英文都有，含几道“资料里没有”的陷阱题），自动测：答对、附对出处、陷阱题不瞎编；通过率达标才上线，以后每次改动都跑 | “能正确回答”要能证明 |

## 三、合规提醒（国内站）

国内面向公众的生成式 AI 功能，按《生成式人工智能服务管理暂行办法》要到属地网信办登记，编号放在页面上（`.env` 的 `WQ_AI_REG` 还空着）。建议：**国内站客服先只对登录的单位用户开放**（与现在“按单位开通体验”一致），登记办好后再对公众开放；美国站直接对公众开放。

## 四、施工顺序与验收

1. 知识库生成（帮助、方案、清单 → 分段、建索引）+ 60 道考题。
2. 网关加客服接口（检索 + 模型 + 出处 + 限流 + 记录）；先跑考题，调到达标。
3. 前端小组件（一个脚本，各站点页面引用一行）；先上官网和演示页，再上学习平台、数字工厂、各软件。
4. 后台：答不上的问题列表。
5. 帮助：《AI 客服》使用与维护说明。推送、跟踪部署、写验收。

## 五、成本估计

美国站用 Claude 的较小模型、国内站 DeepSeek，一次问答约几分钱人民币；按每天几百次估，每月几十到一两百元，设每日上限。

## 七、Eddie 的决定（2026-11-05 09:49–09:54）与据此的做法

## 十、返修：国内站答非所问（2026-11-06）

起因：Eddie 11-06 00:29 在国内站问“管理员能打开 erp 吗”，客服堆出“缝纫机真机套件意向登记 · 给管理员”“课程委员会”等不相干片段；01:45：“每次回答都一样，乱七八糟”“太给 AI 丢脸了”。

原因：① 国内站没开大模型，只是按词搜帮助文件、把片段原样堆出来；② 知识库混进了大量给管理员、运维、开发看的小节，一个“管理员”就能把它们顶上来；③ 搜索只看词出现多少，不管问题里最要紧的词（如 ERP）有没有对上；④ 没有“没找到”的门槛，总能凑出几条。

Eddie 决定（01:47）：**国内站开 DeepSeek**（已备案模型，只依据我们自己的资料回答、标“AI 生成”；网信办登记前对公众提供有被认定未登记的风险，已告知，同体验账号开 AI 的决定）；**补一套常见问答库**作为第一道答案。

做法：
1. **常见问答库** `tools/assistant/faq.yaml`：官网访客最常问的约 60 条（是什么、能做什么、怎么体验、价格、部署、数据安全、AI 用什么模型、联系方式……），每条几种问法，中英对照，标国内 / 美国 / 两站。问题和某条问法足够像，直接给这条标准答案（标“常见问题”）。
2. **大模型档**：问答库没对上时，检索资料（问答库也作为资料）交 DeepSeek（国内）/ Claude（美国）组织回答；国内站开关 `WQ_ASSIST_CN_AI`（默认开，填 0 关）。
3. **检索改进**：给管理员 / 运维 / 开发的小节不进知识库；问题里要紧的词（越少见越要紧）资料覆盖不到 45% 就不拿出来；去掉表格分隔线、轮次备注、文件路径等杂质。
4. **没找到就说没找到**：问答库、资料都对不上时，只说“这个问题资料里没有，请留下联系方式，我们回复你”，不再堆片段。
5. 测试：原 60 题照过；加“管理员能打开 ERP 吗”“你们是做什么的”“能不能本地部署”“今天天气怎么样”等 20 题，要求答到点子上或明确说没找到。

**施工与验收（2026-11-06）**：
- `tools/assistant/faq.yaml` 36 条（国内 29、美国 21，中英），`build_kb.py` 把它并进知识库（463 段）；给维护、运维、开发的小节和表格分隔线、轮次备注、文件路径不进客服。
- 网关：先比常见问答（两字词重合度 ≥ 0.6 直接给标准答案，`mode: faq`）；再检索（问题里要紧的词覆盖不到 25% 的段落不要，资料里根本没有的词也算进分母，“火星”这类问题自然落空；`iso13485` 拆成 iso、13485）；国内站大模型档改由 `WQ_ASSIST_CN_AI` 控制（默认开，DeepSeek）；没有大模型时只给覆盖 ≥ 55% 的资料，原文摘一两句作直接回答；都对不上就说“这个问题资料里没有，请留下联系方式”。
