## 一、软件公司和工厂哪里不一样、哪里一样

软件没有毛坯、没有机床，但“生产”照样有一条线：**需求 → 编码 → 评审 → 构建 → 测试 → 安全扫描 → 签名发布 → 灰度上线 → 运维**。
所以数字工厂那一套全都用得上，只是换个说法：

| 工厂里 | 软件公司里 |
|---|---|
| 物料清单 BOM | **软件物料清单 SBOM**：用到的开源组件、第三方库（带许可证、版本、已知漏洞） |
| 进货检验 | 开源组件进来先查许可证（GPL 传染不传染）、查漏洞（CVE） |
| 工艺路线 | **发布流水线**：编译 → 单元测试 → 集成测试 → 硬件在环 / 压力测试 → 安全扫描 → 签名发布 |
| 工单 | 一次构建 / 一个版本 |
| 设备 | 构建服务器、测试机群、硬件在环测试台（真的关节驱动板、工控机）、云平台机房 |
| 测量值 | 测试通过率、代码覆盖率、构建时长、启动时间、中断延迟、内存占用、接口延迟 p99、可用性 |
| 出厂测试 | 发布前的门禁（不过不发） |
| 售后 | 线上监控、故障工单、值班、在线升级（OTA） |

## 五、软件公司要有的东西（“还需要哪些”）

1. **发布流水线页**（相当于计算机厂的“整机老化曲线”）：每次构建走到哪一步、哪一步失败、测试通过率、覆盖率趋势、构建时长。
2. **服务监控页（SLO）**：云平台各服务的延迟 p99、错误率、可用性和“错误预算”还剩多少；线上故障单和处理时间。
3. **软件物料清单与合规**：每个版本用了哪些开源组件、什么许可证、有没有已知漏洞；国内产品还要等保 2.0、软件著作权登记（写在帮助里，不做申报）。
4. **老师能注入的隐藏问题**（学生从数据里追）：
   - 第 3 台构建服务器时钟漂移 → 只有它跑的测试偶发失败（“重跑一下就过”是掩盖）；
   - 某次提交带进内存泄漏 → 长时间压测内存一直涨；
   - 云平台某台宿主机被“吵闹的邻居”占满 → 只有这台上的服务延迟高；
   - 一个配置错误随灰度发布推到 A 可用区 → 只有 A 区错误率上升；
   - 硬件在环测试台 2 号缓存配置错 → 只有它测的中断延迟偏高。
   不对症的措施：重跑测试、加机器、放宽门禁阈值、全员培训。
5. **AI 巡检规则**：每种问题一条（按构建服务器、宿主机、可用区、测试台分组看）。
6. **帮助**：“软件公司”一册（中英）。
7. **下一轮（167b）三个设计案例**：A 实时 OS 的调度（可调度性分析 + 在关节驱动板模型上跑中断延迟）；B 云存储三副本还是纠删码（可靠性和成本）；C 云平台在 20 柜算力中心上的容量规划与 SLO（排队论 + 仿真）。
