# 实施细则 · 第 157 轮：零件库连上外部零件库（只链接、不搬内容）

日期：2026-11-11
依据：Eddie 11-11 问 OpenPartsLibrary、SnapEDA 上 Seeed 的 Open Parts Library 是否进了我们的零件库，以及“其他类似的库可以借鉴吗”“或者我们直接连上就行”→ 提议三类做法 →“先做这个吧”（排在第 156 轮按单设计第三期前面）。
状态：**待 Eddie 确认**（第七节）

## 一、现在有什么、缺什么

| 外部库 | 内容 | 许可 / 条款 | 现在 |
|---|---|---|---|
| OpenPartsLibrary（GitHub alekssadowski95） | 直线导轨、铝型材、紧固件、板件，FreeCAD 装配 | AGPL-3.0 | 没进库。和我们的 Apache-2.0 不相容，不能搬 |
| SnapEDA / SnapMagic（含 Seeed 的 Open Parts Library 页面） | 电子元件符号、封装、部分 3D 模型 | 单个元件 CC BY-SA 4.0 + 设计例外；网站条款不许拿它的网站当来源在网上转发内容 | 没进库 |
| Seeed OPL KiCad 库（GitHub Seeed-Studio/OPL_Kicad_Library） | 约 340 种常备元件（电阻 113、连接器 55、芯片 50……），每种带厂商型号（MPN）和 Seeed 物料号（SKU）；另有 XIAO 等模块封装 | CC BY-SA 4.0 | 没进库 |
| FreeCAD-library | FreeCAD 零件 | CC BY 3.0 | **已接**：只收索引和缩略图，模型从原仓库固定提交下载（零件库页“F”部分） |
| bd_warehouse | 按参数生成螺钉、螺母、垫圈、轴承等 | Apache-2.0 | **已用**：标准件的造型程序（A 部分） |
| KiCad 官方元件库、MuJoCo Menagerie、robot_descriptions、ROS-Industrial | 电子元件、机器人模型 | 各自开源许可，已登记 | **已接** |
| FreeCAD 紧固件工作台 | ISO/DIN/ASME 紧固件 | GPL-2.0 | 没接；bd_warehouse 已覆盖同类件 |
| BOLTS | 标准件 | 整体 GPL-3.0，数据逐份不同 | 没接 |

缺的：
1. 零件库页上看一个件，没法顺手到外部库查同类件、厂商现货、别人的封装。
2. 电子件做物料清单时，不知道哪些料在 Seeed 深圳常备库（OPL）里——全用 OPL 的料，贴片最快 7 个工作日、价格也低。这是问渠贴片 11-06 定的“暂缓的供货查询”的一小步。

## 二、决定

1. **外部库一律“只链接、不搬内容”**：零件库页每个条目加“到外部库查”一组链接，链接按条目自己的标准号、型号或名称拼成对方网站的搜索地址，新窗口打开；
   不抓取、不转存对方页面和文件，链接旁写“外部网站，内容以对方为准”。AGPL、GPL、只许个人下载的库都只能这样接。
2. **Seeed OPL 只收“型号—物料号”索引**：从 OPL KiCad 库的固定提交里只取每种元件的名称、类别、厂商型号、Seeed 物料号，生成一份索引（单独一个文件，写明 CC BY-SA 4.0 和出处）；
   不收它的符号、封装图形。问渠贴片和电路板设计页的物料清单里，有厂商型号的行显示“在 Seeed OPL（物料号 …）”，查不到写“不在 OPL KiCad 库里（不代表没货）”——**这一栏只是提示，不参与任何合格判定**。
3. **不接 FreeCAD 紧固件工作台和 BOLTS**：标准紧固件已由 bd_warehouse 生成（同为 Apache-2.0），再接 GPL 的库只多了许可证上的麻烦。
4. **来源照规矩登记**：freecad-ai-parts 写一份 ADR（外部库的两种接法：链接、开源许可索引），`data/sources.yaml` 登记 Seeed OPL KiCad 库（`license: open`，CC BY-SA 4.0，核实条款）；链接类外部库在 ADR 里列清单，不入库所以不进 `sources.yaml`。

## 三、规则

### A 链接怎么拼（确定性，按条目类别）

| 条目 | 链接到 | 用什么查 |
|---|---|---|
| 电子元件（A-ELE-*、电路板设计用的芯片） | SnapMagic（SnapEDA）搜索、Seeed OPL 页面 | 厂商型号；没有型号的用“封装 + 数值”，如 0402 100nF |
| 机械标准件（A 部分 bd_warehouse 生成的） | FreeCAD-library 搜索、McMaster-Carr、MISUMI | 标准号 + 规格，如 ISO 4762 M5x16 |
| 厂商件（伺服电机、减速器、驱动器、传感器） | 已有的“官方技术参数表”链接；另加厂商官网搜索（有的话） | 厂商型号 |
| 机器人、机构 | 不加（已有原仓库链接） | — |

- 每个外部网站的搜索地址施工时逐个在浏览器里打开核实，打不开结果页或要求登录才能搜的不放。
- 地址模板集中写在一个配置文件里（网站名、地址模板、适用类别），以后换网站、加网站只改这一处。

### B OPL 索引

- 来源：`Seeed-Studio/OPL_Kicad_Library` 固定提交（施工时记下提交号），读 `Seeed Fusion Component Libraries for KiCad/*.lib` 里每个 `DEF` 的名称和 `MPN`、`SKU` 字段。
- 输出：`eda/parts/opl_index.json`：`{source, commit, license: "CC-BY-SA-4.0", attribution, items: [{mpn, sku, name, category}]}`；生成脚本可重复跑，测试核对“重新生成与仓库里的一致”。
- 匹配：物料清单行的厂商型号与 `mpn` 完全相同（忽略大小写、空格）才算“在 OPL”；不做模糊匹配，不按“封装 + 数值”猜。
- 显示：物料清单表加一列“Seeed OPL”；整张清单上方写“N 行中 M 行在 OPL 里；其余不代表没货，到 Seeed 报价时再核”。

## 六、不做的

- 不复制 OpenPartsLibrary、SnapEDA、McMaster-Carr 等网站的文件、图片、参数（许可或条款不允许）。
- 不调用 SnapEDA、Octopart 等商业接口实时查价查库存（要付费、要钥匙；以后有试点客户再定）。
- 不收 OPL 的符号、封装图形；不按“封装 + 数值”模糊匹配被动件。
- 不接 FreeCAD 紧固件工作台、BOLTS（理由见第二节第 3 条）。
- 链接只是方便查找，外部网站上的参数不进零件参数、不参与校验；要用就按原来的规矩登记来源、逐项核实。
