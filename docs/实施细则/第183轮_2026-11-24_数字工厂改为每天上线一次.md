# 实施细则 · 第 183 轮：数字工厂改为每天上线一次

状态：**已完成**（2026-11-24 Eddie “按建议”）

起因：学习平台和官网已改成每天上线一次（11-24 Eddie：不要频繁上线，全部完成、核查后再上线）。但数字工厂（`.github/workflows/factory.yml`）一推送就构建、上线。11-24 改帮助文字也触发了两次上线，都手动取消了。

## 决定

1. **推送只跑检查**：测试、本地版能起来、电路板检查、录帮助视频照跑，不构建镜像、不上线。
2. **每天上线一次**：UTC 21:13（北京时间 5:13、美东 16:13）。和学习平台的 UTC 19:43 错开，两边都要往国内服务器传镜像，错开免得抢。
3. **没改动不上线**：每日定时先比“上次成功的定时 / 手动上线”到现在，数字工厂相关文件（推送触发的那些路径）有没有改动。没有就整轮跳过，不白构建。
4. **要马上上线**：Actions 里手动启动“Digital factory 数字工厂部署”。照规矩先问 Eddie。
5. 推送检查和每日上线分开排队，推送不会排在上线后面等。

## 交付物

- `.github/workflows/factory.yml`：加每日定时、`changes` 作业；构建（及其后的上线）只在非推送时跑；排队分组按事件区分。
- `CLAUDE.md` 技术速查写明。

## 验收

- 推送本改动时，数字工厂工作流只跑检查，“构建镜像”“部署到服务器”“部署到国内服务器”都显示跳过（记录见下）。
- 第一次每日定时：有改动就构建、上线；没有就跳过。
