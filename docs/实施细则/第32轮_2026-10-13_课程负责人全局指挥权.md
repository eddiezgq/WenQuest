# 实施细则 · 第 32 轮：课程负责人的全局指挥权（已确认）

日期：2026-10-13
起因：Eddie：“交互性非常重要。课程负责人应该对开发课程的全局有指挥权，相当于开发者有这个权利，要不停地修改、补充。开发课程是一个不断完善的过程。”

## 一、现状：课程负责人能做什么、不能做什么

第 31 轮以后，课程负责人（Claude）**能**：
- 看：资料、教材、研读笔记、大纲、设计书、已写的课（正文、练习、审稿意见）。
- 改草稿：要求、主教材、大纲（章、课时、周次、目标、教材章节）、课程设计书，可撤销。
- 派活：写一课、写几课、写下一课、整课重写、重做大纲或设计书、研读教材、推倒重来。

**不能**（这就是“没有全局指挥权”的地方）：
1. **改一课的局部**：只能整课重写。想换掉机器人问题、改一段讲义、加一道例题、调一个动画分镜，都得从头再写一遍，又慢又容易把好的部分改坏。
2. **单独重做某一样成品**：老师页面上有“重做实验”“重做动画”“重录讲课视频”的按钮，课程负责人却调不动。
3. **课程层面的东西**：考试、测验、作业的整体安排；教学日历；课程首页、公告等，目前都不在它手里。
4. **已发布的课**：规定“永远不改”，课上线后发现问题也没有办法完善。
5. **自己的工作计划**：没有一份它自己维护的“开发计划/待办”，每次对话都从头想；一课写完、审稿提了意见，它不会主动接着改。

## 二、决定（待确认）

**D1 课程负责人是这门课的总开发者**：课程的每一样东西（大纲、设计书、每一课的每一部分、每一样成品、课程层面的考试与日历）都能看、能改、能重做；老师随时插话、改主意，它随时调整。自主程度三档照旧决定“直接做还是先问”。

**D2 改一课的局部，不整课重写**：新增“改课时”能力——指定一课的某一部分（机器人问题、概念、某段讲义、例题、动画分镜、实验任务、建模五步、生活例子、小结、自测题、插图、练习与答案），直接改这一部分；只重新生成受影响的成品（例如只改了讲义就只重排讲义和课件，不重做动画和实验）。改前存快照，可撤销。

**D3 单独重做任一成品**：课程负责人能调用已有的“重做实验 / 重做动画 / 重录讲课视频”，以及新增的“重做插图 / 重出练习 / 重排课件”。

**D4 课程层面**：考试、测验、作业的整体安排（题量、分值、覆盖哪些课）和教学日历由课程负责人起草、修改；第一步先做“期中/期末考试”和“课程测验计划”，课程首页与公告放后面。

**D5 已发布的课可以继续完善**（建议）：改动先做在“新版本”上，学生看到的仍是旧版；老师确认后新版本替换上线（等于重新发布，走原来的审核流程）。

**D6 开发计划（看板）**：课程负责人维护一份“课程开发计划”：每章每课的状态、审稿意见、它认为还要完善的地方、下一步做什么。老师在右边能看到、能改。每完成一项工作，它读结果、更新计划，并说出下一步建议。

**D7 持续完善的节奏**：
- “小改直接做”：局部修改直接做；整课重写、批量工作、重新发布先问。
- “放手做”：审稿意见、检查清单没过的项，它自己接着改，直到过关或需要老师决定；每一步都在对话里留改动卡片，老师随时能停、能撤销。

## 三、规则

- 守则（`principles/course_lead.md`）加“总开发者”一节：对全局负责；先看再改；改局部不推倒；每做完一步更新开发计划；说清改了什么、下一步是什么。
- 已发布的课：只改新版本，学生看到的版本要老师确认才换。
- 撤销：所有局部修改都进改动历史；撤销恢复这一课改动前的内容和成品。
- 删除写好的课、推倒重来、发布、重新发布，永远要老师确认（不变）。

## 四、交付物

1. 网关：`edit_lesson`（按部分改一课）、`redo_part`（重做某样成品）、课程层面的考试/测验计划与日历工具、已发布课的新版本、开发计划；对应的提示与守则。
2. 网页：右边加“开发计划”页签；课时页显示“新版本待发布”；改动卡片点开能看到改了哪一部分。
3. 测试：局部修改只重做受影响的成品；撤销恢复；已发布的课改的是新版本；“放手做”下按审稿意见自动接着改并能停。
4. 帮助：《AI 建课使用说明》加“和课程负责人一起不断完善课程”。

## 五、施工顺序与验收

1. D2 + D3（局部修改、单独重做）——价值最大，先做；验收：让它“把 1.1 的机器人问题换成移动机器人”，只改问题及相关例题，课件更新，动画实验不动。
2. D6 + D7（开发计划、持续完善）；验收：写完一课后它自己读审稿意见、列出要改的、在“放手做”下改到过关。
3. D5（已发布课的新版本）；验收：改已发布的一课，学生端不变，确认后才更新。
4. D4（考试、测验计划、日历）；验收：让它出期中考试，按大纲覆盖、可改可重出。
5. 收尾：按细则逐条验收，写进本文件；更新帮助与 `docs/方案/`。

## 施工记录

### 第 1 步：D2 + D3 改一课的局部、单独重做成品（2026-10-14）

- 新模块 `services/gateway/app/lesson_edit.py`：后台工作 `rework_lesson {lesson_id, set, rewrite, note, redo}`。
  - `set`：课程负责人自己写好的新内容，直接替换这一部分（机器人问题、概念、讲义、例题、动画分镜、实验设计、建模五步、生活例子、小结、自测题、插图设计、课名、目标）。
  - `rewrite` + `note`：主讲教授只重写这几部分（带上现在的整课，保持同一个机器人问题和记号）。
  - `redo`：单独重做动画、虚拟实验、插图、练习与答案、实验指导书和教案、讲解视频。
  - 只重做受影响的成品：改了动画分镜就重做动画，改了实验设计就重做实验，改了插图设计就重画插图；课件、讲义页、指导书、报告模板、教案每次重新排版；内容有改动时讲解视频重新生成。
  - 改之前把这一课的文件夹（讲解视频除外）和记录存一份（每课保留最近几份），“撤销上一步”恢复。
  - 每次改动记入这一课的 `edits`，页面上显示“课程负责人改过的地方”。
- 课程负责人的新工具 `edit_lesson`；`get_lesson` 现在给出这一课每一部分的内容，供它对照修改。单课改动算“轻活”：“小改直接做”档直接开始，“每步都问”档变提议。
- 守则加“你是这门课的总开发者”一节。

**施工中发现并修好的一个老问题**：后台连续写几课（`write_lessons`）、以及课程负责人派的连续几步工作，每一步都另读一份项目来做，最后被后台工作的收尾保存盖掉——写好的课会丢（10-13 Eddie 那次就算模型没出错，写好的第一课也会丢）。现在整个工作只用一份项目，每步之前先存盘再就地刷新。加了回归测试。

**偏差**：
1. 已发布的课暂不能改（第 3 步做“新版本”）。
2. 撤销不恢复已经重新生成的讲解视频（视频文件大，不做备份）。

**测试**：`tests/test_lesson_edit.py`（换机器人问题只改这一部分、其他成品不重做、页面更新；改实验设计只重做实验；两次撤销回到原样；课程负责人用 `edit_lesson` 重出练习；连续写两课两课都在）。网关测试全部通过（210 个，微电子 7 个本机跳过）；前端测试、H5 构建通过。

**待验收**（上线后 Eddie 试）：对一课说“把机器人问题换成……”，看是否只改这一部分、课件跟着更新；再说“撤销”。

## 附：部署提速、省 GitHub 用量（2026-10-14，Eddie 同意）

**问题**：每次推送都把 9 本教材全部重新检查一遍（《机器人学》一本就近两小时），哪怕这次只改了网关程序。10-13 修了几轮，GitHub Actions 当月额度用完，第 32 轮第 1 步卡在最后一步没上线。

**决定**：只检查这次改到的教材。
- 和“上一次部署成功的那个版本”比，看哪些文件变了：
  - `textbook/<书>/` 变了 → 检查这本书；
  - 检查工具或多本书共用的东西变了（`textbook/tools/`、`services/labcheck/`、实验工具包 `services/gateway/app/production/labkit/`、`factory/`）→ 全部检查（部署工作流本身改了不算，免得改一次流程就全检一遍；要全检可以手动运行一次）；
  - 每周一的定时部署、手动运行 → 全部检查（顺带更新 Moodle 安全补丁）。
  - 找不到上一次成功部署（例如第一次）→ 全部检查。
- 没有教材要检查时，跳过教材检查，部署照常进行；服务器上的教材保持不变（部署只替换这次检查过的书，本来如此）。
- 预计只改程序时，从推送到上线约 15–20 分钟。

**交付**：`.github/workflows/deploy.yml`（`books` 任务算出要检查的书；`textbook` 没有书时跳过；`deploy` 在教材检查跳过时照常进行）。帮助文件《本地测试环境》“推送与部署”一段补一句。

## 附：按钮点了“没反应”（2026-10-14，Eddie 试用）

**现象**：点“提交委员会”没反应。
**原因**：按钮背后的请求被服务器拒绝时（最可能是“课程委员会还没有设立”），错误提示只显示在页面最上方，人在页面下方看不到，像是没反应。
**修正**：AI 建课页面所有按钮操作失败时，除页面顶部提示外，再弹出一条 4 秒的提示，说清原因。
