## 二、查到的原因（对照代码，2026-10-12）

| 现象 | 原因 |
|---|---|
| **专家版一开口就 ai_error** | 专家版课程负责人用的模型是 `claude-opus-5-5`（`config.lead_model`），请求里带了 `thinking: {"type": "enabled", "budget_tokens": …}`（`ai.py` 的 `agent()` 和 `think_json()`）。Anthropic 的 Opus 5.5 迁移指南写明这种写法会被拒（400：`"thinking.type.enabled" is not supported for this model`），新模型只接受自适应思考 `{"type": "adaptive"}`，深浅用 `output_config.effort` 控制；Opus 5.5 也不接受强制 `tool_choice`。所以专家版**每一次**都失败。审稿人（`review.py`）也走 `think_json` 加这个模型，同样会失败。 |
| **ai_bad_output** | 原来的课程负责人每一步都要求模型“只按固定 JSON 格式回答”（强制工具调用），输出上限 8000 词元。完善 17 课的大纲这种大活，输出被截断或格式不全，就判为“没有结构化输出”。 |
| **server_error** | 上一步失败后的连锁错误，程序没有把失败接住、讲人话。 |
| **大纲用说的改不了** | 原来的课程负责人只能做事先写死的十来种动作，“先把大纲完善”不在其中；专家版能改，但它坏了。 |
| **整体僵硬** | 建课被做成固定的四步流水线（了解要求 → 资料盘点 → 大纲与日历 → 逐课建设），每步一个专门的提示词和固定格式。AI 只能在格子里填空，老师一说格子外的话就接不住。 |

## 三、决定（建议）

**课程负责人就是 AI 内核本身**（美国用 Claude，国内部署用已备案模型），带着一套工具和一份守则，跟老师自由对话、自己判断下一步做什么。不再有写死的流水线和意图分类。

### 3.1 一个课程负责人，一份守则

把各步骤的提示词换成一份《课程负责人守则》（原则性的，不规定步骤）：

1. **目标**：建出一门完整的课，按问渠课程标准：内容、网页互动课件、视频、作业、测验、考试；理工课每节“实际问题 → 概念 → 动画 → 虚拟实验 → 建模求解”；中英对照；实验配指导书和报告模板。
2. **方式**：
   - 先听懂老师要什么，拿不准就问一个问题；
   - 读了资料再说话，引用页码，不编；
   - 有主见：老师的安排有问题就说出理由，给出更好的做法，老师拍板。
3. **边界**：
   - 已发布的课不改；
   - 花大量算力的工作和发布，要老师点头（见 3.3）；
   - 老师说“停”就立刻停；
   - 做了什么就说什么，没做成就说没做成。
4. **四步变成清单**：了解要求、资料盘点、大纲与日历、逐课建设，还会显示在顶上，但只是进度，不是关卡。随时可以回头改大纲、换教材、重做设计书。

### 3.2 工具（课程负责人自己决定什么时候用）

| 类别 | 工具 |
|---|---|
| 看 | 资料清单、读某几页、在资料里搜、教材目录、研读笔记、课程设计书、大纲与日历、某课全文、审稿意见 |
| 改草稿（立即生效、可撤销） | 大纲：增删课时和章、改名、调顺序、拆分合并、改周次与日历、改目标与对应教材页码；课程设计书逐项改；研读笔记；某课的局部修改 |
| 派活给专门的助手 | 课时撰写、动画设计（Manim 3Blue1Brown 风格）、虚拟实验设计、网页互动课件、作业测验与考试命题、审稿；可并行。每个助手也只是一张**原则卡**：角色、标准、要交出的东西，具体怎么做由 AI 自己判断 |
| 要老师点头 | 批量写课（比如“把剩下 15 课都写了”）、重做全部大纲、删除已写好的课、提交课程委员会发布 |

### 3.3 自主程度（老师可以随时调）

| 档位 | 改草稿（大纲、设计书、未发布的课） | 批量生成、删除、发布 |
|---|---|---|
| 每步都问 | 先给出改动预览，老师点“确认” | 先问 |
| **小改直接做（默认）** | 直接改，右边高亮改了哪里，一键撤销 | 先问 |
| 放手做 | 直接改 | 批量生成直接做，删除和发布仍然先问 |

### 3.4 互动

- 回复逐字流式显示，同时显示正在做什么（“正在读教材第 3 章”“正在改第 5–6 周”），随时能按“停”。
- 右边的大纲、日历、设计书**实时跟着变**，改过的地方高亮；每次改动都进历史，可以逐条撤销。
- 老师也可以在右边**直接改**大纲（拖动排序、点名字改名、改周次），课程负责人看得到这些改动。
- AI 在忙的时候老师说话，立刻得到回应，不排队、不丢。
- 出错时讲人话（“模型这会儿太忙，30 秒后自动重试”），不显示错误代码；自动重试一次，再不行换备用模型。

### 3.5 AI 内核可换

- 课程负责人只依赖一层“内核接口”：对话、思考、调用工具。
- 美国用 Claude：课程负责人用 Opus 5.5（自适应思考，effort 中到高）；大量撰写用 Sonnet。
- 国内部署时换成已备案的模型：DeepSeek、通义等都支持工具调用。守则和工具不变。

## 七、施工记录

### 第 0 步：先修故障（2026-10-12）

- `ai.py`：新增 `model_rules()` / `thinking_fields()`：Claude 5 代模型改用自适应思考（`thinking: adaptive` + `output_config.effort`），不再发 `budget_tokens`；5.5 及以后的模型不强制 `tool_choice`（改为 auto，并在提示里要求调用 `output`，文本里有 JSON 也接受）；输出被截断时自动放大上限重试一次（最多 32000）。专家版课程负责人、审稿人、教材研读都走这里。
- 错误不再显示代码：`ai.plain()` 把错误码换成中文说明（专家版、逐课建设的提示都改了）。
- 测试：`test_expert` 改为检查自适应思考；新增 `test_model_rules_for_new_claude_models`。网关测试 199 通过（本机缺 yosys 的 4 个微电子测试除外，CI 上有 yosys）。

### 第 1–3 步：AI 课程负责人、改草稿与撤销、自主程度、流式回复（2026-10-12）

- **守则**：`services/gateway/app/principles/course_lead.md`，每次对话读一次，改了即生效。与第三节不同：守则放在网关程序目录里，没有放 `docs/方案/`，因为服务器上的网关容器只带程序目录（见下“偏差”）。
- **默认就是 AI 课程负责人**：`lead_v2_on()` 改为模型能当代理时默认开启；“专家版（试用）”开关从页面上去掉。系统提示 = 守则 + 工具用法 + 步骤清单 + 项目概况（含自主程度）。
- **新工具**（`lead_agent.py`）：`edit_course`（改草稿，按自主程度直接做或变提议）、`start_work`（派活，按自主程度直接开始或变提议）、`undo`、`history`；原有的看资料、研读笔记、`propose` 保留。
- **细粒度大纲操作**（`lead.py`）：`set_lesson`（改名、目标、周次、教材章节）、`add_lesson`、`move_lesson`、`remove_lesson`（只限未写的课）、`move_chapter`、`rename_chapter`、`set_calendar_note`；批量写课 `write_lessons`。
- **自主程度**：`ask` / `small`（默认）/ `free`；删除已写的课、推倒重来永远是提议。接口 `PUT /studio/projects/{pid}/autonomy`。
- **改动历史与撤销**：课程负责人和老师的每次改动（含老师在右边手改大纲、改设计书）先存一份快照，最多 30 份；`POST /studio/projects/{pid}/undo` 恢复安排，不丢之后写好的课时内容和已发布的课。对话里出现“改动卡片”；右边改过的课时高亮；“大纲与日历”里列出最近的改动。
- **流式回复与停止**：`ai.agent()` 支持流式（`_stream` 解析 SSE，文字边到边显示），回复草稿通过项目的 `lead_draft` 给页面（思考时每秒刷新一次）；思考中发“停”或点“停”，下一轮工具调用前停下。
- **测试**：新增 `tests/test_lead_agent.py`（直接改大纲并撤销；“每步都问”变提议；小改档下批量写课变提议；老师手改可撤销；流式解析）。网关测试 203 通过（本机缺 yosys 的 4 个微电子测试除外）；前端测试、H5 构建通过。
