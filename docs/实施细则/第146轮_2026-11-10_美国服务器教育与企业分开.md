# 实施细则 · 第 146 轮：美国服务器教育与企业分开

日期：2026-11-10
依据：Eddie 11-10“美国这边没有合适的升级方案”“美国可以考虑另开一个服务器”“我倾向于教育和企业业务分开”。
状态：**草案，待 Eddie 确认**（确认前不施工；改部署流程、搬数据都要 Eddie 同意）

## 一、现状

- 美国只有一台服务器（DigitalOcean 纽约，8 GB）：学习平台（Moodle、网关、网页、动画、实验检查、配音、三维、文档服务）、官网、凸轮、轴承、问渠电子、数字工厂（教学工厂、演示工厂、6 座班级厂，ERPNext 共用一套）、问渠质量 ERP（演示 + 试点企业，`wenquest-ops` 仓库部署）。
- 11-10 部署时 `free -m`：总 7.9 GB、已用 6.5–6.7 GB、可用约 1.3 GB。Eddie 看过 DigitalOcean 升配，没有合适的方案。

## 二、决定（草案）

1. **按业务分两台**：

| 放哪台 | 内容 |
|---|---|
| **教育服务器**（现有这台） | 官网、学习平台（含 AI 建课、教材、白板、三维视频、虚拟实验、评价、校情）、经典界面、文档服务、教学用数字工厂（教学工厂 + 班级厂，ERPNext 一套）、问渠电子 |
| **企业服务器**（新开） | 问渠质量 ERP（演示 + 每家试点企业）、企业版演示工厂（`demo.`、`demo-erp.`）、凸轮、轴承 |

2. **要 Eddie 定的两处“两边都用”的**：
   - **缝纫机设计软件**：现在是学习平台里的一页（企业按账号开通，课程也用它）。建议**先留在教育服务器**（拆出来要改登录和账号），以后企业客户多了再单独拆。
   - **数字工厂里给企业的工业园各厂**（电路板、芯片、传感器、电机、缝纫机厂）：现在是班级厂，学生和企业演示都用。建议**留在教育服务器**，企业演示用 `demo.` 那座。
3. **新服务器**：DigitalOcean 纽约机房、Ubuntu 24.04、**8 GB**（质量 ERP 每家约 0.85 GB，演示工厂约 1.2 GB，凸轮、轴承各几百 MB；留出再开几家试点企业的余量）。
4. **网址不变**，只改 DNS 指向：`qms`、`qms-erp`、`*.qms`、`*.qms-erp`、`demo`、`demo-erp` 指到新服务器；其余不动。新服务器自己的 Caddy 办证书。
5. **搬数据**：质量 ERP（演示和试点企业）用 `wenquest-ops` 的备份恢复；演示工厂的 ERPNext 站点 `demo` 和历史库 `wq_demo` 用数字工厂的备份恢复脚本拆出来搬。搬的那段时间这几个网址停用（约半小时），挑晚上做。
6. **两台之间**：单点登录、演示工厂转 PDF、凸轮和缝纫机提交计算等原来在同一台机器的内部网络里走的，改成走 HTTPS 网址加钥匙。
7. **国内不变**：国内服务器已升到 16 GB，这次不拆。

## 四、施工顺序与验收

1. Eddie 在 DigitalOcean 开新服务器（8 GB、纽约），加部署用的 SSH 钥匙（步骤另给），把 IP 告诉 Claude。
2. 初始化新服务器 → 部署流程加新目标 → 先在新服务器装好空的企业服务（不切 DNS）。
3. 晚上：两边备份 → 搬质量 ERP 和演示工厂数据 → 改 DNS → 核对。
4. 原服务器停掉已搬走的服务，看内存。
5. 验收：所有网址照常打开、能登录（学习平台、数字工厂、质量 ERP 演示和每家试点企业、演示工厂、凸轮、轴承）；试点企业的数据一条不少；原服务器可用内存明显增加。
