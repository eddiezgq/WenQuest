# 实施细则 · 第 146 轮：美国服务器教育与企业分开

日期：2026-11-10
依据：Eddie 11-10“美国这边没有合适的升级方案”“美国可以考虑另开一个服务器”“我倾向于教育和企业业务分开”。
状态：**草案，待 Eddie 确认**（确认前不施工；改部署流程、搬数据都要 Eddie 同意）

## 一、现状

- 美国只有一台服务器（DigitalOcean 纽约，8 GB）：学习平台（Moodle、网关、网页、动画、实验检查、配音、三维、文档服务）、官网、凸轮、轴承、问渠电子、数字工厂（教学工厂、演示工厂、6 座班级厂，ERPNext 共用一套）、问渠质量 ERP（演示 + 试点企业，`wenquest-ops` 仓库部署）。
- 11-10 部署时 `free -m`：总 7.9 GB、已用 6.5–6.7 GB、可用约 1.3 GB。Eddie 看过 DigitalOcean 升配，没有合适的方案。

## 二、决定（草案，11-10 23:13 按 Eddie“ERP、FreeCAD 等工业及软件在一块，教育要数字工厂实训”改）

1. **按业务分两台**：

| 放哪台 | 内容 |
|---|---|
| **教育服务器**（现有这台） | 官网、学习平台（AI 建课、教材、白板、三维视频、虚拟实验、评价、校情、课程）、经典界面、文档服务、**数字工厂实训**（教学工厂 + 工业园各厂，ERPNext 一套） |
| **企业服务器**（新开） | **问渠质量 ERP**（演示 + 每家试点企业）、**工业软件**：缝纫机设计与制造（网页版 + FreeCAD 工作台）、凸轮、轴承、问渠电子（电路板、芯片设计）、企业版演示工厂（CAD → ERP → CAM 集成平台演示，`demo.`）、FreeCAD 相关下载 |

2. **要 Eddie 定的一处**：缝纫机设计软件现在是学习平台里的一页，用学习平台的账号登录。搬到企业服务器，企业服务器要有自己的登录：
   - **A（建议）**：企业服务器跑一套“企业版平台”（同一份程序，只开工业软件这几页），账号跟学习平台**分开**（企业客户一套、学校师生一套），网址 `app.wenquestrobotics.com` 之类；课程里要用缝纫机软件的地方链过去。
   - B：账号共用学习平台（企业服务器登录时回教育服务器验证）：省事，但两台互相依赖，教育服务器停了企业也登不上。

3. **新服务器**：DigitalOcean 纽约机房、Ubuntu 24.04、**8 GB**（质量 ERP 每家约 0.85 GB，演示工厂约 1.2 GB，凸轮、轴承、问渠电子、缝纫机软件各几百 MB；留出再开几家试点企业的余量）。
4. **网址尽量不变**，只改 DNS 指向：`qms`、`qms-erp`、`*.qms`、`*.qms-erp`、`demo`、`demo-erp` 指到新服务器；凸轮、轴承、问渠电子现在是官网下的路径（`/cam/`、`/bearing/`、`/eda/`），搬后改成企业服务器的网址，官网旧路径自动跳转过去；缝纫机软件按第 2 条的网址。新服务器自己的 Caddy 办证书。
5. **搬数据**：质量 ERP（演示和试点企业）用 `wenquest-ops` 的备份恢复；演示工厂的 ERPNext 站点 `demo` 和历史库 `wq_demo` 用数字工厂的备份恢复脚本拆出来搬。搬的那段时间这几个网址停用（约半小时），挑晚上做。
6. **两台之间**：单点登录、演示工厂转 PDF、凸轮和缝纫机提交计算等原来在同一台机器的内部网络里走的，改成走 HTTPS 网址加钥匙。
7. **国内不变**：国内服务器已升到 16 GB，这次不拆。
