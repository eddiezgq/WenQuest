# 实施细则 · 第 136 轮：缝纫机厂白板图（厂区 → 车间 → 工位 → 工艺文件）

日期：2026-11-10
依据：Eddie 11-10 09:09：“用白板软件画一个立体的厂区示意图，可以点进每个车间，车间也用白板画好示意，可以点开每个工位，查阅工艺卡、工序卡、检验规程等”。
状态：**已完成**（11-10）。按长期授权（“不要问了，我都同意”）按建议施工；Eddie 看了有不同意见随时改。

## 一、决定

| 编号 | 决定 |
|---|---|
| B-1 | **形式**：一页网页（单文件 HTML），手绘白板风格（Rough.js 画线），发布成 claude.ai 页面给 Eddie 看。现有的页面类型里没有“白板”，所以自己画；原件放仓库 `prototypes/缝纫机厂白板图/` |
| B-2 | **三层**：① 厂区立体图（等轴测），五个车间 + 计量室 + 库房，车间之间画物料流（铸件 → 机壳加工 → 装配；零件 → 装配；机壳回铸造车间时效）；② 点车间进车间白板图：设备按清单的位置和尺寸画成立体方块，按工艺路线画流向箭头，旁边列出工序流；③ 点工位弹出工艺文件 |
| B-3 | **工艺文件三种**：**工艺卡**（工艺过程卡：零件、材料、物料清单、全部工序与工时，当前工序高亮）；**工序卡**（这一道工序的设备、定位与夹紧、工步与要点、工时、工序检验）；**检验规程**（本工序的测量特性：名义值、上下限、单位；工序检验要求、频次；铸造检验规程；通用的三检、SPC、不合格品、追溯、量具规定）。一个工位做几种零件、几道工序时，先选“零件 · 工序” |
| B-4 | **数据来源**：全部取自仓库，不另编：设备、位置、工序、工艺路线、工时、物料清单、测量特性取自 `factory/plants/wenquest-sewing.yaml`；工步、定位、检验要求取自《缝纫机厂工艺方案》（`docs/方案/缝纫机厂工艺方案.md`）。方案里没写到的（针杆、旋梭、偏心各工序的工步）只显示工艺路线和关键特性，不补编。页面注明“工时、公差、名义值都是示例值” |
| B-5 | **生成**：`prototypes/缝纫机厂白板图/build.py` 读上面两份文件生成 `index.html`；清单或方案改了重新生成 |
| B-6 | 手机能看（工序流列表可以代替点图）；浅色、深色两种主题 |

## 二、规则

1. 只读清单和方案，不改工厂行为，不动测试。
2. 不编参数；方案和清单里没有的就不显示。

## 四、施工顺序

1. 生成脚本：读清单、拆方案表格、把工序对到方案的行。
2. 页面：厂区图、车间图、工艺文件面板。
3. 检查、发布、提交仓库。

## 五、施工记录

### 施工

- `prototypes/缝纫机厂白板图/build.py` 读清单和工艺方案，`template.html` 是页面，生成 `index.html`（约 143 KB，单文件）。手绘线条用 Rough.js 4.6.6（jsDelivr）；没加载到时画普通线。
- 厂区：五个车间、计量室、库房按清单分区画成立体厂房（屋顶天窗、大门、道路），8 条物料流箭头；便签写厂况；点厂房进车间。
- 车间：设备按清单的位置、尺寸、高度画立体方块，标设备号和工作中心；按工艺路线画流向和工序序号（中间去了别的车间画虚线），当前路线的设备顶面涂黄；右侧（手机在下方）列工序流，每道工序的设备可点。
- 工位：抽屉里三张卡——工艺卡（零件号、材料、用于哪台整机、全部工序与工时，当前工序高亮，点一行跳到那道工序的工位；物料清单；机壳另列关键孔系和加工原则）、工序卡（设备、工序类别、工时、方案里这一道的设备、定位与夹紧、工步与要点、工序检验，前后工序）、检验规程（工序检验要求、测量特性表、铸造检验点、常见缺陷与对策、通用检验规程）。一个工位做几种零件、几道工序时先选。
- 地址栏 `#车间` 或 `#车间--设备号` 能直接打开某个车间、某个工位。
- 发布：claude.ai 页面“问渠缝纫机厂白板图”（私有，Eddie 可在页面的分享菜单里分享）。

### 偏差

- 方案没有逐道写工步的零件（针杆、旋梭、偏心，41 个“零件·工序”），工序卡只列方案 4.1 节的工艺路线和关键特性，并注明“不补编”。
- 设备、库位不在任何工艺路线上的（库房 5 个、计量室三坐标 cmm-3…5），只显示设备卡。
