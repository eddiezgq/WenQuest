# 实施细则 · 第 53 轮：国内服务器自带镜像仓库（不用阿里云 ACR）

日期：2026-10-29
起因：Eddie 05:42 截图，阿里云“容器镜像服务”只能创建企业版实例（账号是企业认证，没有免费的个人实例）；企业版按月收费。第 34 轮的国内自动部署按 ACR 设计（GitHub 先把镜像复制到 ACR，国内服务器再从 ACR 拉）。

状态：**草案，待 Eddie 确认**。

## 一、决定

国内服务器自己跑一个镜像仓库，只在服务器内部监听（`127.0.0.1:5000`），不对外开端口。GitHub 部署时通过 SSH 安全通道把镜像直接复制进去；服务器从本机仓库拉镜像。ACR 的路线保留（以后买企业版或换别的仓库，填 `CN_REGISTRY` 就照旧）。

| | ACR（第 34 轮） | 自带仓库（本轮） |
|---|---|---|
| 费用 | 企业版按月收费 | 免费 |
| 要管的账号 | 阿里云仓库用户名、密码 | 无 |
| 传输 | GitHub → ACR（同一路线） | GitHub → SSH 通道 → 服务器；只传变化的部分 |
| 磁盘 | 不占服务器 | 服务器多占一份（约 15 GB，只留最近 3 个版本） |
| 端口 | — | 不新开端口，只走 22 |

## 二、怎么做

1. **开关**：GitHub 仓库变量 `CN_REGISTRY` 填 `local` 表示用自带仓库；填 ACR 地址表示用 ACR；不填则国内部署全部跳过（美国部署不变）。
2. **mirror-cn 任务**（`local` 时）：
   - 用 `CN_DEPLOY_SSH_KEY` 登录 `deploy@CN_DEPLOY_HOST`；
   - 服务器上没有仓库容器时，GitHub 把 `registry:2` 镜像打包传过去（国内拉不到 Docker Hub），以 `127.0.0.1:5000`、数据目录 `/opt/wenquest/registry`、开机自启的方式启动；
   - 建 SSH 通道 `localhost:5000 → 服务器 127.0.0.1:5000`，用 `skopeo` 把 8 个平台镜像和 postgres、redis、caddy、rclone 4 个基础镜像复制进去（已有的层跳过）；
   - 清理：每个平台镜像只留最近 3 个版本，然后让仓库回收空间；
   - 超时放宽到 180 分钟（第一次十几 GB 跨境）。
3. **deploy-cn 任务**：`local` 时不需要 `docker login`，直接 `update.sh 127.0.0.1:5000/engine:<版本>`（Docker 默认允许本机的 http 仓库）。
4. **init-env.sh**：国内那一问的提示改为“镜像地址前缀：自带仓库填 127.0.0.1:5000；用 ACR 填 registry.cn-xxx.aliyuncs.com/命名空间”，默认 `127.0.0.1:5000`。
5. **帮助**：《国内部署指南》第 8 节加“路线 A0：自带仓库（推荐）”，ACR 降为可选。
