## 一、为什么做、做给谁

- 缝纫机企业大量集中在台州、宁波，多是中小企业：Teamcenter、Windchill 这类大 PLM 买不起、用不好，通用的国产 PLM 又不懂缝纫机。
- 一台工业缝纫机上千个零件，机械、电控都有；平缝、包缝、绷缝、花样机各有大量衍生型号。**BOM 乱、改了零件说不清影响到哪些型号**，是这些企业的日常痛点。
- 我们手上正好有三样东西能接起来：缝纫机设计软件（网页版 + FreeCAD 工作台，有“本单位零件库”）、问渠质量 ERP（已上线，有变更控制、CAPA、追溯）、ERPNext 底座。通用 PLM 做不到“设计—生产—质量”闭环，这是我们和它们拉开差距的地方。

## 四、规则（建议）

### 1. 零件库与编码

1. **零件主数据就是 ERPNext 的物料**，PLM 在中枢里加它没有的东西：版本（A、B、C…）、状态（设计中 → 已发布 → 停用）、类别参数、三维模型（STEP）和图纸附件。
2. **类别和参数沿用缝纫机零件库**（`partlib.py` 的类别：电机、机针、旋梭、送布牙……），加缝纫机通用件（轴、连杆、凸轮、机壳、紧固件）和外购件。每个类别定义必填参数、单位、范围。
3. **编码规则企业自己定**（类别前缀 + 流水号，或沿用老编码）；系统按规则发号，不允许重号。
4. **AI 查重**：新建零件时，AI 按类别和参数找“几乎一样的已有零件”（例如同针号、同长度的机针），提示复用；只提示，不替人决定。
5. **已发布的零件不能直接改**：要改就走设计变更，出新版本；旧版本留着，能查到哪批产品用的是哪一版。

### 2. BOM 版本

1. **两层 BOM**：设计 BOM 在 PLM 里，有版本、能比较两版差异；**发布**后生成 ERPNext 的生产 BOM（提交状态、设为默认），生产、采购、MRP 照常用 ERPNext 的。
2. **发布要人签字**（AI 只起草）；发布前自动检查：子件都已发布、没有循环、数量和单位齐全、外购件有供应商。缺数据的检查结果是“未知”，不算通过。
3. **反查（where-used）**：任意零件能查到用在哪些 BOM、哪些型号、哪一版。

### 3. 型号衍生配置

1. **基础机型 + 选项组 + 规则**：例如平缝机基础机型，选项组有针距（5 / 7 mm）、送布方式（下送布 / 综合送布）、电控（直驱伺服 / 普通电机）、自动剪线（有 / 无）。
2. 每个选项写清楚“加哪些零件、去哪些零件、数量多少”；选项之间的规则（互斥、必须同时选）写成表，程序判定，不靠 AI 猜。
3. 选好一组选项，程序生成这个型号的设计 BOM 草稿和 ERPNext 物料变体；同一组选项不会生成两个型号。
4. 配置表改了（例如换了一个电机），程序列出受影响的已有型号，走设计变更。

### 4. 设计变更（ECN）

1. **直接用质量模块的变更控制（17g）**，类型“产品变更”；它原有的规矩照旧：评估四问、批准人不能是发起人或改过内容的人、实施后有人确认有效才能关闭、什么都不删。
2. ECN 多出的内容：**改了哪些零件、哪些 BOM，从哪一版到哪一版**；**生效方式**（立即 / 用完库存 / 某日起 / 某序列号起）。
3. **影响分析**：程序先算出确定的部分——受影响的型号、库存数量、在途采购单、未完工单、未发货订单（都从 ERPNext 取）；AI 在此基础上起草一段影响说明和建议的生效方式，人改了再提交。
4. **和质量闭环**：CAPA 可以直接发起 ECN；ECN 实施后回到 CAPA 验证效果；不合格、投诉能追到是哪个零件的哪一版。
5. 批准后实施：新版本零件和 BOM 发布、ERPNext 生产 BOM 换成新版，都在一张 ECN 里按步签字完成。

### 5. 接设计数据

1. **FreeCAD**：缝纫机设计工作台（以后也给通用的 FreeCAD）加“推送到 PLM”：按装配树送出零件清单、每个零件的 STEP 和参数、装配结构。用企业发的钥匙（和 MES 接口一样每个钥匙限权、可吊销、只存哈希）。**FreeCAD 只能送审**：送来的东西进 PLM 的“待确认”收件箱，工程师核对、对上已有零件后签字才写入。
2. **STEP 导入**：上传整机或部件的 STEP，程序读出装配结构和零件名，生成设计 BOM 草稿；对不上已有零件的，由人选“新建”或“对应到某个已有零件”。
3. **Excel 旧 BOM 导入**：沿用 20a 的做法：给模板、预览即预演、对不上的标红、签字写入；原文件留存。
4. 先在本机拿一台平缝机的完整装配实测 FreeCAD 推送和 STEP 导入，确认零件多时扛得住，再对外说能用。

### 6. 部署、语言、AI

1. PLM 是质量 ERP 的一个模块，按企业开关；没开的企业看不到 PLM 页面。云上、私有部署同一套代码，私有部署按现有安装程序装。
2. 中英文同一套代码（ADR-0023），国内版先用中文验收。
3. AI：国内只用 DeepSeek，美国用 Claude；AI 只起草（查重、影响说明），写入一律人签字，每次运行留记录。
4. 图纸、模型属于企业机密：只存在这家企业自己的那一套里，不进任何公共库；不进仓库。

### 7. 演示企业

1. 虚构一家缝纫机厂，名字标“（演示）”。产品：平缝机一个基础机型配出 4–6 个型号，再加一台包缝机。
2. 零件和装配从缝纫机设计软件导出的机构零件来，外购件（电机、控制器、机针、旋梭）用典型值，标明是演示数据。
3. 准备一条完整的演示故事：旋梭供应商换料 → 客户投诉断线 → CAPA → 发起 ECN 换旋梭 → 影响分析列出 3 个型号、库存 120 件、在途 2 张采购单 → 选“用完库存后生效” → 发布 B 版 → 回到 CAPA 验证。

### 偏差（已按此做）

1. **ERPNext 里的 BOM 建成草稿，由人在 ERPNext 里提交**（第四节第 2 条原写“发布后生成提交状态的生产 BOM”）：质量 ERP 的规矩是中枢从不提交、取消、删除 ERPNext 单据（ADR-0001），所以签字发布后建草稿，PLM 页面显示它是“草稿（待提交）”还是“已提交”。
2. **查重先用规则**（第四节第 1 条第 4 款原写“AI 查重”）：同类别必填参数都相同（数值差 1% 以内）的先列出来；AI 按名称、描述找相似放在后面（规则是没有 AI 时的退路，ADR-0010）。
3. **外购件要在“合格供应商”名录里有已批准的供应商**才能发 BOM；名录里没有这个零件 = “未知”，不算通过。演示时要先在合格供应商里批准供应商。
4. **新角色“工程设计”**（engineering）：看、建零件、签字发布、设编码规则；不能上传受控文件。两家演示企业各加一位工程师（美国 Morgan Engineer、国内 陈越），演示企业人数从 7 变 8，相关测试照改。
5. **国内演示企业打开 PLM 模块**，部署时按仓库里的演示企业清单更新（以前只在第一次安装时用），这样 Eddie 线上就能看到。
6. **BOM 一行的单位要和零件的单位一样**（不同单位的换算以后按 ERPNext 换算系数做）；数量大于 0、不超过 100 万、最多 6 位小数。
7. **填老编码**：ERPNext 里已有这个物料时，要勾“关联已有物料”且单位一致才行，不会悄悄占用别人的物料；ERPNext 物料建好后单位不能再改；改名称同步到 ERPNext；有 BOM 的零件不能改成外购。
8. 独立 AI 审读后改（第 7 条以及）：发布时有人同时改明细或文件，改的人要等发布完再被拒（数据库读上级“for share”）；发布在锁里再检查一遍；所依据的变更被取消就不能发布；循环检查同时看其他零件的已发布版和设计中的版本；数量 10 不再显示成 1E+1；ERPNext BOM 带标记、重试不重复建；已发布零件的名称、类别、来源、单位在数据库层锁定；有未保存的修改不能发布；BOM 选零件按编码或名称在服务器上搜（不止前 500 个）。

## 十三、第三步：型号衍生配置（26c）细化（2026-11-06 23:2x Eddie 确认 Q1–Q4 按建议）

按第四节第 3 条做，落实成下面几条：

1. **基础机型**：一个自制的“部件 / 整机”零件，它已发布的 BOM 是各型号共用的零件（例如 GC-6150 平缝机机头）。
   零件页多一个“型号配置”页签。
2. **选项组**：每组一个名称和代码，组里每个选项一个名称和代码，每次只能选一项。例如：
   - 针距 P：5 mm（5）、7 mm（7）；
   - 送布方式 F：下送布（D）、综合送布（C）；
   - 电控 E：直驱伺服（S）、普通电机（M）；
   - 自动剪线 T：有（T）、无（N）。
3. **每个选项改 BOM**：在基础 BOM 上加零件、去掉零件、换零件（去掉 X 加上 Y），写编码和数量。
   用到的零件必须已发布；去掉的必须在基础 BOM 里。
4. **规则表**（程序判定，不靠 AI）：
   - “A 要求 B”：例如自动剪线要求直驱伺服；
   - “A 和 B 不能同时选”。
   生成时违反规则就拒绝，并说明违反了哪一条。
5. **生成型号**：每组选一项，点“生成”。
   - 程序检查规则，新建一个型号零件；
   - 新建它的 BOM 草稿：基础 BOM 加上各选项的改动；
   - 型号零件和 BOM 照第一步签字发布。
   - 同一组选择只生成一次；再选同样的，直接打开已有型号。
6. **型号矩阵**：列出这个基础机型已生成的所有型号和它们的选项。
7. **配置表改了**：例如基础 BOM 出了新版本、某个选项换了零件。程序列出“和现在配置表不一致的型号”，由人走设计变更去改。
8. 权限：编辑配置、生成型号要 plm:edit；发布照旧要 plm:release 签字。
