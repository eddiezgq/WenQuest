## 三、决定（建议）

| 编号 | 决定 | 理由 |
|---|---|---|
| S-1 | **供应链模块推广到按清单起的厂**：供应商的准时率、合格率（教学模拟器用）、备选供应商（价格指数、提前期）写进清单 `suppliers` 一节（可不写，不写用缺省值）；减速器厂的现有数值搬进它的清单，结果不变 | 第 30 轮的约定：新厂靠清单，不改代码 |
| S-2 | **机器人厂打开“采购与来料”**：请购单 → 采购单 → 发货 → 到货 → 来料检验 → 入库，与减速器厂同一套页面和规则；来料检验的特性按物料类别（谐波减速器测背隙、伺服电机测空载电流、铝棒查材质证明，示例值） | 补上 D-2 的缺口；库存不再靠负数撑 |
| S-3 | **两厂互发订单**：机器人厂向“问渠减速器厂”下的 WQR-105 采购单，自动送到减速器厂，在那边成为客户“问渠机器人厂”的一张**销售订单**（教学模式）。减速器厂照常算料、下工单、做完入库、发货；发货时把**出厂编号和批号**回传机器人厂，机器人厂那边这批货变成“在途 → 到货”，再做来料检验 | 第 28 轮“各厂是上下游，学生能做跨厂的供应链与排产” |
| S-4 | **减速器厂那边谁接单**：订单进“订单与计划”的待接列表，计划员接单、算料；**老师可打开“自动接单”**（缺省打开），没人管时 3 分钟后平台代接、按层下达，免得机器人厂一直等货 | 两边同学都有事做，又不会卡死 |
| S-5 | **两厂怎么通信**：两座厂是两套独立部署（第 45 轮 R-5），本轮不合并。机器人厂的枢纽调用减速器厂枢纽的一个新接口（`/api/park/orders`），两边用服务器上的共享密钥认证；减速器厂发货时回调机器人厂（`/api/park/shipments`）。减速器厂连不上时，这张采购单按普通外部供应商处理（提前期 10 天，示例），页面写明“减速器厂未连通，按外部供应商处理” | 不动登录、总线、ERP；一座厂停了，另一座照常 |
| S-6 | **只连教学模式**：机器人厂教学模式 ↔ 减速器厂教学模式。演示模式、班级工厂（各班自己的厂）不互连，照旧按外部供应商 | 演示数据不被打乱；班级之间互连以后再说 |
| S-7 | 实验 25 的“一批谐波减速器背隙偏大”改用真实到货批号：问题注入时挑当前在用的那一批；措施“隔离批次”= 把这批来料判不合格、退货，换下一批 | 批次有了来历，追溯能从关节一路查到供应商和采购单 |
| S-8 | **帮助**：“机器人厂”一册加一章“采购到货与减速器厂供货”；减速器厂的帮助在“订单与计划”一章补一段“来自机器人厂的订单”。实验暂不新增；“两厂之间的一张订单”作为以后的实验 26，跟课程一起定 | 先把机制做稳 |

## 四、规则

1. 减速器厂现有的供应链、实验 15–23、两周情景、闭环演练结果不变：数值搬进清单后，现有测试不改断言通过。
2. 准时率、合格率、提前期、价格都是示例值，页面标“示例”。
3. 两厂之间只传订单、发货两类消息；对方的库存、成本、客户资料互不可见。
4. 减速器厂接到的机器人厂订单，开票、收款照减速器厂教学版现有的做法；机器人厂收到货后，应付只记录不模拟付款（与第 45 轮 D-1 一致）。
5. 共享密钥只放服务器环境变量，不进仓库。
