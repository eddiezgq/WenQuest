## 三、方案（建议）

### 3.1 镜像：在 IIC-OSIC-TOOLS 上加一层问渠的内容

`wenquest/micro-lab` = IIC-OSIC-TOOLS 2026.08（按摘要值锁定版本，不跟 latest）＋ 问渠层：

- `/foss/wenquest/`：各实验的起始文件与参考解（第 1 章：反相器原理图、版图脚本、仿真网表、8 位计数器的 LibreLane 配置）；
- `wqlab` 小工具：运行检查（DRC、LVS、时序、仿真）并把结果整理成实验报告要用的“结果名 → 数值”，格式与 GPU 实验的 `wqgpu submit` 一致，以后由调度服务回传问渠；
- 默认打开 SKY130，桌面上放好常用工具的快捷方式和中文说明。

自己从头编译全套工具要几个小时、几十个依赖，还得自己跟着上游升级。用维护良好的现成镜像，只做薄薄一层，升级时改一个版本号即可。

### 3.2 第 4 步全部在 GitHub Actions 里验收，不需要新服务器

新增手动工作流 `micro-lab.yml`（也在镜像相关文件变动时自动运行）：先给 GitHub 的运行机腾出磁盘（默认只有约 14 GB 空闲，删掉不用的预装软件可到 30 GB 以上），拉取镜像，然后无界面跑完下面的验收，把日志、版图图片、测得的数值作为构建产物保存。网页远程桌面也在运行机里启动，用无界面浏览器打开截图，确认能用。

给每个学生开容器（按班级预启动、计时、自动回收）属于第 5、6 步的平台工作，另起细则；那时沿用第 14 轮附 GPU 实验的调度做法（适配器、额度、计时、自动关机），只是机器换成 CPU 机型。

### 3.3 综合服务 `micro-synth`

- 形式：与现有的 `labcheck` 服务一样的小容器，只装 Yosys（约 150 MB），放进现有服务器的 docker compose，不对外开端口，只由网关调用。
- 接口：网关新增 `POST /api/micro/synth`（登录用户可用），提交 Verilog，返回 Yosys 的 JSON 网表和统计；手机端 Verilog 页拿到 JSON 后照旧用 DigitalJS 仿真和自动测试。
- 限制：源码不超过 64 KB；单次 20 秒超时；同时最多 2 个综合任务，其余排队；每个用户每分钟最多 10 次；容器无网络、只读文件系统、限 1 CPU 和 1 GB 内存。
- 页面行为：电脑浏览器默认仍在本机用 WebAssembly 版 Yosys（不占服务器）；手机、或本机加载超过 15 秒时，自动改用服务器综合；页面上显示当前用的是哪一种。

### 3.4 用 SKY130 校准第 1 章参数

在镜像里用 ngspice 加 SKY130 的 1.8 V 器件模型（`sky130_fd_pr__nfet_01v8` / `pfet_01v8`，W = 0.42 μm、L = 0.15 μm 起），测：饱和电流、阈值电压、反相器传输特性、FO4 延时、单位宽度栅电容。据此拟合 `params.json` 的有效参数（k′n、k′p、VT、Cg、Cd），并把“示意值 → 校准值”的对照、各题参考结果的变化写回第 17 轮第四节。校准后重新生成实验台、指导书、课件（构建脚本已经能一键完成）。

说明：长沟道公式拟合短沟道器件只能在一个工作区间内贴近，校准目标是 FO4 延时、饱和电流误差在 10% 以内，其余量作为“模型局限”写进课件第⑤步，这本身也是教学内容。

## 七、风险

- GitHub 运行机磁盘或时间不够（镜像 20 GB、LibreLane 跑计数器需几分钟到十几分钟）：先腾磁盘；仍不够时改用较大的运行机或临时开一台云服务器，届时先告诉 Eddie 费用。
- 上游镜像更新导致行为变化：按摘要值锁定版本，升级单独做一次验收。
- 国内访问 Docker Hub 不稳定：国内部署时把镜像同步到国内镜像仓库（与 GPU 实验镜像一起处理）。
