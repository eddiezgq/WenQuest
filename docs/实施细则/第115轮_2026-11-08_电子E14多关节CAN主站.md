## 一、这一轮做出什么

到第 114 轮为止，每次仿真只有一块驱动板，“主站”是仿真脚本里写死的一串指令。真机器人是一个主站（机器人控制器）同时带好几个关节。
这一轮写一个**主站程序**，在仿真里同时带两块驱动板（两个关节），做一台水平两关节机械臂（SCARA 的前两轴）：

1. **主站程序** `fw/master/master.py`（Python，学生能读懂）：上电等各关节就绪 → 规划末端走直线（逆运动学换成两个关节角）→ 100 Hz 同时给两个关节发位置指令 → 读状态、核对跟踪 →
   **任何一个关节报警，主站 10 ms 内让所有关节一起停**；某个关节心跳没了，也一起停。
2. **仿真**：Renode 里同时跑两台“驱动板”（同一份固件，节点号 1、2 分别编译），主站经仿真 CAN 与它们通信，一拍一拍地推进（每拍 10 ms）。
3. **页面**：“电机控制与 CAN”旁加“多关节主站”：机械臂俯视图（末端轨迹、两个关节角）、场景判据、CAN 帧。

## 二、决定（建议）

| 编号 | 决定 | 理由 |
|---|---|---|
| D-1 | **机械臂（示例）**：水平两关节，大臂 0.30 m、小臂 0.25 m；关节就是第 102 轮的关节模组（电机 + 1:100 减速器 + 驱动板 B 版），水平面里转、没有重力；两关节之间的动力学耦合不模拟（写明） | 先走通协同和主站逻辑 |
| D-2 | **节点号**：固件 `NODE` 改成编译时给（`make NODE=2`），默认 1；ID 照旧 0x200 / 0x180 / 0x080 / 0x700 + 节点号 | 同一份固件，一个总线上多块板 |
| D-3 | **主站周期** 100 Hz；每拍：收各关节状态帧和报警帧 → 算下一拍末端位置（梯形速度直线）→ 逆运动学 → 给每个关节发位置指令（关节 0.001°） | 与第 102 轮协议一致，固件不改协议 |
| D-4 | **监督**：报警帧 → 所有关节发“停”（受控停车：停住、抱闸、关输出）；任一关节心跳 300 ms 没来 → 一起停；跟踪误差（实际关节角 − 指令）> 2°（示例）→ 一起停 | 多轴系统“一个停、全停” |
| D-5 | **仿真推进**：Renode 开监视端口，主站每拍 `RunFor 10 ms`，再读两台机器的 CAN 记录、发下一拍指令；两台机器在同一个仿真里、时间同步 | 主站真的“在环”，不是事先写好的指令表 |
| D-6 | **场景**：⑱ 直线：末端从 (0.40, 0.15) m 走到 (0.20, 0.35) m，用时 1.5 s（示例）：路径偏离直线 ≤ 0.5 mm、终点误差 ≤ 0.2 mm、两关节同时开始同时到位（相差 ≤ 20 ms）；⑲ 关节 2 输出端编码器线断（走到一半）：关节 2 报故障 5 → 主站 10 ms 内让关节 1 停，两个关节都停住、抱住；⑳ 关节 2 的 CAN 掉线（不再发帧）：主站 300 ms 没收到心跳 → 让关节 1 停，关节 2 自己也按通信超时停住保持 | 覆盖协同、报警联动、掉线 |
| D-7 | CI 照旧重跑、核对逐字一致；以前的单板场景不变；帮助加一段；freecad-ai-parts 同步 0 差异 | 不倒退 |
