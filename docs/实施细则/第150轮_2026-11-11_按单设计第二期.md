## 二、决定

1. **A 设计变更处理**：设计出新版本发布时，对比新旧两版，把受影响的单据逐条列出并给出**建议处理**（确定性规则，见第三节）；
   人逐条选“照用 / 改量 / 取消 / 换新版”，一次提议交 ERPNext 执行，人在界面上确认。作业成本分“变更前 / 变更后”，变更造成的报废和多买单列一行“变更损失”。
2. **B 采购发票对账**：外协和本单专料的实际成本，有已提交的采购发票就按发票，没有就按采购单并标“按采购单，发票未到”；
   发票价和采购单价不同的逐行列出差额；毛利跟着变。不改 ERPNext 的付款与核销流程，只读。
3. **C 多张作业抢工位**：工位负荷里加上“已接单、设计未发布或还没下工单”的其他作业（按各自倒排摊到各周）；
   超负荷时列出这一周这个工位上是哪几张作业，**建议推迟松紧最大的那张**（确定性：按各作业的松紧天数排序），并算出推迟后各自的最早交期；
   报价时的“能否按期”也算上其他作业。只给建议，不自动改任何作业的日期。
4. **D 接设计发布与审批**（`/design`，上传 STEP、图纸、加工程序，审批人批注批准）：作业里的本单新件可以直接在那里提交模型和图纸；
   作业设计发布的检查加一条：**本单新件都要有批准的图纸版本**，没有就挡住（演示工厂可在清单里关掉这条，默认开）；
   作业单（traveler）每道工序显示批准的图号和版本。
5. **ERPNext 只用自带单据、不改源码**：工单改量用 ERPNext 自带的“更新数量”或停止旧单再下新单；采购单改量用自带的“更新明细”；取消走自带取消 / 关闭。
6. **缺数据不猜**：发票没到、单价没有、图纸没批，都是“未知”或“挡住”，不填估计值。
7. **不动现有流程**：第 139 轮的接口、页面、实验 33 已有任务和演练 13b 不改不放宽，只往后加。

## 三、规则

### A 受影响单据的建议处理（确定性）

| 单据 | 新版本里这一项 | 建议 |
|---|---|---|
| 工单（还没开工） | 物料清单或工艺变了 | 换新版：取消旧工单，按新版下新工单 |
| 工单（已开工） | 变了 | 照用到完工（已做的件按旧版），不够的数量按新版补一张工单；人可改选“停止” |
| 工单 | 没变 | 照用 |
| 请购单 / 采购单 | 用量变了 | 改量（新需求 − 已到货，不少于已到货） |
| 请购单 / 采购单 | 新版不用这一项 | 取消（已到货的部分转普通库存，记“变更损失”= 到货数量 × 单价） |
| 请购单 / 采购单 | 没变 | 照用 |

变更损失 = 停掉的已开工件的工序成本 + 转库存的专料金额；单价缺时为“未知”。

### B 实际成本取数

- 外协：每项外协按“已提交的采购发票（关联到那张采购单）数量 × 单价”；同一项既有发票又有采购单，以发票为准；只有采购单的标“发票未到”。
- 专料（编号挂作业号的物料、或采购单挂作业项目的物料）：同上；其他通用物料仍按标准价。
- 差额 = 发票金额 − 采购单金额，逐行列出，正数是多付。

### C 负荷与建议

- 其他作业：状态“已接单”及以后、没完工的，按它自己的倒排（第 139d 段 `schedule`）摊到各周各工位；已有工单的部分按工单算，不重复算。
- 超负荷（某工位某周 > 能力）：列出占用这一周的作业和各自分钟数、松紧天数；建议推迟松紧最大的一张，推迟天数 = 把这一周超出的分钟数挪到下一周所需的工作日；
  推迟后它的最早交期仍晚于客户交期时，改建议“加班或外协”，并写出缺多少分钟。

### D 图纸检查

- 本单新件 = 物料编号以作业号开头、在这一单设计里新建的件（第 139b 段 `copy_as_new`）。
- 设计发布检查：每个本单新件在 `/design` 有状态“已批准”的版本；有就记下版本号写进发布记录（指纹里也包含它）。
- 作业单：工序行显示 `图号 物料编号 rev N（批准人、日期）`。

## 八、施工记录

### 150a 设计变更处理（11-11）

1. **新模块** `hub/eto_change.py`：比对上一版和最新一版发布的设计——每个件的物料清单和工艺有没有变（`changed`），按作业件数展开的需求（`explode`）减了多少；
   `suggest()` 是纯函数，按第三节 A 的表给每张单据建议和可选项；`plan()` 读挂在作业项目上的工单（用旧版物料清单、没完的）、请购单、采购单；
   人选好后 `preview()` 出提议（动作 `eto_change`），确认执行后 `record()` 记进新表 `eto_change`（每张单据一行：处理方式、变更损失、谁定的）。
2. **关口**：这次变更还有没处理的单据时，`作业算料`和`再发布设计`都被挡（提示还有几张）；选了“照用”的旧版工单可以下达车间（原来一律不许）。
3. **变更损失**：停掉的已开工工单 = 已花的工序成本（已含在实际成本里）；本单专用件已到货、新版用不上的 = 多出的到货数 × 采购单价（单价缺为未知）；
   通用件转普通库存，不算损失。“车间与成本”页签加“设计变更前后”表（按工单所用的设计版本分开工序和材料）和变更损失合计。
4. **桥接** `eto_change`：工单取消（`frappe.client.cancel`）/ 停止（`work_order.stop_unstop`），请购单取消，采购单改量（`accounts_controller.update_child_qty_rate`，不少于已收）/ 取消 / 关闭（`purchase_order.update_status`）；
   已经是目标状态的跳过，重发不重做；“照用”不动 ERPNext。模拟 ERPNext 补了这四个接口，规则照真 ERPNext v16（已收货不能取消、不能改到已收以下）。
5. **页面**：“设计”页签加“处理设计变更”表（每张单据：物料与改量、建议与原因、下拉选处理方式、变更损失）；提议窗口列出每条处理；中英文都有（i18n 0 缺口）。
   截图 `docs/截图/第150轮-ETO二期/150a-*.png`（本机枢纽，演示数据直接写进本机库：第 1 版 → 第 2 版改了输出轴工艺、去掉压板）。
6. **测试** `tests/test_eto_change.py` 6 条：展开与比对；六种建议与损失手算（原材料少用 4：请购 3 全扣取消、采购单 7 → 6；专用件少用 3 但 4 件已到 → 关闭、损失 3 × 12.5 = 37.5）；
   单价缺 → 损失未知；数据库全流程（建议、挡算料、挡发布、挡下达、选项校验、记录后放行、损失合计）；只发布过一版没有变更；桥接五种动作。
   本机数字工厂单元测试 859 过，12 条失败都是本机缺 mujoco、gmsh（和上一轮一样，CI 上过）。
7. **偏差（第三节 A 第二行）**：“已开工的照用到完工，不够的按新版补一张工单”——工单整张照用时数量不会不够，所以实际做法是：建议“照用”（按旧版做完、记让步），
   可改选“停止”，停止后再算料就按新版补整张工单（已做的件和工序成本记变更损失）。不在已开工的工单上拆数量（ERPNext 不支持改已提交工单的数量）。


### 150b 采购发票对账（11-11）

1. **取数**（`hub/eto_exec.py`）：`purchase_lines()` 把挂在作业上的采购单逐行对上已提交的采购发票（按“采购单 + 物料”对行，草稿发票不算），
   每行给出采购单价与金额、已开票数量与金额、发票单价、差额（= 发票金额 − 采购单价 × 已开票数量，正数是多付）、状态（发票未到 / 部分 / 已开票）。
2. **实际成本**：外协按发票，开票不全的部分按采购单（返回“发票未到”的编号）；本单专料（编号以作业号开头的外购件、原材料）单价按发票加权平均，没发票按采购单，再没有按设计里的单价；
   通用物料仍按标准价。毛利跟着实际成本变。`outside_actual` 多返回一项“发票未到”的外协编号，原测试按新返回值改了写法，判定没放宽。
3. **桥接**：总线上的采购发票原来只带收货单号，现在带上每行（物料、数量、单价、金额、采购单、收货单），供对账用。
4. **页面**：“开票与毛利”页签加“采购对账”表（差额正数红色），发票未到的列在表下；中英文 0 缺口。截图 `150b-采购对账.png`（本机枢纽，演示数据：外协发票单价 92 比采购单 85 多付 14）。
5. **测试**：`tests/test_eto_billing.py` 加 1 条（别的项目的采购单不算；外协开 1 张发票后 92 + 80 = 172；开齐后 184 且没有“发票未到”；专料按发票单价 13；草稿发票不算；差额 12、24、2）。
