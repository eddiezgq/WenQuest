# 实施细则 · 第 5 轮：AI 建课的互动改造——先听懂、说清、你点头，再动手（2026-09-30 起草；Eddie 21:38 答复并确认）

## 一、Eddie 的反馈（2026-09-30 21:32）

> 互动效果很差：说过、答应了，什么也不动，在埋头干。比如主教材搞错了，说了几遍也不改；第一章大纲还没有确定也改不了。不停地自动开始工作。应该停下来互动、理解意图，再按要求工作，不是自动机。

## 二、查到的原因（对照代码）

| 现象 | 原因 |
|---|---|
| **说了没反应** | 团队在干活时，你发的话**存下了，但课程负责人不回**：后台一次只允许一件工作，回复也要排队，排不上就直接放弃了，界面上看不出来。 |
| **答应了却没改** | 课程负责人能做的事只有 8 种（回答问题、记要求、改资料身份、指定主教材、重写某课、写下一课、设节奏、进入下一步）。**改大纲、换章节、重做大纲、改设计书、用一本没上传的书当主教材，都没有**。做不到时它也照样回“好的，记下了”。 |
| **主教材改不过来** | 指定主教材只能指向**已上传的文件**；你说的书不在资料里时，它只能反复问“是哪一份”。改了主教材之后，大纲和设计书也**不会跟着重做**。 |
| **大纲改不了** | 页面上能手改未发布的课时，但**用说的改不了**；“按新教材重排第 1 章”这类要求没有对应的动作。 |
| **自己往下跑** | 你的一句话被理解成“进入下一步/重写/写下一课”后，**立刻开工**，没有先跟你确认；回复是在动作之前写的，所以说的和做的对不上。 |

## 三、改法

### 3.1 原则

1. **你说话，团队先停下来听**：任何时候发消息都马上有回复，不因为团队在忙而丢掉。
2. **先复述，再动手**：凡是会改动课程或启动工作的要求，课程负责人先用一两句话说清“我理解你要……，打算这样做……”，附 **[确认] [不对，我再说]** 两个按钮；你点确认才执行。
3. **只记录的事立即生效**（回答问题、课程名、周数、语言等要求），回复里写明改了什么。
4. **说到做到**：回复在动作执行**之后**生成，内容来自实际结果（“已把主教材改为《机器人学导论》；大纲第 1 章已按新教材重排，请看右边”）；做不到的直接说做不到、为什么、该点哪里。
5. **不自动往下走**：每一步做完就停下，汇报并等你；只有你自己设了“每天自动写一课”才会自动写。拿不准你的意思时，问**一个**问题，不猜。

### 3.2 课程负责人新增的能力

| 能力 | 你可以这样说 | 怎么做（确认后） |
|---|---|---|
| 改大纲 | “第 1 章拆成两章”“把第 3 课挪到第 2 章”“删掉第 5 课”“第 2 章改名为……” | 直接改大纲（已发布的课时不动），右边立刻看到 |
| 按要求重做大纲 | “按 Craig 的书重排大纲”“第 1 章只讲概论和空间描述” | 课程设计师带着你的要求重做（全部或某几章），已发布的不动 |
| 换主教材 | “主教材是 Craig《机器人学导论》” | 资料里有就指定那一份；**没有也照样记下书名**，不再反复追问；然后问你要不要按新教材重做大纲和设计书 |
| 改课程设计书 | “贯穿全课的机器人用 UR5e”“符号按 Craig” | 改设计书对应项 |
| 停下 | “先停一下”“别写了” | 立即停止当前工作（已完成的保留） |
| 问进度/问为什么 | “为什么用这本书？”“现在在做什么？” | 只回答，不动手 |

### 3.3 忙的时候说话

- 团队在干活时你发消息：课程负责人**立刻回复**（单独通道，不排队）。
- 你的话如果和正在做的事冲突（比如正在写第 1 课，你说主教材错了），回复里给 **[停下来先改]** 按钮；不冲突的要求记下，当前工作完成后按顺序处理，并在对话里说一声。

### 3.4 界面

- 对话里的“待你确认”卡片：一句话复述 + 要做的改动清单 + [确认] [不对，我再说]；确认后卡片变成“已完成：……”，失败就写原因。
- 团队在忙时，对话框上方一直显示“正在做什么”和 **[停下]**；输入框不禁用。
- “已改动”的地方（大纲、设计书、资料清单）短暂高亮，方便你对照。

## 四、交付物

1. 网关：课程负责人的新动作（改大纲、重做大纲、记书名式主教材、改设计书、停下），“提议—确认”流程（提议存进项目，确认/取消接口），忙时的独立回复通道，执行后再生成回复。
2. 去掉所有“说完话就自动开工”的路径；保留按钮和“每天自动写一课”（只在你开启时）。
3. 网页：对话里的确认卡片、忙时状态条和停下按钮、改动高亮。
4. 测试：照你说的场景写成自动测试（换主教材、改第 1 章、忙时说话、说“好的”不会开工、做不到时说实话）。
5. 帮助文件《AI 建课使用说明》“和课程负责人对话”一节。

## 五、施工顺序与验收

1. 网关提议—确认、新动作、忙时回复、执行后回复。验收：本地用真实模型（Claude）跑这些对话——
   - “主教材错了，应该是 Craig 那本”（资料里有/没有两种）→ 复述 → 确认 → 主教材改了，问是否重做大纲；
   - “第 1 章大纲改成：1.1 机器人概论 1.2 空间描述”→ 复述 → 确认 → 大纲变了；
   - 团队正在写课时说“先停一下，教材不对”→ 马上回复并停下；
   - 只说“好的”“嗯”→ 不开工；
   - 要求做不到的事 → 说做不到和原因。
2. 网页确认卡片和状态条，老师账号实际走一遍。

## 八、第二步：课程负责人要像专家教授（2026-09-30 22:14 Eddie 提出，待确认）

> 课程负责人首先要是专家教授，有权威，要先把教材吃透。不要急于回复，要思考，查清楚问题，拿出具体的方案执行。甚至可以推倒重来。可以有反应和思考时间。我感觉直接接 Claude 都比那个强。

### 8.1 为什么现在不如直接用 Claude

| 原因 | 现在的做法 |
|---|---|
| 不让它想 | 每次回复都是“立刻填一张表”（强制结构化输出），没有思考过程 |
| 没读书 | 它手里只有资料清单和大纲标题，**主教材的内容一页都没看到** |
| 不能查 | 不能自己翻教材原文、讲义、已写的课；只看到最近 14 句对话，每句截到 600 字 |
| 模型偏弱、篇幅短 | 用的是和写课相同的中档模型，回复上限约 3000 字 |

### 8.2 改法

| 编号 | 做什么 |
|---|---|
| L1 **先吃透教材** | 主教材一确定，课程负责人先读书：逐章写**教材研读笔记**——每章讲什么、核心概念和公式、符号约定、典型例题、前后依赖、适合配的机器人问题、建议几次课，注明页码。笔记存进项目，在“资料清单”里能看能改；大纲、设计书、每一课都以它为依据。书不在资料里时，按它对这本书的了解写，并标明“未见原书，建议上传”。读一本书可能要几分钟到十几分钟，界面显示进度。 |
| L2 **会思考、会查证** | 回复改成“研究式”：开深度思考；可以自己翻资料——按章节或关键词查教材原文、看研读笔记、看大纲和设计书、看已写的课——查几轮、想清楚再答。回复可以慢，界面显示它在做什么（“正在查阅教材第 1 章…”“正在思考…”），喊停照样立刻停。 |
| L3 **拿出具体方案** | 发现问题时给**可直接执行的完整方案**，例如“第 1 章导论按《机器人学导论》1.1–1.3 排 2 次课：第 1 次……（目标、对应页码、机器人问题），第 2 次……”，作为提议卡片，你确认就照做。 |
| L4 **可以推倒重来** | 新增提议“推倒重来”：重读教材→重写研读笔记→重做设计书和大纲（已发布的课保留，待审的课标为“需重写”）。 |
| L5 **用最强的模型** | 课程负责人单独用最强模型（Claude Opus，可用 `WQ_LEAD_MODEL` 改），写课等其他角色不变。费用会高一些，但对话次数不多。国内部署用 DeepSeek 时，L1、L3、L4 照做，深度思考按 DeepSeek 的能力。 |
