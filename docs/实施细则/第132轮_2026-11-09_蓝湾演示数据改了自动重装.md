# 实施细则 · 第 132 轮：蓝湾演示数据改了，部署自动重装

日期：2026-11-09　状态：**已完成**（2026-11-10 蓝湾已按新演示数据重装上线；Eddie 在蓝湾看一遍配件手册待做）。原定：2026-11-09 Eddie 确认

## 一、为什么

第 124 轮做完、上线后，线上的蓝湾缝纫机械（演示）和以前一样：没有三维、没有爆炸图、没有英文名、没有现成配件手册。

原因：程序每次部署都更新，**演示数据只在第一次安装时装一次**（11 月 7 日），之后部署从不动数据（为真实客户定的规矩：升级不能清掉企业的数据），每晚还原也回到那天拍的快照。演示数据后来改了（第 124 轮 27d），线上却进不去。

不能“往里补”：蓝湾的零件和 BOM 都已发布，按 PLM 规矩发布后不能悄悄改，补三维要走设计变更，演示故事会多出一堆莫名其妙的变更单。

## 二、决定

1. **演示数据有版本**：版本 = 质量 ERP 仓库里最后一次改演示数据（`wqops/demo/` 和 `companies/demo-sewing.yaml`）的那次提交。装好后把版本写进服务器上蓝湾目录的 `.demo-loaded`。
2. **部署时比一比**：国内部署每次都把当前版本告诉服务器；和 `.demo-loaded` 里记的不一样，就**清空蓝湾、从头装一遍**（约 20 分钟），装完重拍每晚还原用的快照。一样就什么都不做（和现在一样）。
3. **只动蓝湾**：海港五金（主演示）和试点企业一律不动。海港五金以后要不要也这样，另议。
4. **密码不用重设**：
   - 老板账号：重装前把密码记下来（存加密后的样子，不存明文），装完原样写回。你设一次，以后重装多少次都能用。
   - 体验账号：用现成的“导出 → 导入”（每晚还原就是这么保留的），账号、密码、到期日都不变。
5. **重装期间**：蓝湾网址打不开约 20 分钟；邮件里给的蓝湾账号照常能用（重装完）。重装中途失败，下一次部署接着装（安装脚本会跳过已完成的步骤）。

## 三、交付物（质量 ERP 仓库）

| 文件 | 改什么 |
|---|---|
| `deploy/tenant.sh` | `demo` 命令加 `--data-version <版本>`：和 `.demo-loaded` 不一样就重装（导出账号 → 停掉并删除蓝湾的容器和数据卷 → 删快照 → 按第一次安装的步骤装 → 装数据 → 写版本 → 拍快照 → 导回账号） |
| `wqops/hub/accounts.py` | 加 `export-owner` / `import-owner`：只导出、导回老板账号的加密密码 |
| `.github/workflows/deploy-cn.yml` | 算出演示数据版本，传给 `tenant.sh demo sewing` |
| 测试 | `accounts` 两个新命令的单元测试；`tenant.sh` 的版本比较用 shell 测试（不联网）；CI 的 install-sewing 里**装两次**：第二次换一个版本号，检查确实重装了、老板密码和一个体验账号还能登录 |
| 帮助 | `docs/帮助/缝纫机企业PLM使用说明.md` 写明：演示数据改了会自动重装，期间约 20 分钟打不开 |

## 四、施工顺序与验收

1. `accounts` 的导出、导回老板密码 + 测试。
2. `tenant.sh demo --data-version` + shell 测试。
3. 部署脚本传版本；CI 装两次的检查。
4. 推上线后跟踪国内部署：第一次部署时蓝湾的 `.demo-loaded` 里还没有版本（11 月 7 日装的），**按“不一样”处理，会重装一次**，这正是要的。
5. 验收：
   - 蓝湾里能看到 `WQ88-0000-5TA` 的配件手册第 1 版（29 节），6 个部件有三维爆炸图。
   - 你原来设的老板密码还能登录；已开的体验账号还能登录。
   - 再部署一次（演示数据没改），蓝湾不重装。

## 五、施工记录（质量 ERP PR #127）

- `deploy/demo-reinstall.sh`（新）：`out` 先把体验账号和老板密码（加密后的样子）存到蓝湾目录的 `backups/reinstall/`（只有服务器管理员能读），再删掉蓝湾的容器和数据；`in` 在装好、导入数据后把它们放回去。中途失败再跑，不会把已存的覆盖掉。
- `deploy/tenant.sh demo … --data-version 版本`：和 `.demo-loaded` 里记的不一样就 `out` → 安装 → 导入演示数据 → 拍快照 → `in`；`.demo-loaded` 改为记版本。
- `wqops/hub/accounts.py`：`export-owner` / `import-owner`。
- 测试：老板密码经过“重装”还能登录；`tenant.sh` 的重装顺序（用假的 docker、安装、快照）、版本写对、旧的 ERPNext 接口密钥删掉、账号放回、同一版本再跑什么都不做。
- **偏差**：
  1. 版本不用“最后一次提交”，改用**演示数据文件内容的指纹**（`wqops/demo/sewing*.py`、`machines/`、`manual/`、`companies/demo-sewing.yaml`）。部署时只取最新一版代码、没有提交历史，算不出“最后一次提交”；指纹也更准：只在蓝湾的数据真改了时才重装，改海港五金的演示不会牵连蓝湾。
  2. CI 的“装两次”不经过 `tenant.sh`（CI 里蓝湾是主安装，不是旁边那家），而是直接跑同一个 `demo-reinstall.sh out` → 安装 → 导入 → `in`，再用老板账号和体验账号登录；`tenant.sh` 外面那一层由上面的测试管。

## 六、上线时发现的故障：海港五金演示起不来（2026-11-10 凌晨起）

- **现象**：第 132 轮合并后国内部署两次失败，海港五金 https://qms.wenquestech.online 打不开。Eddie 在服务器上查到：每晚还原（北京时间 04:40）恢复快照后，程序启动时报 `column "name_en" of relation "plm_parts" already exists`。
- **原因**：每晚还原是把快照“盖”到现有数据库上。第 124 轮新加的“配件手册”表指着“零件”表，盖的时候“零件”表删不掉，于是留着新加的“英文名”一列；可“哪些升级已做过”的记录却回到了快照里的旧样子，程序以为还没加这一列，再加一次就报错，起不来。还原脚本又没把这当回事，把坏掉的样子拍成了第二天的快照。这是 ADR-0027 每晚还原从一开始就有的漏洞，第 124 轮第一次加了“指着旧表的新表”，才暴露出来。和第 132 轮的改动无关。
- **修**（质量 ERP PR #128）：还原先把数据库清空再恢复，恢复完检查“升级记录”在；还原后的升级失败就停下，**不拍新快照**（快照保持原样）。测试用真的 PostgreSQL 复现了这次故障：旧脚本过不了，新脚本过。
- **服务器上要手工补一次**（Eddie 做，步骤见下）：用 11-10 凌晨 04:10 的每日备份（还原之前拍的，是好的）恢复海港五金，重拍快照；蓝湾也一样坏了，用它当天凌晨的备份恢复，再部署（随后蓝湾按第 132 轮重装）。

## 七、第二次补丁与上线（2026-11-10）

- 第一次自动重装在**动手之前**安全停下（“could not read the owner; nothing changed”）：蓝湾自己跑的还是旧版程序，没有“导出老板密码”这条命令。改（质量 ERP PR #129）：重装前先把蓝湾的程序版本换成正在部署的这一版，并用这一版新起一个临时容器来导出账号，不用正在跑的旧程序。
- 服务器上的手工修复（Eddie 做）：海港五金用 11-10 04:10 的备份恢复（用的是旧还原脚本，但这份备份和当时的数据库一样新，所以没问题），确认程序 healthy，再把 12:00 的新备份换成每晚还原快照（`demo-reset.sh snapshot` 第一次碰巧失败，改为手工备份后改名）。在服务器上用 root 跑部署脚本会碰到锁文件权限问题，要用 `sudo -u deploy`。
- 上线（国内部署手动触发，2026-11-10 12:3x–13:02 北京时间）：蓝湾清空 → 重装 → 导入演示数据（3 分钟）→ 拍快照 → 体验账号和老板密码放回（“owner password kept”）。
