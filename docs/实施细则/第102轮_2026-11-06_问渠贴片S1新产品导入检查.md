## 一、这一轮做什么

在主域名下新开 `/pcba/`（问渠贴片 / WenQuest PCBA）。贴片厂的工程师上传客户资料包，几分钟拿到三样东西：
- 一份检查报告：红、黄、绿、未知四种结果，每项都在板图上标出位置；
- 一份工程问题单草稿：AI 起草，人改完、确认后才能导出；
- 一张数量统计：贴片点数、正反面数、通孔件数、细间距器件数，给报价用，本轮不算钱。

不做的（方案第八节已排到后面）：报价单价、贴片坐标与料站表、钢网和炉温建议、机台数据、追溯、客户门户、KiCad 插件、元件停产缺货查询。

## 二、决定

1. **认的资料**：
   - 光绘文件：Gerber RS-274X / X2 / X3，含钻孔文件（Excellon）；
   - 物料清单：CSV 或 Excel；
   - 坐标文件：CSV。
   可以打成一个 zip 上传，也可以分开传。
   - 光绘文件按文件名和 X2 属性自动认层，认错了可以手改。
   - 物料清单和坐标的列名千差万别，第一次上传时用“列映射”对一次（位号、数值、封装、数量、X、Y、角度、正反面），映射存成企业配置，下次自动套用。
2. **读光绘用 gerbonara**（Apache-2.0，1.6.3）。11-06 已用驱动板 A 版的 gerber.zip 实测：
   - 11 层光绘、232 个钻孔全部读出，0.1 秒；
   - 板框 100.1 × 70.1 mm；
   - X2 属性里能分出焊盘、走线、过孔。
   - 钻孔文件有“表头之后又出现 G90”的提示，不影响读数，报告里不显示。
   PyGerber 作备用，本轮不用。
3. **工艺能力是企业配置**：最小线宽、线距、孔径、孔环、阻焊桥、铜到板边、元件间距、最小元件、能贴的板子尺寸、细间距门槛等。
   - 存在企业自己的配置里，代码里不写数值；
   - 某项没填，相关检查就判“未知”；
   - 演示企业的数值标“示例值”。
4. **订单带验收等级**（方案四之一）：IPC-A-610 第 1、2、3 级，由企业填，不填就显示“未定”。本轮只记录、显示在报告和问题单上，不据此改判定。不同等级的判据由企业按自己买的标准录入，这留到 S3。
5. **客户资料只在当次处理中用，不存服务器**。
   - 云端项目只存检查结果、列映射、问题单（照凸轮云端项目的做法，存在网关里，按企业隔开，保留 20 版）；
   - 原始光绘和物料清单留在用户自己电脑上，要复查就重新上传。
   - 理由：客户设计资料是贴片厂替客户保管的机密，第一期少存为好。等有了试点企业，按他们的要求再定。
6. **极性检查改得更保守**（与方案三节 A.2 有偏差，写回方案）：
   - 光绘文件里通常没有“哪个焊盘是第 1 脚”的信息。驱动板这份光绘就没有元件属性（X2 的 `%TO.C`）。
   - 所以本轮把有极性的元件（二极管、电解电容、芯片等，按封装名和企业的极性元件表识别）**列出来请人确认**，判“未知”，不自动判对错。
   - 光绘里带元件属性时，才自动核对第 1 脚和丝印标记。
7. **判定代码**放在 `services/pcba/pcbakit/`：
   - 纯函数，不 import 网络库和 AI 库，加一条测试专门检查这一点；
   - AI 起草放在单独的 `ai_api.py`，只读判定结果、不改结果；
   - 每次 AI 运行留记录。
   - 国内部署用 DeepSeek，美国用 Claude（沿用凸轮的通道）。

## 三、检查项（第一批 18 项）

“示例值”是演示企业的配置，不是标准值。

**对资料（D）**

| 编号 | 查什么 | 怎么判 |
|---|---|---|
| D1 | 物料清单与坐标的位号一一对上 | 多的、少的、重复的都列出来；有就判红 |
| D2 | 物料清单的数量 = 位号个数 | 不等判红 |
| D3 | 坐标点落在该面的焊盘群上 | 坐标点到最近焊盘群的距离超过企业设的容差，判黄 |
| D4 | 坐标的正反面与焊盘所在面一致 | 不一致判红 |
| D5 | 不贴（DNP）的位号单独列出 | 只列，不判 |
| D6 | 有极性的元件 | 第二节第 6 条：列出请人确认，判“未知” |

**做不做得出板子（F，读光绘）**

| 编号 | 查什么 | 怎么判 |
|---|---|---|
| F1 | 最小线宽 | 走线光圈小于企业能力判红 |
| F2 | 最小铜间距 | 同一层上互不相连的铜之间最近距离小于能力判红。光绘里没有网络名，这里按“铜块”算 |
| F3 | 最小孔径、孔环 | 钻孔与外层焊盘对比 |
| F4 | 阻焊桥 | 相邻阻焊开窗之间的距离 |
| F5 | 铜到板边 | 按板框算 |
| F6 | 板子尺寸 | 与企业贴片线能做的最大、最小尺寸比 |

**好不好贴（A）**

| 编号 | 查什么 | 怎么判 |
|---|---|---|
| A1 | 元件间距 | 用焊盘外接框加企业设的余量，算相邻元件的距离 |
| A2 | 元件到板边或工艺边 | 按企业设的距离 |
| A3 | 细间距器件 | 锡膏层焊盘间距小于门槛的器件列出，提示钢网和检测 |
| A4 | 小件 | 0201 及以下或焊盘小于门槛，对照企业能力 |
| A5 | 底部焊端器件 | QFN、BGA 等按封装名识别，提示光学检测看不到焊点，需要 X 光或其他手段（提示，不判对错） |
| A6 | 通孔件 | 统计通孔件数，提示选择焊或手工焊 |

**物料（M）**

| 编号 | 查什么 | 怎么判 |
|---|---|---|
| M1 | 湿敏等级 | 企业物料库里有才显示等级；没有就判“未知”。本轮物料库只给空表和导入功能 |
| M2 | 物料清单本身 | 空料号、同一料号对应不同封装、同一位号出现两次 |

每项结果都带三样：哪里（板图上的位置）、实测值和企业能力值、为什么要查。“为什么”沿用第 88 轮 `dfm.py` 的写法。

## 四、交付物

1. **计算内核** `services/pcba/pcbakit/`：
   - 读资料包、认层、列映射；
   - 第三节 18 项检查；
   - 数量统计；
   - 报告数据。
2. **服务** `services/pcba/`（FastAPI，照 `services/cam`）：
   - 上传与检查接口；
   - AI 起草问题单接口；
   - 云端项目（照 `projects_api.py`，网关加 `pcba` 类型）；
   - 下载报告（Excel、可打印网页）和问题单（Word）。
3. **网页** `apps/pcba/`（Vue，照 `apps/cam`），中英两种界面：
   - 上传与列映射；
   - 板图：正反面、各层开关，点结果跳到位置；
   - 结果表；
   - 问题单编辑与确认；
   - 企业配置：工艺能力、列映射、极性元件表、物料库导入、验收等级。
4. **演示企业与资料包**（`services/pcba/examples/`，全部标“示例”）：
   - “示例贴片厂”的工艺能力配置；
   - 驱动板 A 版、B 版资料包，从 `factory/designs/drv-joint*/out/` 打包，只读引用，不改电子会话的文件；
   - 一份故意埋问题的改版：用脚本从 A 版改出来，问题清单写在脚本里。脚本里列出的每个问题都必须被查出来。
5. **网页帮助**：照第 90 轮的写法（`docs/帮助/贴片软件帮助/`），包括开始使用、三份资料包的演示、每项检查的说明、企业配置。录像放下一轮。
6. **部署**：
   - Caddy 加 `/pcba/`；
   - `docker-compose.yml` 加 `pcba` 服务；
   - `deploy.yml` 加测试、镜像构建、上线后探活；
   - 国内镜像同步，`lib.sh` 加镜像变量。
   照轴承第 64 轮的接法。
7. **AI 客服**：问答库加“问渠贴片是什么、能查什么、资料存不存”，考题加对应问法。
8. 方案文件第三节 A.2 按第二节第 6 条改写。交接说明加一行。
