ICP 备案（必须，最先办）

在国内服务器上用域名对外提供网站，必须先做 ICP 备案。在购买服务器的云服务商控制台里办理（阿里云、腾讯云都有“备案”入口）：填主体信息和网站信息 → 人脸核验 → 云服务商初审 → 通信管理局审核。

问渠用到的网址都在一个主域名下（官网、learn.、classic.，装数字工厂还有 factory.、erp. 等），备案主域名一次即可。网站名称填“问渠科技”，内容描述按企业官网如实填写：人工智能应用软件与工业软件、信息系统集成、技术服务与咨询、教学软件（第 48 轮：与营业执照经营范围一致；公司不做需审批的教育培训，不要按“在线教育”填）。

备案通过后，官网和学习平台页面底部要显示备案号并链接到工信部备案系统（beian.miit.gov.cn）。备案后加 拿到备案号后加到页面底部。

公安联网备案

网站开通后 30 日内，到“全国互联网安全管理服务平台”办理，通过后页面底部同样要显示公安备案号。

生成式 AI：只用已备案模型、属地登记、内容标识
  • 只调用已备案的大模型：问渠国内部署用 DeepSeek（.env 里只填 DEEPSEEK_API_KEY，ANTHROPIC_API_KEY 留空）。数字工厂的 AI 助手会自动沿用这把钥匙。
  • 属地登记：面向公众、调用已备案模型的应用，很多地方要求上线前到属地网信部门登记。各地做法不一，先电话咨询。
  • AI 生成内容标识：AI 写的课程内容、回答要能让人看出是 AI 生成的。问渠的 AI 助教回答注明出处、AI 建课的课时要经老师审核和课程委员会批准才发布；对外上线前再核对一遍界面上的标识是否符合最新要求。
网络安全等级保护（等保）

面向学校的教学平台，通常要定级（多为二级或三级）、到公安机关备案、请测评机构测评。学校客户常会要求测评报告。问渠在设计上按三级准备：不改 Moodle 核心、操作留痕、每日备份、只开 22/80/443 端口、SSH 只允许密钥登录（服务器初始化脚本已做）。

个人信息保护与数据境内存储
  • 学生、老师的数据只存在国内服务器和国内对象存储里；异地备份不要再传到境外。
  • 注册页要有隐私政策和用户协议并取得同意；未成年人（中学合作）另有要求。
  • 国内部署时，不要把服务器上的数据传回美国的问渠服务器做 AI 处理。

07初始化服务器

以 root 登录新服务器，做一次。问渠的 deploy/bootstrap.sh 会装 Docker、建 deploy 用户、只允许密钥登录、开防火墙、建 2 GB 交换区和每天 03:30 的备份任务。国内要先换掉它里面的 Docker 安装方式。

1
用国内镜像装 Docker（bootstrap.sh 里检测到已装 Docker 就会跳过安装） 
# 官方安装脚本支持 --mirror Aliyun，从阿里云的软件源下载
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun
systemctl enable --now docker
2
配置拉 Docker Hub 基础镜像的加速地址（postgres、redis、caddy、rclone、ERPNext 等来自 Docker Hub） 
# 加速地址在云服务商控制台查（阿里云：容器镜像服务 → 镜像工具 → 镜像加速器）。
# 注意：各家加速器一般只对自家云服务器有效，且对 Docker Hub 的覆盖有限，拉不到时用第 8 节的“转存”办法。
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{ "registry-mirrors": ["https://<你的专属地址>.mirror.aliyuncs.com"] }
EOF
systemctl restart docker
3
运行初始化脚本（把仓库的 deploy/bootstrap.sh 传到服务器上；参数是自动部署用的公钥，手工部署时填你自己的公钥） 
bash bootstrap.sh "ssh-ed25519 AAAA...你的公钥 deploy"
4
把部署文件放到 /opt/wenquest（以 deploy 用户） 
# 在能访问 GitHub 的电脑上打包仓库里需要的文件，传到服务器
tar czf wq-deploy.tgz docker-compose.yml docker-compose.prod.yml .env.example deploy site
scp wq-deploy.tgz deploy@<服务器IP>:/opt/wenquest/
ssh deploy@<服务器IP> 'cd /opt/wenquest && tar xzf wq-deploy.tgz && chmod +x deploy/*.sh'
第 4 步可以不做：设置好第 8 节的自动部署后，GitHub 每次部署都会把这些文件、教材、字体复制过去。美国服务器专用的站点段已移到 deploy/caddy-extra/us/，WQ_REGION=cn 时不会加载，不用手工删。

路线 A（推荐）：GitHub 自动同步到阿里云 ACR，并自动部署到国内服务器

部署工作流里有两个国内专用的步骤：同步到国内仓库（每次构建后把 7 个平台镜像和 postgres、redis、caddy、rclone 4 个基础镜像复制到 ACR）和部署到国内服务器。没有设置下面这些变量时它们自动跳过，美国的部署照常。

  1. 阿里云开通“容器镜像服务”，建一个命名空间（如 wenquest），设置“访问凭证”的固定密码。仓库不用一个个建：命名空间里打开“自动创建仓库”，设为私有。
  2. GitHub 仓库 → Settings → Secrets and variables → Actions：
    • Variables 加 CN_REGISTRY = registry.cn-hangzhou.aliyuncs.com/wenquest（地域、命名空间按你的填）；
    • Secrets 加 CN_REGISTRY_USER（阿里云账号全名）、CN_REGISTRY_PASSWORD（访问凭证密码）；
    • 要自动部署到国内服务器，再加 Secrets CN_DEPLOY_HOST（服务器公网 IP）、CN_DEPLOY_SSH_KEY（第 7 节第 3 步公钥对应的私钥），可选 CN_DEPLOY_KNOWN_HOSTS。
  3. 服务器上先运行一次 deploy/init-env.sh，第一个问题回答 cn（第 9 节）。
  4. 在 GitHub 的 Actions 页面手动运行一次 “Build and deploy”，或推送一次。之后每次推送，美国和国内服务器各自更新。

只想手工部署时（不设 CN_DEPLOY_HOST），镜像仍会同步到 ACR，在服务器上：

docker login --username=<阿里云账号> registry.cn-hangzhou.aliyuncs.com
cd /opt/wenquest
deploy/update.sh registry.cn-hangzhou.aliyuncs.com/wenquest/engine:<版本号>
# 版本号 = GitHub 部署记录里的 12 位提交号；update.sh 会按 engine 的地址推出其余 6 个，写进 .env 后拉取、启动

路线 B（临时）：在能访问外网的机器上转存

# 在海外或能访问 ghcr.io 的电脑上（TAG 是 GitHub 部署记录里的 12 位版本号）
TAG=abc123def456; R=ghcr.io/eddiezgq/wenquest
for n in engine gateway web animator labcheck micro-synth voice; do docker pull $R/$n:$TAG; done
docker pull postgres:16-alpine; docker pull redis:7-alpine; docker pull caddy:2; docker pull rclone/rclone:1
docker save $(for n in engine gateway web animator labcheck micro-synth voice; do echo $R/$n:$TAG; done) \
  postgres:16-alpine redis:7-alpine caddy:2 rclone/rclone:1 | gzip > wq-images.tgz
# 传到国内服务器后
gunzip -c wq-images.tgz | docker load
cd /opt/wenquest && deploy/update.sh $R/engine:$TAG
镜像合计十几 GB（动画、语音镜像较大），路线 B 每次更新都要整包传，只适合首次部署或应急。

12常见问题

  
浏览器打不开网站，提示“网站暂时无法访问”或被拦截
多半是备案还没通过或域名不在备案名下。云服务商会拦截未备案域名的 80/443。先在控制台确认备案状态，并确认解析的子域名都在备案的主域名下。

  
证书申请失败，Caddy 日志里一直在重试
Caddy 用 Let's Encrypt，需要域名已解析到这台服务器、80/443 能从外网访问。检查：解析记录（第 6 节）、安全组放行 80/443、备案已通过。查看：docker compose ... logs --tail 50 caddy。

  
docker pull 卡住或报 timeout
Docker Hub 和 ghcr.io 在国内不稳定。用第 8 节路线 A：平台镜像和基础镜像都从 ACR 拉（.env 里 DB_IMAGE 等 4 项指向 ACR）；临时可用路线 B 转存。

  
AI 功能都不工作，/api/health 里 "ai" 是 "none"
.env 里 DEEPSEEK_API_KEY 没填或填错，改好后 deploy/update.sh（不带参数）重启。确认 ANTHROPIC_API_KEY 留空——填了会优先用 Claude，国内调不通。

  
AI 建课对话里改大纲、改课时不像美国版那样灵活
第 31 轮起的“AI 课程负责人”目前要 Claude 才能当代理（自己查资料、直接改草稿、撤销）。国内只有 DeepSeek 时，自动退回原来的流程：课程负责人给出提议，老师确认后执行。接入国内模型的代理能力在计划中。

  
收不到找回密码、通知邮件
国内云服务器通常封 25 端口。用邮件服务商给的 SSL 端口（如 465），SMTP_SECURE=ssl；发件地址必须是服务商验证过的域名；在服务商控制台看投递记录。

  
页面字体、三维模型从哪里来
第 34 轮起，官网、网页版教材、实验页用的字体和 three.js、KaTeX 都由自己的服务器在 /vendor/ 提供（部署时自动生成、复制），不再从 Google 和 cdnjs 取。Verilog 实验在国内（WQ_REGION=cn）自动改用服务器综合，仿真器也从 /vendor/ 取。看到字体不对，先确认服务器上有 /opt/wenquest/site/vendor/VERSION。

  
Moodle 15 分钟还没“健康”，update.sh 报错退出
首次安装大数据库或服务器内存不够。看 logs --tail 200 moodle；内存不足时升级配置（第 5 节）。更新后出错可 deploy/rollback.sh。
