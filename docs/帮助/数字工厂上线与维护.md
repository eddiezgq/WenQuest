# 数字工厂上线与维护

数字工厂和学习平台在同一台服务器上，各自独立运行、各自自动部署。

## 一、网址与登录

| 网址 | 内容 | 谁用 |
|---|---|---|
| https://factory.wenquestrobotics.com | 数字工厂工作台（运营看板、角色工作区、3D 车间、AI 工厂助手、实验 7） | 学生、老师 |
| https://erp.wenquestrobotics.com | ERPNext 减速器厂 | 所有人用问渠账号自动登录：老师可操作，学生只读 |
| https://demo.wenquestrobotics.com | 企业版演示工厂（生产模式，第 9 轮） | 老师；企业来宾由老师在“企业成员”授权 |
| https://demo-erp.wenquestrobotics.com | 演示工厂的 ERPNext（同一套程序里的 demo 站点） | 同上 |

- **工作台用问渠账号登录**：在学习平台登录过的，打开工作台选角色就能进；没登录的点“用问渠账号登录”，登录后自动回来。
- **学生**：只有教学模式，可选计划员、工艺员、操作工、质检员。
- **老师**（学习平台里能建课的账号）：另有厂长角色、生产模式和教师控制台（“经营与成本”页：重置实验 7、改仿真倍速、制造设备故障）。
- **所有人进同一座工厂**，看同一份实时数据；实验 7 的得分按人分开记。
- **AI 工厂助手**：每人每小时最多问 30 次。
- **ERPNext 单点登录**（第 7 轮）：点工作台左侧“ERPNext”或直接打开 erp 网址，会自动用问渠账号登录（第一次自动开账号，账号名形如 `wq123@users.wenquestrobotics.com`）。老师有制造、库存、采购、销售、质量等经理权限；学生只能查看单据，改动都在工作台里做。登出 ERPNext 会被自动重新登录，要彻底退出请退出学习平台。
- **ERPNext 管理员**：用密码登录请打开 `https://erp.wenquestrobotics.com/login?manual=1`；用户名 `Administrator`，密码在服务器 `/opt/wenquest/factory/.env` 的 `ERP_ADMIN_PASSWORD`（安装时自动生成）。
- **设计发布不用装软件**：“设计与工艺”页的“在线设计”直接改参数并发布（服务器出 STEP、零件图、G 代码）。想用桌面 FreeCAD 的，在同一页下载“我的 FreeCAD 宏包”（已填好线上地址和本人凭证，7 天有效）。
- **班级（小组）工厂**（第 10 轮）：每个班或小组一座独立的教学工厂，网址 `https://<编号>.factory.wenquestrobotics.com`，ERPNext `https://<编号>.erp.wenquestrobotics.com`。**加一个班**：在仓库 `factory/deploy/classes.yaml` 里照样子加一行（编号、名称，可选任课老师的问渠账号编号），推送即可，部署时自动建好（约 10 分钟）。删掉一行只停掉这个班的工厂，数据保留。能建课的老师账号在任何班级工厂里都是厂长。
- **演示工厂**：和教学工厂同一批程序、一起部署；数据（历史库 `wq_demo`、ERPNext 站点 `demo`）完全分开。每次部署自动检查并补齐演示工厂的配置。
- **仿真与分析**（第 11 轮）：工作台左侧“专业软件 → 仿真与分析”（有限元强度、疲劳寿命）。所有工厂（公共、演示、各班）共用一个计算服务（容器 `cae`），一次算一个任务，其余排队；每个任务最多 5 分钟、约 20 万个单元，超了提示调大网格；计算容器内存上限 2.5 GB，超了只中止这一次计算。使用说明见《仿真与分析》。第 12 轮起“运动与动力”（多体动力学，MuJoCo）也由这个容器计算；机械臂模型（Menagerie 固定提交里的 UR5e、UR10e、FR3）在镜像构建时取进镜像，要加机型改 `deploy/fetch_menagerie.sh` 和 `digital/cae/mbd_models.py`。第 13 轮起“数控编程”也在这个容器里生成程序和仿真（不排队，每次在独立进程里做、限时 2 分钟），编程记录和计算任务存在一起；机床参数表在 `digital/cae/cam_post.py`（教学示意值，要按真机床改行程、最高转速、快移速度）。CI 测试另装独立的 G 代码解析器 pygcode 核对程序格式（只在测试环境，不进镜像）。使用说明见《数控编程》。
- **每次部署后自动做“线上车间检查”**：在 GitHub 的部署记录里看“线上车间检查”注释——总线是否连上、教学模式有几台仿真设备在发数据，以及服务器上各容器的状态和仿真日志。

## 二、日常维护

登录服务器：`ssh deploy@<服务器 IP>`，然后 `cd /opt/wenquest/factory`。

| 要做的事 | 怎么做 |
|---|---|
| 更新数字工厂 | 改代码推送到 GitHub（改动 `factory/` 目录），自动测试、演练、部署 |
| 看运行状态 | `deploy/status.sh`：各容器状态、内存、历史库大小、两个网址的响应 |
| 看日志 | `docker compose -p wq-factory logs --tail 100 hub`（把 `hub` 换成 `sim`、`bridge`、`bus`、`erp-backend`） |
| 重启 | `deploy/update.sh`（不带参数：用现有版本重启，改了 `.env` 后也这样生效） |
| 查 ERPNext 管理员密码 | `grep ERP_ADMIN_PASSWORD .env` |
| 手动备份 | `deploy/backup.sh`；每天 03:30 随学习平台的备份自动执行 |
| 从备份恢复 | `deploy/restore.sh backups/<时间>`（先自动再备份一次当前数据） |
| 改 AI 次数、历史保留天数 | `.env` 里加 `WQ_AI_PER_HOUR=50` 或 `WQ_HISTORY_DAYS=60`，再运行 `deploy/update.sh` |
| 看有限元计算服务 | `docker compose -p wq-factory logs --tail 100 cae`；计算记录和结果在数据卷 `cae-data`（不进每日备份，可以重算） |
| 放宽有限元限制 | `.env` 里加 `WQ_CAE_TIME_LIMIT_S=600`、`WQ_CAE_MAX_ELEMENTS=400000`、`WQ_CAE_MEM=4g`（服务器内存要够），再运行 `deploy/update.sh` |

## 三、看 Node-RED 数据流

Node-RED 不对外开放，要看时用 SSH 隧道：

1. 在服务器上查桥接容器的内部地址：
   ```bash
   docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}} {{end}}' wq-factory-bridge-1
   ```
   会显示一两个地址，任取一个，例如 `172.19.0.7`。
2. 在自己电脑上（PowerShell 或终端）：
   ```bash
   ssh -L 1880:172.19.0.7:1880 deploy@<服务器 IP>
   ```
3. 保持这个窗口不关，浏览器打开 `http://localhost:1880`。

只想看有没有出错，直接在服务器上看桥接日志：`docker compose -p wq-factory logs --tail 100 bridge`。

## 四、服务器内存不够时

第一次部署会先检查空闲内存（至少 3 GB）。不够时部署停下，提示升级服务器，学习平台不受影响。升级方法：

1. DigitalOcean 控制台 → Droplets → 选这台服务器 → **Resize**。
2. 选 **CPU and RAM only**，选 16 GB 的规格，点 Resize（服务器会关机几分钟，数据不丢）。
3. 服务器开机后，学习平台自动恢复；到 GitHub → Actions → **Digital factory 数字工厂部署** → **Run workflow** 重新部署数字工厂。

## 五、文件在哪里

| 位置 | 内容 |
|---|---|
| 仓库 `factory/deploy/` | 服务器配置与脚本（安装、更新、状态、备份、恢复） |
| 仓库 `factory/digital/mosquitto/server/` | 数据总线的授权规则 |
| 仓库 `.github/workflows/factory.yml` | 自动测试、演练、部署 |
| 服务器 `/opt/wenquest/factory/.env` | 全部密码与设置（只在服务器上，自己另存一份） |
| 服务器 `/opt/wenquest/factory/backups/` | 最近 7 天的本机备份；配了 Spaces 时同时传到 `wenquest-factory/` |
