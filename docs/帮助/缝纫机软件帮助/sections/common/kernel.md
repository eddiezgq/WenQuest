### 缝纫机设计软件直接用到的

| 开源软件 | 做什么 | 在我们这里用在哪一步 | 许可证 |
|---|---|---|---|
| **OpenCASCADE**（OCCT） | 三维几何内核：实体建模、布尔运算、STEP 读写 | 服务器上经 build123d 出零件 STEP；FreeCAD 本身就建在它上面 | LGPL-2.1（带例外） |
| **build123d** | 用 Python 写参数化 CAD | 服务器上按参数生成机构零件、零件库的零件族 | Apache-2.0 |
| **FreeCAD** 1.0 | 开源参数化 CAD | “问渠缝纫机”工作台的宿主；本机有限元用它自带的 FEM 工作台 | LGPL-2.0+ |
| **Gmsh** | 有限元网格划分 | 零件、机壳剖成二次四面体（服务器和 FreeCAD 都是它） | GPL-2.0+ |
| **CalculiX** | 有限元求解器（静力、模态） | 零件强度、机壳固有频率 | GPL-2.0 |
| **pyLife** | 疲劳寿命分析 | 雨流计数、S–N 曲线、Miner 累积损伤 | Apache-2.0 |
| **MuJoCo** | 多体动力学 | 刺布（引针）机构动力学，核对主轴转矩公式 | Apache-2.0 |
| **SciPy / NumPy** | 数值计算 | 拓扑减重（SIMP，按经典 88 行算法重写）、曲线与数据处理 | BSD-3 |
| **trimesh、Shapely** | 网格与平面几何 | 数控编程识别铣削特征、花样模板的槽 | MIT、BSD-3 |
| **three.js** | 网页三维 | 三维虚拟样机、零件库的三维预览 | MIT |
| **python-docx、openpyxl** | Word、Excel 文件 | 计算书、调机卡、参数表、零件库模板、ERPNext 物料表 | MIT |
| **FastAPI** | 网页接口框架 | 问渠网关：账号、项目、导出、AI 助手、零件库 | MIT |

### 整个平台用到的（设计软件连着的那些）

| 开源软件 | 做什么 |
|---|---|
| **ERPNext** | 开源 ERP：物料、BOM、订单、工单、质量、财务 |
| **Moodle** | 学习平台的后台引擎（账号、课程） |
| **PostgreSQL** | 数据库（数字工厂历史库、学习平台） |
| **Mosquitto**（MQTT）、**Node-RED** | 数字工厂的统一数据总线和桥接 |
| **OpenFOAM** | 流体分析（数字工厂“仿真与分析”） |
| **OpenPLC** | 虚拟 PLC 的标准运行时 |
| **Optuna** | 数字工厂的设计优化（贝叶斯优化，驱动有限元、温度场） |

大模型不是开源软件：国内部署用已备案的 DeepSeek，美国用 Claude，经统一的模型接口调用。

### 我们自己做的是什么

1. **计算核心**：六种机型、{{checks_all}} 项校核的公式和判据，全部出自教材《缝纫机设计与制造》31 讲，数经教材审过；网页版和 FreeCAD 共用一份。
2. **把参数变成仿真**：按设计参数自动生成零件、找支承孔和受力孔、取一转里最大的力、定载荷谱——这是让不会仿真的人也能做仿真的关键。
3. **把 AI 关进笼子**：AI 起草，计算核心重算，数字逐个核对，人点采用。
4. **打通上下游**：设计 → 计算书 → STEP / DXF → 数控程序 → 审批 → ERP 物料 → 车间。
5. **按单位隔离的企业版**：项目、零件库、CAE 次数、钥匙都按单位。

### 为什么用开源内核

- **成熟**：这些求解器和几何内核，全世界的大学、研究所、工厂用了很多年，结果有大量文献可对照。
- **透明**：算法公开，结果可复核；需要时可以拿同一个 STEP 在别的软件里核对（例如“复杂 CAE 快速上手”一节里 FreeCAD 本机和服务器的有限元对照）。
- **不被卡脖子**：没有按席位收费的商业许可，部署在国内服务器也不受限制；数据在自己手里。
