# 两台美国服务器：教育与企业分开

给谁看：Eddie。依据：《实施细则 · 第 146 轮》，wenquest-ops ADR-0029。

## 哪台跑什么

| | 教育服务器 | 企业服务器 |
|---|---|---|
| 地址 | 原来那台（DigitalOcean 纽约，8 GB） | 161.35.185.35（DigitalOcean 纽约，8 GB，11-10 开） |
| 网址 | 官网、`learn.`、`classic.`、数字工厂（`factory.`、`demo.`、各厂）、官网下的 `/cam/` `/bearing/` `/eda/` | `app.`（工业软件），`qms.`、`qms-erp.`、`<企业>.qms.`（问渠质量 ERP；切换以后） |
| 谁部署 | 推送 main 后由 `deploy.yml` 自动部署 | 前门和工业软件：手动跑 `Enterprise server 企业服务器` 工作流，任务选 `deploy`；质量 ERP：`wenquest-ops` 的 `deploy-us.yml` |

## 账号

- 两台用的是同一套账号，都是学习平台的账号。登录在 `learn.` 上，整个 `wenquestrobotics.com` 共用一份登录状态。
- `app.` 上的凸轮、轴承、问渠电子：身份、云端项目、AI 起草都经教育服务器的网关。企业的项目按单位分开存。
- 企业另要一套独立账号的话，等“企业中枢”那一轮再做。

## 试点企业的开通怎么转

- 管理员在学习平台的“管理 → 质量 ERP 试点”发邀请，对方注册。这些都在教育服务器的网关上。
- 切换以后，开通申请由企业服务器每分钟用钥匙来取（交接桥 `deploy/enterprise/bridge-sync.py`），在企业服务器上装好，再把账号送回网关，由网关发邮件。
- 企业服务器的 Caddy 只给“开通了的企业”办证书，这份名单也是交接桥每分钟取回来的。

## 常用操作

- **企业服务器上的工业软件跟上新版本**：学习平台部署成功后，跑一次 `Enterprise server 企业服务器`，任务选 `deploy`。它会照教育服务器正在跑的镜像更新。
- **检查企业服务器**：同一个工作流，任务选 `check`，会显示内存、磁盘和 Docker 的情况。
- **开桥 / 回退**：任务 `bridge-on` 把试点开通交给企业服务器；`bridge-off` 改回教育服务器。

## 出问题看哪里

- `app.` 打不开：先用 `check` 看企业服务器还能不能登录；再看 `/opt/wenquest/edge` 里 `docker compose ps`。
- 试点企业一直“排队开通”：看企业服务器 `/opt/wenquest/edge/bridge.log`（交接桥）和 `/opt/wenquest/qms/pilot-runner.log`（开通程序）。
- 新开的企业网址报证书错误：看 `/opt/wenquest/edge/allow/` 里有没有这家的网址；没有就是交接桥没取到名单。
