# 问渠机器人（AI 原生机器人设计、仿真与控制）：V1 开发方案与计划

- 2026-11-25 起草 · **草案，待 Eddie 定第九节**
- 依据：Eddie 11-25“关于机器人，有什么完整的软件解决方案”，同日“好”（照电子线格式写成 V1 开发方案）
- 本计划是《问渠产品系列规划》（`docs/方案/问渠产品系列规划.md`）里机器人一线的展开；体例照《问渠电子 V1 开发方案与计划》
- 按产品系列规划，机器人线排在电子 V1 之后；**本计划现在只定方案，不施工**

**问渠机器人**和问渠 CAD、问渠电子一样，是问渠系列的一员：以 ROS 2（机器人操作系统）生态为母体，加上 AI 原生的一层，用问渠的名字和安装包发布。

一句话：**从一句需求，到一台能在仿真里干活、能下发到真机的机器人**——需求 → 构型 → 载荷计算与选件 → 自动生成仿真模型 → 运动规划与控制 → 真机。

V1 计划 20 周：2027-05-10 开工，2027-09-26 完成端到端演示。

## 一、开源母体：一个环节配一个软件

机器人没有一个“全套”开源软件，业界做法是以 ROS 2 为底座，各环节配专用软件。问渠机器人选用如下（全部是允许集成的开源协议，BSD、Apache 一类）：

| 环节 | 干什么 | 选用 | 现在有没有 |
| --- | --- | --- | --- |
| 底座 | 各部分通信，串起整条链 | ROS 2 Lyrical（长期支持版，支持到 2031 年 5 月，Ubuntu 26.04） | 没有 |
| 结构建模 | 三维结构 → 机器人模型文件（URDF / MJCF 两种格式） | 问渠 CAD（FreeCAD）＋导出；Pinocchio（运动学、动力学计算库） | 问渠 CAD 有；导出、Pinocchio 没有 |
| 仿真 | 虚拟样机、虚拟实验 | **MuJoCo**（物理仿真引擎，不用显卡也快，主力）；Gazebo（仿真器，只用于 ROS 教学） | MuJoCo 有（68 款真实机器人模型）；Gazebo 没有 |
| 运动规划 | 机械臂轨迹、避障、抓取 | MoveIt 2（机械臂规划软件） | 没有 |
| 控制 | 关节控制、对接硬件 | ros2_control（ROS 2 控制框架） | 规划里有，未做 |
| 移动机器人 | 建图、定位、导航 | Nav2（导航软件）、slam_toolbox（建图工具） | 没有 |
| 感知 | 视觉、点云 | OpenCV（图像处理）、Open3D（三维点云） | 教材实验里有 |
| 机器人学习 | 模仿学习、强化学习、视觉语言动作模型 | LeRobot（Hugging Face 的机器人学习库） | 没有 |
| 工业控制 | PLC（可编程控制器） | OpenPLC | 有（问渠 PLC） |
| 显示调试 | 三维显示、数据回放 | RViz 2（ROS 可视化工具）；网页端用问渠自己的三维查看器 | 网页查看器有 |

**不用的**：英伟达 Isaac Sim / Isaac Lab、智元 Genie Sim 3.0（建在 Isaac Sim 上）——要英伟达显卡，分发还要另外的商业授权，和“不开租用显卡”的规矩冲突。以后要做大规模训练，走 Newton 物理引擎（MuJoCo 是它的求解器之一），不用推倒重来。

**国产部分作适配件接入**：宇树的 MuJoCo 模型进虚拟实验；节卡、越疆、遨博机械臂通过它们的 ROS 2 驱动接真机；地瓜机器人 RDK 板子（TogetheROS，基于 ROS 2）作实物实验的低价主控；智元 AGIBOT WORLD 数据集给 LeRobot 用。

## 二、和机械、电子两线的对照

| 机械线 | 电子线 | 机器人线（本计划） |
| --- | --- | --- |
| FreeCAD 作母体 | KiCad 作母体 | ROS 2 + MuJoCo + MoveIt 2 作母体 |
| 零件：端口 + 参数 + 包络 | 功能块：端口 + 参数 + 包络 | **机器人描述**：关节、连杆、执行器（引用零件库的关节模组）、传感器、任务 |
| 判定全用确定性代码，AI 只提议 | 同 | 同：工作空间、关节力矩、转速、刚度、碰撞，全由代码算和判；缺数据判“未知” |
| 问渠 FEA、MBD | ngspice、热分析 | MuJoCo 仿真、Pinocchio 动力学；每个模块带标准题（和解析解、教材公式对照） |
| 数字工厂：减速器厂 | 电路板厂 | 机器人厂、电机厂、传感器厂 |

## 三、前提与假设

- **人力**：Eddie 兼职，负责设计、评审、验收；编码靠 AI 编码助手。剩余工期主要取决于人工验收的时间。
- **已有基础**：
  - 《机器人学》33 章、149 个实验文件。
  - MuJoCo 模型 68 款（MuJoCo Menagerie）＋ robot_descriptions 40 款。
  - 自有机器人 WQ-CR5（六轴协作臂）、WQ-H1（人形）。
  - 数字工厂机器人厂、电机厂、传感器厂。
  - 零件库 V1（关节模组：伺服电机、减速器、驱动器、轴承选型与校验，`freecad-ai-parts`）。
  - 问渠 PLC，四专业虚拟实验室规划里的机器人 16 个实验室。
- **V1 范围**：三类机器人做到端到端——
  1. 六轴机械臂（以 WQ-CR5 为样板）：构型、选件、规划、控制全做。
  2. 移动操作机器人（差速底盘 + 机械臂）：导航 + 抓取。
  3. 低价实物臂（SO-101 一类，几百元）：仿真到真机、机器人学习。
  - 不做：人形和四足的设计（WQ-H1、宇树模型只做仿真展示）、无人机、大模型训练。
- **显卡**：V1 不用显卡。机器人学习只做 CPU 能跑的小策略（ACT 小模型）和现成模型的推理、评测。
- **AI**：国内用 DeepSeek，美国用 Claude，自动切换（同问渠 CAD、问渠电子）。
- **原则**：范围、接口、数据格式的任何变更，先改本计划或写 ADR（决策记录），再动代码。

## 四、仓库结构与模块

独立仓库 `wenquest-robot`（同机械线、电子线），一样有 plan、实施细则、ADR、里程碑。

| 模块 | 做什么 | 依赖 | 首次用到 | 能否独立测试 |
| --- | --- | --- | --- | --- |
| `schema` | 机器人描述格式（需求、构型、关节、执行器、传感器、任务） | 无 | R1 | 能：格式校验样例 |
| `model` | 机器人描述 ↔ URDF / MJCF 双向转换；导入现有 108 款模型 | schema | R1 | 能：往返转换比对 |
| `engine` | 运动学、工作空间、载荷 → 关节力矩与转速、刚度；调零件库选型校验 | schema、Pinocchio、零件库 | R2 | 能：golden 测试集（标准题） |
| `sim` | 自动生成 MuJoCo 场景、跑任务、出指标 | model | R3 | 能：标准题与解析解对照 |
| `control` | ros2_control 控制器、MoveIt 2 规划、Nav2 导航的配置自动生成 | model | R3 | 能：在容器里无界面跑 |
| `ai`、`mcp_server` | AI 起草需求和构型、只在候选里提议；给 AI 用的工具接口 | engine | R4 | 能：模拟模型测试，不联网 |
| `learn` | LeRobot 接口：仿真遥操作采数据、回放、小策略训练与评测 | sim | R5 | 能：CPU 小样例 |
| `real` | 真机适配：SO-101、WQ-CR5、国产臂的 ROS 2 驱动对接 | control | R6 | 部分：需实物 |
| `web` | 学习平台里的网页端：三维查看、参数面板、结果报告 | engine、sim | R3 起 | 能：页面测试 |

## 六、各阶段任务、交付物与验收

| 阶段 | 主要任务 | 交付物 | 验收标准 |
| --- | --- | --- | --- |
| R0 拆仓与骨架 | 建 `wenquest-robot`；CI 用装好 ROS 2 Lyrical + MuJoCo + MoveIt 2 的容器；`CLAUDE.md`、实施细则、ADR 模板 | 仓库、CI 绿 | 空项目在 CI 里能启动 ROS 2 和 MuJoCo 并跑通一个测试 |
| R1 机器人描述定稿 | 机器人描述格式 1.0；URDF / MJCF 双向转换；108 款现有模型全部导入 | `schema`、`model` | 108 款往返转换后关节数、质量、惯量一致；格式样例全部通过校验 |
| R2 构型与选件引擎 | 运动学、工作空间、雅可比；由负载、速度、节拍算各关节力矩和转速；调零件库给每个关节选电机、减速器、驱动器并校验 | `engine`、计算书 | 标准题 20 道和教材公式对照误差 < 1%；WQ-CR5 选件结果和实际选型一致或给出理由；缺数据判“未知” |
| R3 仿真、规划与控制 | 自动生成 MuJoCo 场景；ros2_control 控制器；MoveIt 2 规划（避障、抓取）；Nav2 导航；网页端三维查看 | `sim`、`control`、网页 | 三类机器人各完成一个标准任务（码垛、移动抓取、桌面抓放）；成功率、节拍、关节力矩峰值自动出报告 |
| R4 AI 自主设计 | 一句需求 → AI 起草需求和构型 → 引擎算和判 → 不合格按结果改（最多 N 轮）→ 人确认 | `ai`、`mcp_server` | 10 个需求样例中 8 个以上自动得到通过全部校验的方案；AI 每次运行留记录 |
| R5 机器人学习 | 仿真里遥操作采数据（LeRobot 数据格式）；ACT 小策略 CPU 训练；现成模型推理与评测 | `learn` | 桌面抓放任务：仿真采 50 条数据，训练后成功率 ≥ 60%；全程不用显卡 |
| R6 真机与工厂闭环 | SO-101 真机：仿真策略下发到真机；WQ-CR5 接数字工厂机器人厂（订单 → 选件 → 物料清单 → 工厂） | `real` | SO-101 真机完成抓放；机器人厂能收到问渠机器人出的物料清单 |
| R7 端到端演示与文档 | 串通全流程；演示视频（网页版 PPT + 真页面录屏）；帮助（教学版、企业版）；对接四专业虚拟实验室的机器人实验室 | 演示、帮助 | 从一句需求到仿真干活、到真机，一次走通并录屏 |

## 七、风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| ROS 2 在 Windows 上支持差 | 老师、学生本机装不上 | 主形态是网页（服务器跑仿真）；本机用 Docker 包，Windows 经 WSL2；不做原生 Windows 安装包 |
| 服务器资源（11-24 刚瘦身） | 多人同时仿真时卡 | 仿真按需启动、用完即停（同第 184 轮“按需开工”）；MuJoCo 不用显卡，单核能跑一个场景 |
| 不用显卡，机器人学习效果有限 | R5 只能做小任务 | V1 明确只做小策略和推理评测；需要大训练时另报 Eddie |
| 真机型号多、驱动质量不一 | R6 拖期 | V1 只承诺 SO-101 和 WQ-CR5（仿真）；国产臂只做驱动对接演示 |
| 零件库数据不全 | 选件判不了 | 判“未知”，不猜；出待补清单（同零件库规则） |
| 兼职投入不稳定、窗口上限 | 整体延期 | 缓冲期吸收；每阶段结束重估；电子 V1 收尾后用它的窗口接机器人，不增加窗口 |
