# 问渠电子（AI 原生 EDA × 元器件库）：V1 开发方案与计划

- 2026-11-24 起草，同日按 Eddie 23:44 修订 · **草案，待 Eddie 定第九节**
- 依据：Eddie 11-23“电这条线的软件开发，我讨论过几次了，我希望拿出和机械那边一样的一个开发计划”；23:44“我的意思是利用开源软件，进行 AI 原生和重构，做成问渠产品系列”
- 本计划是《问渠产品系列规划》（`docs/方案/问渠产品系列规划.md`）里电子一线的展开
- 体例照机械线《AI 原生 FreeCAD × 零件库：V1 开发方案与计划》（`eddiezgq/freecad-ai-parts` 的 `docs/plan.md`）

**问渠电子**和问渠 CAD 一样，是问渠系列的一员：以 KiCad 为母体，必要时打补丁，加上 AI 原生的一层，用问渠的名字、图标、安装包和授权发布。

V1 计划 22 周：2026-11-30 开工，2027-05-02 完成“从一句需求到可投产资料包”的端到端演示。

## 二、前提与假设

- **人力**：Eddie 兼职，负责设计、评审、验收；编码靠 AI 编码助手。和机械线一样，开发通常会比计划快，**剩余工期主要取决于人工验收的时间**。
- **已有基础**（P1–P6，11-06 到 11-09 完成，11-09 线上核对通过）：
  - `eda/wqeda`：约 1.25 万行，16 个测试文件；31 个器件；20 种功能块（16 种有生成器，4 种有仿真标准题）。
  - 已有能力：四层设计描述、工艺能力表、两条入口（KiCad 文件 / 光绘）、统一检查引擎、功能块计算器与计算书、AI 起草、通用板子生成与自动布线、热分析、手工改动读回、工厂端、网页审图、KiCad 9 插件。
  - 两类真板子已经用它做出来：关节伺服驱动板 A / B 版（`factory/designs/drv-joint*`），平缝机控制器（`factory/designs/ctrl-ls`，第 159 轮）。
- **V1 范围**：
  - 电路板：电机驱动、电源、主控通信三类。
  - 每个功能块都带四样：计算器、生成器、仿真标准题、布局规则。
  - 元器件库约 200 个型号，覆盖这三类板子。
  - 不做：多层高速板、射频、芯片设计（芯片归电子会话的教学线）。
- **环境**：KiCad 9.x（锁定小版本）、Python 3.11+、Freerouting、ngspice、CalculiX、gerbonara、KiCanvas。AI 国内用 DeepSeek，美国用 Claude，自动切换（同问渠 CAD）。
- **日历**：
  - 12/14–2027/1/3 预留 3 周缓冲，对应 UF 期末与假期。
  - 课程和开发冲突时课程优先（总控规则 P1）。
- **窗口**：按总控规则，同时最多 3 个 Opus 窗口。电子窗口开工后，问渠 CAD 和零件库合成一个窗口（同一条 FreeCAD 线），总数不变。
- **原则**：范围、接口、schema 的任何变更，先改本计划或写 ADR，再动代码。

## 三、仓库结构与模块分工

新建独立仓库 `wenquest-eda`（公开，同 `freecad-ai-parts`），把 `eda/` 连同提交历史迁过去。WenQuest 只留网页服务（`services/eda`）和数字工厂的板子设计（`factory/designs`），按版本号引用引擎。

```text
wenquest-eda/
├── schema/          # 设计描述 L1–L4、元器件、功能块、工艺能力表、问题单的格式（共同契约，最先定稿、最少改动）
├── parts/           # 元器件库：型号数据（带出处）、KiCad 官方库符号/封装的对应关系
├── blocks/          # 功能块库：每块 = 计算器 + 生成器 + 仿真标准题 + 布局规则
├── engine/          # 展开（L1→L4）、生成 KiCad 文件、读回、检查（纯函数）
├── sim/             # ngspice 标准题、热分析、以后的信号完整性
├── mfg/             # 生产资料：光绘、钻孔、物料清单、坐标、贴片程序、测试程序；工厂端检查
├── ai/              # 起草、自主设计循环、问题单起草（只提议，不判定）
├── ingest/          # 企业建库：物料清单通道、器件手册通道、人工复核队列
├── mcp_server/      # 给外部 AI 客户端的工具（同机械线）
├── kicad_plugin/    # KiCad 插件（进程间接口）
├── desktop/         # Windows 一键安装包：官方 KiCad + 插件 + 本机引擎 + 授权 + 更新
├── tests/golden/    # 标准测试集：已知正确 / 已知错误的设计
└── docs/            # 本计划、架构、实施细则、adr/、帮助
```

| 模块 | 依赖 | 首次用到 | 能否独立测试 |
| --- | --- | --- | --- |
| `schema` | 无 | E1 | 能：格式校验样例 |
| `parts`、`ingest` | schema | E2 | 能：对样例手册比对抽取结果 |
| `blocks`、`engine` | schema、parts | E1（已有，E3 扩充） | 能：golden 测试集 |
| `sim` | engine | E3 | 能：标准题与手算对照 |
| `ai`、`mcp_server` | engine | E4 | 能：模拟模型测试，不联网 |
| `kicad_plugin`、`desktop` | engine | E5 | 部分：需 KiCad 与 Windows |
| `mfg` | engine | E6 | 能：产物比对 |

## 四、开发方法与质量保障

照搬机械线的方法：schema 先行、测试先行。先定契约和验收用例，再让 AI 编码助手照着做，人只在契约和验收上把关。

1. **schema 先行**：每个模块开工前写清输入输出格式，评审通过再编码。
2. **golden 测试集**：E1 起维护，分两类，每次改动全部跑通。
   - 已知正确的设计，应该通过。
   - 故意做错的设计，应该被拒，而且原因要对。例如：耐压余量不够、采样电阻功率不够、去耦电容太远、大电流线太窄、栅极电阻接反、工厂做不出的线距、缺物料编号。
3. **产物一致回归**：驱动板 A / B 版、平缝机控制器三块真板子，每次改动后重新生成，原理图、物料清单、坐标、网表与基准一字不差；布线结果按现有方式核对。
4. **判定是纯函数**：检查、计算、选型核对不联网、不调 AI，加测试检查这一点。
5. **数据可追溯**：器件参数记录出处（文件、页码、日期、置信度），没有就不写，判“未知”；示例值标“示例值”。
6. **AI 编码的约束**：按模块下任务；同一个 PR 不同时改 `schema/` 和实现；合并前看 diff。
7. **持续集成**：每次提交跑 schema 校验、单测、golden、产物一致回归。装 KiCad 的重任务（插件实测、安装包）只在 main 推送或打标签时跑，不在 PR 和 push 上重复跑（总控规则）。
8. **决策记录**：重要取舍写成 ADR，存进 `docs/adr/`。

## 七、风险与应对

最大的风险在数据层和母体接口：器件手册条款、参数不全，以及 KiCad 的进程间接口还不成熟。

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 器件厂家或分销商条款不允许提取 | 公共库变小 | E2 第一周先做条款核查；以企业自建库为主（同机械线 M9 决定）；公共库只收条款允许的；缺数据判“未知” |
| 器件手册参数不全（热阻、开关特性只在曲线里） | 计算、仿真判不了 | 判“未知”，不猜；出待补清单给企业补；优先选手册清楚的型号 |
| KiCad 进程间接口不能嵌面板、9 到 10 有变动 | E5 插件体验差 | 结果放本机网页里看（P6 已这样做）；封装一层适配；锁 KiCad 小版本 |
| 自动布线在密的板子上质量不够 | E3、E4 板子检查过不了 | 布局约束先行；人在 KiCad 里改，读回设计描述；V1 只承诺两层、四层的中低密度板 |
| GPL 边界（KiCad、Freerouting） | 许可风险 | KiCad 是 GPL：改过的 KiCad 源码和补丁随安装包公开（仓库本来就公开，成本很小），名字改成问渠电子、注明基于 KiCad；我们的引擎、AI、库作为独立程序，经进程间接口通信，不受 GPL 约束 |
| 拆仓打断电子会话和线上页面 | E0 延期、线上出错 | 拆仓前在电子会话最新一轮细则里留说明；产物路径不变是 E0 的验收条件 |
| 兼职投入不稳定、窗口上限 | 整体延期 | 缓冲期吸收；每阶段结束重估剩余工期；一个电子平台窗口，不并行开第二个 |

## 八、工作节奏与计划维护

以周推进，以阶段验收为关口；计划是活文档，先改计划再改代码。

- **每周开始**：从当前阶段选本周目标，写进 `STATUS.md`。
- **每周结束**：跑 golden 和产物一致回归，记下完成情况和问题。
- **阶段结束**：按验收标准演示；更新本计划的剩余工期；方案调整先写进架构文档或 ADR。
- **和电子会话的分工**（沿用 11-06 定）：
  - 本计划（平台）：格式、元器件库、功能块库、生成与读回、检查、仿真接口、生产资料、AI、插件、桌面版、网页。
  - 电子会话：数字工厂各厂、芯片、固件、虚拟仪器、教学内容；板子的电路内容（器件、数值）由他们定，改的是设计描述。
