## 一、做法：每个问渠产品都是同一个配方

问渠 CAD 已经把路走通了（FreeCAD 1.1.4 + 27 个补丁 + AI 工作台 + 零件库 + 安装包 + 一年授权）。其余产品照同一个配方做：

| 层 | 做什么 | 问渠 CAD 的样子 |
| --- | --- | --- |
| 1 母体 | 选一个成熟的开源软件，锁定版本 | FreeCAD 1.1.4、OCCT |
| 2 补丁 | 只改非改不可的：缺陷、品牌（名字、图标、启动页、菜单）、嵌 AI 面板 | 27 + 6 个补丁 |
| 3 设计描述 | 设计的源头是一份 AI 能读写的文本描述（YAML），母体的文件由它生成；人在母体里改的读回描述 | 零件“端口 + 参数 + 包络” |
| 4 判定 | 能不能用全由确定性代码判：纯函数，不联网、不调 AI；缺数据判“未知” | `engine/` 校验 |
| 5 库 | 企业用 AI 从物料表、手册、模型自建，公共库为辅 | 零件库、企业库 |
| 6 AI | 只提议、起草、按检查结果改；人确认才算数；国内 DeepSeek、美国 Claude，自动切换 | AI 工作台 |
| 7 发布 | Windows 一键安装或网页版；问渠下载中心、一年授权、能更新（第 175 轮） | 问渠 CAD 安装包 |
| 8 教学与工厂 | 配教材、虚拟实验，和数字工厂对接 | 机械教材、减速器厂 |

许可规则（每条线施工前核对许可证全文）：
- **LGPL**（FreeCAD、OCCT）：改过的母体源码随安装包公开，我们自己的代码可以闭源。
- **GPL**（KiCad、Magic 的部分组件、KLayout、ngspice 的部分组件）：改过的母体整体按 GPL 公开。我们的引擎、AI、库作为独立程序，走进程间接口或命令行，不受影响。
- **BSD、Apache、MIT**（OpenROAD、Yosys、LibreLane、MuJoCo 等）：可以直接集成。
- 仓库现在本来就公开，所以“公开补丁”这一条几乎没有额外成本。

## 三、问渠芯片（新列）

**定位**：从一句需求或一段 RTL 到可流片的版图，全程用开源工具链；AI 起草设计和约束，确定性程序跑综合、布局布线、签核，判定看签核结果。先服务教学和小规模的专用芯片，例如 WQ-ENCIF 这类编码器接口、传感器接口、电机控制专用芯片。

**设计描述**（和问渠电子同一套思路）：

| 层 | 内容 | 谁起草 | 谁把关 |
| --- | --- | --- | --- |
| C1 规格 | 功能、接口、时钟、面积、功耗、工艺库、封装 | AI 从需求起草 | 人确认，缺项标“未定” |
| C2 架构 | 模块划分、寄存器表、状态机、接口时序 | AI 提议 | 代码检查一致性（寄存器地址不重叠、时序闭合的预算） |
| C3 RTL 与验证 | Verilog、cocotb 测试平台、断言 | AI 起草，人审 | 仿真全过、覆盖率达标、形式验证（SymbiYosys） |
| C4 实现 | 综合、布局布线配置（LibreLane） | 程序生成，AI 只在参数候选里提议 | DRC、LVS、时序、天线、IR 压降全过才算“能流片” |
| C5 封测与上板 | 引脚、封装、测试向量、上板接口 | 程序生成 | 和数字工厂芯片封测厂、问渠电子的板子设计对上 |

**产品形态**：
- 网页版（手机、电脑都能用）：RTL 编辑、Yosys 综合、DigitalJS 仿真。已有，放进问渠芯片的门户。
- 服务器版（每人一个容器）：完整流程到 GDS，基于现在的微电子容器（IIC-OSIC-TOOLS）。
- 桌面版：不做 Windows 原生（这些工具在 Windows 上不成熟），用“本机容器 + 浏览器界面”。

**分期**（每期写细则、确认后施工）：

| 期 | 内容 | 验收 |
| --- | --- | --- |
| X1 底座 | 设计描述 C1–C5 格式；把 WQ-ENCIF 迁成设计描述，生成 RTL 配置与 LibreLane 配置 | 迁移后重新跑出的 GDS 与签核结果和现有的一致 |
| X2 签核判定 | 统一读 LibreLane 报告，出一份“能不能流片”的判定和中文说明；按判定把 WQ-ENCIF 的 204 处最大转换时间超限修掉（加缓冲、调扇出约束） | WQ-ENCIF 判定从“不能流片（转换时间超限）”变成“能流片”；故意做错的设计（时序不过、LVS 不对）被拒且原因对 |
| X3 AI 起草与自动改 | 需求 → C1、C2 → RTL 与测试平台 → 跑流程 → 按报告改，最多改 N 轮 → 人确认 | 三条需求走通：一个计数器类、一个接口类（SPI / SSI）、一个电机控制 PWM |
| X4 门户与发布 | 问渠芯片门户；网页版 + 容器版；下载中心、授权；中英帮助 | 不装软件在网页里从需求走到版图图片 |
| X5 与问渠电子、数字工厂打通 | 芯片引脚、封装进问渠电子的元器件库；芯片封测厂接收新芯片 | 一颗新芯片从设计到上板的闭环 |

**先做哪一期**：X1、X2 只需要现有容器和 CI，不要 GPU。现在 `chip.yml` 跑一次 WQ-ENCIF 的时间在可接受范围内（施工前实测记录）。

## 四、怎么排先后

总控规则规定同时最多 3 个 Opus 窗口，所以各条线不能齐头并进：

1. **机械**（在做）：问渠 CAD、零件库、CAM 收尾到 V1；问渠 CAD 和零件库合成一个窗口。
2. **电子**（下一个）：按问渠电子 V1 计划，11-30 开工。
3. **芯片**：电子 E3 之后开 X1、X2（2027 年 2 月起），因为芯片的引脚和封装要进电子的元器件库。
4. **机器人**：资源最多，但它要用到机械、电子、芯片三线的成果，排在电子 V1 之后整合。在那之前，虚拟实验照样用现有资源（见四专业虚拟实验室规划）。
5. **计算机与 AI**：问渠 AI 实验台主要是课程侧的东西，跟着虚拟实验室规划走，不单开产品窗口。

《多体动力学》书是机械线的一部分，照总控规则一次只推一本，不受影响。

## 五、共用的东西（每条线都用，不重复造）

- 下载中心、授权、更新（第 175 轮）
- AI 模型网关和国内外切换
- 设计描述的通用写法（YAML、版本管理、手工改动读回）
- 判定引擎的规矩（纯函数、未知不判通过、标准题和手算对照）
- 企业建库的通道（物料清单、手册、模型）
- 帮助和录屏教程的做法（网页版 PPT + 真页面录屏）
- 数字工厂：每个产品至少对接一个厂（机械 → 减速器厂、机器人厂；电子 → 电路板厂；芯片 → 芯片封测厂；机器人 → 机器人厂、电机厂、传感器厂）
