## 一、要解决的问题

现有开源机器人软件有三个毛病：

1. **零散**：设计、仿真、规划、控制、学习各是一个软件，数据不通。
2. **门槛高**：模型文件（URDF）、配置文件（YAML）、启动文件都要手写，要懂 ROS（机器人操作系统）才用得起来。
3. **和设计、生产脱节**：三维结构、选件、电路、生产都在别处，改一处，其他全靠人手跟着改。

问渠机器人要做的：**用开源软件当“发动机”，问渠重构“车身和驾驶方式”，再让 AI 来开。**

## 二、重构：一份数据，全部自动生成

| 重构点 | 做法 |
| --- | --- |
| 统一数据 | 问渠原创“机器人描述”（需求、构型、连杆、关节、执行器、传感器、末端、任务、场景），是唯一源头；格式定版后受 ADR（决策记录）管理 |
| 不再手写 | URDF / MJCF（两种模型文件）、SRDF 与 MoveIt 配置、ros2_control 配置、Nav2 参数、启动文件，全部由“机器人描述”生成；人改了生成物，读回描述 |
| 打通问渠全线 | 问渠 CAD 出结构 → 零件库出电机、减速器、驱动器、轴承 → 问渠电子出驱动板 → 问渠有限元、问渠多体动力学校核 → 数字工厂（机器人厂）生产 → ERP 出物料、采购、质量 |
| 网页化、中文化 | 学习平台里打开就用（服务器跑仿真，按需启动）；本机用 Docker 一键包（Windows 经 WSL2，即 Windows 自带的 Linux 子系统） |
| 确定性判定 | 工作空间、可达性、奇异性、关节力矩与转速、刚度、碰撞、稳定裕度，全由代码计算和判定；每个计算模块带标准题（和解析解、教材公式对照） |

## 三、AI 原生：AI 干活，代码判定，人确认

- **AI 做**：读需求、起草机器人描述、提议构型和选件（只在候选里提）、把一句话任务变成程序、调控制参数、诊断故障、写计算书和设计说明书。
- **代码判**：所有影响“能不能用”的结论；不合格退回 AI 改（有轮数上限）；缺数据判“未知”，不猜，不判通过。
- **人确认**：方案、定稿、下发真机。
- **留记录**：AI 每次运行都记下输入、输出、判定结果，供追溯和“自动迭代”使用（见上位文件第四节）。
- **模型**：国内用已备案模型（DeepSeek），美国用 Claude，自动切换；智能体通过 MCP（给 AI 用的工具接口）调用各工作台。

## 四、产品构成：一个软件，九个工作台

| 工作台 | 开源母体 | 重构做什么 | AI 原生做什么 |
| --- | --- | --- | --- |
| 1 设计 | Pinocchio（运动学、动力学库）、问渠 CAD（FreeCAD）、问渠零件库 | 需求 → 构型 → 尺寸 → 选件 → 结构一条线；自动出模型文件和物料清单 | 构型综合（串联、SCARA、并联、移动、足式）、尺寸优化、选件提议；计算书自动写 |
| 2 仿真 | MuJoCo（物理仿真引擎，主力）、Gazebo（ROS 教学用仿真器） | 模型、场景、传感器自动生成；网页里跑，结果出报告 | 按需求自动生成工况和极限场景；读仿真结果找问题 |
| 3 规划 | MoveIt 2（机械臂规划）、Nav2（导航）、BehaviorTree.CPP（行为树） | 取代手工配置向导，配置自动生成 | 一句话任务 → 行为树 / 任务程序 → 仿真验证 |
| 4 控制 | ros2_control（控制框架） | 控制器按构型自动配：PID、计算力矩、阻抗、力控 | 控制器选型、参数自整定；诊断振荡、跟踪误差 |
| 5 编程与工作站 | ROS 2 + 问渠自研 | 离线编程、示教；码垛、焊接、喷涂、上下料、装配工作站模板 | 自然语言编程 → 程序 → 仿真验证 → 下发 |
| 6 视觉 | OpenCV（图像处理）、Open3D（点云处理） | 相机标定、手眼标定、识别、定位做成流程 | 自动标定，自动选识别方法，自动评估精度 |
| 7 学习 | LeRobot（机器人学习库）、MuJoCo Playground（强化学习环境） | 采数据、训练、评测一体，数据格式统一 | AI 设计奖励函数与训练课程；评测策略、找失败原因 |
| 8 真机与孪生 | ROS 2、厂情中枢（数字工厂枢纽） | 真机部署、标定、状态监控、数字孪生；国产机械臂通过 ROS 2 驱动接入 | 故障诊断、维护建议；现场问题回流研发 |
| 9 产线集成 | OpenPLC（问渠 PLC）、ERPNext（问渠 ERP） | 工作站接 PLC、接 ERP 和 MES（生产管理系统） | 从工艺描述生成 PLC 程序；产线节拍平衡 |

**共用底座**：机器人描述（问渠原创）、机器人模型库（现有 108 款 + 宇树等国产模型）、计算引擎、AI 层（MCP 工具 + 智能体）、网页端与本机包。

**不用的**：英伟达 Isaac Sim / Isaac Lab、智元 Genie Sim（要英伟达显卡，分发另需商业授权）。以后要大规模训练，走 Newton 物理引擎（MuJoCo 是它的求解器之一），不推倒重来。

**两个版本**：

- **教学版**：嵌在四专业虚拟实验室里（机器人专业 16 个实验室），带实验指导、作品、自动判分。
- **企业版**：研发、集成、运维；是《问渠智能企业总体架构》里研发、工艺、运维智能体的“手”。

## 七、风险与应对

| 风险 | 应对 |
| --- | --- |
| ROS 2 在 Windows 上支持差 | 网页为主；本机 Docker + WSL2；不做原生 Windows 安装包 |
| 服务器资源有限 | 仿真按需启动、用完即停（同第 184 轮）；MuJoCo 不用显卡 |
| 不用显卡，学习工作台能力有限 | V2 只做小策略和现成模型推理评测；大训练另报 Eddie |
| 生成的配置被人手改后和描述不一致 | 读回机制 + 一致性检查，不一致就提示 |
| 零件库数据不全 | 判“未知”，出待补清单 |
| 兼职投入、窗口上限 | 每期结束重估；不新增窗口 |
