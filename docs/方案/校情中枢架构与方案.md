# 校情中枢：架构与方案（初稿）

2026-11-05 · 状态：**初稿**（第 83 轮）。Eddie 在另一个 Project 里已有设计讨论，找到后以那边为准修订本稿。

## 一、定位（Eddie 已定，2026-10-04、11-01）

- 一个像 Palantir 那样的**学校决策软件**：评价教与学，动态呈现学校的状态，给出决策建议和方向。
- **独立产品**，不只是问渠的一个模块；同时服务校长、院长和一线教师、辅导员。
- **先做模拟数据演示**。
- 分工：**校情中枢**承载院校评估与认证模块（合格评估、审核评估、专业认证、常态监测）和学校看板；**问渠**提供数据和课程层结果（课程目标达成度、增值、评教、学业预警），保留教师层评价。

## 二、架构：照厂情中枢的“学校版”

厂情中枢（`docs/方案/厂情中枢架构与方案.md`，数字工厂第 17 轮起已建成）的地基直接复用：对象浏览器、规则（发现问题）、追因、场景推演、动作框架、AI 代理、指挥台、报告。

| 层 | 校情中枢里是什么 |
|---|---|
| **本体** | 学校 → 学院 → 专业 → 培养方案 → 毕业要求 / 指标点 → 课程 → 开课班 → 教师、学生；评估项目（合格 / 审核评估、专业认证、常态监测）→ 指标 → 佐证材料 |
| **数据接入** | ① 问渠按《问渠数据契约 v1》（`services/eval/r4/contract/`）推送：课程目标达成度、学习增值、评教主题、学业预警；② 教务系统（学籍、选课、成绩、培养方案）先导入表格，后接接口；③ 其他教学平台按同一契约接入 |
| **规则** | 课程目标未达成；毕业要求指标点低于阈值或逐年下降；某课连续两学期评教最低题不变；学业预警人数上升；评估指标缺佐证、佐证过期 |
| **追因** | 指标点 → 支撑课程 → 课程目标 → 考核环节 → 题目 / 实验 / 答辩（契约样例已有这条链） |
| **动作** | 改进任务（契约已定义 `improvement_task`）下达给课程负责人或专业负责人 → 跟踪完成 → 下学期复核：评价—反馈—改进闭环 |
| **报告** | 毕业要求达成情况评价报告；专业自评报告（数据章节先行，整本后续）；本科教学质量报告的数据部分；审核评估的数据与佐证清单。网页 + Word，报告结构做成可换的模板，对上各校当年采用的标准 |
| **AI 代理** | 周报、风险提醒、自评报告起草；AI 只起草和提醒，不下结论，定稿由人确认。国内只用已备案模型 |

## 三、分期

1. **V0（第 83 轮，已做）**：官网 `/xq/` 演示，模拟数据。三个学院、六个专业的看板；机器人工程专业的毕业要求由问渠评价流水线真算的一门课 + 示例课程汇总；规则亮灯（低于 0.70 红、0.70–0.72 黄）；改进任务一键下达；生成毕业要求达成情况评价报告（网页 + Word）。程序在 `services/eval/reports/`。
2. **V1**：独立站点；教务数据导入；评估项目与佐证材料管理；专业自评报告整本生成；与问渠真实数据对接（契约推送）。
3. **V2**：AI 代理（周报、风险、自评起草）；常态监测数据填报；真实学校试点。
