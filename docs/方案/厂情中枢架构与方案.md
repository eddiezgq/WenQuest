## 一、我们要做的是什么

Palantir（Foundry / AIP）在制造业被看重，不在于某一个算法，而在于下面四件事连成了闭环：

| Palantir 的核心 | 一句话 | 在问渠数字工厂里对应什么 |
|---|---|---|
| **本体（Ontology）** | 把散在各系统里的数据，变成业务人员认得的“对象”（客户、订单、设备、员工、隐患……）和它们之间的“关系”；所有应用和 AI 都在这张图上工作 | 新建：**工厂本体**，覆盖工厂的全部业务领域 |
| **数据集成与血缘** | 各系统的数据自动同步进本体；每个数值都能追到它来自哪条原始记录 | 已有统一数据总线和历史库；新增同步器、采集应用、导入接口、溯源 |
| **动作（Actions）与人在回路** | 在对象上定义“能做的事”，带参数、校验、权限、审批，执行后写回业务系统，全程留痕 | 已有“提议 → 确认 → 执行”，扩展成正式的**动作框架** |
| **AIP（AI 平台）** | 大模型通过本体查询、推演、起草动作这些“工具”工作，结论带引用，写操作必须人批准 | 已有 AI 工厂助手，改成在本体上工作的**代理** |

另加 Palantir 在工厂常用的两项能力：
- **场景推演**（Vertex / Scenarios）：在当前状态的副本上试一组改动，比较结果；
- **运营应用**（Workshop 做出来的“作战室”）：给厂长、各部门负责人用的一页式指挥台。

**厂情中枢 = 覆盖全厂的工厂本体 + 异常与追因 + 场景推演 + 动作 + AI 代理 + 指挥台。**

它不替代前 16 轮的任何页面，而是把整个工厂连成一张图：从市场和客户，经设计、采购、生产、质量、仓储、交付，到现场服务；同时把人、设备、安全、能源、资金这些“支撑面”连进来。在这张图上发现问题、算清影响、给出可执行的方案。

### 两个最能说明价值的故事

**故事一：数字主线（从现场追到车间）**

> 港口客户的一台 WQR-105 孪生报警，中间轴轴承 B 振动上升。
> 在中枢里沿链接往回走：现场设备 → 出厂序列号 → 输出轴 SH301-00016-05 → 三坐标测量 → 加工它的外圆磨床 GRD-01 → 当时砂轮剩余寿命 → 同一阶段磨的其他轴 → 装进了哪几台、在哪些客户现场 → 这些客户的合同保修期、服务工程师排班。
> AI 起草三个动作：给同批几台开点检工单并排上工程师、把砂轮修整间隔从 30 件改为 20 件、给客户发预防性服务通知。人确认后执行。

**故事二：安全牵动交付（从一张隐患单到客户）**

> 车间巡检发现数控车床 B 的防护门联锁失效，开了一张隐患单，等级“重大”。
> 按安全规程，这台设备必须挂牌上锁停用，直到维修和复检完成。
> 中枢自动算出后果：精车产能减半 → 两张工单延后 → 峰顶搅拌机的订单延期 1.5 天。同时给出三个方案：精车改走数控车床 A 加夜班、外协精车 4 件、跟客户协商分批交货。每个方案都注明对安全的要求，比如加班人员必须持该设备的上岗资质，系统已经核对过技能矩阵。

前 16 轮已经有的数据，足够让故事一跑通；故事二要用到的“安全、人员资质”这些领域，按第三节的领域包补上。

## 二、总体架构

```
┌───────────────────────────── 应用层（网页 / 手机） ─────────────────────────────┐
│ 厂情中枢指挥台（全厂态势 + 异常 / 因果 / 推演）│ 对象浏览器（任何对象的 360 页、关系图、时间线）│
│ 推演工作台 │ 动作收件箱 │ AI 对话（带引用）│ 各领域采集应用（隐患上报、点检、来访、能耗……）│
└──────────────▲──────────────────────────────────▲─────────────────────────────┘
               │ 本体 API（查询 / 遍历 / 搜索）     │ 动作 / 推演 / AI API
┌──────────────┴────────────────── 服务层 ─────────┴─────────────────────────────┐
│ ① 对象查询与图遍历  ② 异常检测（规则库，按领域）  ③ 影响分析（追因 / 影响面）      │
│ ④ 场景推演（仿真副本 / 解析模型）  ⑤ 动作框架（校验·权限·审批·执行·审计）         │
│ ⑥ AI 代理（工具 = ①–⑤；引用；运行记录；评测）  ⑦ 主动提醒、复盘、日报周报          │
└──────────────▲────────────────────────────────────────────────────────────────┘
┌──────────────┴────────────────── 本体层 ───────────────────────────────────────┐
│ 15 个领域的对象类型 · 属性 · 链接 · 时间序列 · 事件（Postgres；定义写在 ontology/*.yaml，│
│ 每个领域一个文件；可按时间回看任意时刻）                                         │
└──────────────▲────────────────────────────────────────────────────────────────┘
               │ 同步器（增量、可重放）＋ 映射规则 ＋ 身份解析 ＋ 血缘 ＋ 数据质量检查
┌──────────────┴────────────────── 数据接入（四条通道） ──────────────────────────┐
│ ① 已有：总线历史（设备、MES、质量、物流、孪生、虚拟 PLC）、PLM、计算服务、零件库、任务单   │
│ ② ERPNext 模块（启用即可）：CRM、销售、采购、库存、质量、资产与维护、支持与保修、项目、财务 │
│ ③ 新建轻量采集应用：安全环保、人员资质与排班、能源计量、来访与门禁、设备点检……          │
│ ④ 外部接入：Excel / CSV 导入、REST 接口、设备网关（MQTT / OPC UA）、表单             │
│ ＋ 教学模拟器：每个领域都有情景数据生成器，让教学工厂的全貌“活”起来                    │
└───────────────────────────────────────────────────────────────────────────────┘
               ▲ 动作执行器回写：MES 指令 · ERPNext · PLM · 采集应用 · 通知（邮件 / 消息）
```

五条原则：

1. **本体是唯一的“业务语言”**。网页、AI、推演、动作都只认对象和链接。新增一个数据源或领域，只在本体里加映射。
2. **本体先建全，数据分批接**。15 个领域的对象类型一次定义好。每类对象标明数据成熟度：已有 / ERPNext 可启用 / 待采集 / 教学模拟。没有数据的对象照样出现在图上，标为“待接入”。这样全貌从第一天就看得到，缺口也一目了然。
3. **事件溯源，可回看任意时刻**。本体由事件流重放得到，可以问“上周三 14:00 全厂是什么状态”。推演和复盘都依赖这一点。
4. **AI 只读本体、只起草动作**。写操作都走动作框架，由人批准、留审计。没配大模型时用规则版，照样能用。
5. **教学和生产同一套**。教学模式下数据来自仿真车间和各领域模拟器，生产模式下来自真实系统和人；本体、应用、动作完全一样。

### 3.3 跨领域追因的典型链（规则库的种子）

| 起点 | 链路 | 终点 |
|---|---|---|
| 重大隐患（安全） | 设备挂牌上锁 → 产能 → 工单延后 | 订单延期、客户、违约金 |
| 客户投诉（客户） | 现场设备 → 出厂零件 → 测量 / 设备 / 刀具 → 同批 | 召回范围、服务工单、整改措施 |
| 来料检验不合格（供应链） | 批次 → 物料 → 受影响工单 → 替代供应商 | 交期、供应商评价 |
| 关键岗位员工请假（人员） | 资质 → 可开设备 → 排班缺口 → 工序 | 产能、加班需求 |
| 能耗突增（能源） | 计量点 → 设备 → 状态（空转、泄漏） | 成本、碳排放、维修工单 |
| 量具校准过期（质量） | 量具 → 期间所有测量 → 零件 | 复检范围 |
| 预防性维护逾期（设备） | 设备 → 故障概率上升 → 关键工序 | 停机风险、交期 |
| 成本差异超标（财务） | 工单 → 工序 → 调整、换刀工时 / 废品 | 根因、改善机会 |

人员数据只记必要字段（工号、姓名、部门、岗位、资质与有效期、排班）。健康类只记“是否按期完成体检”，不记任何诊断信息。

### 3.5 存储与实现

- **本体定义**放在 `ontology/` 目录，每个领域一个 yaml 文件：对象类型、属性（类型、单位、显示名、是否时间序列、敏感级别）、链接类型、映射规则、数据成熟度。改本体只改文件，同步器可从头重建。
- **存储**用现有 Postgres：对象表、链接表、事件表（jsonb 加索引）；时间序列复用历史库，按需降采样。全厂几十万对象也在 Postgres 的舒适区内。
- **同步器**：增量同步加从头重放，两者结果一致（测试核对）；每个属性记来源，这就是血缘。
- **身份解析**：同一个东西在不同系统里的编号统一起来，规则写在映射文件里。例如轴承在 ERPNext 里是 BRG-6207，零件库里是 A-BRG-DG/6207，孪生里叫“中间轴轴承 B”；员工在 HR、门禁、排班系统里的编号也要对上。

**17A 的实际做法（2026-10，已上线）**

- **定义**：`factory/digital/ontology/` 下 15 个领域 yaml 加 `_core.yaml`，共 95 类对象、94 种链接。成熟度分五档：已有、ERPNext 可启用、待采集、教学模拟，以及“后续各期生成”（异常、场景、动作、AI 运行）。启动时校验链接目标、属性类型、标题引用。
- **存储**：历史库里 5 张表：`ont_object`（属性 jsonb，加每个属性的来源序号）、`ont_link`（链接也带属性，例如加工记录上的刀具和剩余寿命）、`ont_event`（每次变化的旧值 → 新值）、`ont_alias`、`ont_state`（游标和上下文）。搜索用 pg_trgm。
- **同步器**：枢纽进程里的后台线程，每 2 秒读一批 2 秒前入库的总线消息，按消息类型的映射函数（`hub/ont/mappers.py`）写对象。游标、上下文（当前刀具序号、未闭合的停机等）和对象写入在同一个事务里提交。不在总线上的数据每分钟对账（`hub/ont/sources.py`）。从头重放与增量同步逐对象一致，由自动测试核对。
- **映射规则写在代码里，不写在 yaml 里**：映射需要上下文（例如当前装的是第几片砂轮），写成 yaml 规则反而难读难测。yaml 只管“有什么”，映射函数管“从哪来”；每个映射函数只能写 yaml 里定义过的属性和链接，写错直接报错。
- **实测性能**：合成 100 万条总线消息（约 29 万个对象、59 万条链接，是目标规模的 6 倍）。
  - 从头重放 213 秒，增量延迟 2.2 秒；
  - 搜索 12–225 毫秒，360 页约 45 毫秒，三跳关系图约 110 毫秒。

## 四、六项核心能力

### 4.1 对象浏览器（地基）

- 全局搜索：任何对象的编号或名称。
- **对象 360 页**：属性、关系图（逐跳展开）、时间线、相关的异常 / 场景 / 动作；每个数值都能点“来源”。
- **对象集**：按条件筛选一组对象，保存后作为 AI、推演、报表的输入。例如：本周延期风险的订单、资质 30 天内到期的员工、逾期的隐患。
- **全貌地图**：15 个领域、对象数量、数据成熟度、今天的异常数，一张图看到工厂哪里“亮着”、哪里“还暗着”。

### 4.2 异常检测（按领域的规则库）

每条规则都是声明式的，可以单独测试，按领域开关。

| 领域 | 规则（举例） |
|---|---|
| 客户与销售 | 订单预计完工晚于交期；重要客户投诉；满意度下降；报价转化率异常 |
| 生产 | 停机、OEE 低于目标、换刀频率异常、在制积压 |
| 质量 | SPC 判异（Western Electric 规则）、不合格率上升、量具校准过期、客诉同批次重复 |
| 供应链 | 到货晚于需要日期、来料不合格、低于安全库存、供应商准时率下降 |
| 设备维护 | 预防性维护逾期、同类故障重复、备件低于最低库存 |
| 服务 | 孪生报警、同批多台报警、保修期内故障率高、服务响应超时 |
| 安全环保 | 重大隐患未关闭、整改逾期、作业许可缺资质、事故 / 未遂、培训到期、排放超限 |
| 人员 | 关键资质人员不足（单点依赖）、排班缺口、连续加班超限 |
| 能源 | 单耗突增、空转能耗、峰时用电超标 |
| 财务 | 工单成本差异超 10%、应收逾期、毛利低于目标 |

### 4.3 追因与影响面

在本体图上双向传播：往下游算“影响了谁、影响多大”，往上游找“为什么”。影响量化调用推演（4.4）。每条边都写明依据（哪条规则、哪些数据）。大模型只负责把链条讲成人话，不负责猜。种子链路见 3.3。

**17B 的实际做法（2026-10，已上线）**

- **规则 = 目录 + 检测函数**：
  - 目录在 `ontology/rules/<领域>.yaml`：编号、名称、严重度、负责角色、阈值、开关、说明、处理提示；
  - 检测函数在 `hub/ont/rules/<领域>.py`，只读、只返回“发现”。
  - 纯声明式的规则语言写不出 SPC 判异、成本分解这类计算，所以没有采用；阈值放在 yaml 里，老师在网页上能改，改动有审计。
- **规则数量**：20 条在跑（生产 5、质量 5、交付与计划 2、供应链 2、服务 3、维护 1、财务 1、研发 1），12 条“待数据”。
  - 原 AI 提醒的 6 项检查迁成规则 P1、P2、Q2、Q3、S1、W1，文字逐条核对一致。
- **异常存在自己的表里（`anomaly`）**，对账时再映射成本体的“异常”对象，用通用链接“涉及”连到任何类型的对象。
  - 原因：处理记录是人的操作，不能随本体重建清掉。
  - 生命周期：去重、升级重发、连续两轮消失自动解除、人工关闭后 24 小时内复现重开。
- **检测频率**：跟着原 AI 提醒的循环，每 20 秒一轮。教学工厂规模下一轮约 0.1 秒；老师注入停机后 4–20 秒出现异常。
- **追因**：6 条种子链路写在 `hub/ont/chain.py`，量化只用已有计算（看板订单预测、BOM 展开、成本模块、孪生）。
  - 这一期还不调用推演（4.4，17C）。
- **服务链路的取舍**：“同批多台”只算可能与制造批次有关的报警（轴承、输出轴）。换油过期、散热变差与批次无关，不算。
- **大模型**：只把链条改写成一段话。输出里出现链条里没有的数字，就退回规则版文字。

### 4.4 场景推演

- **场景** = 某时刻的状态快照 + 一组改动 + 推演结果。可以保存、比较、分享，事后和实际对比（复盘）。
- **引擎**：
  - 生产相关：用仿真车间同一个离散事件引擎做快进副本，教学模式拿精确快照，生产模式从本体重建；
  - 物料、产能、成本：用解析模型（现有 MRP、成本模块）；
  - 安全、人员约束作为推演的硬约束：挂牌上锁的设备不可用；无资质的人不能排到该设备；加班受工时上限约束。
- **可试的改动**（第一期）：改派、插单 / 调序、加班（需要班次日历）、紧急采购、外协、维修加急、分批交货；领域包陆续增加，如调整排班、启用替代供应商、提前预防性维护。

**17C 的实际做法（2026-10，已上线）**

- **班次日历**：仿真车间有两种模式。“24 小时连续”是教学默认：学生随时做实验，车间不能在夜里停着；“按班次”可以加班。推演用车间当时的模式。班次表由枢纽经总线下发，仿真器不连数据库。
- **快照与快进副本**：
  - 仿真引擎能把全部内存状态导出、原样恢复（含随机数状态），从快照恢复的副本与原车间逐事件一致（测试核对）；
  - 生产模式从各设备最近的状态消息近似重建，实验 7 情景下剩余工期误差小于 10%（测试核对）；
  - 一次推演约 0.1 秒（实验 7 规模）。
- **改动与成本**：
  - 7 种改动由引擎的同一套指令实现（改派、调序、维修加急、外协），真车间的执行器发的也是这些指令，推演和执行不会两套说法；
  - 物料只影响“等料的订单什么时候能下达”，紧急采购就是把到料日提前；
  - 加班费按设备小时费率 × 1.5，外协按本厂工时成本 × 1.3 加运费，违约金只在订单有条款时计（教学数据一张）。

### 4.5 动作框架

每种动作 = 参数 + 前置校验（含安全和资质约束）+ 发起权限 + 批准权限 + 执行器 + 回写 + 审计；都可以先“试运行”（交给推演）。

| 领域 | 动作（举例） | 回写 |
|---|---|---|
| 生产 | 改派工序、调序、下达工单、安排加班 | MES、班次日历 |
| 供应链 | 紧急采购、外协、切换供应商 | ERPNext |
| 质量 | 开 8D、扩大复检范围、冻结批次 | 质量模块 |
| 设备 | 开维修工单、调整维护计划、挂牌上锁 / 解锁 | 维护模块、MES（设备不可用） |
| 服务 | 开服务工单、指派工程师、发预防性服务通知 | ERPNext、通知 |
| 安全 | 关闭隐患（要复检照片）、签发作业许可、安排培训 | 安全应用 |
| 客户 | 申请改交期、分批交货 | ERPNext、通知 |

动作提交后进**动作收件箱**，按权限批准后执行，结果回到本体，并关联到发起它的异常和场景。现有的“提议”迁移成动作框架的第一种动作。

### 4.6 AI 代理（AIP 式）

- **工具**全部是上面的能力：搜索、读对象、遍历、算指标、追因、推演、起草动作（只能起草）。
- **引用**：每个结论附上它依据的对象和原始记录。
- **运行记录**：每次运行都存成对象，可以回看、评审。
- **评测集**：按领域出固定题，例如“这张隐患单会影响哪些订单？”“谁能顶替请假的磨床操作工？”。每次改动都跑一遍。
- **模型**：国内用已备案模型（DeepSeek），美国用 Claude；没配模型时用规则版。
- **主动提醒与报告**：每天自动生成“厂情日报”，每周生成“经营周报”，按领域汇总异常、处理情况和趋势，推送给相应负责人。

**17D 的实际做法（2026-10）**

- **代理 = 原 AI 工厂助手的后台换掉**，入口不变。工具 14 个：本体的搜索 / 读对象 / 邻居 / 影响面，指标，异常清单 / 异常详情（含因果链），推演（可加“假设某设备再停 N 分钟”），按预案比较方案，起草动作（只生成草稿），以及原助手的查总线消息、工单成本、算料、起草订单提议。
- **引用与核对是程序做的，不靠提示词**：工具结果里每个对象、消息、异常、推演场景编号 [n]；回答发出前把每个数字和本次工具结果比对（允许四舍五入、百分比、分钟 ↔ 小时换算），找不到的句子标“未经核实”。
- **规则版是一等公民**：没有模型时识别十类问题，按固定步骤调同一套工具，答案同样带引用；30 道评测题规则版必须全对才能推送上线。模型版在服务器上考（临时库载入实验 7 情景），分数留档，目标 ≥ 90%。
- **“假设停机”**作为推演专用的改动（breakdown），不能变成动作；推演的“如果再停一天”与先改快照再推演结果一致（测试核对）。
- **提醒**发给“角色”或“个人”，站内按订阅过滤，负责角色不受过滤；邮件和企业微信 / 钉钉 / 飞书群机器人只在生产模式发；“严重”异常 30 分钟没人确认再提醒厂长一次。
- **日报周报**的数字与看板、异常表、动作表同一套计算（测试逐项核对），文字有模型时改写、数字逐个核对。
- **复盘**用工厂时间（车间事件里的 factory_ts）比较推演和实际；实际的“多花的钱”= 执行了的动作的费用 + 按实际交付算的违约金。教学模式精确快照、没有新扰动时，预测与实际相差远小于 10%（测试核对）。
- **实验 15** 的“比对模式”：学生开始实验、提交自己的选择之前，指挥台右栏、AI 代理都不给“建议”和推荐理由（推演数字照常可看）。

## 六、治理与安全

- **权限**：按角色控制到领域、对象类型、属性（敏感级别）和动作。员工个人信息只给人事和直属负责人看；事故详情按安全管理权限开放；学生看不到老师注入的情景。企业版沿用企业成员与角色（第 8 轮）。
- **审计**：查看敏感对象、发起和批准动作、AI 运行，全部记录，不可删改。
- **数据质量**：同步时检查缺字段、编号对不上、时间倒序等问题，在“数据健康”页列出。数据有问题的对象在 360 页上标黄。
- **合规**：国内部署只用已备案模型；本体数据不出服务器；发给 AI 的只是必要的对象摘要，员工个人信息默认不发。

## 九、分期

### 核心平台（数字工厂第 17 轮，分四期，每期都能上线、演示）

| **17B 异常、追因与指挥台 v1**（已上线） | 规则库框架和已有数据领域的规则；异常对象；跨领域因果链；指挥台“全厂态势”加三栏（右栏本期只做处理） | 实验 7 情景的异常全部识别；老师注入停机，5 分钟内出现；因果链与人工核对一致 |
| **17C 推演与动作**（已上线） | 仿真快照、班次日历、快进副本、解析模型；第一期 7 种改动；动作框架（试运行、收件箱、审批、执行、回写、审计）；指挥台右栏 | “什么都不做”的推演与实际完工相差不到 10%；推演可重复；采纳的动作真的执行 |
| **17D AI 代理、提醒与复盘**（已上线） | 本体工具、引用、运行记录、评测集；主动提醒、厂情日报 / 周报；复盘；实验 15、帮助；补拍宣传 | 评测集达标；日报正确；实验 15 文档齐全 |

### 领域包（第 18 轮起，每包都是“采集应用 + 教学模拟器 + 规则 + 动作 + 态势卡 + 帮助”）

| 顺序 | 领域包 | 主要内容 |
|---|---|---|
| E1 | **客户与服务**（第 18 轮 E1，已上线） | CRM（线索、商机、报价、合同保修条款）、客户投诉与满意度、服务工程师与排班、备件发运、回访；投诉 → 数字主线追溯 → 召回范围 |
| E2 | **安全环保（EHS）**（第 18 轮 E2，已上线） | 危险源与风险评估、隐患随手拍、事故 / 未遂、作业许可（含挂牌上锁）、安全培训、劳保用品、化学品与废弃物、排放；隐患 → 设备不可用 → 交付影响 |
| E3 | **设备维护与资产**（第 18 轮 E3） | 资产台账、预防性维护计划、点检（扫码）、维修工单、备件；维护逾期 → 停机风险 |
| E4 | **人员与组织** | 部门岗位、虚拟员工、技能矩阵、资质与有效期、培训、排班出勤；资质约束进入推演 |
| E5 | **供应链深化** | 采购收货、来料检验、批次、供应商评价、替代供应商 |
| E6 | **能源与环境** | 计量点、能耗时间序列（仿真按功率生成）、单耗、空转、碳核算 |
| E7 | **经营与财务** | 经营目标与指标树、预算、应收应付、毛利、成本差异、经营周报 |

**E1 的实际做法**（细则：`factory/digital/实施细则_第18轮E1_客户与服务.md`）：
- 数据：线索、商机、报价、合同、服务单（Issue）、备件出库（Stock Entry）以 ERPNext 为准，经桥接写入、轮询读回；合同条款（违约金、响应时限、保修期）存在 ERPNext 合同的自定义字段里。投诉、工程师、服务工单排班、回访、通知、召回批次在平台自己的表里；投诉同时在 ERPNext 开 Issue。
- 推演：订单违约金改为读客户合同（不再写死）。投诉与现场报警的处理方案不进车间仿真，按 6 位虚拟服务工程师的排班估算（同区域每人每天 2 单、外区域 1 单）。
- 规则 C1–C5、R3 上线（在跑的规则 26 条）；新动作：服务派工、备件出库、客户通知；新角色“售后”。
- AI 代理新增客户 360、投诉追溯与排查范围、服务派工估算三个工具，评测集 38 题；配套实验 16。

**E2 的实际做法**（细则：`factory/digital/实施细则_第18轮E2_安全环保.md`）：
- 数据：隐患、作业许可、事故、培训、危险源、化学品、废弃物都在平台自己的表里；整改工单经桥接进 ERPNext（Issue，类别“安全整改”）。先建 12 位虚拟员工和培训记录，人员领域包（E4）上线后并入员工档案。
- 挂牌上锁：仿真车间新增 lockout / unlock 指令；挂着锁的设备不能复位、不会自动恢复，直到验收解锁。推演里新增“停机挂牌整改”改动（可延后开始）。
- 规则 E1–E7 上线（在跑的规则 33 条）；新动作：停机挂牌整改、整改工单、验收解锁、安排培训；新角色“安全员”。
- AI 代理新增安全概况、设备安全状态、风险评估三个工具，评测集 44 题；配套实验 17。

**E3 的实际做法**（细则：`factory/digital/实施细则_第18轮E3_设备维护与资产.md`）：
- 数据：资产（Asset）、保养计划（Asset Maintenance，每台一个保养任务，周期以运行小时记在自定义字段里）、保养记录（Asset Maintenance Log）、维修单（Asset Repair）以 ERPNext 为准，经桥接写入；平台第一次用到时整批建。点检、故障记录、失效率参数、维修 / 保养单的进度在平台自己的表里；维修用件走备件出库（Stock Entry）。
- 失效率：每台设备一个威布尔分布（β、η、平均修复时间、保养周期），仿真车间按“自上次保养以来的运行小时”抽签故障，平台用同一套参数算未来 80 运行小时的故障概率和预期损失。教学模式默认打开、情景载入时关闭、生产模式不模拟。
- 保养、维修都走 E2 的挂牌上锁；推演里新增“保养停机”改动（可延后开始）。
- 规则 M2–M7 上线（在跑的规则 39 条）；新动作：保养工单、维修单、调整保养周期；新角色“维修工”。
- AI 代理新增设备台账与保养状态、故障风险与预期损失、维修与备件三个工具，评测集 50 题；配套实验 18。

建议的顺序是 17A → 17B → 17C → 17D，然后 E1 → E7。E1、E2 也可以提到 17B 之后先做，因为宣传和企业客户最关心客户与安全。领域包每包写一份细则，确认后施工。

## 十一、主要风险与对策

| 风险 | 对策 |
|---|---|
| 范围太大、做不完 | 本体一次定全，数据和功能分期；每期、每个领域包都能独立上线演示 |
| 本体设计返工 | 定义都在 yaml 里，可从头重放；先覆盖主干对象，按需扩展 |
| 新领域没有真实数据，显得空 | 每个领域配教学模拟器；全貌地图如实标出“待接入”，这本身就是企业咨询的切入点 |
| 推演和实际对不上 | 推演存档、事后自动复盘，偏差公开；教学模式用精确快照兜底 |
| 人员、安全数据敏感 | 最少字段、属性级权限、审计；健康类不记诊断；AI 默认不读个人信息 |
| AI 编造 | 只用本体工具、结论带引用、评测集把关、规则版兜底 |

## 十二、需要 Eddie 确认

1. **方向**：按“覆盖全厂 15 个领域的工厂本体 + 异常追因 + 场景推演 + 动作 + AI 代理 + 指挥台”做，对标 Palantir 的 Ontology / AIP / Vertex。可以吗？
2. **本体先建全、数据分批接**：没有数据的领域先出现在全貌地图上，标“待接入”。可以吗？
3. **分期**：核心平台 17A–17D，再做领域包 E1–E7。是否把 E1（客户与服务）、E2（安全环保）提前到 17B 之后？我的建议是提前。
4. **技术路线**：不引入图数据库和大数据组件，用现有 Postgres 加总线；推演用仿真车间同一个引擎；采集应用用现有工作台技术栈。可以吗？
5. **仿真车间改动**：加班次日历（默认三班 24 小时，实验 7 不受影响）、挂牌上锁、能耗数据。可以吗？
6. **人员数据最少化**：教学工厂用虚拟员工，健康类只记“是否按期完成”。可以吗？
