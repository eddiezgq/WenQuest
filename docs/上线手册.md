# 上线手册：机器人学院官网 + 学习平台（美国 · DigitalOcean）

上线后的样子：

| 地址 | 内容 |
| --- | --- |
| `https://<你的域名>` | 学院官网（`site/` 目录里的静态页面） |
| `https://learn.<你的域名>` | 学习平台（Moodle 5.2 + Claude，中英双语） |

整体流程：代码在 GitHub → 每次推送，GitHub Actions 自动构建镜像并部署到服务器 → 服务器每天凌晨自动备份。HTTPS 证书由 Caddy 自动申请和续期。

预计用时：动手操作约 1 小时，加上首次构建和安装约 30 分钟等待。

---

## 0. 需要准备的账号

| 账号 | 用途 | 必需 |
| --- | --- | --- |
| 域名注册商（Cloudflare、Namecheap 等） | 买域名、设置 DNS | 是 |
| [DigitalOcean](https://www.digitalocean.com) | 云服务器、异地备份存储（Spaces） | 是 |
| [GitHub](https://github.com) | 代码仓库、自动部署 | 是 |
| [Anthropic Console](https://console.anthropic.com) | Claude API Key（claude.ai 订阅不含 API） | 是 |
| 邮件服务（Postmark、Mailgun、SendGrid、Brevo 等） | 找回密码、课程通知邮件 | 建议 |

> DigitalOcean 的服务器封锁了 25、465、587 发信端口（[官方说明](https://docs.digitalocean.com/support/why-is-smtp-blocked/)），所以发邮件要走邮件服务商的 2525 端口。

## 1. 在自己电脑上生成部署密钥

在 Mac 的“终端”里执行（生成一对专给 GitHub 自动部署用的密钥，不设密码）：

```bash
ssh-keygen -t ed25519 -f ~/.ssh/wenquest_deploy -C github-deploy -N ""
```

如果你还没有自己登录服务器用的密钥（`~/.ssh/id_ed25519.pub` 不存在），再执行一次 `ssh-keygen -t ed25519`，一路回车。

## 2. 创建服务器

DigitalOcean 控制台 → **Create → Droplets**：

| 选项 | 选择 |
| --- | --- |
| Region | New York（离东部学生近；学生多在西部可选 San Francisco） |
| Image | Ubuntu 24.04 (LTS) x64 |
| Size | Basic → Regular，**4 vCPU / 8 GB** |
| Authentication | SSH Key → New SSH Key，粘贴 `cat ~/.ssh/id_ed25519.pub` 的内容 |
| Backups | 可选。平台自带每日备份；再开 DigitalOcean 整机备份更保险，另收费 |
| Hostname | `wenquest` |

建好后记下服务器的 **IP 地址**。

## 3. 设置域名解析

在域名注册商的 DNS 设置里加三条 A 记录，都指向服务器 IP：

| 类型 | 名称 | 值 |
| --- | --- | --- |
| A | `@` | 服务器 IP |
| A | `www` | 服务器 IP |
| A | `learn` | 服务器 IP |

用 Cloudflare 的话，这三条先设为 **DNS only（灰色云朵）**，否则 Caddy 申请证书会受影响。解析通常几分钟生效，可用 `ping learn.<你的域名>` 检查。

## 4. 初始化服务器（一次性）

在代码目录里执行（把 `<IP>` 换成服务器 IP）：

```bash
scp deploy/bootstrap.sh root@<IP>:
ssh root@<IP> "bash bootstrap.sh '$(cat ~/.ssh/wenquest_deploy.pub)'"
```

脚本会做这些事：系统更新、安装 Docker、开 2 GB 交换空间、建 `deploy` 用户、关闭密码登录、防火墙只开 22/80/443、开启自动安全更新、安装每日 03:30 的备份任务。

## 5. 建 GitHub 仓库并设置密钥

1. GitHub → **New repository**，名字如 `wenquest`，选 **Private**，不要勾选 README。
2. 在代码目录里推送：

   ```bash
   git remote add origin git@github.com:<你的用户名>/wenquest.git
   git push -u origin main
   ```

3. 仓库 → **Settings → Secrets and variables → Actions → New repository secret**，添加三项：

   | 名称 | 值 |
   | --- | --- |
   | `DEPLOY_HOST` | 服务器 IP |
   | `DEPLOY_SSH_KEY` | `cat ~/.ssh/wenquest_deploy` 的全部内容（私钥，含首尾两行） |
   | `DEPLOY_KNOWN_HOSTS` | `ssh-keyscan -t ed25519 <IP>` 的输出 |

## 6. 首次部署

1. 仓库 → **Actions → Build and deploy → Run workflow**。首次构建镜像约 15–20 分钟，之后有缓存会快很多。
2. 第一次运行会停在 “.env is missing”，这是预期的：部署文件已经复制到服务器，还缺配置。
3. 登录服务器生成配置：

   ```bash
   ssh deploy@<IP>
   cd /opt/wenquest && deploy/init-env.sh
   ```

   按提示输入域名、管理员邮箱、平台名称、默认语言（`en` 或 `zh_cn`）、时区、Anthropic API Key。脚本会自动生成管理员和数据库密码，**把屏幕上显示的密码存进密码管理器**。

4. 回到 GitHub，在失败的那次运行里点 **Re-run failed jobs**。首次安装 Moodle 需要几分钟，部署任务会等到平台就绪。

## 7. 检查

- 打开 `https://<你的域名>`，应看到学院官网，右上角可切换中英文。
- 打开 `https://learn.<你的域名>`，用 `admin` 和刚才的密码登录。
- **网站管理 → AI → AI 提供方**：应有一个已启用的 Claude。
- 在任意课程页面试一下“总结本页”。
- 服务器上执行 `deploy/status.sh`，看服务状态、磁盘、最近备份和两个网址的响应码。

## 8. 建议尽快补上的两项

编辑配置 `nano /opt/wenquest/.env`，改完执行 `deploy/update.sh` 生效。

**发信**：在邮件服务商验证你的域名（按它的说明加几条 DNS 记录），然后填：

```
SMTP_HOST=<服务商的 SMTP 地址>
SMTP_PORT=2525
SMTP_USER=<用户名>
SMTP_PASSWORD=<密码>
MOODLE_NOREPLY_EMAIL=noreply@<你的域名>
```

**异地备份**：DigitalOcean → **Spaces Object Storage** 建一个桶（与服务器同一区域），再在 **API → Spaces Keys** 生成密钥，然后填：

```
BACKUP_S3_ENDPOINT=https://nyc3.digitaloceanspaces.com
BACKUP_S3_BUCKET=<桶名>
BACKUP_S3_ACCESS_KEY=<Access Key>
BACKUP_S3_SECRET_KEY=<Secret Key>
```

填好后手动跑一次 `deploy/backup.sh` 确认能上传。建议在 Spaces 里给桶设置生命周期规则，自动删除 30 天前的备份。

## 日常维护

| 要做的事 | 怎么做 |
| --- | --- |
| 改插件、部署配置或官网 | 改代码 → `git push`，自动构建、备份、部署 |
| 看运行状态 | `ssh deploy@<IP>`，`cd /opt/wenquest && deploy/status.sh` |
| 改配置（密钥、邮件、语言） | `nano .env`，然后 `deploy/update.sh` |
| 看日志 | `docker compose -f docker-compose.yml -f docker-compose.prod.yml logs --tail 100 moodle` |
| 手动备份 | `deploy/backup.sh`（每天 03:30 自动执行，日志在 `backups/backup.log`） |
| 更新后出问题，回到上一版 | `deploy/rollback.sh`（若新版升级了数据库，还要恢复更新前自动做的那份备份） |
| 从备份恢复 | `deploy/restore.sh backups/<时间戳>` |
| 从异地备份恢复 | 先从 Spaces 把 `wenquest/<时间戳>/` 下载到服务器的 `backups/<时间戳>/`，再执行上一行 |
| Moodle 安全更新 | 每周一凌晨（美东约 3 点）自动重新构建并部署，拉取 Moodle 5.2 稳定分支的最新修复 |
| 系统安全更新 | 已开启自动安装；偶尔 `sudo reboot` 让内核更新生效，Docker 服务会自动起来 |

**每次更新前都会自动备份**，更新失败时部署任务会显示最近日志并提示回滚。

## 文件都在哪里

| 位置 | 内容 |
| --- | --- |
| GitHub 仓库 | 全部代码和部署配置（不含 `.env`） |
| 服务器 `/opt/wenquest/.env` | 密码、API Key 等，只在服务器上，自己另存一份 |
| 服务器 `/opt/wenquest/backups/` | 最近 7 天的本机备份 |
| DigitalOcean Spaces | 异地备份 |
| GitHub → Packages | 学习平台镜像，每个版本一个标签，可随时回滚 |
| GitHub → Actions → 某次运行 → Artifacts | `aiprovider_claude.zip`，给已有 Moodle 的学校单独安装插件用 |
