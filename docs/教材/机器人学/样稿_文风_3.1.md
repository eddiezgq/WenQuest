# 文风样稿：3.1 手腕转了 30°，零件的角跑到哪里去了？

> 这是一篇文风样稿，用来和 Eddie 对齐写法，不是定稿正文。
> 书中数字已用程序复算。【动画】【实验】标出的是正式稿中会放动画和实验的位置。

机械臂把一个长方形零件从传送带上吸了起来。吸盘吸在零件中间。现在要把零件放进一个斜着的托盘里，所以手腕要先转 30°，再放下去。

问题来了：零件有一个角，离吸盘中心向右 0.2 米、向上 0.1 米。手腕转过 30° 以后，这个角在哪里？

这件事机器人每天要做成千上万次。如果算错了，零件的角就会撞在托盘边上。所以我们要把它算清楚，而且要找到一个以后不管转多少度都能直接套用的办法。

## 先把问题画在纸上

我们以吸盘中心为原点，画一个平面坐标系：向右是 x，向上是 y。零件的角就是点 P，坐标是 (0.2, 0.1)，单位是米。

手腕转 30°，零件跟着一起转，点 P 就绕着原点转了 30°，到了一个新的位置。我们叫它 P′。这里的“转”指逆时针转，这是数学里通常的约定：从 x 轴转向 y 轴的方向算正。

【动画 3.1-1】零件绕吸盘中心慢慢转 30°，点 P 画出一段圆弧，停在 P′。

## 第一个想法：转动不改变距离，只改变角度

看动画会发现一件事：P 在转的时候走的是一段圆弧，它离原点的距离始终没有变。变的只是它的方向。

所以，我们可以换一种方式描述点 P：不说“向右多少、向上多少”，而说“离原点多远、在什么方向”。

- 离原点的距离用勾股定理算：√(0.2² + 0.1²) = √0.05 ≈ 0.22361 米，记作 r。
- 方向是从 x 轴量起的角度 φ。它满足 tan φ = 0.1 / 0.2 = 0.5，所以 φ ≈ 26.57°。

这样描述，转动就变得非常简单：距离 r 不变，角度从 φ 变成 φ + 30°。

于是新位置是：

> x′ = r cos(φ + 30°)，y′ = r sin(φ + 30°)

代进去，φ + 30° ≈ 56.57°，可以算出 x′ ≈ 0.12321，y′ ≈ 0.18660。

问题算出来了。但这个办法有一点别扭。每转一个点，都要先算距离和角度，转完再换回 x、y。如果零件有上千个点（比如三维模型的每个顶点），每个都这样来回换算，既慢，又容易在角度换算上出错。

我们想要的是：直接从 (x, y) 得到 (x′, y′)，中间不绕路。

## 把绕的路拆开：和角公式

绕路的地方在 cos(φ + 30°) 和 sin(φ + 30°)。中学学过的和角公式正好能把它们拆开：

> cos(φ + θ) = cos φ cos θ − sin φ sin θ
> sin(φ + θ) = sin φ cos θ + cos φ sin θ

这里我们把 30° 写成一般的 θ，这样推出来的结果对任何角度都成立。

代进 x′ = r cos(φ + θ)：

> x′ = r cos φ · cos θ − r sin φ · sin θ

再看 r cos φ 和 r sin φ 是什么。它们正是原来的 x 和 y：距离乘以方向角的余弦，就是在 x 方向上走了多远；乘以正弦，就是在 y 方向上走了多远。

于是距离 r 和角度 φ 一起从式子里消失了：

> x′ = x cos θ − y sin θ

同样的办法处理 y′：

> y′ = x sin θ + y cos θ

这两行就是我们要的“直接办法”。只要知道转了多少度，就能从旧坐标一步算出新坐标。

用数字验一遍。cos 30° ≈ 0.86603，sin 30° = 0.5：

> x′ = 0.2 × 0.86603 − 0.1 × 0.5 = 0.17321 − 0.05 = 0.12321
> y′ = 0.2 × 0.5 + 0.1 × 0.86603 = 0.1 + 0.08660 = 0.18660

和前面绕路算的结果一模一样。零件的角转到了 (0.12321, 0.18660)，离吸盘中心向右约 12.3 厘米、向上约 18.7 厘米。

## 四个数决定了一切

仔细看这两行式子，会发现一个规律：x′ 和 y′ 都只是 x 和 y 各乘一个数再相加。乘的数一共只有四个：cos θ、−sin θ、sin θ、cos θ。

既然决定这次转动的只有这四个数，我们就把它们排成一个方块，放在一起：

```
R(θ) = ┌ cos θ   −sin θ ┐
       └ sin θ    cos θ ┘
```

这个方块叫做**旋转矩阵**。

读法是：
- 第一行的两个数，分别乘上 x 和 y 再相加，得到 x′；
- 第二行的两个数这样做，得到 y′。

把点也竖着写成一列，整个转动就写成一个短短的式子：

> P′ = R(θ) P

这种“一行乘一列再相加”的规则，就是矩阵乘法。第 2 章已经讲过它的一般规则；在这里，它第一次有了一个看得见的意思：**把点转过一个角度**。

30° 的旋转矩阵是：

```
R(30°) = ┌ 0.86603   −0.5     ┐
         └ 0.5        0.86603 ┘
```

## 矩阵的两列在说什么

一个矩阵摆在面前，只看四个数很难有感觉。下面这个看法会让它一下子变得直观。

先拿最简单的点来转：x 轴上的单位点 (1, 0)。

代进式子，得到 (cos θ, sin θ)。这正是矩阵的**第一列**。

再转 y 轴上的单位点 (0, 1)，得到 (−sin θ, cos θ)。这正是**第二列**。

所以，旋转矩阵的两列，就是原来的两根坐标轴转过去以后指向哪里。

【动画 3.1-2】坐标系的两根单位箭头一起转 30°，矩阵的两列随之亮起，数字与箭头尖的位置同步变化。

有了这个看法，很多事情不用算就能看出来：
- 两根坐标轴转完仍然互相垂直、长度都是 1，所以旋转矩阵的两列也互相垂直、长度都是 1；
- 转动只是把整张平面整体转了一下，所以任何点到原点的距离都不会变。

用零件的角验证：转之前距离是 0.22361 米，转之后算 √(0.12321² + 0.18660²)，还是 0.22361 米。

## 怎么转回去

把零件放进托盘以后，手腕要转回原来的方向，去吸下一个零件。转回去就是转 −30°。

把 −30° 代进旋转矩阵。余弦不变，正弦变号：

```
R(−30°) = ┌ 0.86603    0.5     ┐
          └ −0.5       0.86603 ┘
```

把它和 R(30°) 对照，会发现它正好是 R(30°) 沿对角线翻过来：第一行变成第一列，第二行变成第二列。这种翻法叫**转置**，记作 Rᵀ。

用它去乘 P′ = (0.12321, 0.18660)，得到的正是 (0.2, 0.1)，零件的角回到原位。

“转回去等于转置”，这件事对一切旋转矩阵都成立，不管是平面的还是后面要讲的三维的。它的原因就在上一节：两列互相垂直、长度为 1。机器人程序里处处要“转过去、再转回来”，求逆本来要做一番计算，旋转矩阵却只要把四个数换个位置。

## 一个容易弄反的地方

有时我们说的“转 30°”，并不是零件转了，而是我们看零件的坐标系转了。

比如相机装歪了 30°。相机里看到的零件，是零件不动、坐标系转了。这时零件在相机坐标系里的坐标，要用 R(−30°) 也就是 Rᵀ 去乘，而不是 R(30°)。

两种情况的数字正好差一个转置。把它们弄混，是初学者最常见的错误，也是现场调试中机器人“总往反方向偏”的常见原因。第 4 章讲坐标系变换时，我们会专门把这两种看法放在一起对照。

【实验 3.1】打开虚拟实验：屏幕上有一个吸着零件的手腕。拖动滑块改变转角，零件四个角的坐标和旋转矩阵实时显示。实验有三项任务：
1. 找出一个转角，使零件的长边与托盘边平行；
2. 只看矩阵的两列，画出转动后的坐标轴，再与屏幕对照；
3. 在“坐标系转动”模式下，说明读数为什么与“零件转动”模式相反。

完成后，系统自动检查读数。

## 生活里的旋转

钟表的分针每分钟转 6°，只不过是顺时针，也就是 θ = −6°。针尖的位置就是旋转矩阵乘以针尖的初始位置。

手机横过来时，屏幕上的画面也做了一次 90° 的旋转。把 θ = 90° 代进去，cos 90° = 0、sin 90° = 1，矩阵变成只有 0、1 和 −1。把点 (x, y) 送到 (−y, x)，正好就是“横过来”。

## 下一步

平面上的转动，只要一个角度就能说清。可机械臂的手腕在空间里转，转轴可以朝向任何方向。

下一节，我们把这四个数扩成九个数，看看三维空间里的转动是什么样子。我们会发现，上面这几个看法——两列就是转过去的坐标轴、转回去就是转置——在三维里依然成立。

**工程师笔记**
- 程序里的角度单位多半是弧度，不是度。30° 要先换成 π/6 ≈ 0.5236 再取三角函数。把度直接代进 `cos()`，是现场最常见的低级错误。
- 判断一个 2×2 矩阵是不是合法的旋转矩阵，看三件事：两列长度都是 1；两列互相垂直；行列式等于 +1。行列式等于 −1 的不是旋转，而是镜像翻转。从传感器或标定得到的矩阵，常因误差不完全满足这三条，要先“正交化”再用（3.6 节讲方法）。
