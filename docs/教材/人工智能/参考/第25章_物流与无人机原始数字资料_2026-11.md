# 第 25 章（无人机与智能物流）原始数字资料卡

> 建卡日期：2026-11-18。规矩同前几章：**只收论文正文、官方公告、官方文档、官方规格书、
> 官方基准库里的原始值**；新闻稿、公司宣传、维基一律不算。每条都写清口径（谁测的、
> 怎么测的、规模多大、统计期多长、基线是什么、标称条件是什么）；缺哪一样要注明；
> 核不到的写“**未核到**”，正文宁可不印，也不印没有口径的数。
>
> 本章另有一条自己的硬规矩：**没有最优解或下界作对照的改进不采信**。
> 本章讲的是路径与调度——这类问题的好处是**真值是可以求的**（公开基准库里有已证明
> 的最优解，有下界）。所以凡说“我们的方法好了多少”，必须指明是跟谁比：跟最优解比、
> 跟下界比，还是只跟另一个启发式比。本卡第 1、2、3 节就是为了给这条规矩备好对照物。
>
> 相应地，**本章不收任何企业运营口径的“效率提升百分之多少”“省了多少人力”**——
> 除非基线、规模、统计期、测量方四样齐全。本次查下来一样都没齐，全部进第 7 节。

| 表格的列头 | “Instance / Vehicles / Distance / Reference / Comment” | 同上 |
| 个别实例的修正 | 注 `*`（r111）：“As pointed out to us by Victor Allis, the total distance for the best known solution for instance **r111 is 1096.73**” | 同上。**例：BKS 的数值本身也会被人订正** |

**本章用法**：25.2、25.3 节讲 VRP，必须先讲清楚“**我们拿什么当真值**”。
顺序是：①先在小实例（Augerat A/B/P，31—79 客户）上跟**已证明的最优解**比，
这才叫“差多少”；②在 X 集的 61 个已证明实例上同样可以这么比；
③到了 XL、AGS 这种几千上万客户的规模，没有最优解，只能跟 **BKS 或下界**比，
那时候说的就不是“离最优差多少”，而是“离目前最好的已知结果差多少”。
本章所有算例都按这个顺序排，**先在能求最优的规模上把方法校准，再放到大规模上去**。

**引用警告（本章第一号，也是本章最重要的一条）：“最好已知解”不是“最优解”。**
三条硬证据摆在一起：
1. CVRPLIB 库里 `UB`（上界）与 `Opt`（是否已证明最优）**本来就是两个不同的列**；
2. Uchoa 2017 把 BKS 定义成“**ever found since the instances were created**”——
   它是历史最好记录，会被下一篇论文改掉；同一个 X 集，“已证明最优”从论文当年的
   **40/100** 变成今天的 **61/100**；
3. SINTEF 的 Solomon 表**只有 best known，没有最优性标记**，而且官方自己写明
   “results are not directly comparable”，因为那张表用的是分层目标（先少车、再短路），
   精确算法用的是单一总距离目标。

所以本章正文凡写“比 BKS 好 x%”，必须同时写明**那个实例有没有已证明的最优解**；
没有的话，“超过 BKS”只说明“比历史记录好”，**不等于“接近最优”**。
更不许把两张不同目标函数的表（分层目标 vs. 总距离目标）放在一起算百分比。

## 2. 多智能体路径规划（MAPF）的公开基准（25.4、25.5 节用）

| 条目 | 原始值 | 出处与口径 |
|---|---|---|
| 基准论文 | Roni Stern, Nathan R. Sturtevant, Ariel Felner, Sven Koenig, Hang Ma, Thayne T. Walker, Jiaoyang Li, Dor Atzmon, Liron Cohen, T. K. Satish Kumar, Eli Boyarski, Roman Barták，*Multi-Agent Pathfinding: Definitions, Variants, and Benchmarks*（SoCS 2019；arXiv:1906.08291） | 论文正文（经 ar5iv 全文页核到） |
| **makespan 的定义** | “**Makespan. The number of time steps required for all agents to reach their target.**” | 同上 §2.3。论文另给了公式（取各单体计划长度的最大值） |
| **sum of costs 的定义** | “**Sum of costs. The sum of time steps required by each agent to reach its target.**”；并注明“**Sum of costs is also known as flowtime.**” | 同上 §2.3 |
| 地图集规模 | “This publicly available benchmark consists of **24 maps** taken from”（城市地图、Dragon Age: Origins 与 Dragon Age 2、有/无随机障碍的空旷栅格、迷宫型、房间型） | 同上 §4.3。**注意：正文写 24，表 1 却列了 28 行——两处不一致，见第 8 节** |
| 场景文件怎么组织 | “**Every map has 25 scenarios.**”；“Every scenario has a list of **source and target vertices** that were set using a variant of the random method”；“All points in the largest reachable region of each map were randomly paired”；“**the first 1000 problems were put into the scenario**” | 同上 §4.3 |
| 起终点怎么选 | “**Random.** Setting the source and target vertices by randomly choosing vertices and making sure there is a path in the graph between them.” | 同上 §4.2 |
| 智能体数怎么加 | 从两个智能体的问题开始（“by creating a MAPF problem of two agents”），然后“**in consecutive order**”逐个加，直到算法超时 | 同上 §4.3 |
| 基准放在哪 | 论文称这些地图“publicly available in **Sturtevant's movingai.com** repository”（该句原指 Dragon Age: Origins 地图），脚注给出 movingai.com 的 MAPF 基准页 | 同上 §4.3 |
| “random” 与 “even” 两类场景文件的官方说明 | **未核到**。论文正文**只写了 Random 一种方法，全文没有出现 “even”**；movingai.com 的基准页本次环境取不到（不在可访问清单内），所以 `.scen` 文件格式、random/even 的官方区别**都没核到原文** | — |
| “完备性 / 最优性”在本文里的说法 | **未核到**。这篇基准论文**没有给出完备性与最优性的定义**；本章这两个词的定义只能引 CBS 论文（见第 3 节） | — |

**本章用法**：25.4 节讲多机协同，**先把代价函数讲清楚再讲算法**。
makespan 与 sum-of-costs 是**两个不同的目标**，最优解不是同一个解，数值也不可互换——
本章每张结果表都要在表头写明用的是哪一个。基准的组织方式（一张地图 25 个场景、
每个场景 1000 对起终点、智能体数从 2 开始逐个加）正好说明一件事：
**MAPF 的实验是“加到跑不动为止”，所以报结果必须连超时上限和成功率一起报**，
只报“解出来的那些算例的平均代价”会把难算例悄悄筛掉。

**引用警告（本章第二号）：makespan 与 sum-of-costs 不可混用。**
同一批解，按 makespan 排序和按 sum-of-costs 排序结果可以完全不同。
凡引别人的 MAPF 数，先确认它用的是哪个代价；两篇用不同代价的论文**不能放在一起比**。

## 3. 冲突搜索（CBS）等算法的性质（25.5 节用；只要性质，不要跑分）

| 条目 | 原始值 | 出处与口径 |
|---|---|---|
| 论文 | Sharon, Stern, Felner, Sturtevant，*Conflict-based search for optimal multi-agent pathfinding*，*Artificial Intelligence* (2015) | 论文正文 PDF |
| **最优性** | §5.1 **定理 1**：“**CBS returns an optimal solution.**”（证明依赖引理 1、2 与按代价的最佳优先展开顺序） | 同上 §5.1 |
| 最优性的推广 | §7.3 **定理 4**：“**If Φ is admissible then CBS_Φ is guaranteed to return the optimal solution.**” | 同上 §7.3 |
| **完备性（只成立一半）** | §5.2 的 Claim a：“**CBS will return a solution if one exists.**”（由定理 3 证明，依赖定理 2：每个代价下冲突树节点有限）。但同一节明确写出：**Claim b “does not always hold for CBS”**——实例无解时冲突树可以“**grow infinitely**”；论文的办法是先跑一个独立的可解性判定（引 Yu and Rus） | 同上 §5.2 |
| 完备性证明的适用范围 | §7.4：完备性证明“holds for any cost function Φ **as long as there is a finite number of solutions per given cost**”；fuel 代价不满足这个条件，论文改用 SoC 上的 `|V|^4` 界 | 同上 §7.4 |
| sum-of-costs 在本文的定义 | §2.5：“**Sum-of-costs is the summation, over all agents, of the number of time steps required to reach the goal.**”；§6.1 举例：两个智能体分别要 2 步和 3 步，“the sum-of-costs for these two agents is 2 + 3 = 5” | 同上 §2.5、§6.1 |
| 与 fuel 代价的区别 | §2.5：fuel 算“**the total amount of distance traveled by all agents**”，等待动作不计费 | 同上 §2.5 |
| **复杂度** | §1：“Finding an optimal solution for the MAPF problem is **NP-hard**, as the state space grows exponentially with the number of agents.”；§2.5：“Finding the optimal solution, i.e., the minimal sum-of-costs, has been shown to be **NP-hard**.” | 同上 §1、§2.5（均引 Yu and Rus） |
| CBS 什么时候退化 | §5.3.2：“Since the **Conflict Tree grows exponentially in the number of conflicts encountered**, CBS behaves poorly when a set of agents is **strongly coupled**.”；§9 重申“basic CBS is **exponential in the number of conflicts encountered**” | 同上 §5.3.2、§9 |
| 节点数上界 | §5.3 给的是 2 的（与 `|V| × C*` 成正比的指数）次幂这一**最坏情况界**，论文自己说这不是紧界 | 同上 §5.3 |
| “CBS is complete and optimal” 这句原话 | **未核到**。论文**全文没有这一句**；它把最优性写成定理，把完备性拆成 Claim a（成立）与 Claim b（**不总成立**）两半 | — |
| 跑分（求解率、运行时间、与 ICTS/EPEA* 的比较） | **本章不收**（按本节纪律：只要性质） | — |

**本章用法**：25.5 节用 CBS 讲一件事——**“最优”是对某个代价函数而言的、而且是有代价的**。
正文写三句：①CBS 在 sum-of-costs 下返回最优解（定理 1）；②它在有解时一定能找到解
（Claim a），但**不保证判定无解**（Claim b），所以工程上要另配可解性判定或超时兜底；
③它的冲突树随冲突数指数增长，智能体耦合得紧就不行了——这正是本章后面要讲
“什么时候必须退回到启发式、退回去之后拿什么当对照”的理由。

**引用警告（本章第三号）：不要把 CBS 说成“完备且最优”。**
到处流传的 “complete and optimal” 这个说法，**在论文里找不到原句**。
论文自己把完备性拆成两半，并写明无解实例上冲突树可能无限增长。
本章引用时必须按论文的分法写，并注明完备性的那个限定条件。

**本章用法**：25.1 节提出问题、25.6 节算巡检航线时，**续航一律按“标称条件下的上界”用**，
并且在正文里把脚注原话摆出来：那 55 分钟和 49 分钟是**无载重、无风、巡航速度、
放电到 0%** 测出来的。真实巡检要挂吊舱、要有风、不能放到 0%，所以**可用航时一定更短**。
本章的做法是：把官方标称值当**下界检验**（算出来的航线时间若超过标称续航，方案必定不可行），
真正排航线用的是**显式假设的可用航时**（写在正文里，并写明是怎么从标称值折下来的）。

**引用警告（本章第四号）：两家规格页的抗风口径不一样。**
Matrice 350 RTK 的 12 m/s **没有脚注**；Matrice 4 系列的 12 m/s 官方明确写的是
“**during takeoff and landing**”。数值相同，口径不同——**不许把这两个 12 m/s 并列成
“两款都抗 12 m/s 风”**。同理，M350 的 5000 m / 7000 m 升限各自带起飞重量上限，
M350 **官方没有整机最大载重**（960 g 是单吊舱减震器承载，不是载重），
这两处都不许简化。

## 6. 排队论与利特尔法则（25.7 节的吞吐估算对照用）

本节只要定义与适用条件，**不需要任何实测数**。

| 条目 | 原始值 | 出处与口径 |
|---|---|---|
| 论文 | John D. C. Little，*A Proof for the Queuing Formula: L = λW*，*Operations Research* **9**(3), 383–387 (1961)，INFORMS，DOI 10.1287/opre.9.3.383 | 期刊条目与摘要 |
| λ 的定义 | 摘要：“In a queuing process, let **1/λ be the mean time between the arrivals** of two consecutive units” | 同上摘要 |
| L 与 W 的定义 | 摘要定义 **L 为系统中单元数的均值**，**W 为一个单元在系统中停留时间的均值** | 同上摘要 |
| **适用条件（原话）** | “It is shown that, **if the three means are finite and the corresponding stochastic processes strictly stationary**, and, **if the arrival process is metrically transitive with nonzero mean**, then **L = λW**.” | 同上摘要。**三个条件：三个均值有限、相应随机过程严格平稳、到达过程度量传递且均值非零** |
| 与排队规则无关 | **未核到原文**（“与服务规则、到达分布无关”这个广为流传的说法，本次没核到 1961 年摘要里的原话） | — |

**本章用法**：25.7 节用 L = λW 做**量纲级的对照**，不做精度预测。
用法是倒着用：给定一个拣选工位的到达率 λ 与允许的在制品数 L，反推单件允许停留时间 W，
用它去检验上面第 5 节那种“节拍折速率”的算法有没有自相矛盾。
正文必须把三个条件（均值有限、严格平稳、到达过程度量传递）**写出来**，
并立刻说明一件事：**厂区早晚高峰的订单流不是平稳过程**，所以 L = λW 在本章里
只能用于**稳态近似下的粗校验**，不能用来给调度方案背书。

## 7. 本章明确不印的数

1. **任何企业运营口径的“AI/自动化让物流效率提升百分之多少”“省了多少人力/多少台车”**——
   本章要求**基线、规模、统计期、测量方四样齐全**才印。本次查下来，连一组四样齐全的都没有；
   唯一沾边的（Kiva 论文的 600 行/小时）是厂商自述的设计节拍，四样缺三样，
   只能按第 5 节的引用警告当算术示例用。
2. **“我们的算法比别人快多少/好多少”的跨论文比较**：VRP 与 MAPF 两边的基准口径都不统一
   （VRP：分层目标 vs. 总距离目标，SINTEF 官方自己写明不可直接比较；
   MAPF：makespan vs. sum-of-costs，还有超时上限与成功率的差别）。
   要比，只能在**同一套实例、同一个代价函数、同一个超时上限**下自己跑（本章算例就这么做）。
3. **没有已证明最优解或下界作对照的任何“改进幅度”**——这是本章的硬规矩。
   只跟另一个启发式比出来的百分比，本章不采信、不印。
4. **仓储机器人的吞吐、车速、充电门限、安全停车距离**：没核到任何带口径的官方原始值
   （ISO 3691-4 的条文本次拿不到，只有条款标题）。本章这些量**全部写成显式假设**。
5. **无人机的整机最大载重（Matrice 350 RTK）**：官方没给，**不许从最大起飞重量减空重自己算**。
   同机型的最大悬停时间、Matrice 4 系列的 IP 等级，同样未核到，不印。
6. **任何没有标称条件的无人机规格值**：本章规矩是**标称条件核不到，值就不印**。
7. **MAPF `.scen` 文件格式与 random/even 两类场景的官方区别**：movingai.com 本次环境取不到，
   基准论文正文只写了 Random 一种方法、全文没有 “even”。要印必须先核到官方页。
8. **“CBS is complete and optimal” 这句常见表述**：论文正文没有这一句，不许当原话引。

## 8. 方法学限制

- 抓取工具对逐字引文有长度上限（约 125 字符/条），本卡里标“原话”的英文片段，
  **付印前都要回原始页面逐字核一遍**；个别长句在本卡里是按原文拼接的。
- **口径矛盾一：MAPF 地图数。** 基准论文正文写 “consists of **24 maps**”，
  但其表 1 列了 **28 行**。本章若要印地图数，必须回论文表 1 自己数，并把这处不一致写明。
- **口径矛盾二：CVRPLIB 的 XML 集。** 库首页列表显示 XML 集 “No instances in this set”（0 个），
  而官方 BKS Challenge 页说 XML 是 **10000 个各 100 客户的实例**、且全部已知最优解。
  两处对不上（很可能是列表分页或下载方式不同所致），**本章不印 XML 的实例数，
  只引“All XML instances have known optimal solutions”这句性质**。
- **口径矛盾三（同一数据的时间差）：** Uchoa 2017 正文说精确算法当年解到最优 **40/100**，
  CVRPLIB 今天说 **61/100**。两个数都对，**但属于不同时点**；
  本章引用时必须带时点，并把它当成“BKS 与已证明最优都会随时间变化”的证据。
- Kiva 那篇论文本次拿到的 PDF **只有 AAAI 2007 的版权页，没有印 AI Magazine 29(1), 2008 的卷期**。
  本章若要正式引该文，**付印前须核定卷期页码**。
- ISO 3691-4:2023 本卡只核到**条款标题与版本日期**（来自官方预览页），**条文一律未核到**。
  本章讲安全只指向条款结构，不印任何数值。
- 第 6 节的利特尔法则来自 1961 年论文的**摘要**，不是正文。
  适用条件的三条表述取自摘要原话；若正文要更细的条件表述，须回原文。
