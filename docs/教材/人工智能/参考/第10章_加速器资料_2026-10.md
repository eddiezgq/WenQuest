## 0. 使用这份资料的三条纪律

1. **稠密/稀疏必须说清。** 例：H100 "1979 TFLOPS FP16" 是稀疏值，稠密值是 989。A100/H100/H200 的数据手册默认印稀疏值，Blackwell 之后 NVIDIA 改为同时给出 "dense/sparse"。
2. **"算力"要带精度。** 国产厂商宣传常只说 "算力 1000 TFLOPS" 而不说精度，几乎都是 FP8 或 INT8。
3. **路线图 ≠ 产品。** 2027—2028 的型号（昇腾 960/970、MI500、Rubin Ultra、昆仑芯 M300）是**发布会公布的目标**，不是可买到的实物。

### 2.1 AMD CDNA / RDNA

| 项目 | MI300X / MI325X (CDNA 3) | MI355X / MI350X (CDNA 4) | RDNA 3 / RDNA 4 |
|---|---|---|---|
| LLVM target | `gfx942` | `gfx950` | `gfx1100` / `gfx1201` |
| **Wavefront 大小** | **64** | **64** | **32 或 64**（wave32/wave64 双模） |
| CU 数 | 304 | 256 | — |
| **LDS / CU** | **64 KB** | **160 KB**（读带宽翻倍） | — |
| L1 / CU | 32 KB | 32 KB | — |
| L2 | 4 MB/XCD（共 32 MB，8 XCD） | 4 MB/XCD（共 32 MB） | — |
| Infinity Cache (MALL) | 256 MB | 256 MB（MI350P 128 MB） | — |
| VGPR / SGPR | 512 / 12.5 KB | 512 / 12.5 KB | — |
| XCD × CU | 8 × 40（38 启用） | 8 × 36（**32 启用**） | — |
| 工艺 | N5 (XCD) + N6 (IOD) | **N3P (XCD) + N6 (IOD)** | — |

🟢 <https://rocm.docs.amd.com/en/latest/reference/gpu-specs.html>（含 RDNA "32 or 64" 注记）
🟢 <https://rocm.docs.amd.com/en/latest/reference/gpu-arch/mi350.html>

**对比记忆点（教材可用）**：NVIDIA warp = 32 固定；AMD CDNA wavefront = 64 固定；AMD RDNA 可 32 也可 64。这决定了 occupancy 计算、`__shfl` 类操作的 lane 掩码宽度，以及从 CUDA 迁移时 `warpSize` 不能写死为 32。

**矩阵核心数据类型**
- CDNA 3：FP16、BF16、FP8、INT8。
- CDNA 4：新增 OCP MX 微缩放格式 **MXFP8 / MXFP6 / MXFP4**。
- 🟢 同上 MI350 微架构页。

**MFMA 指令形状**
- 命名规则 `v_mfma_<输出类型>_<M>x<N>x<K><输入类型>`，计算 `D = A·B + C`。例：`v_mfma_f32_32x32x8f16`（输入 FP16、累加输出 FP32、形状 32×32×8）。
- 常用两档：**32×32×8**（payload 大、软件效率高）与 **16×16×16**（功耗低，实测可达更高 MAF）。
- 稀疏变体为 `SMFMAC`；RDNA 侧对应指令是 `WMMA` / `SWMMAC`。
- 官方工具 **AMD Matrix Instruction Calculator** 可查某条 MFMA 的吞吐、寄存器布局、CBSZ/ABID/BLGP 修饰符。🟢 <https://github.com/ROCm/amd_matrix_instruction_calculator>
- 实测 MAF（AMD 自测，非峰值）🟢 <https://rocm.blogs.amd.com/software-tools-optimization/measuring-max-achievable-flops-part2/README.html>：
  - MI300X：FP16 654 / BF16 708 / FP8 1273 TFLOPS
  - MI325X：FP16 794 / BF16 843 / FP8 1519 TFLOPS（软件效率最高 94%）
  - **教学价值极高**：MI300X 峰值 FP16 1307 TFLOPS，实测 654 —— 约 50%。教材讲"峰值算力"时应该拿这组官方数字说明峰值与可达的差距。

**Infinity Fabric**
- MI300X / MI325X：**7 条 IF 链路，每条 128 GB/s 双向**，8 GPU 全互联（ring/all-to-all）。🟢 MI325X 数据手册。
- MI455X（2026 H2）：**3.6 TB/s** chip-to-chip。🟡 The Register。

### 2.3 华为达芬奇（Da Vinci）架构与 CANN

**AI Core 三类执行单元**（🟢 CANN 官方文档 <https://www.hiascend.com/document/detail/en/CANNCommunityEdition/900/programug/Ascendcopdevg/atlas_ascendc_10_0008.html>）
- **Cube 单元**：官方表述 "每次执行可以完成两个 16×16 的 float16 矩阵相乘"。常写作 **16×16×16 FP16 矩阵乘累加**。
- **Vector 单元**：类 SIMD，支持 repeat 和带间隔（stride）的向量直接计算。
- **Scalar 单元**：相当于一个小 CPU，负责标量运算、循环与分支控制，并**调度其他单元的流水线**。

**片上缓冲**（🟢 同上）
- **L0A / L0B**：Cube 指令的两个输入缓冲。
- **L0C**：Cube 指令输出缓冲（FP32 累加）。
- **Unified Buffer (UB)**：Vector / Scalar 计算的输入输出缓冲。
- **L1 Buffer**：通用数据缓冲，减少访问总线的次数。
- ⚠️ **官方文档明确写"存储单元大小随 AI 处理器型号不同"，没有给出 910B 的具体 KB 数**。

**耦合 / 分离架构**（🟢 同上）
- **分离架构（Separated）**：Cube 与 Vector 各自配独立 Scalar 单元，分别部署在 **Cube Core（AIC）** 和 **Vector Core（AIV）** 上 —— **Atlas A2、A3 系列（即 910B/910C）属此类**。
- **耦合架构（Coupled）**：Cube 与 Vector 共用一个 Scalar 单元 —— Atlas 推理系列（310P 等）属此类。

**910B 具体数字（🟡 第三方资料，华为未公开官方数据手册）**
> 来源：<https://github.com/OminiX-ai/OminiX-Ascend/blob/main/docs/ascend_910b4_datasheet.md>（以 910B4 为例）
> - AIC : AIV = **20 : 40**（1:2 分离比例），1.65 GHz
> - FP16 峰值 280 TFLOPS；FP32 75 TFLOPS
> - 32 GB HBM2e，800 GB/s；L2 共享 192 MB
> - **UB 192 KB / AIV；L1 512 KB / AIC；L0A 64 KB；L0B 64 KB；L0C 128 KB / AIC**
> - 工艺标注 SMIC N+1（约 7 nm），die 665.6 mm²
> - 架构注记："AIC↔AIV 之间没有直连通路，必须经 GM/L2 中转"
>
> 🟡→🔴 **这组 KB 数字和 AIC/AIV 计数只有第三方来源。教材里如要给出，必须写"据第三方整理，华为未公开官方规格"。** 另有资料给 910B FP16 为 320 或 376 TFLOPS，数值随 B1/B2/B3/B4 子型号不同，且无官方统一表。

**CANN 版本**
- **CANN 9.1.0**（社区版）：已支持 **Ascend 950PR / 950DT**、Atlas A2/A3、Atlas 350 加速卡；新增 SMLA、Mhc 等算子，适配 DeepSeek V4 / Qwen 3.6 / Kimi-K2.6 / GLM5.2；**SHMEM** 让 AI Core 直接发起 MTE/UDMA/RDMA 传输；**CATLASS** 支持 MXFP8/MXFP4 量化的 Tile 组件；Python 3.14。🟢 <https://www.hiascend.com/document/detail/en/CANNCommunityEdition/910/softwareinst/releasenote/9.1.0/release-notes_en.md>
- **CANN 9.0.0** 为商用版基线。🟢 <https://www.hiascend.com/document/detail/zh/canncommercial/900/releasenote/release-notes.md>
- CANN 于 **2025-08** 宣布开源。🟡 <https://www.guancha.cn/economy/2025_08_05_785551.shtml>

**Ascend C 编程模型**（🟢 <https://www.hiascend.com/developer/techArticles/20230830-1>）
- **三段流水**：`CopyIn`（GM → Local）→ `Compute`（向量/矩阵计算）→ `CopyOut`（Local → GM）。三段之间用队列同步，形成多片数据并发的流水并行。
- **TQue**：任务队列，`EnQue` / `DeQue`。三个逻辑内存位置：**VECIN**（输入暂存）、**VECCALC**（中间）、**VECOUT**（输出暂存）。
- **TPipe**：统一管理各任务之间通信内存的内存模块。
- **GlobalTensor**：指向多 AI Core 共享的 Global Memory；**LocalTensor**：指向 Local Memory（带宽极高、容量小，"数百 KB 到 1 MB"）。`DataCopy` 在两者之间搬运。
- **SPMD 模型**：所有 AI Core 执行同一份指令代码，唯一区别是 `block_idx`；数据切分靠 `address + block_idx × BLOCK_LENGTH` 偏移。
- 两种范式：**矢量（Vector）编程范式**与**矩阵（Cube）编程范式**。

### 3.1 需要特别谨慎的几点

- **"SMIC 已量产 5 nm"是错的。** 可核实的事实是 **N+3 已确认用于量产手机 SoC（Kirin 9030）**，TechInsights 的结论是"接近但仍不是 5 nm"，且无 EUV。昇腾芯片用的是哪一代 SMIC 工艺，**华为与 SMIC 均未公开**。
- **华为产量数字分歧很大**：美方官员口径（2025 ≤ 20 万颗）与 Bloomberg 报道（2025 约 100 万 die、2026 目标 160 万 die）口径不同——一个按"芯片/封装成品"，一个按"die"，且前者是政策表态。教材如引用，**必须同时给出两个口径并说明差异**。
- **H200 对华销售实际规模极小**：美方批准（2026-01）→ 中方海关拦截（2026-01）→ 少量放行（2026-07）→ 收入占比 < 1%（2026-08）。这是比"批准/禁止"二元叙事更准确的描述。
- **🔴 本次未能证实的 2026 年传闻**：950PR 单价、ByteDance/Alibaba 大额订单、B30A 发布、Ascend"CUDA 兼容"。**勿写入教材**。
