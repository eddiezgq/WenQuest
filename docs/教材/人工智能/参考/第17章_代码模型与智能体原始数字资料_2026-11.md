## 1. Codex 与 HumanEval（Chen 等 2021）

论文：Chen、Tworek、Jun、Yuan、Pinto、Kaplan 等（OpenAI），*Evaluating Large Language Models Trained on Code*，arXiv:2107.03374。本卡核对的是 ar5iv 的全文 HTML。

### 1.1 pass@k 的无偏估计量（**教材要印的原式**）

论文的做法：对每道题生成 $n$ 个样本（$n \ge k$），记其中**通过全部单元测试**的样本数为 $c$，则

$$
\text{pass@}k := \mathop{\mathbb{E}}_{\text{Problems}}\left[\, 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}} \,\right]
$$

| 项目 | 数值／内容 | 口径 | 类型 |
|---|---|---|---|
| 论文实际用的 $n$ 与 $k$ | **$n = 200$，$k \le 100$** | 全部 HumanEval 评测都按这个采样规模 | 论文正文（第 2.1 节 Metric） |
| "通过"的判定 | **只要有一个样本通过全部单元测试，该题即算解出** | 原话 "a problem is considered solved if any sample passes the unit tests" | 论文正文（第 2.1 节） |
| 为什么不能直接算这个式子 | 论文说直接算会**数值不稳定**，给了一段**逐项相乘**的数值稳定实现（Figure 3 的代码） | 教材要印这段的话，注明是"论文给的数值稳定实现" | 论文正文（第 2.1 节 / Figure 3） |
| 为什么不能用 $1-(1-\hat p)^k$ | 论文明确说用经验 pass@1 的 $\hat p$ 去算 $1-(1-\hat p)^k$ 是**有偏的** | 这是教材讲"为什么要用组合式估计量"的原始依据 | 论文正文（第 2.1 节） |

### 3.2 EvalPlus（Liu 等 2023）：HumanEval 测试不足带来的虚高

### 3.3 折算（本卡自算）

把 3.1 与 3.2 放在一起看，**"HumanEval 上 1 个百分点"大致意味着 1.64 道题**（164 道题，100% ÷ 164 ≈ 0.61 个百分点／题）。所以：
- Riddell 等剔掉的 31 道"完全匹配"题 ≈ **18.9% 的题量**；
- EvalPlus 查出的 18 处标准解错误 ≈ **11.0% 的题量**（18 ÷ 164 = 10.98%，与论文称的 11% 一致）。

**都是折算，两篇论文都没写"每题值多少个百分点"。**

**规模效应**：试了 GPT-2 的 **124M / 355M / 775M / 1.6B** 四档加 GPT-J。论文结论：**约 775M 以上才从工具里得到好处**；更小的模型带不带工具差不多（维基搜索除外）；而且**即使最大的模型，"带 API 调用"和"不带"之间的差距依然很大**。

## 7. 任务成功率随步数衰减——**没有逐步曲线的原始数字**

| 问题 | 核对结论 |
|---|---|
| 有没有正式论文给出"多步任务的逐步成功率"或"步数—成功率曲线"？ | **本次没核到**。能查到的最接近的两组原始数字（下面 7.1、7.2）**都不是按"步数"来的**：一个按"独立重跑次数 k"，一个按"人类完成该任务要多久"。 |
| 教材怎么办 | **明确写"未确认，本书只给数学推导"**：若每步独立成功概率 $p$，$n$ 步全对的概率 $p^n$。**这是数学恒等式，不是任何论文的实测数字**，教材不得给它挂引文。 |

### 7.1 τ-bench 的 pass^k（Yao 等 2024）

论文：Yao、Shinn、Razavi、Narasimhan（Sierra），*τ-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains*，arXiv:2406.12045。

| 项目 | 数值／定义 | 类型 |
|---|---|---|
| pass^k 的定义 | **同一任务独立重跑 k 次全部成功**的概率，再对任务取平均。原话 "the chance that all k i.i.d. task trials are successful, averaged across tasks" | 论文正文 |
| 公式（与 pass@k 对照） | $\text{pass}^k = \mathbb{E}_{\text{task}}\!\left[\dfrac{\binom{c}{k}}{\binom{n}{k}}\right]$，而 $\text{pass@}k = 1-\mathbb{E}_{\text{task}}\!\left[\dfrac{\binom{n-c}{k}}{\binom{n}{k}}\right]$；默认 $\text{pass}^1=\text{pass@}1=\mathbb{E}[c/n]$（教材把 pass@k 与 pass^k 并排印最有价值） | 论文正文 |
| 任务数 | τ-retail **115 个**；τ-airline **50 个** | 论文正文 |
| 工具数 | τ-retail **15 个**（7 个写操作 + 8 个非写）；τ-airline **13 个**（6 + 7） | 论文正文 |
| 温度 | **智能体 0.0；用户模拟器 1.0** | 论文正文 |

### 9.2 "一切都算进上下文"（教材 17.3 算账的前提，官方原话）

## 12. 为什么这些数字不能横向直接比较

1. **pass@k 的每一档都可能用不同的温度。** Codex 论文 Table 1 里 pass@1 用 $T=0.2$、pass@10 用 $T=0.6$、pass@100 用 $T=0.8$。所以"pass@100 ÷ pass@1 = 2.5 倍"**不是"多采几次的增益"**，而是"两套采样设置下两个指标的比值"。引 pass@k 必须连温度一起引。而 Codex-S 又换成 $T^*=0$ 与 $T^*=1$，和 679M 模型的 0.2 / 0.8 **不是同一组**。
2. **HumanEval 与 MBPP 的提示口径不同。** MBPP 的默认少样本提示**把 3 个 assert 交给模型看**；HumanEval 不给测试。还有采样规模：MBPP 的 59.6% 是 **80 个样本、$T=0.5$**，而 MBPP 的执行实验用**贪心单样本**。三个数字放一起排名没有意义。
3. **"每题平均几个测试"两家数字不同。** Codex 论文算出 HumanEval **7.7**，EvalPlus 算出 **9.6**。统计方式不同。
4. **换一套测试，排名会翻。** EvalPlus 把测试加到 80 倍后，WizardCoder-CodeLlama 与 Phind-CodeLlama（34B）从"不如 ChatGPT"变成"超过 ChatGPT"。而且 HumanEval 原本有 **11% 的标准解是错的**。所以"HumanEval 上差 2 个点"没有意义。
5. **SWE-bench ≠ SWE-bench Lite ≠ SWE-bench Verified。** 同一个 gpt-4o 在 SWE-bench 上 16%、在 Verified 上 33.2%。Verified 筛掉了原集的 **68.3%**。三者**都不能直接比**，Lite（300 题）也不能当全集（2,294 题）的代表。
6. **SWE-bench 的分数强烈依赖"给了什么上下文"。** oracle（直接给改动文件）> oracle-collapsed > BM25；而 BM25 里**上下文给得越多分数反而越低**（Claude 2：13k 时 1.96、50k 时 1.22）。引任何 SWE-bench 分数都要写清检索设置。
7. **有没有 agent 框架是量级差别。** SWE-bench 原论文是**单轮"读提示→出 diff"，不是 agent**（最高 9.39%）；官方公告里同一个 GPT-4 换脚手架能从 2.7% 到 28.3%。**模型相同、脚手架不同，差十倍。**
8. **允不允许执行测试，是两套世界。** Codex 的 filtered pass@1（先跑 3 个公开测试筛一遍，22.78%）比 raw pass@100（20.20%）还高；Reflexion 的 91% 靠的是**自生成单元测试 + 多轮反思**，去掉测试生成就掉到 52%。"能跑测试"的分数不能和"一次性生成"的分数并排。
9. **自生成测试的假阳性率随基准变化极大。** HumanEval Python 只有 **1.4%**，MBPP Python 高达 **16.3%**。所以"自动验证"在不同基准上可信度完全不同。
10. **污染的影响依模型而异，而且不可反推因果。** 剔掉完全匹配题后，StarCoderBase 在 HumanEval 上相对掉 **25.9%**，Pythia-12B 掉 **57.1%**。Riddell 等明确说**无法确定因果**（不能重训一个没见过测试解的模型）。教材不能写成"污染使分数虚高 X%"。
11. **pass@k 与 pass^k 是两件事。** pass@k 是"**至少有一个**对"的概率（多采几次就涨），pass^k 是"**k 次全对**"的概率（k 越大越低）。一个衡量能不能做到，一个衡量能不能稳定做到。两者都不是"按步数"的衰减。
12. **"成功率随步数衰减"没有实测曲线。** τ-bench 的 pass^k 按**重跑次数**、METR 的 logistic 模型按**人类耗时**。拿 pass^8 < 25% 去说"8 步后只剩 25%"是错的。
13. **工具带来的提升依任务而定，而且可能是负的。** Toolformer 在数学上从 7.5 → 40.4，但在开放域问答上**仍明显不如 GPT-3 175B**；ReAct 在 HotpotQA 上（27.4）**低于** CoT（29.4）；Reflexion 在 MBPP Python 上（77.1）**低于** GPT-4 基线（80.1）。只挑涨的那一行写，是失真。
14. **工具只对够大的模型有用。** Toolformer 的规模实验：**约 775M 以上**才从工具里得到好处。Reflexion 在 starchat-beta 上**完全没有提升**（0.26 → 0.26）。
15. **MCP 的概念要连版本号一起讲。** `2026-07-28` 版去掉了 `initialize` 握手与会话、改成无状态、弃用了 Roots / Sampling / Logging。照 2025-06-18 版写的段落在新版下已不成立。

18. **上下文长度的官方数字只有 Anthropic 一家是全的。** Google 模型页大部分型号不写 token 上限，OpenAI 本次没核到。**不要把三家的数字排成一张"对比表"印进书里**，那张表里会有两列是编的。
