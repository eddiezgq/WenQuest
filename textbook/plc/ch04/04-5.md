### 4.5.1 一个循环不够用的时候

到目前为止，PLC 只做一件事：一遍又一遍地扫描同一个程序。小设备这样就够了。设备一复杂，问题就来了：温度的 PID 调节要每 100 ms 算一次，间隔要均匀；轴的位置要每 2 ms 采一次；安全门打开要立刻处理；而统计报表几秒钟算一次也无妨。把它们都放进一个循环里，扫描时间由最慢的那部分决定，最急的那部分只好跟着等。

IEC 61131-3 用**任务**（task）解决这个问题。一个任务规定一段程序在什么条件下执行、优先级多高。程序（以及功能块实例，第 7 章）挂在任务下面，由任务来调用。标准里只有一种任务，按 SINGLE、INTERVAL 两个参数的设置，可以分出三种执行方式：

- **循环任务**：两个参数都不设，执行完一遍马上再执行，就是前面说的扫描。一般只有一个，优先级最低，叫主循环；
- **周期任务**：每隔一个固定的时间执行一次，用参数 INTERVAL 规定间隔，例如 `INTERVAL := T#2ms`。适合 PID 调节、采样、运动控制；
- **事件任务**：某个事件发生时执行一次，用参数 SINGLE 指定触发它的布尔变量（在它的上升沿执行）。厂家把硬件输入、计数器到值、通信报文等触发的中断也做成这一类任务，这是对标准的扩展。

每个任务还有一个优先级 PRIORITY，数字越小优先级越高，0 最高。注意西门子正好相反：OB 的优先级数字越大越高，OB1 是 1。在 IEC 61131-3 的配置里大致这样写：

```
TASK Fast  (INTERVAL := T#2ms,  PRIORITY := 1);
TASK Alarm (SINGLE := B5_Door, PRIORITY := 0);
PROGRAM Axis  WITH Fast  : AxisCtrl;
PROGRAM Guard WITH Alarm : DoorStop;
```

没有挂任务的程序，由系统按循环任务执行。各厂家的编程软件里，任务大多在图形界面里配置，不手写这几行，概念是一样的：西门子叫组织块（OB），OB1 是主循环，OB30–OB38 是循环中断（即周期任务），OB40 起是硬件中断；三菱用中断指针 I 标记中断程序；CODESYS 的任务有循环、自由运行、事件、状态几种。

### 4.5.2 优先级与抢占

一台 PLC 通常只有一个处理器核在执行用户程序，几个任务同时“该执行了”，只能一个一个来。谁先来由优先级决定。高优先级的任务到了，正在执行的低优先级任务要不要停下来让路？IEC 61131-3 允许两种做法：**抢占**式，低优先级任务立即被打断，等高优先级任务做完再接着做；非抢占式，等当前任务做完再轮到高优先级任务。大多数 PLC 采用抢占式。

图 4.5.1 是三个任务在抢占式调度下的执行时间线。主循环任务 Main 每遍执行 6 ms；周期任务 Fast 每 2 ms 执行一次，每次 0.4 ms；事件任务 Alarm 由外部事件触发了两次，每次 0.3 ms。Main 不断被 Fast 和 Alarm 打断，每遍实际用了约 {{ex4_5.main_cycle}} ms（模拟中的平均值），比它自己的 6 ms 长了不少：Fast 占去了 {{ex4_5.load}}% 的处理器时间。

从图中可以看出几条规律：

1. 周期任务按时执行，间隔均匀，不受主循环长短的影响，这正是要把 PID、采样放进周期任务的原因；
2. 事件任务的响应时间与扫描周期无关，只取决于它前面有没有更高优先级的任务在执行；
3. 高优先级的任务要短。它执行多久，低优先级的任务就被耽搁多久；周期任务的执行时间如果接近它的间隔，主循环就几乎得不到处理器时间，扫描时间会变得很长，甚至触发看门狗；
4. 周期任务一次没做完、下一次又到了，叫任务超时。PLC 会记录下来，有的会转入停止。

### 4.5.3 任务之间共享数据

主循环正在用一个变量，被周期任务打断，周期任务改了这个变量，主循环回来以后，前半段用的是旧值，后半段用的是新值，与 4.2.2 节说的“前后一致”的问题一样。一个变量占好几个字节时更糟：主循环刚写了一半，被打断，周期任务读到的是一半新、一半旧的数。这叫**数据一致性**问题。

避免它的办法：一个变量只由一个任务写；任务之间交换数据时，先在本任务里复制一份，用副本工作；交换多个相关的数据时，用标志位、过程映像分区，或者在复制的几行前后暂时禁止中断（三菱的 DI、EI 指令，西门子的 DIS_AIRT、EN_AIRT），保证一次取到的是同一组。周期任务和事件任务里的输入输出，要么用分配给这个任务的过程映像，要么用直接读写（4.2.3 节），不能指望主循环的映像。
