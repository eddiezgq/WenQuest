### 6.3.1 问题的提出

一块 GPU 的算力和显存都有上限。训练第 2 章的小型 Transformer，一块 A10 足够；训练 70 亿参数一级的模型，仅权重、梯度和优化器状态就要上百 GB，一块 80 GB 的 H100 也放不下，把训练数据算完一遍更要好几年。于是要用很多块 GPU 一起算。最常见的办法是**数据并行**：每块 GPU 放一份完整的模型，各自处理一批不同的数据，算出各自的梯度；然后把所有 GPU 的梯度加起来（取平均），每块 GPU 用同样的平均梯度更新参数，模型始终保持一致。

“把梯度加起来”就要在 GPU 之间搬数据，而且每一步训练都要搬一次，数据量就是模型的大小。搬得快不快，取决于 GPU 之间怎样连接。本节讲多 GPU 编程的基本接口和互联硬件，6.4 节讲怎样高效地把数据加起来。数据并行之外的张量并行、流水线并行、完全分片数据并行等，第 9 章再讲。

### 6.3.2 一个进程使用多块 GPU

CUDA 用一个整数编号区分 GPU。`cudaGetDeviceCount` 查有几块，`cudaSetDevice(i)` 指定“当前”GPU：之后在这个主机线程中分配的显存、创建的流、启动的核函数都属于第 $i$ 块。

```cpp
for (int i = 0; i < n; i++) {
    cudaSetDevice(i);
    cudaMalloc(&buf[i], bytes);            // buf[i] 在第 i 块 GPU 上
    kernel<<<grid, block, 0, st[i]>>>(buf[i]);   // st[i] 也要在第 i 块上创建
}
```

各块 GPU 上的核函数是异步的，上面的循环几乎立即结束，$n$ 块 GPU 同时工作。实际的训练程序更常用“每块 GPU 一个进程”的方式（PyTorch 的 `torchrun`），进程之间的通信交给 NCCL（6.4 节）。

### 6.3.3 点对点访问与统一虚拟地址

两块 GPU 之间复制数据，最笨的办法是经主机中转：先拷回主机内存，再拷到另一块 GPU，两次穿过 PCIe。**点对点访问**让数据直接从一块 GPU 的显存到另一块：

```cpp
int can;
cudaDeviceCanAccessPeer(&can, i, j);       // 硬件是否允许 i 直接访问 j
cudaSetDevice(i);
cudaDeviceEnablePeerAccess(j, 0);          // 打开
cudaMemcpyPeerAsync(dst, j, src, i, bytes, stream);   // 从 i 直接复制到 j
```

打开点对点访问以后，第 $i$ 块 GPU 上的核函数甚至可以直接读写第 $j$ 块的显存，就像访问自己的一样。这靠的是**统一虚拟地址**：主机内存和所有 GPU 的显存在同一个 64 位地址空间里，各占一段，一个指针本身就说明了数据在哪里。

### 6.3.4 互联：PCIe、NVLink 与 NVSwitch

点对点访问走哪条路，取决于硬件。

**PCIe**：每块 GPU 都经 PCIe 连到主机。GPU 之间的点对点数据经 PCIe 交换机转发；两块 GPU 若挂在不同的 CPU 下，还要穿过 CPU 之间的连接，更慢，有的平台干脆不允许点对点。

**NVLink**：NVIDIA 专为 GPU 之间设计的高速链路，2016 年随 P100 推出。第 1 代（P100）每条链路每个方向 20 GB/s，第 2—4 代 25 GB/s，第 5 代 50 GB/s；一块 GPU 有许多条：P100 4 条、V100 6 条、A100 12 条、H100 18 条、B200 18 条。

**NVSwitch**：NVLink 交换芯片。早期的 8 卡服务器用 NVLink 把 GPU 连成一个网，有的两块之间要绕路；从 DGX-2（2018）起，每块 GPU 的全部 NVLink 都接到 NVSwitch 上，任意两块 GPU 之间都有满带宽（图 6.3.1(a)）。到了 GB200 NVL72，NVSwitch 把一个机柜里的 72 块 GPU 连成一个 NVLink 域。

不同机器之间则靠网络：InfiniBand 或以太网（RoCE），每块 GPU 常配一块网卡，经 GPUDirect RDMA 直接读写显存，不经过主机内存。

**工程师笔记**

- 用多块 GPU 之前先看 `nvidia-smi topo -m`：只有 PCIe 的机器上，GPU 之间的通信可能比计算还慢。
- 一个进程管多块 GPU 时，每次操作前都要 `cudaSetDevice`，流和显存都属于创建时的当前 GPU。
- 训练中 GPU 之间的通信几乎都用 NCCL（6.4 节），不要自己用 `cudaMemcpyPeer` 拼。
- 机器之间的带宽比机器内小一个数量级：设计并行方案时，让通信最多的部分留在机器内（第 9 章）。
