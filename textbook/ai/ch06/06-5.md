### 6.5.1 问题的提出

第 5 章对矩阵乘法下了许多判断：分块版被共享内存带宽压住，寄存器分块版有 4 路存储体冲突，L2 缓存使实际的显存流量比不计缓存的估计小一个数量级……这些判断都来自模型和推理。它们对不对，要用测量来检验。NVIDIA 提供两个配套的工具：**Nsight Systems** 看整个程序在时间上怎样展开，**Nsight Compute** 看单个核函数内部发生了什么。先用前者找出时间花在哪里，再用后者弄清那里为什么慢——这是 GPU 性能分析的标准顺序。

### 6.5.2 Nsight Systems：时间线

Nsight Systems 记录程序运行期间发生的一切：主机各线程在做什么、调用了哪些 CUDA 接口、每个核函数和每次复制在 GPU 上何时开始何时结束、各个流的情况、NCCL 通信、操作系统的调度。结果画成一条时间线，一眼就能看出：

- GPU 有没有闲着（核函数之间的空隙）——可能是启动开销、同步、或主机在准备数据（6.2 节）；
- 传输与计算有没有重叠（6.1 节）；
- 哪几个核函数占了大部分时间——接下来该分析谁。

```bash
nsys profile -o timeline --trace=cuda,nvtx ./streams     # 运行并记录
nsys stats timeline.nsys-rep                              # 文字汇总：每种核函数、每种复制的总时间
```

`.nsys-rep` 文件用图形界面打开就是时间线。在程序里用 **NVTX** 标出自己的阶段（`nvtxRangePushA("第 3 帧")`…`nvtxRangePop()`；PyTorch 中是 `torch.cuda.nvtx.range`），它们会作为一段段带名字的区间出现在时间线上，长程序里很容易找到想看的部分。Nsight Systems 的开销很小，程序几乎按原速运行。

### 6.5.3 Nsight Compute：一个核函数的内部

Nsight Compute 读取 GPU 的**性能计数器**：GPU 里成千上万个硬件计数器，记录每个部件做了多少事——发了多少条指令、读了显存多少字节、L2 命中了多少次、共享内存的访问分了几次……一次运行能读的计数器有限，所以 Nsight Compute 会把同一个核函数**重放**几十遍，每遍读一部分，最后拼成完整的报告。代价是被分析的核函数慢几十倍，而且各核函数被强行串行执行；所以只分析少数几个关键的核函数，用 `--kernel-name` 和 `--launch-count` 挑出来。

```bash
ncu --set full --kernel-name regtile --launch-count 1 -o regtile ./gemm 4096
```

报告分成若干节，最常看的是：

- **速度之光**（Speed of Light，SOL）：计算部件和内存部件各自用到了峰值的百分之几。哪一个接近 100%，核函数就受哪一个限制；两个都低，说明受延迟限制——线程束不够多，或者每个线程束都在等。
- **内存负载分析**：显存、L2、L1、共享内存各层的流量与命中率，存储体冲突。
- **占用率**：理论占用率、实际达到的占用率，以及是寄存器、共享内存还是线程块数限制了它（3.7 节）。
- **线程束状态统计**：线程束的时间都花在了什么上。几种常见的停顿原因：*long scoreboard*（等全局内存或本地内存的数据），*MIO throttle*（共享内存等的指令队列满了，发不出去），*short scoreboard*（等共享内存或特殊函数的结果），*barrier*（在 `__syncthreads()` 处等别的线程束）。
- **屋顶线**：把核函数按实测的运算量和流量画到屋顶线上（6.6 节）。
- **源代码对照**：每一行源代码（或每一条机器指令）各发生了多少停顿、多少存储体冲突，直接指到出问题的那一行。

读计数器需要权限。默认只有管理员能读；在虚拟机上可以用 `sudo` 运行，或者由管理员把驱动参数 `NVreg_RestrictProfilingToAdminUsers` 设为 0。在容器平台上（包括许多云 GPU 平台），普通用户往往读不到，会报 `ERR_NVGPUCTRPERM`。这时 Nsight Systems 照常能用，Nsight Compute 只好换到有权限的机器上。

**工程师笔记**

- 先 Nsight Systems，后 Nsight Compute：先找出时间花在哪里，再看那里为什么慢。
- 分析之前先用模型写下预期（流量、强度、上限），再拿测量去对；不要在一大堆计数器里漫无目的地找。
- Nsight Compute 会重放核函数并串行化，量到的时间只作参考；计时以正常运行的事件计时为准。
- 云平台的容器里常读不到计数器（`ERR_NVGPUCTRPERM`）；需要时换虚拟机，或请管理员开放权限。
