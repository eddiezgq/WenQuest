### 6.1.1 问题的提出

第 4、5 章优化的都是单个核函数。一个实际的程序却是一串操作：把数据传到 GPU，启动几个核函数，再把结果传回来。检测工位每帧都要这样走一遍：彩色图像从主机内存经 PCIe 传到显存，灰度化、找暗斑，把结果传回主机。4.3 节已经看到，一帧图像的传输时间比灰度化本身长得多。核函数再快，整条流水线也快不过传输。

能不能在传第 2 帧的同时处理第 1 帧、传回第 0 帧的结果？可以。GPU 上有几个互相独立的硬件：执行核函数的 SM，以及负责主机与显存之间复制数据的**复制引擎**（数据中心的 GPU 至少有两个，上传与传回可以同时进行；程序 6.1.1 会读出它的个数）。只要告诉 GPU 哪些操作之间没有先后关系，它们就能同时进行。告诉的办法就是**流**。

### 6.1.2 流

一个流是 GPU 上的一个命令队列：同一个流里的操作按发出的顺序一个接一个执行，前一个做完后一个才开始；不同流里的操作之间没有顺序约束，GPU 可以让它们重叠。到现在为止我们的程序都只用了**默认流**（核函数启动时不指定流，就进入默认流）。传统的默认流还有一个特别之处：它与其他（阻塞的）流互相同步，不能与它们重叠。所以要重叠，就要显式地创建流：

```cpp
cudaStream_t s;
cudaStreamCreate(&s);
cudaMemcpyAsync(d_in, h_in, bytes, cudaMemcpyHostToDevice, s);   // 异步复制：立即返回
kernel<<<grid, block, 0, s>>>(d_in, d_out);                        // 第 4 个启动参数是流
cudaMemcpyAsync(h_out, d_out, bytes2, cudaMemcpyDeviceToHost, s);
cudaStreamSynchronize(s);                                          // 主机等这个流里的操作全部完成
```

`cudaMemcpyAsync` 与 `cudaMemcpy` 不同，它只把复制命令放进流里就返回，主机可以接着发别的命令。异步复制有一个前提：主机一侧必须是**锁页内存**（4.3 节）。复制引擎直接按物理地址读写主机内存，可分页内存可能被操作系统换出，驱动只好先把它拷到一块内部的锁页缓冲区，这一步是同步的，重叠也就无从谈起。

### 6.1.3 让三个流交替

做法是把各帧轮流放进几个流里：第 $f$ 帧放进第 $f \bmod 3$ 个流，每个流有自己的显存缓冲区。同一帧的上传、处理、传回在同一个流里，仍然按顺序；不同帧在不同的流里，可以重叠。理想情况下，复制引擎在上传第 $f+1$ 帧，SM 在处理第 $f$ 帧，另一个复制引擎在传回第 $f-1$ 帧的结果，三个硬件同时忙碌（图 6.1.1）。

设每帧上传、处理、传回各需 $t_h$、$t_k$、$t_d$，处理 $F$ 帧，串行的总时间是 $F(t_h + t_k + t_d)$；流水线灌满以后每 $\max(t_h, t_k, t_d)$ 出一帧，总时间约为

$$
T_{\text{流水线}} \approx (t_h + t_k + t_d) + (F - 1)\max(t_h, t_k, t_d) . \tag{6.1.1}
$$

$F$ 很大时，加速比趋于 $(t_h + t_k + t_d)/\max(t_h, t_k, t_d)$：三段一样长时是 3 倍；有一段特别长时，重叠帮不了多少，瓶颈就是这一段。

### 6.1.4 流使用中的几个要点

**异步就要注意同步。**`cudaMemcpyAsync` 返回时数据还没有复制，主机不能马上去改或读那块锁页内存。要等的时候用 `cudaStreamSynchronize`（等一个流）、`cudaDeviceSynchronize`（等全部），或者用事件（6.2 节）只等某一步。

**流之间的依赖用事件表达。**如果流 2 中的核函数要用流 1 算出的结果，在流 1 中记录一个事件，再让流 2 等这个事件：`cudaEventRecord(e, s1); cudaStreamWaitEvent(s2, e);`。这样只有这一处有先后，两个流的其他部分仍可重叠。

**重叠不是一定会发生。**几个核函数能否同时执行，取决于资源：一个核函数的线程块已经占满了所有 SM，另一个就只能等。所以“计算与计算的重叠”主要发生在小核函数之间；“计算与传输的重叠”则因为用的是不同的硬件，最容易得到。

**默认流的行为可以改。**编译时加 `--default-stream per-thread`，每个主机线程的默认流就成了普通的流，不再与其他流同步。多线程的程序（例如每个线程处理一台相机）常这样做。

本节的道理在深度学习框架里随处可见。PyTorch 的数据加载器把下一批数据放进锁页内存（`pin_memory=True`），再用 `tensor.to(device, non_blocking=True)` 异步上传，与当前这一批的计算重叠；多 GPU 训练时，梯度的通信（6.4 节）在单独的流里与反向传播重叠。
