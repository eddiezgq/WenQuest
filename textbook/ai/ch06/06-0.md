title: 本章提要
---

第 4、5 章关心的是单个核函数在单块 GPU 上跑得多快。真实的程序是一串操作，常常还要用到好几块 GPU：数据要在主机与 GPU 之间来回，核函数一个接一个地启动，多块 GPU 之间要交换数据。本章把视野放大到整个程序：怎样让传输与计算重叠、怎样减少启动开销、怎样在多块 GPU 之间高效地通信，以及怎样用工具找出程序真正的瓶颈。

本章有三个贯穿的问题。前两节是检测工位的整条处理流水线：每帧图像的上传、处理、传回怎样重叠，一连串小核函数的启动开销怎样减少。中间两节是数据并行训练：多块 GPU 之间怎样交换梯度。后三节用 Nsight 工具回头检验第 5 章矩阵乘法的分析，并总结调优的方法。

本章的内容安排如下：

- 6.1 节讲 CUDA 流与异步执行，用三个流让传输与计算重叠；
- 6.2 节讲事件与计时，核函数的启动开销，以及用 CUDA 图减少它；
- 6.3 节讲多 GPU 编程：点对点访问、统一虚拟地址，PCIe、NVLink 与 NVSwitch；
- 6.4 节讲集合通信：α–β 模型，朴素、环形、树形全归约，NCCL，通信与计算的重叠；
- 6.5 节讲 Nsight Systems 与 Nsight Compute，并用它们检验第 5 章的判断；
- 6.6 节讲分层屋顶线，把第 5 章的矩阵乘法画上去；
- 6.7 节总结调优的方法与常见的瓶颈。

本章的 CUDA 程序与前两章一样在云端 GPU 上实测，还没有实测的数字显示为“〔待实测〕”。多 GPU 的程序在一台 8 块 A100 的机器上测，Nsight Compute 的测量在能读性能计数器的虚拟机上做。本章有两个云端 GPU 实验（6.1 节流的重叠、6.5 节读 Nsight Compute 报告）和一个浏览器实验（6.4 节集合通信的代价）：学生的 GPU 实验都只用一块 GPU，多块 GPU 之间的通信用浏览器实验的模型来亲手试。

学完本章，读者应能：

1. 用流、锁页内存与异步复制让传输与计算重叠，用式 (6.1.1) 估计收益；
2. 用事件正确地计时与同步，判断启动开销何时成为瓶颈，用 CUDA 图减少它；
3. 在一个程序中使用多块 GPU，打开点对点访问，读懂 `nvidia-smi topo -m` 给出的拓扑；
4. 用 α–β 模型分析集合通信的耗时，说明环形全归约为什么带宽最优，用 NCCL 实现全归约并衡量总线带宽；
5. 用 Nsight Systems 找出时间花在哪里，用 Nsight Compute 分析一个核函数的瓶颈；
6. 画出分层屋顶线，判断瓶颈在哪一层存储；
7. 按“测量—判断—改进—再测量”的循环调优，并保证结果正确、测量可复现。
