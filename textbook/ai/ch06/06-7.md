### 6.7.1 先看全局

第 4—6 章介绍了许多优化手段。实际工作中最常见的错误，不是不会用这些手段，而是用错了地方：花一周把一个核函数加快一倍，结果整个程序只快了 3%。3.2 节的阿姆达尔定律早就说过：只优化占时间一小部分的地方，总的收益有限。所以调优的第一步永远是测出时间花在哪里。

**算例 6.7.1** 检测工位每帧的全部 GPU 工作（按理论带宽估计，程序 6.7.1）：上传彩色图像 {{ex6_7.h2d_us:.0f}} μs；灰度化 {{ex6_7.gray_us:.0f}} μs，平滑 {{ex6_7.smooth_us:.0f}} μs，直方图 {{ex6_7.hist_us:.0f}} μs，暗像素的流压缩 {{ex6_7.compact_us:.0f}} μs，启动开销约 {{ex6_7.launch_us:.0f}} μs；传回暗像素坐标 {{ex6_7.d2h_us:.1f}} μs。合计约 {{ex6_7.total_us:.0f}} μs，其中上传占 {{ex6_7.h2d_frac:.0f}}%。

由此可以得出三个结论：

1. 每帧的预算是 {{ex6_7.budget_ms:.1f}} ms，远远够用。如果上传与计算重叠（6.1 节），每帧的间隔由最长的上传决定，一块 A10 能同时处理约 {{ex6_7.cams:.0f}} 台相机。
2. 把所有核函数再加快 10 倍，串行时每帧也只从 {{ex6_7.total_us:.0f}} μs 降到 {{ex6_7.faster_us:.0f}} μs，只省 {{ex6_7.gain:.0f}}%。在这里优化核函数几乎没有意义。
3. 真正值得做的是减少上传的数据：让相机直接输出灰度图（数据量减到三分之一），或者传压缩的图像、在 GPU 上解码（nvJPEG）。

### 6.7.2 调优的循环

调优是一个循环：

1. **测量**：用 Nsight Systems 看整体，找出占时间最多的部分（6.5 节）；GPU 有没有闲着、传输有没有重叠、启动开销大不大。
2. **判断瓶颈的类型**：对占时间最多的核函数，用计算强度和屋顶线（3.8、6.6 节）估计它的上限，用 Nsight Compute 看速度之光：受带宽限制、受算力限制，还是受延迟限制。
3. **对症下药**：按表 6.7.1 选择手段，一次只改一处。
4. **再测量**：确认变快了，并确认结果仍然正确（与可信的参照比较，4.4 节）；然后回到第 1 步——瓶颈常常换了地方。

什么时候停？当一个部分已经接近它的屋顶线上限（比如八成以上），或者它在总时间中的占比已经很小，就该转向别处，或者停手。

| 看到的现象 | 可能的原因 | 对策 |

| 时间线上核函数之间有空隙 | 启动开销、频繁同步、主机准备数据慢 | CUDA 图、融合（6.2、5.1）；去掉不必要的同步；数据加载并行化 |

| 速度之光：计算高 | 受算力限制 | 张量核心、更低的精度（5.10、第 8 章）；更好的算法（5.5） |
| 两者都低 | 受延迟限制：线程束不够或都在等 | 提高占用率或指令级并行（3.7、5.9）；增大并行度 |
| 停顿：long scoreboard 多 | 等显存的数据 | 预取、双缓冲（5.9）；提高复用 |
| 停顿：MIO throttle 多 | 共享内存的指令太多 | 寄存器分块、向量化读（5.9） |
| 存储体冲突多 | 共享内存的访问模式 | 填充或错位布局（4.7） |
| 停顿：barrier 多 | 同步太频繁，或线程束之间负载不均 | 减少同步，平衡工作（5.6） |
| SIMT 效率低 | 线程束分化 | 让分支在线程束内一致（3.6、5.2） |
| 原子操作慢 | 同一地址的争用 | 私有化、线程束内合并（4.8、5.4） |
| 最后一波线程块很少 | 波次量化 | 改块的大小、拆分工作（5.11） |
| 多 GPU 时 GPU 在等通信 | 通信没有与计算重叠，或互联太慢 | 分桶重叠（6.4）；让通信多的部分走 NVLink（6.3） |

### 6.7.4 正确性与可复现

最后两条纪律，与速度同样重要。

**每次改动都要核对结果。**优化最容易引入的是隐蔽的错误：少了一次同步、越界读了一点、改变了浮点加法的顺序。第 5 章的做法值得照搬：选择能精确比较的测试数据，与可信的参照逐个比较；用 compute-sanitizer 查竞争与越界（4.4 节）。

**测量要可复现。**写下 GPU 型号、驱动与 CUDA 版本、频率（数据中心的卡在功耗或温度超限时会降频）、输入的大小；预热后多次测量取中位数。本书每个实测数字都在实测记录中附有这些信息，就是为了让读者能复核。同一块 GPU 上两次测量相差几个百分点很常见，小于这个幅度的“改进”不能当真。

---

**工程师笔记**

- 先测量，后优化；先全局，后局部。
- 用模型（计算强度、屋顶线、α–β）写下预期，再用工具去对；对不上的地方最有价值。
- 一次只改一处，改完核对结果、记录数字。
- 停在“够快”的地方：接近上限、或占比已小，就去优化别处。
