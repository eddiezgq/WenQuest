### 5.8.1 分块

$C$ 的一个 $T\times T$ 的块，只用到 $A$ 中对应的 $T$ 行和 $B$ 中对应的 $T$ 列。把这 $T$ 行、$T$ 列沿 $K$ 方向切成一段段 $T\times T$ 的块，$C$ 的这一块就是

$$
C_{IJ} = \sum_{L} A_{IL}\,B_{LJ} , \tag{5.8.1}
$$

其中 $I, J, L$ 是块的编号。分块矩阵乘法的公式与普通矩阵乘法的公式形式相同，只是元素换成了块。

GPU 上的做法是：一个线程块负责 $C$ 的一个 $T\times T$ 块，$T\times T$ 个线程各算一个元素。沿 $K$ 方向一步步走，每一步：

1. 全体线程合作，把 $A_{IL}$ 和 $B_{LJ}$ 两块从显存读进共享内存，每个线程各读一个数；
2. 同步；
3. 每个线程从共享内存读 $A_{IL}$ 的一行、$B_{LJ}$ 的一列，做 $T$ 次乘加，累加到自己的寄存器里；
4. 再同步，然后进入下一步。

每个数从显存读进共享内存以后，被块内 $T$ 个线程使用，显存的读取量降为朴素版的 $1/T$。

**算例 5.8.1** 用 GPU 执行模拟器部分 ⑤ 统计 $n = {{ex5_8.n}}$ 时的显存读取量（不计缓存）：不分块（$T = 1$）{{ex5_8.GB_1:.0f}} GB；$T = 8$、16、32、64 时分别为 {{ex5_8.GB_8:.1f}}、{{ex5_8.GB_16:.1f}}、{{ex5_8.GB_32:.1f}}、{{ex5_8.GB_64:.1f}} GB。计算强度相应地从 {{ex5_8.I_1:.2f}} 升到 {{ex5_8.I_8:.1f}}、{{ex5_8.I_16:.1f}}、{{ex5_8.I_32:.1f}}、{{ex5_8.I_64:.1f}} FLOP/B，约为 $T/4$（图 5.8.1(b)）。

$T$ 不能无限增大：$T\times T$ 个线程算一个块，$T = 32$ 就是 {{ex5_8.threads}} 个线程，已经到了一个线程块的上限；两块共享内存 {{ex5_8.smem_KB:.0f}} KB。

```cpp
for (int k0 = 0; k0 < K; k0 += T) {
    As[ty][tx] = A[row * K + k0 + tx];          // 读合并：相邻线程读同一行中相邻的数
    Bs[ty][tx] = B[(k0 + ty) * N + col];
    __syncthreads();
    for (int k = 0; k < T; k++) s += As[ty][k] * Bs[k][tx];
    __syncthreads();                             // 下一步覆盖共享内存之前，大家都要算完
}
```

两次同步缺一不可。第一次保证块已经全部读进来；第二次保证所有线程都用完了这一块，才允许下一步覆盖它。少了第二次，快的线程会在慢的线程还没算完时就把下一块写进共享内存，结果时对时错，这种错误最难查（4.4 节的 compute-sanitizer 的 racecheck 能发现）。

内层循环读共享内存时没有存储体冲突：一个线程束是 `ty` 相同、`tx` 为 0—31 的 32 个线程，`As[ty][k]` 是同一个字（广播），`Bs[k][tx]` 是连续的 32 个字。

### 5.8.2 新的瓶颈：共享内存

实测：{{run5_7._gpu}} 上共享内存分块版 {{run5_7.tiled_GFs:.0f}} GFLOP/s。按下面的分析，显存已经不再是主要瓶颈，瓶颈换成了共享内存。

**算例 5.8.2** 内层循环每做一次乘加，每个线程要从共享内存读两个数（模拟器部分 ⑤ 给出每次乘加读 {{ex5_8.smem_t32:.0f}} 次共享内存）。一个 SM 每周期能做 {{ex5_8.lanes}} 次单精度乘加，即 4 条线程束的乘加指令；而共享内存有 32 个存储体，每周期只能完成一次线程束的 32 位访问（32 个线程各读一个字，无冲突时）。也就是说，**每个线程每次乘加最多只能读 {{ex5_8.budget:.2f}} 次共享内存**，否则运算单元就要等共享内存。注意广播并不省这一次：`As[ty][k]` 虽然 32 个线程读的是同一个字，仍占共享内存一个周期。分块版每次乘加读 {{ex5_8.reads:.0f}} 次，于是最多只能达到峰值的 {{ex5_8.bound_pct:.1f}}%，即 A10 上约 {{ex5_8.bound_GF:.0f}} GFLOP/s。（编译器有时会把 `As[ty][k]` 到 `As[ty][k+3]` 合成一条 128 位的读，$A$ 每 4 步只读一次，上限升到约 {{ex5_8.bound_vec_pct:.0f}}%。生成的是哪种指令，可以用 `cuobjdump -sass` 查看。）

指令也是问题。内层循环每做一条乘加指令，要配两条读共享内存的指令，还有地址计算；每个调度器每周期只能发一条指令（3.5 节）。A10 这一代（GA10x）每个处理块的 32 条单精度通道中有 16 条与整数运算共用，要达到每周期 128 次乘加，调度器必须每个周期都发出乘加指令，任何一条读共享内存或整数地址运算都直接占掉一次发射机会。

两方面指向同一个结论：每从共享内存读一个数，必须多用几次。下一节把这个思路再往下推一层：从共享内存读到寄存器里，在寄存器中复用。

**工程师笔记**

- 分块的大小由共享内存、线程块的线程数上限和寄存器共同决定；32×32 是最直观的起点，不是终点。
- 共享内存分块的循环里有两次 `__syncthreads()`，第二次常被遗漏。
- 衡量共享内存是否成为瓶颈：每次乘加读几个字，与“每周期 32 个字 ÷ 每周期乘加次数”比较。
