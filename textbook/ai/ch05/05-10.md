### 5.10.1 张量核心

前三节的优化都在争取让单精度乘加单元一直忙着，可它们的峰值本身就有限。3.4 节讲过，从 Volta（2017）开始，NVIDIA 的 GPU 里有专门做小矩阵乘加的**张量核心**：一条指令完成一个小矩阵块（如 16×8×16）的 $D = AB + C$，输入用半精度（或 BF16、TF32、FP8 等），累加用单精度。

**算例 5.10.1** A10 的单精度峰值 {{ex5_10.fp32_TF:.1f}} TFLOP/s；用张量核心时，TF32 输入 {{ex5_10.tf32_TF:.1f}} TFLOP/s，半精度输入 {{ex5_10.fp16_TF:.0f}} TFLOP/s，是单精度的 {{ex5_10.x16:.0f}} 倍（都按稠密计）。从编程的角度看，一次 16×16×16 的矩阵乘加调用（下面的 `mma_sync`；在 A10 上编译成两条 16×8×16 的张量核心指令）让一个线程束完成 {{ex5_10.ratio:.0f}} 条单精度乘加指令的工作量。指令的发射、寄存器的读写都按“块”来做，控制开销被摊薄了，这是张量核心快的根本原因。

### 5.10.2 WMMA 接口

CUDA C++ 用 WMMA（warp matrix multiply-accumulate）接口使用张量核心，定义在 `<mma.h>` 中，名字空间 `nvcuda::wmma`。它的基本单位是**片段**：一个线程束合作持有的一个小矩阵，片段中的元素分散在 32 个线程的寄存器里，具体怎样分布不公开，程序只能整体地读、写、运算：

```cpp
using namespace nvcuda;
wmma::fragment<wmma::matrix_a, 16, 16, 16, half, wmma::row_major> fa;   // A 的 16×16 片段，半精度
wmma::fragment<wmma::matrix_b, 16, 16, 16, half, wmma::row_major> fb;
wmma::fragment<wmma::accumulator, 16, 16, 16, float> fc;              // 累加片段，单精度
wmma::fill_fragment(fc, 0.0f);
wmma::load_matrix_sync(fa, ptr_a, lda);       // 整个线程束一起从内存读一个 16×16 块；lda 是相邻两行起点相隔的元素数（含填充）
wmma::load_matrix_sync(fb, ptr_b, ldb);
wmma::mma_sync(fc, fa, fb, fc);               // fc = fa × fb + fc
wmma::store_matrix_sync(ptr_c, fc, ldc, wmma::mem_row_major);
```

这些函数名都带 `_sync`：线程束的 32 个线程必须一起调用（与 5.2 节的洗牌指令一样）。`load_matrix_sync` 的地址要 32 字节对齐，`lda` 对半精度要是 8 的倍数。

程序 5.7.1 中的 `wmma_gemm` 把 5.8、5.9 节的分块原样搬过来，只是最内层换成了张量核心（图 5.10.1）：线程块负责 $C$ 的 128×128 块，沿 $K$ 每步 32；8 个线程束排成 4×2，每个线程束负责 32×64，即 2×4 个 16×16 的累加片段——这相当于“线程束级的寄存器分块”，每读一个 $A$ 片段用 4 次，每读一个 $B$ 片段用 2 次。共享内存中每行多留 8 个半精度数（16 字节）作填充，减少 `load_matrix_sync` 的存储体冲突，共 {{ex5_10.smem_KB:.1f}} KB。

**算例 5.10.2** 换上张量核心以后，屋脊也右移了：A10 半精度张量核心的屋脊是 {{ex5_10.ridge16:.0f}} FLOP/B，而 `wmma_gemm` 的计算强度（不计缓存，$A$、$B$ 半精度，$C$ 单精度）只有 {{ex5_10.I_w:.0f}} FLOP/B；线程块改成 256×128 也只到 {{ex5_10.I_w256:.0f}}。运算快了四倍，对数据供给的要求也高了四倍。好在 L2 缓存承担了相当一部分复用：同时运行的一百多个线程块读的是 $A$ 的相邻几个行块、$B$ 的相邻几个列块，它们在 L2 中反复命中，实际的显存流量远小于不计缓存的估计。高性能的库还会刻意安排线程块的执行顺序（按小方块而不是按整行遍历 $C$），提高 L2 的命中率。

### 5.10.3 精度

张量核心的输入精度低，结果会不会不准？

**算例 5.10.3** $256\times{{ex5_10.k}}$ 与 ${{ex5_10.k}}\times256$ 的标准正态随机矩阵相乘，以双精度的结果为准，相对误差（按矩阵的范数）：单精度 {{ex5_10.e32:.1e}}；半精度输入、单精度累加 {{ex5_10.e16:.1e}}；TF32 输入、单精度累加 {{ex5_10.etf:.1e}}。半精度与 TF32 的尾数都是 10 位，输入舍入的相对误差约 $2^{-11}$，所以两者的误差几乎相同；单精度累加使误差不随 $K$ 的增大而迅速增长。万分之几的误差对神经网络的训练和推理通常无关紧要，这正是混合精度训练（第 8 章）的依据。但要注意：半精度能表示的最大数只有 65 504，范围远小于单精度；TF32 与 BF16 的指数位与单精度相同，没有这个问题。

### 5.10.4 从 WMMA 到 MMA、WGMMA 与 tcgen05

WMMA 是最高层的接口，方便但不够灵活：片段在寄存器中的分布不公开，就没法在寄存器里对它做别的处理，也没法精细地安排数据流动。更底层的接口按 GPU 的代际逐步演进：

- **`mma.sync`**（PTX 指令，计算能力 8.0 起常用的形状是 m16n8k16）：同样是一个线程束执行，但规定了每个线程持有片段的哪些元素，程序可以直接在寄存器上操作。CUTLASS 2.x 和许多手写的高性能核函数用它。
- **`wgmma`**（Hopper，计算能力 9.0，编译目标须为 sm_90a）：由一个“线程束组”（4 个线程束，128 个线程）一起执行，操作数可以直接取自共享内存，并且是异步的——发出以后线程可以去做别的事，与 TMA 的异步复制配合，组成深度流水线。
- **`tcgen05`**（数据中心的 Blackwell，计算能力 10.0 等，编译目标为 sm_100a 一类；消费级的 Blackwell 没有）：累加器放在专门的**张量内存**中，而不再占用寄存器；由单个线程发出，一对 SM 可以合作计算一个更大的块。

每一代的指令都不兼容地变化，这是手写张量核心程序的最大困难。CUTLASS（C++ 模板库，其中的 CuTe 描述数据布局）以及 CUTLASS 4 起提供的 Python 接口 CuTe DSL 把这些差异封装起来；Triton（第 8 章）则让程序员只描述块级的计算，由编译器生成对应 GPU 的张量核心指令（截至 2026 年 10 月）。

**工程师笔记**

- 能用张量核心就用：深度学习中的矩阵乘法、卷积几乎都用半精度或 BF16 输入、单精度累加。
- WMMA 适合学习和简单的场合；追求性能用 cuBLAS、cuBLASLt、CUTLASS 或 Triton。
- 张量核心对维度有对齐要求：半精度时 $M$、$N$、$K$ 最好都是 8 的倍数（更好是 64 的倍数），否则库会退回慢的实现或补零。
- 半精度输入要注意范围（最大 65 504）；训练时用 BF16 或配合损失缩放（第 8 章）。
