### 5.7.1 问题的提出

2.10 节的统计说明，神经网络的运算量几乎全在矩阵乘法上：全连接层、注意力的投影、卷积（5.5 节）都是。cuBLAS 的矩阵乘法能达到峰值算力的七八成以上，而直接照定义写出的核函数往往只有峰值的百分之几。差距在哪里？本节和后面四节从朴素写法出发，一步一步找出瓶颈、消除瓶颈，最后与 cuBLAS 比较。每一步都在云端 GPU 上实测（程序 5.7.1），把速度画到屋顶线上（GPU 实验 5.11）。

统一的测试问题是 $C = AB$，三个矩阵都是 $n\times n$ 的单精度矩阵、行主序存放，$n = {{ex5_7.n}}$。

**算例 5.7.1** 运算量 $2n^3 = {{ex5_7.GFLOP:.0f}}$ GFLOP。A10 的单精度峰值 {{ex5_7.peak_TF:.1f}} TFLOP/s，耗时至少 {{ex5_7.t_min_ms:.1f}} ms。如果每个矩阵只从显存读写一次，总共只搬运 {{ex5_7.min_MB:.0f}} MB，计算强度高达 {{ex5_7.I_best:.0f}} FLOP/B，远在屋脊（{{ex5_7.ridge:.0f}} FLOP/B）右边。所以矩阵乘法原则上完全受算力限制：数据搬运不是问题，问题在于能不能让运算单元一直忙着。

### 5.7.2 朴素实现

一个线程算 $C$ 的一个元素：读 $A$ 的第 row 行、$B$ 的第 col 列，做 $n$ 次乘加。

```cpp
__global__ void naive(int M, int N, int K, const float* A, const float* B, float* C) {
    int row = blockIdx.y * blockDim.y + threadIdx.y, col = blockIdx.x * blockDim.x + threadIdx.x;
    float s = 0.0f;
    for (int k = 0; k < K; k++) s += A[row * K + k] * B[k * N + col];
    C[row * N + col] = s;
}
```

（$n$ 是 128 的倍数，这里省去了越界检查。）每个线程读 $2n$ 个数、做 $n$ 次乘加，两次读做一次乘加。如果这些读都去显存，

**算例 5.7.2** 朴素版要从显存读 {{ex5_7.naive_GB:.0f}} GB，计算强度只有 {{ex5_7.I_naive:.2f}} FLOP/B——与算例 5.7.1 的 {{ex5_7.I_best:.0f}} 差了两千多倍。按显存带宽算要 {{ex5_7.t_naive_ms:.0f}} ms，只能达到 {{ex5_7.gf_naive_bound:.0f}} GFLOP/s，不到峰值的 1%。

同一个数被读了 $n$ 次：$A$ 的第 row 行被 $C$ 第 row 行的 $n$ 个线程各读一遍，$B$ 的第 col 列同样。实际上 GPU 的 L1、L2 缓存会兜住其中一部分重复读取，实测会比这个估计快，但缓存的行为难以控制。后面几节的全部工作，就是有计划地让数据在芯片上被反复使用。

### 5.7.3 线程映射与合并访问

朴素版还有一个容易忽略的细节：`threadIdx.x` 对应 $C$ 的列还是行？

**算例 5.7.3** 一个线程束的 32 个线程 `threadIdx.x` 相邻。若 x 对应列（上面的写法），这 32 个线程在 $C$ 的同一行、相邻 32 列：第 $k$ 步它们读 $A$ 的同一个数（广播），读 $B$ 第 $k$ 行中相邻的 32 个数（合并），由 GPU 执行模拟器部分 ③，一共 {{ex5_7.good}} 个扇区。若 x 对应行，32 个线程在同一列、相邻 32 行：读 $A$ 时相邻线程相隔一整行（{{ex5_7.row_KB:.0f}} KB），读 $B$ 是同一个数，一共 {{ex5_7.bad}} 个扇区（图 5.7.1）。

### 5.7.4 测试数据与结果核对

程序 5.7.1 的测试矩阵取 −2 到 2 的随机整数。这样每个乘积、每个部分和都是绝对值不超过 $4n = 16\,384$ 的整数，单精度能精确表示（$2^{24}$ 以内的整数都能），所以不论按什么顺序相加、是否用张量核心，各版本的结果都应与 cuBLAS 逐位相同。程序先用 CPU 抽样 4096 个元素核对 cuBLAS，再要求每个版本与 cuBLAS 完全一致——比“误差小于某个容限”的检查严格得多，任何下标错误都逃不过去。这是测试数值程序的一个实用技巧：选择让舍入误差消失的数据，就能做精确的比较。

性能测试则不受这个选择影响：乘加单元处理整数值的浮点数与处理一般的浮点数一样快。

**工程师笔记**

- 矩阵乘法原则上受算力限制；朴素实现的瓶颈在于数据没有在芯片上复用。
- 线程映射要使一个线程束读连续的地址：行主序时 `threadIdx.x` 对应列。
- 核对矩阵乘法时选小整数作数据，可以要求结果逐位相同；性能测试与数据无关。
- 计时用 2MNK 计算 FLOP/s，并注明精度（单精度、TF32、半精度）。
