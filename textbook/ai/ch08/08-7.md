### 8.7.2 融合的注意力 softmax

softmax 对每一行独立计算，于是让每个程序实例处理一行（程序 8.7.2）：

```python
@triton.jit
def attn_softmax_kernel(s_ptr, p_ptr, stride, n, T, scale, BLOCK: tl.constexpr):
    row = tl.program_id(0)
    pos = row % T                                    # 这一行是第几个位置
    cols = tl.arange(0, BLOCK)
    keep = (cols < n) & (cols <= pos)                # 因果掩码：只看自己和之前的位置
    x = tl.load(s_ptr + row * stride + cols, mask=cols < n, other=0.0).to(tl.float32) * scale
    x = tl.where(keep, x, -float("inf"))
    x = x - tl.max(x, axis=0)                        # 减去最大值，防止 exp 溢出（2.2.5 节）
    e = tl.exp(x)
    tl.store(p_ptr + row * stride + cols, e / tl.sum(e, axis=0), mask=cols < n)
```

整行一次读进寄存器（`BLOCK` 取不小于行长的 2 的幂），缩放、掩码、求最大值、求指数、求和、相除都在寄存器里完成，最后写一次。被掩掉的位置当作 $-\infty$，取指数后为 0，正好不参与求和。每一行的最大值与和是行内的归约，由编译器用线程束洗牌与共享内存完成（8.6.3 节）。

### 8.7.5 行太长时

一个程序实例把整行放进寄存器，行长到几千、几万时就放不下了。办法是把一行分成几段，循环处理：先扫一遍求最大值，再扫一遍求和，第三遍写出——读三遍。更好的办法是“在线 softmax”（米拉科夫与吉梅尔斯坦，2018）：只扫一遍，边读边维护到目前为止的最大值 $m$ 与和 $\ell$；遇到更大的值 $m'$ 时，把已有的和乘以 $e^{m - m'}$ 修正：

$$
m' = \max(m, x_j),\qquad \ell' = \ell\, e^{m - m'} + e^{x_j - m'} . \tag{8.7.1}
$$

在线 softmax 把 softmax 变成了可以分段、可以合并的计算。第 9 章的 FlashAttention 就建立在它上面：把 $QK^{\mathsf T}$、softmax、乘 $V$ 三步融合成一个核函数，分数矩阵 $S$ 根本不写进显存。
