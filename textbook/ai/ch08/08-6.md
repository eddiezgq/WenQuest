### 8.6.1 问题的提出

第 7 章留下一个问题：那些受带宽限制的小运算，最好融合成一个核函数，可为每种组合手写 CUDA 太费事（7.7 节写一个“加偏置 + GELU”就要两个核函数、一个 C++ 包装）。`torch.compile` 自动融合时生成的是 Triton 程序（7.8.4 节）。Triton 是蒂莱（P. Tillet）等人 2019 年提出的一种用 Python 写 GPU 核函数的语言和编译器，2021 年 OpenAI 发布了 1.0 版。它的出发点是：程序员只管“一块数据怎样算”，块内的线程怎样分工交给编译器。

### 8.6.2 程序实例与块

先看第 4 章的向量加法在 Triton 中怎样写（程序 8.6.1）：

```python
@triton.jit
def add_kernel(x_ptr, y_ptr, z_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(0)                       # 第几个程序实例
    offs = pid * BLOCK + tl.arange(0, BLOCK)     # 这个实例负责的 BLOCK 个下标：一个向量
    mask = offs < n                              # 最后一块可能不满
    x = tl.load(x_ptr + offs, mask=mask)
    y = tl.load(y_ptr + offs, mask=mask)
    tl.store(z_ptr + offs, x + y, mask=mask)

add_kernel[(triton.cdiv(n, 1024),)](x, y, z, n, BLOCK=1024)   # 网格：几个程序实例
```

与 CUDA 对照（图 8.6.1）：CUDA 的核函数描述一个线程做什么，下标 `i` 是一个数；Triton 的核函数描述一个**程序实例**做什么，下标 `offs` 是一个长 `BLOCK` 的向量，`tl.load` 一次读进一整块，`x + y` 是整块的逐元素相加。网格由程序实例组成，`tl.program_id` 相当于 `blockIdx`。越界的处理不用 `if`，而用掩码：`mask` 为假的位置不读不写（读时可以指定一个填充值）。`BLOCK` 标为 `tl.constexpr`，是编译时的常数，每个不同的取值编译出一个核函数。

### 8.6.3 编译器做了什么

程序实例里的一块数据，最终还是要分给线程。Triton 的编译器（`num_warps` 指定一个实例用几个线程束）替程序员做了第 4、5 章中那些手工的事：

- 把块中的元素分给各线程，使相邻线程读相邻的地址（合并访问，4.6 节），能用 128 位读写时自动向量化；
- 块与块之间做矩阵乘法（`tl.dot`）时，把数据放进共享内存、安排成避免存储体冲突的布局，用张量核心指令计算（5.8—5.10 节）；
- 沿循环把下一步的读提前发出，与计算重叠（软件流水线，`num_stages` 控制级数，相当于 5.9 节的双缓冲）；
- 归约（`tl.max`、`tl.sum`）在线程束内用洗牌、线程束之间用共享内存完成（5.2 节）。

编译流程是：Python 函数的语法树 → Triton IR → 带有“数据在线程间怎样分布”信息的 TritonGPU IR → LLVM IR → PTX → 机器码。核函数第一次以某组参数类型和常数调用时编译，结果缓存在磁盘上。

块的大小、线程束数、流水线级数怎样选最快，与形状和 GPU 有关。**自动调优**：`@triton.autotune` 可以给出几组候选，第一次调用时逐个实测，记住最快的：

```python
@triton.autotune(configs=[triton.Config({"BLOCK": b}, num_warps=w) for b in (512, 1024, 2048) for w in (4, 8)],
                 key=["n"])                      # n 变了就重新挑选
@triton.jit
def add_kernel(x_ptr, y_ptr, z_ptr, n, BLOCK: tl.constexpr): ...
```

Triton 还有一个解释模式：设环境变量 `TRITON_INTERPRET=1`，核函数在 CPU 上逐个程序实例地解释执行，可以设断点、打印中间结果。本书的 Triton 核函数在开发时都先这样与 PyTorch 的结果核对，再到 GPU 上实测。

### 8.6.4 实测

程序 8.6.1 的向量加法在 A10 上（{{run8_7._gpu}}）对 $2^{26}$ 个单精度数用了 {{run8_7.add_triton_us:.0f}} μs，达到 {{run8_7.add_triton_GBs:.0f}} GB/s；PyTorch 的加法 {{run8_7.add_torch_us:.0f}} μs（{{run8_7.add_torch_GBs:.0f}} GB/s）。若两者接近，就说明十来行 Python 写出了与框架自带的核函数同一水平的程序。

Triton 的抽象也有代价：块内的分工由编译器决定，程序员看不到、也难以控制线程级的细节（例如哪个线程读哪个存储体）；一些需要精细控制的核函数（如 Hopper 上用线程束专门化、TMA 的矩阵乘法），仍要用 CUDA 或 CUTLASS 写。Triton 的目标是用 20% 的力气得到 80% 以上的性能，对融合类的核函数通常做得到。

**工程师笔记**

- 写 Triton 核函数，先想清楚“一个程序实例处理哪一块”，再写块内的向量运算；越界一律用掩码。
- 块大小取 2 的幂；先用解释模式核对结果，再上 GPU 计时。
- 形状多变时用 `@triton.autotune`，`key` 里写上影响最优配置的维度。
- 想看 `torch.compile` 生成的 Triton 代码，用 `TORCH_LOGS="output_code"`（7.8.6 节），这是学习写法的好材料。
