### 7.2.1 问题的提出

小型 Transformer 一层里有 6 个矩阵乘法：QKV 投影、注意力分数、加权求和、输出投影、前馈网络两层。它们形状各异，有的是一个大矩阵乘法，有的是 192 个小矩阵乘法（每个样本每个头一个），有的后面紧跟着加偏置和 GELU。cuBLAS 怎样调用，才能既算得对、又不在启动和显存往返上白白浪费时间？

### 7.2.2 句柄、流与列主序

使用 cuBLAS 先创建一个**句柄**（`cublasHandle_t`），它保存库的内部状态和工作区；之后每次调用都带上它。用 `cublasSetStream` 把句柄绑定到一个流（6.1 节），库发出的核函数就进入这个流，与其他操作按流的规则排序和重叠。多个主机线程各用各的句柄。

cuBLAS 的接口沿袭了 Fortran 的 BLAS（1979 年的第 1 级向量运算，1990 年的第 3 级加入矩阵乘法）：矩阵按**列主序**存放（2.3.3 节），第 $(i, j)$ 个元素在 `A[i + j*lda]`，`lda` 是相邻两列之间隔多少个元素。而 C/C++、NumPy、PyTorch 默认按行主序存放。这不需要搬数据来解决：一块按行主序存放的 $M\times K$ 矩阵，按列主序读出来正好是它的转置 $K\times M$（图 7.2.1(a)）。所以要算行主序的 $C = AB$，只需请 cuBLAS 算

$$
C^{\mathsf T} = B^{\mathsf T} A^{\mathsf T} , \tag{7.2.1}
$$

即把 $B$ 当作第一个矩阵、$A$ 当作第二个，$M$ 与 $N$ 对调，算出来的“列主序的 $C^{\mathsf T}$”在内存里就是行主序的 $C$：

```cpp
// 行主序：C（M×N）= A（M×K）· B（K×N）
cublasSgemm(h, CUBLAS_OP_N, CUBLAS_OP_N, N, M, K, &alpha, B, N, A, K, &beta, C, N);
```

### 7.2.3 数据类型与数学模式

`cublasSgemm` 只做单精度。更通用的接口是 `cublasGemmEx`：分别指定 $A$、$B$、$C$ 的数据类型（单精度、半精度、BF16、INT8……）和**计算类型**（累加用什么精度）。例如半精度输入、单精度累加，就能用上张量核心。单精度输入也可以选择用 TF32 张量核心：计算类型设为 `CUBLAS_COMPUTE_32F_FAST_TF32`，或把句柄的数学模式设为 `CUBLAS_TF32_TENSOR_OP_MATH`。第 5 章的实测（表 5.11.1，{{run5_7._gpu}}）中，同一个 4096×4096 的矩阵乘法，cuBLAS 单精度 {{run5_7.cublas_GFs:.0f}} GFLOP/s，允许 TF32 时 {{run5_7.cublas_tf32_GFs:.0f}} GFLOP/s，半精度 {{run5_7.cublas_h_GFs:.0f}} GFLOP/s。

TF32 只保留 10 位尾数，相对精度约千分之一，对深度学习的训练通常足够，但改变了单精度的数值结果。所以 PyTorch 对矩阵乘法默认不用 TF32（`torch.backends.cuda.matmul.allow_tf32 = False`，或 `torch.set_float32_matmul_precision("highest")`），对卷积却默认允许（`torch.backends.cudnn.allow_tf32 = True`）——这是历史原因造成的不一致，要用 TF32 时最好显式地设置。较新的 PyTorch 又提供了按后端分别设置的 `torch.backends.cuda.matmul.fp32_precision`（取 `"ieee"` 或 `"tf32"`），用意相同。

### 7.2.4 批量矩阵乘法

注意力分数 $QK^{\mathsf T}$ 是 $B\times h$ 个各自独立的矩阵乘法（2.3.5 节）。

**算例 7.2.1** 小型 Transformer 训练时 $B h = {{ex7_2.nb}}$，每个矩阵乘法是 256×64 乘 64×256，只有 {{ex7_2.MFLOP_one:.1f}} MFLOP，A10 按单精度峰值只要 {{ex7_2.t_one_us:.2f}} μs；按 128×128 的输出块，一个只有 {{ex7_2.blocks_one}} 个线程块，{{ex7_2.sm}} 个 SM 中只能用上 {{ex7_2.blocks_one}} 个。若逐个调用，{{ex7_2.nb}} 次启动光开销就要约 {{ex7_2.launches_us:.0f}} μs，而全部计算按峰值只要 {{ex7_2.total_us:.0f}} μs（图 7.2.1(b)）。

cuBLAS 为此提供批量矩阵乘法：一次调用、一次启动，算一批同样形状的矩阵乘法，各批的线程块一起铺满 GPU。`cublasSgemmBatched` 接受三个指针数组，每批的矩阵可以在任意位置；更常用的是**等步长批量矩阵乘法** `cublasSgemmStridedBatched`：各批的矩阵在内存中等距排列，只需给出第一批的地址和相邻两批之间的距离：

```cpp
// 每批：行主序 S = Q·Kᵀ（T×T）⇔ 列主序 Sᵀ = K·Qᵀ；K 的缓冲区按列主序是 Kᵀ，所以要转置（OP_T）
cublasSgemmStridedBatched(h, CUBLAS_OP_T, CUBLAS_OP_N, T, T, dh, &alpha,
                          K, dh, T * dh,     // 第一批的地址、lda、相邻两批相隔的元素数
                          Q, dh, T * dh, &beta, S, T, T * T, B * heads);
```

实测（程序 7.2.1，{{run7_2._gpu}}）：192 个矩阵乘法逐个调用共 {{run7_2.loop_us:.0f}} μs，一次等步长批量调用 {{run7_2.batched_us:.0f}} μs，快 {{run7_2.batch_speedup:.1f}} 倍；两种做法的结果逐位相同，并与主机核对过。

“等步长”是一个硬约束：每批之间的距离必须相同。PyTorch 中注意力的 $q$、$k$、$v$ 由形状 $(B, T, h, d_h)$ 转置成 $(B, h, T, d_h)$ 后只是一个视图（2.3.3 节），把前两维合成一维后批与批之间的距离不再相等，所以 `matmul` 要先把它复制成连续的再调用批量矩阵乘法——这就是算例 7.1.1 中“转置复制”的来历。

### 7.2.5 cuBLASLt 与尾处理

cuBLASLt（“Lt”是 lightweight）是 cuBLAS 中专为矩阵乘法设计的一套更灵活的接口。它把一次矩阵乘法拆成几个描述符：运算描述符（计算类型、是否转置、尾处理）、每个矩阵的布局描述符（数据类型、行列数、主维、批量），再用 `cublasLtMatmulAlgoGetHeuristic` 让库按形状挑出合适的算法（分块大小、流水线级数、是否沿 $K$ 方向拆分），最后调用 `cublasLtMatmul`。挑出的算法可以缓存起来，以后同样的形状直接用。

它最有用的功能是**尾处理**：矩阵乘法算完、结果写回显存之前，顺带对每个元素做一些运算——加偏置、ReLU、GELU，以及为反向保存激活函数的输入（`GELU_AUX`）等。这些运算在寄存器里完成，不再单独读写一遍显存。

**算例 7.2.2** 前馈网络第一层 $Y = \mathrm{GELU}(XW_1 + b)$，$X$ 为 8192×384，$W_1$ 为 384×1536（半精度）。矩阵乘法 {{ex7_2.GFLOP_ff1:.1f}} GFLOP，A10 按半精度张量核心峰值要 {{ex7_2.t_ff1_us:.0f}} μs，按带宽读写 $X$、$W_1$、$Y$ 要 {{ex7_2.t_gemm_io_us:.0f}} μs；$Y$ 有 {{ex7_2.y_MB:.0f}} MB，若另起一个核函数读出 $Y$、加偏置、过 GELU 再写回，按带宽要 {{ex7_2.t_epi_us:.0f}} μs——比矩阵乘法本身还长，是它的 {{ex7_2.epi_ratio:.1f}} 倍。

实测（程序 7.2.1）：带 `CUBLASLT_EPILOGUE_GELU_BIAS` 尾处理的矩阵乘法 {{run7_2.fused_us:.0f}} μs；不带尾处理的矩阵乘法 {{run7_2.plain_us:.0f}} μs（{{run7_2.plain_TFs:.0f}} TFLOP/s），加上单独的偏置加 GELU 核函数（{{run7_2.epi_us:.0f}} μs，{{run7_2.epi_GBs:.0f}} GB/s）共 {{run7_2.unfused_us:.0f}} μs。尾处理省下了 {{run7_2.epi_saving_pct:.0f}}% 的时间。两种做法结果的最大差为 {{run7_2.max_diff:.4f}}（结果的最大绝对值为 {{run7_2.max_y:.2f}}），来自 GELU 写法的细节和中间结果的舍入：融合时 GELU 作用在单精度的累加结果上，不融合时中间结果先舍入成半精度。

PyTorch 在满足条件时（例如偏置是一维、输入连续）把线性层的加偏置交给 cuBLASLt 的尾处理；把激活函数也并进去，则要靠 7.8 节的编译器或手工调用。

**工程师笔记**

- 行主序的 $C = AB$ 交给 cuBLAS 时写成 $C^{\mathsf T} = B^{\mathsf T}A^{\mathsf T}$：两个矩阵对调，$M$、$N$ 对调，一个数也不搬。
- 每个句柄用 `cublasSetStream` 绑定到自己的流；不要在多个线程之间共用一个句柄。
- 一批同样形状的小矩阵乘法用等步长批量接口，一次启动；形状不同的一批可以用分组批量接口（`cublasGemmGroupedBatchedEx`，CUDA 12.5 起）。
- 矩阵乘法后面紧跟的逐元素运算，先看能不能放进 cuBLASLt 的尾处理。
- TF32 是否打开会改变单精度的结果：做数值对比时把它固定下来。
