### 1.6.1 问题的提出

1.5 节说明了 GPU 的硬件为什么适合神经网络。但硬件只是一半。一块 GPU 有上万个运算单元，程序员怎样指挥它们？要让每个单元知道自己该算哪个数、到哪里取数据、算完写到哪里，还要让成千上万个单元在需要时互相配合。在 2006 年以前，这件事极其困难，GPU 只能画图。本节讲 GPU 怎样从图形处理器变成通用的计算平台，CUDA 的基本思想是什么，以及 CUDA 与深度学习怎样互相成就。

### 1.6.2 从图形流水线说起

GPU 最初是为三维图形设计的。把一个三维场景画到屏幕上，大致要经过两步：先对场景中成千上万个三角形的顶点做坐标变换和光照计算，再对屏幕上的每个像素计算它的颜色。一块 1920×1080 的屏幕有两百多万个像素，每秒刷新六十次，而且每个像素的计算与其他像素无关、步骤完全相同——这正是 1.5.3 节所说的数据并行。于是图形芯片的设计者从一开始就把芯片做成许多条并行的流水线，同时处理许多个顶点和像素。

1999 年，NVIDIA 推出 GeForce 256，把它称为**图形处理器**（graphics processing unit，GPU），这是这个名称的由来。最初的图形流水线是固定功能的：每一步做什么由硬件决定，程序员只能设置参数。2001 年前后，图形芯片开始支持可编程的着色器：程序员可以写一小段程序，规定每个顶点或每个像素怎样计算。可编程性打开了一扇门。

### 1.6.3 早期的 GPU 通用计算

研究者很快发现，着色器程序可以用来做图形以外的计算。办法相当别扭：把要处理的数据伪装成一张纹理图像，把要做的计算写成像素着色器，然后让 GPU“画”一个铺满屏幕的矩形；画出来的“像素颜色”就是计算结果。用这种办法，人们在 GPU 上实现了矩阵运算、流体模拟、图像处理，甚至神经网络：2004 年，奥（K.-S. Oh）和郑（K. Jung）报告用 GPU 实现多层感知机的前向计算，比 CPU 快了一个数量级以上。这类工作统称为**GPU 通用计算**（general-purpose computing on GPUs，GPGPU）。

但这条路门槛极高。程序员必须精通图形编程接口，把每个问题翻译成“纹理”和“像素”；不能随意读写内存的任意位置；调试几乎无从下手。2004 年，斯坦福大学巴克（I. Buck）等人发表了 Brook 语言，让程序员用类似 C 的“流”和“核函数”来写 GPU 程序，由编译器翻译成图形接口的调用。这是把 GPU 当作通用并行处理器来编程的重要一步。巴克随后加入 NVIDIA，主持了 CUDA 的开发。

### 1.6.4 CUDA 的诞生

2006 年 11 月，NVIDIA 发布了 GeForce 8800 GTX（G80 架构）和 CUDA。G80 第一次采用统一的处理器阵列：不再区分顶点处理器和像素处理器，所有运算单元都是同一种，既能执行图形着色器，也能执行一般的计算程序；它还加入了程序可以直接使用的片上共享内存，以及对显存任意地址的读写。2007 年 6 月，CUDA 1.0 正式发布，同时推出了专门用于计算、不带显示输出的 Tesla 产品。

**定义 1.6.1（CUDA）** **CUDA**（compute unified device architecture，统一计算设备架构）是 NVIDIA 的并行计算平台和编程模型。它在 C/C++ 语言上做少量扩展，让程序员把计算写成由大量线程并行执行的**核函数**，由 CPU（称为**主机**）启动，在 GPU（称为**设备**）上执行。

CUDA 的关键思想是：程序员只写一个线程要做的事，再告诉 GPU 启动多少个这样的线程。以把两个长度为 $n$ 的向量相加为例，CPU 上的写法是一个循环，依次计算 $c_i = a_i + b_i$；CUDA 的写法是去掉循环，让第 $i$ 个线程计算 $c_i$：

```cuda
__global__ void add(const float *a, const float *b, float *c, int n)
{
    int i = blockIdx.x * blockDim.x + threadIdx.x;   // 本线程负责的元素
    if (i < n)                                         // 多出来的线程什么也不做
        c[i] = a[i] + b[i];
}

// 主机上：每块 256 个线程，块数向上取整
int threads = 256;
int blocks  = (n + threads - 1) / threads;
add<<<blocks, threads>>>(d_a, d_b, d_c, n);
```

限定符 `__global__` 表示这是一个核函数：在设备上执行、由主机启动。线程按两级组织（图 1.6.1）：若干线程组成一个**线程块**，若干线程块组成一个**网格**。`<<<blocks, threads>>>` 规定了网格中线程块的个数和每块中线程的个数。每个线程从内置变量中读出自己的编号：`threadIdx.x` 是它在块内的编号，`blockIdx.x` 是它所在块的编号，`blockDim.x` 是每块的线程数。由此算出它负责的元素下标

$$
i = \texttt{blockIdx.x}\times\texttt{blockDim.x} + \texttt{threadIdx.x} . \tag{1.6.1}
$$

若每块有 $b$ 个线程，要覆盖全部 $n$ 个元素，需要的线程块数为

$$
g = \left\lceil \frac{n}{b} \right\rceil , \tag{1.6.2}
$$

$\lceil\cdot\rceil$ 表示向上取整，程序中写成 `(n + b - 1) / b`。当 $n$ 不是 $b$ 的整数倍时，最后一块中有些线程的 $i \ge n$，所以核函数里要有 `if (i < n)` 这一判断，否则会写到数组之外。

为什么要分成两级，而不是直接给每个线程一个全局编号？因为同一个线程块中的线程被放在同一个流多处理器上执行，它们可以通过片上的共享内存交换数据，可以互相等待（同步）；不同线程块之间则彼此独立，可以按任意顺序、在任意一个流多处理器上执行。这一设计让同一个程序既能在只有几个流多处理器的小 GPU 上运行，也能在有一百多个流多处理器的大 GPU 上自动地跑得更快。线程块内的协作是第 4、5 章优化矩阵乘法的关键。

CUDA 的成功，不仅在于这几个语言扩展，还在于它从一开始就配套提供了编译器、调试和性能分析工具，以及线性代数库 cuBLAS、快速傅里叶变换库 cuFFT 等高度优化的函数库，并且保证新一代 GPU 能运行为旧 GPU 编写的程序。此后近二十年，NVIDIA 持续扩充这个生态：数学库、深度学习库、通信库、编译器、性能分析工具，以及数以百万计的开发者和大量的教材、论文、开源代码。

### 1.6.5 GPU 的演进

CUDA 发布以后，NVIDIA 大约每两年推出一代新架构，其中几代与人工智能关系特别密切：2010 年的 Fermi 架构大幅提高了双精度性能，并加入纠错显存（ECC）和一、二级缓存，使 GPU 能用于科学计算；2016 年的 Pascal 架构支持半精度运算和 GPU 之间的高速互联 NVLink；2017 年的 Volta 架构首次加入张量核心，专门做小矩阵的乘加；2020 年的 Ampere 架构增加了 TF32 和 BF16 格式；2022 年的 Hopper 架构支持 8 位浮点（FP8），专为 Transformer 优化；2024 年发布的 Blackwell 架构进一步支持 4 位浮点（截至 2026 年 6 月）。各代的细节在第 3 章展开。图 1.6.2 比较了三块有代表性的 GPU：训练 AlexNet 用的 GTX 580、2020 年的 A100、训练 Llama 3 用的 H100。

### 1.6.6 CUDA 与深度学习的相互成就

CUDA 发布时，NVIDIA 设想的主要用户是科学计算：分子动力学、地震勘探、金融计算。深度学习是后来才出现的“杀手级应用”。

2009 年，拉伊纳、马达万和吴恩达用 GPU 训练深度信念网络，报告了比 CPU 快数十倍的速度。2010 年，奇雷尚（D. Cireşan）等人用 GPU 训练一个很大的多层感知机，在手写数字识别上创造了当时的最好成绩，此后他们的 GPU 卷积网络在交通标志识别等竞赛中多次夺冠。2012 年，克里热夫斯基用自己写的 CUDA 程序（cuda-convnet）在两块 GPU 上训练了 AlexNet（1.3.6 节、1.5.4 节）。深度学习的研究者从此几乎全部转向 GPU。

需求反过来推动了供给。2014 年，NVIDIA 发布了深度神经网络库 cuDNN，把卷积等常用运算做成高度优化的函数，深度学习框架只需调用它即可；Caffe（2013 年）、TensorFlow（2015 年）、PyTorch（2017 年）等框架都建立在 CUDA 之上，并陆续接入 cuDNN（第 7 章）。张量核心、低精度格式、高带宽显存、多卡互联，都是为深度学习而加入 GPU 的。截至 2026 年 6 月，GPU 仍是人工智能最重要的基础设施，CUDA 生态也成为 NVIDIA 在这一领域占据优势的重要原因：大量的软件、库和开发者经验都建立在它之上，换用别的硬件要付出可观的迁移成本。

CUDA 并不是唯一的选择。2008 年，开放标准 OpenCL 发布，可以在不同厂商的处理器上运行；AMD 的 ROCm 平台提供了与 CUDA 写法非常接近的 HIP 接口；谷歌的 TPU、华为的昇腾等专用加速器有各自的软件栈；Triton 等更高层的编程方式和深度学习框架试图把程序员与具体硬件隔开。对我国读者来说，掌握 CUDA 的原理与掌握国产加速器的编程并不矛盾：线程层次、存储层次、计算强度、数据复用这些概念是相通的，学会了在一种硬件上思考，迁移到另一种硬件就容易得多。第 10 章专门讨论异构算力与国产生态。

### 1.6.7 生活中的例子

体育场里的团体操拼图，是 CUDA 编程模型的一个生动的比喻。看台上几千名观众每人手持一叠彩色卡片，听到口令就同时举起其中一张，远处看去，整面看台拼出一幅图案或一行大字。指挥者不需要对每个人分别下令，只要发一条口令“举第 7 张卡片”；每个人按自己的座位号——第几区、第几排、第几号——从手里的卡片中找到该举的那一张。这里的“第几区”就是 `blockIdx`，“区内第几号”就是 `threadIdx`，一条口令就是一个核函数，全体观众同时执行它，各自处理不同的“数据”。如果某一区的观众举慢了，整幅图案就要等它，这对应 GPU 中最慢的线程决定整个任务的完成时间。

**工程师笔记**

- 写核函数时，先按式 (1.6.2) 算网格大小，并在核函数中检查下标越界；这两行是最常见的错误来源。
- 逐元素的核函数几乎总是受带宽限制，优化的方向是减少读写次数（合并多个操作、使用更窄的数据类型），而不是减少运算。
- 选购或租用 GPU 时，同时看峰值算力、显存容量和显存带宽三项；大模型推理往往最先受限于后两项。
- HIP 的写法与 CUDA 几乎一一对应（`hipLaunchKernelGGL`、`threadIdx` 等），昇腾的 Ascend C 编程模型则不同，但线程层次与存储层次的思想相通（第 10 章）。
