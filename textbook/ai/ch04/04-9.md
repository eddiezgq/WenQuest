### 4.9.1 问题的提出

深度学习的程序几乎都用 Python 写。为了一个自定义的运算去写一个 C++ 文件、编译、再接到 Python 里，代价不小。有没有办法直接在 Python 里写核函数？本节介绍两个常用的工具：Numba 和 CuPy。第 8 章还会介绍 Triton，它是今天写深度学习核函数的主力。

### 4.9.2 Numba

Numba 是一个把 Python 函数即时编译成机器码的库，它的 `numba.cuda` 模块可以把 Python 函数编译成 CUDA 核函数（近年 Numba 的 CUDA 支持由 NVIDIA 维护的 `numba-cuda` 包提供，在有 GPU 的机器上用 `pip install numba-cuda` 安装）。程序 4.9.1 用 Numba 写了向量加法和灰度化。

::: 程序 4.9.1
src: code/ex4_9.py
说明: 用 Numba 写向量加法与灰度化的核函数；构建机上用 Numba 的 CUDA 模拟器在 CPU 上执行并核对结果
:::

与 CUDA C++ 对照：`@cuda.jit` 相当于 `__global__`；`cuda.grid(1)` 返回一维的全局编号，即式 (4.2.1)；`cuda.grid(2)` 返回二维的 (x, y)，即式 (4.2.3) 中的 (col, row)；`kernel[blocks, threads](...)` 用方括号写启动配置，相当于 `<<<blocks, threads>>>`。传入 NumPy 数组时，Numba 自动把它复制到显存、核函数结束后再复制回来；为了避免反复传输，可以用 `cuda.to_device` 先把数组放到 GPU 上、用 `copy_to_host` 取回（4.3 节）。共享内存用 `cuda.shared.array`，同步用 `cuda.syncthreads()`，原子操作用 `cuda.atomic.add`。

本书构建时用的机器没有 GPU，程序 4.9.1 设置了环境变量 `NUMBA_ENABLE_CUDASIM=1`，让 Numba 的 **CUDA 模拟器**在 CPU 上一个线程一个线程地执行同样的核函数。程序在 {{ex4_9.blocks}} 个线程块、每块 {{ex4_9.threads}} 个线程上算了 {{ex4_9.n}} 个元素的向量加法；又在暗斑边缘取 48×64 的一小块图像（{{ex4_9.patch_px}} 个像素）做灰度化，找出 {{ex4_9.dark}} 个暗斑像素，都与 NumPy 的结果完全相同。模拟器很慢，只适合用小数据调试和教学；在有 GPU 的机器上去掉这个环境变量，同样的代码就在 GPU 上运行。

注意程序 4.9.1 中的一个细节：Python 的小数默认是双精度，而 CUDA C++ 程序用单精度计算灰度。为了得到完全相同的结果，Numba 版用 `float32(...)` 把系数和像素值都转成单精度。双精度在多数 GPU 上慢得多（消费级 GPU 慢几十倍），在 Numba 核函数中要留意不要无意中用了双精度。

### 4.9.3 CuPy

CuPy 走的是另一条路：它提供一个与 NumPy 几乎相同的数组库，数组存放在显存中，运算在 GPU 上执行：

```python
import cupy as cp
a = cp.arange(1 << 26, dtype=cp.float32)      # 直接在显存中创建
b = cp.ones_like(a)
c = a + b                                     # 在 GPU 上执行，像 NumPy 一样写
c_host = cp.asnumpy(c)                        # 需要时才传回主机
```

需要自定义的运算时，CuPy 允许直接写 CUDA C++ 的核函数源码，在运行时编译：

```python
gray = cp.RawKernel(r'''
extern "C" __global__ void gray(const unsigned char* rgb, unsigned char* y, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) y[i] = (unsigned char)(0.299f * rgb[3*i] + 0.587f * rgb[3*i+1] + 0.114f * rgb[3*i+2] + 0.5f);
}''', 'gray')
gray((blocks,), (256,), (rgb_gpu, y_gpu, cp.int32(n)))  # 网格、线程块、参数；n 要转成 32 位整数
```

注意参数的类型：CuPy 把 Python 的整数按 64 位传给核函数，而核函数声明的是 32 位的 `int n`，所以要显式写成 `cp.int32(n)`，否则核函数读到的 `n` 可能不对。还有更简单的 `ElementwiseKernel`：只写“每个元素做什么”的一行 C 代码，CuPy 自动生成索引和越界检查。

### 4.9.4 怎样选择

| 需求 | 选择 |
|---|---|
| 已有 NumPy 代码，想整体搬到 GPU | CuPy（大多只要把 `np` 换成 `cp`） |
| 写一个自定义的核函数，留在 Python 里 | Numba，或 CuPy 的 `RawKernel` |
| 深度学习中的自定义算子，要和 PyTorch 配合、追求接近手写的性能 | Triton（第 8 章）或 PyTorch 的 C++/CUDA 扩展 |
| 需要用到最新的硬件功能（张量核心、异步拷贝等） | CUDA C++ |

这几种方式最终都生成 PTX 和机器码，在 GPU 上遵循同样的规则：合并访问、共享内存、存储体冲突、同步——本章讲的一切都同样适用。

**工程师笔记**

- Numba 和 CuPy 的数组可以通过 DLPack 或 `__cuda_array_interface__` 与 PyTorch 张量零拷贝互换，例如 `torch.from_dlpack(cupy_array)`。
- 第一次调用 Numba 核函数时要编译，耗时几百毫秒；计时前先调用一次预热（4.1.4 节）。
- 在 Python 中调试核函数逻辑，先开 CUDA 模拟器用小数据跑通，再上 GPU 计时。
