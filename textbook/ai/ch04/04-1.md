### 4.1.1 问题的提出

检测相机的每一帧有八百多万个像素，每个像素做同样的几步运算（算例 3.1.1）。第 3 章说明了 GPU 为什么适合这样的工作，但没有说怎样让 GPU 做它。本节从最简单的数据并行运算——两个向量相加——开始，写出第一个在 GPU 上运行的程序，看清一个 CUDA 程序由哪几部分组成。

### 4.1.2 开发环境

写 CUDA 程序需要三样东西：一块 NVIDIA GPU，它的驱动程序，以及 **CUDA 工具包**。工具包包括编译器 `nvcc`、运行时库、数学库（cuBLAS、cuFFT 等）、调试与性能分析工具（compute-sanitizer、Nsight Systems、Nsight Compute）。本书的云端 GPU 实验已经装好这些，打开即可使用（帮助文件《GPU 实验使用说明》）；在自己的电脑上，按 NVIDIA 的安装指南装驱动和工具包即可。

每一代 GPU 有一个**计算能力**编号，形如“主版本.次版本”：Ampere 架构的 A100 为 8.0，A10 与 RTX 30 系列为 8.6，Ada 架构的 RTX 4090 为 8.9，Hopper 架构的 H100 为 9.0。计算能力决定了硬件支持哪些功能（如张量核心的哪些精度）、每个 SM 有多少资源（3.5 节）。编译时用 `-arch` 指定目标，`-arch=native` 表示为本机的 GPU 编译。

一个 CUDA 源文件的扩展名是 `.cu`。`nvcc` 把它分成两部分（图 4.1.1(a)）：在 CPU 上运行的**主机代码**交给普通的 C++ 编译器，在 GPU 上运行的**设备代码**编译成 PTX（一种与具体型号无关的中间语言）和具体架构的机器码（SASS），一起嵌入可执行文件。程序运行时，驱动程序把设备代码装进 GPU；如果可执行文件里没有本机架构的机器码，驱动程序就把 PTX 即时编译成机器码。

### 4.1.3 第一个核函数

程序 4.1.1 是一个完整的 CUDA 程序。

::: 程序 4.1.1
src: code/runs/run4_1/vadd.cu
说明: 向量加法：核函数 vadd，主机程序分配显存、传输数据、启动核函数、计时并核对结果
:::

它由以下几部分组成。

**核函数。**以 `__global__` 声明的函数称为核函数，它在设备上执行、由主机启动，返回类型必须是 `void`。核函数的代码描述的是“一个线程”做的事：`vadd` 中的每个线程算出自己的编号 `i`，然后算一个元素 `c[i] = a[i] + b[i]`。`blockIdx`、`blockDim`、`threadIdx` 是 CUDA 提供的内置变量，分别是本线程所在线程块的编号、线程块的大小、本线程在块内的编号（4.2 节）。由于线程总数总是线程块大小的整数倍，可能比元素个数多，所以要用 `if (i < n)` 让多出来的线程什么也不做。

**主机与设备上的内存。**主机程序先在主机内存中准备好数据，用 `cudaMalloc` 在显存中分配三个数组，用 `cudaMemcpy` 把输入从主机复制到设备。核函数只能访问显存中的数据，不能直接访问主机内存中的普通数组（统一内存、映射的锁页内存以及少数支持系统级共享内存的平台除外，4.3 节）。

**启动核函数。**`vadd<<<grid, block>>>(da, db, dc, n)` 以 `grid` 个线程块、每块 `block` 个线程启动核函数，共 `grid × block` 个线程，每个线程执行一遍核函数的代码。三对尖括号中的是**启动配置**。

**取回结果、释放内存。**计算完成后，用 `cudaMemcpy` 把结果从设备复制回主机，用 `cudaFree` 释放显存。

**算例 4.1.1** 向量长 $n = {{ex4_1.n_e}}$，每个数组 {{ex4_1.MiB:.0f}} MiB。每块 {{ex4_1.block}} 个线程，需要 $\lceil n/256\rceil = {{ex4_1.grid}}$ 个线程块，共 {{ex4_1.threads}} 个线程。每个元素读 8 字节、写 4 字节，只做 1 次加法，计算强度 $1/12\approx{{ex4_1.I:.3f}}$ FLOP/B，远在屋顶线的平衡点左边（3.8 节），耗时由显存带宽决定：

$$
t \ge \frac{\text{搬运的字节}}{\beta} . \tag{4.1.1}
$$

共搬运 {{ex4_1.MB:.0f}} MB，在显存带宽 {{ex4_1.bw_a10:.0f}} GB/s 的 A10 上至少要 {{ex4_1.t_a10_ms:.2f}} ms，在 RTX 4090（{{ex4_1.bw_4090:.0f}} GB/s）上至少 {{ex4_1.t_4090_ms:.2f}} ms，在 H100（{{ex4_1.bw_h100:.0f}} GB/s）上至少 {{ex4_1.t_h100_ms:.2f}} ms。而 A10 做完这些加法只要 {{ex4_1.t_comp_a10_us:.1f}} µs，是搬运时间的 1/{{ex4_1.ratio:.0f}}。

### 4.1.4 计时

GPU 上的工作是**异步**的：主机启动核函数后，不等它执行完就继续往下走。所以不能用主机的时钟在启动前后各读一次来计时——那只量到了启动本身。程序 4.1.1 用 CUDA 事件计时：`cudaEventRecord` 在 GPU 的工作队列中插入一个时间标记，两个标记之间的时间由 GPU 自己记录，`cudaEventSynchronize` 等到第二个标记完成后再读。另外，第一次启动核函数时要装载代码、初始化，比后面慢得多，所以先预热一次，再重复多次取中位数。

**工程师笔记**

- 拿到一台新的 GPU 机器，先运行 `nvidia-smi`（GPU 型号、驱动、显存占用）和 `nvcc --version`（CUDA 版本），再编译运行一个向量加法，确认环境正常。
- 计时一律用 CUDA 事件或 Nsight Systems，先预热，重复多次取中位数；用主机时钟时，要在结束前调用 `cudaDeviceSynchronize()`。
- 衡量受带宽限制的核函数，看有效带宽与显存带宽之比：达到 80% 以上就很好了。
