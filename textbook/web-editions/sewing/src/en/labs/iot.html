Model (illustrative, same as the book’s model19.py): shift 480 min with a 30 min break; thread breaks = breaks per hour × planned hours, each taking the set handling time; operating time = planned time − waiting for work − faults − thread-break handling; pieces = operating time × operator efficiency / standard minute value; main-shaft running time = pieces × SMV × running fraction, at an average of 3000 stitches/min. Counting by trims: pieces = trims / trims per piece, where the extra trims come from rework re-sewing (probability per piece) and restarting after thread breaks; counting by work tickets: 20 pieces per bundle, with the set probability of a missed scan; counting by hanger is taken as exact. OEE = availability × performance × quality rate.

Four metrics for each scheme

    
Model (illustrative): messages per machine per shift are calculated for the standard conditions of page ①; state changes (entering and leaving each stop) are reported immediately in the “per piece” and “per minute” schemes; each message is about 250 bytes (JSON envelope); average message rate = messages per machine per shift × number of machines / seconds per shift, and peaks will be several times the average; annual storage uses shifts per day × 300 days. Criteria: average message rate ≤ 500 msg/s, annual storage ≤ 100 GB, state latency ≤ 5 s, piece-count latency ≤ 60 s (illustrative values).
