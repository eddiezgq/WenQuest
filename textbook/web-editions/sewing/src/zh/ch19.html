19.1 引子：从教材到一台能缝的样机

设想一个三四人的学生小组，一个学期约 12 周，任务是做出一台电控平缝机原型：买一台拆掉离合器电机的平缝机机头，配上伺服电机、电磁铁和一块主控板，要求能按脚踏调速，松开脚踏能自动剪线、拨线、停在上针位、抬压脚，起缝和结束能自动回针，最高 5000 r/min。第 13、14 章已经讲清楚这些动作“应该”怎样做，难处在别处：选哪个电机、哪个电磁铁，多大的电源，主控板的输入输出够不够；固件从哪里写起；样机做出来以后，怎样知道它“好了”，又怎样知道下一次修改有没有把别的功能改坏。

有经验的工程团队对付这类问题，靠的是一个短而快的循环：搭—测—改（图 19-1 左）。“搭”是按物料清单和接线表把系统装起来，把固件配置和事件表的初值写进去；“测”是从电脑上的单元测试、软件在环，到接上真主控板的硬件在环，再到真机头的测试台，让脚本自动跑，每一条结果都对应需求表里的一条需求；“改”的顺序是先改参数，再换模块，最后才改机械。每一轮都留下数据：测试报告、固件版本、参数版本。没有这些数据，循环就退化成“试试看”，改了三轮还说不清哪一处改动起了作用。

图 19-1 右边是一个 12 周的计划。前两周写需求表、做快速配套（19.4 节），模块下单；第二到第五周一边等模块、装机接线，一边在电脑上把固件框架和软件在环跑起来；第六周达到 P0“能动”：主轴能调速、能停针，事件表能驱动电磁铁；第九周达到 P1“功能全”；最后几周在测试台上自动测试、迭代、写报告。这个节奏能成立，前提是模块不用自己设计：零件库里有现成的、参数清楚的模块，接口统一，固件框架也是现成的。这正是本章要准备的东西。

实验室原型和工业产品差在哪里？表 19-1 列了几项。差距主要不在“功能”，而在“确定性”：同样的动作，在电压波动、温度变化、零件公差和十年的磨损下，是否每一次都对；以及这件事能不能被测出来、被证明。第 18 章讲的热设计、EMC、老化和生产测试，就是补这些差距的工作，19.8 节会把它们排进一条路线。

19.2 参考架构：一套平台，四种机器

平缝机、包缝机、花样机和横机看起来差别很大，电控的骨架却相同：一根“主令”（主轴或机头）决定时间，若干执行器按主令的位置动作，传感器把状态报回来，控制器在中间调度，再把数据送到车间系统。WQ-SC 把这个共同的骨架固定下来，分成五层，加上最下面的机械（图 19-2）。

执行与传感层　主轴用交流永磁同步伺服电机，带 2500 线增量编码器，四倍频后每转 10000 个计数，带 Z 相零位；送布、X–Y、度目、牵拉用闭环步进电机；剪线、拨线、倒缝、抬压脚、选针器用推拉式电磁铁；压框、压脚、吹气用气缸和电磁阀；脚踏用霍尔传感器，布边和断线用光电传感器，原点和限位用接近开关，此外还有电流和温度检测。驱动层是伺服驱动器（速度或转矩模式，经 CAN FD 或 RS-485 接主控）、步进驱动器（脉冲/方向或总线）、电磁铁驱动板（低边 MOSFET，强激磁加斩波维持，稳压管续流，第 13 章）和气阀驱动。实时控制层是 WQ-SC 主控板：一颗 170 MHz 量级的 Cortex-M4F 级微控制器，带编码器接口定时器、高分辨率 PWM 和 CAN FD，跑实时操作系统；横机的逐针选针可以加一块小 FPGA（第 17 章）。人机与联网层是网关模块（以太网或 Wi-Fi，跑 MQTT 客户端和网页参数界面）和可选的 7 英寸触摸屏。最上面是数字工厂接口：设备消息按问渠数字工厂的主题和信封格式上总线（19.7 节）。

表 19-2 是四种原型各用哪些模块。可以看到，主控、网关、电磁铁驱动、电源和固件框架完全共用；差别集中在“主令”是什么、有几根位置轴、电磁铁做哪些动作。这就是“一套平台，四种机器”的含义：做完平缝机，包缝机只是换一张需求表、少几个电磁铁、多一个气阀；花样机多两根步进轴；横机把主令从主轴换成机头。

为什么用主轴转角做时间基准　第 15 章已经讲过一次：主轴转速并不恒定，起缝慢、中间快、剪线前又慢，负载变化也会让它一转之内忽快忽慢。剪线电磁铁、倒缝切换、X–Y 的移动都要对准机构的位置（针在不在布里、送布牙在不在针板下面），而不是对准某个时刻。如果固件写成“上止点后 8 ms 通电”，主轴一变速，动作就错位了；写成“主轴转到 205° 时通电”，不管转速如何，动作总是对准机构。时间只在一个地方进来：执行器有延迟，延迟折算成转角是 6·n·t 度（第 13 章），所以凡是在转动中动作的执行器，都要按动作时的转速检查这个折算角。横机没有主轴，主令是机头的位置，道理完全相同：选针器按针位而不按时刻触发（第 17 章）。

19.3 零件库里的电控模块

“快速配套”能成立，要有一个参数清楚、可以按参数检索的零件库。问渠零件与机器人库是课程和数字工厂共用的库，目前分四部分：A 标准件（如 A-BRG-DG 深沟球轴承、A-BSC-SFU 滚珠丝杠、A-LGD-RAIL 直线导轨、A-PUL-HTD 同步带轮、A-CPL-JAW 梅花联轴器、A-SPR-CMP 压缩弹簧）；B 机器人整机；C 机构（如 C-CAM-DISC 盘形凸轮、C-LNK-SLIDER 曲柄滑块、C-BLT-BELT 带传动、C-SCN-LEAD 丝杠）；D 厂商器件（目前是机器人用的执行器、传感器，如 D-ACT-ROBOTIS-X、D-LDR-SICK-TIM）。

条目格式　每个条目是一个目录：entry.yaml 写身份（编号、种类、中英文名、类别、标签、标准）、参数定义、出处与许可、教学说明和工厂对应；specs.csv 是规格表，一行一个规格。参数定义是关键：每个参数有一个 key、中文名、英文名、单位和角色 role。角色有四种：key 是区分规格的关键参数（丝杠的公称直径和导程），dim 是外形与安装尺寸（造三维模型、画安装图用），perf 是性能参数（额定动载荷、转矩、转速，选型判据比的就是它），info 是说明性信息（样本型号）。例如库里的 A-BSC-SFU，d0_mm、Ph_mm 是 key，螺母外径、法兰尺寸是 dim，Ca_N、C0a_N 是 perf；规格 16x10 那一行写着公称直径 16 mm、导程 10 mm、钢球直径 3.175 mm、额定动载荷 10817 N，并注明数据出自哪份样本。条目要通过库的格式校验（schema/entry.v1.json）才能发布。

19.4.2 计算

主轴转矩　从静止加速到 nmax，所需转矩等于总惯量乘角加速度，再加上库仑摩擦 Tf = 0.15 N·m（第 13 章）：

\[ T_{acc}=\left(J_{load}+J_{rotor}\right)\frac{2\pi n_{max}/60}{t_{acc}}+T_f=6\times10^{-4}\times\frac{523.6}{0.15}+0.15\approx 2.24\ \mathrm{N\cdot m} \]

角加速度约 3491 rad/s²。判据是 Tacc ≤ 0.8 Tpeak，留 20% 给电压偏低和第 8 章讲的随转角周期变化的惯性力矩。另外三条：最高转速不超过电机的最高转速；负载惯量与转子惯量之比不超过 10（直驱、刚性连接时的示意值，比值太大，速度环难调，第 13 章惯量加倍的教训）；间歇工况下的等效转矩不超过额定转矩。最后一条按第 18 章的工况算：每分钟起停 30 次，每次加速、减速各 tacc，加减速占时间的 30 × 2 × 0.15 / 60 = 15%，稳速缝纫占 35%，稳速负载取 0.35 N·m（示意），

\[ T_{rms}=\sqrt{0.15\times2.24^2+0.35\times0.35^2}\approx0.89\ \mathrm{N\cdot m} \]

问渠数字工厂里有一个“AI 选型”功能（仓库 factory/digital/hub/select.py）：用户用一句话提需求，例如“X 轴同步带，24 齿 3M 带轮”，它先按关键词找条目，再按句子里的数字筛规格。它有三条硬规矩：只从零件库里挑；答案里每个推荐都写成“编号/规格”，并列出依据的规格表那一行参数和出处；库里没有合适的就说没有，不编造编号或参数。答案生成以后还要逐个核对其中出现的编号，不在库里的编号会从结果里去掉并单独列出。没有配置大模型时，它用规则回答，同样只从库里挑。

19.5 固件框架：角度驱动的事件调度

固件分层与第 18 章相同：驱动层、运动控制层、工艺层、界面与通信层。WQ-SC 的工艺层围绕三样东西组织：把编码器计数变成角度，按角度查事件表，用状态机管住整个工作周期。三样都是数据驱动的：动作的角度在参数表里，换一台机头只改参数，不改代码。

计数变角度　主轴编码器每转 10000 个计数，固件里角度的单位取 0.1°，一转 0–3599，换算是 角度 = 计数 × 3600 / 10000 = 计数 × 9 / 25，用整数运算。0.1° 在 300 r/min 时约 56 μs，在 5000 r/min 时约 3.3 μs，所以事件不能靠任务轮询去“看”角度到了没有，而要用编码器定时器的比较功能：固件预先算好下一个事件角对应的计数，写进比较寄存器，计数一到就进中断。

事件表　一行一个动作：起始角、结束角、输出、条件（表 19-9，图 19-5）。条件让同一张表能表达“只在剪线那一针”“只在回针针内”这类逻辑。剪线电磁铁在 205.0°–330.0° 通电：原型用的机头是凸轮式剪线，电磁铁只负责把滚子推进凸轮槽，进刀时刻由凸轮决定，所以通电要早，300 r/min 下吸合 6.9 ms 折算 12.4°，217° 以前到位，赶在凸轮槽入口之前；如果改用直接驱动动刀的机头，按第 14 章的算法把起始角改到 290°–300°，代码不动。拨线在剪线后的下一转 15°–60° 通电；倒缝在 114.2°（送布牙沉到针板以下，第 6、14 章）按“回针针数是否未完”置位或复位。表中的角度都是初值，以所用机头的时刻表为准，第 20 章在样机上标定。

下面是事件表的数据结构和角度中断里的调度。中断里只做比较和置位，不调用任何会阻塞的函数；条件只读状态机维护的变量。

/* ---- 事件表：一行一个动作，角度单位 0.1°（0–3599）---- */
typedef enum { EV_WINDOW, EV_LATCH } ev_type_t;
typedef struct {
    uint16_t start;      /* 起始角 */
    uint16_t end;        /* 结束角；end < start 表示跨过 0° */
    uint8_t  out;        /* 输出：SOL_TRIM、SOL_WIPE、SOL_BT …… */
    uint8_t  cond;       /* 条件：TRIM_REV0、TRIM_REV1、BT_LATCH …… */
    uint8_t  type;       /* EV_WINDOW：区间内通电；EV_LATCH：到 start 时按条件置位/复位 */
} evt_t;

/* a 是否落在 (from, to] 内（正转方向，可跨 0°） */
static int crossed(uint16_t from, uint16_t to, uint16_t a)
{
    return (from <= to) ? (a > from && a <= to) : (a > from || a <= to);
}

/* ---- 编码器比较中断：计数到达下一个事件角时进入 ---- */
static uint16_t last;                         /* 上次处理到的角度 */
void ENC_CMP_IRQHandler(void)
{
    uint16_t now = enc_angle_x10();           /* 计数 × 9 / 25 */
    if (now < last) rev_count++;              /* 过 0°：转数加一 */
    for (unsigned i = 0; i < P.n_evt; i++) {
        const evt_t *e = &P.evt[i];
        int c = cond_true(e->cond);           /* 只读状态变量 */
        if (e->type == EV_LATCH) {
            if (crossed(last, now, e->start)) sol_set(e->out, c);
        } else {
            if (c && crossed(last, now, e->start)) sol_set(e->out, 1);
            if (!c || crossed(last, now, e->end)) sol_set(e->out, 0);
        }
    }
    last = now;
    enc_set_compare(next_event_count(now));   /* 排好下一个事件角对应的计数 */
}

状态机　工作周期由状态机管理（图 19-6）：IDLE（停在上针位）→ RUN（脚踏调速）→ SLOW（减速到剪线转速）→ TRIM（剪线那一针，事件表执行剪线、拨线）→ POSITION（位置环停到上针位）→ IDLE。任一状态检测到故障（过流、编码器丢失、超时、急停、机头翻起）都进 SAFE：断开所有电磁铁，主轴自由停或制动，记录故障码；只有故障清除、脚踏回到中位，才回到 IDLE，防止一复位机器就转起来（第 18 章）。

void sew_task(void)                           /* RTOS 任务，每 1 ms 一次 */
{
    if (fault_pending() && state != SAFE) enter_safe();
    switch (state) {
    case IDLE:
        if (pedal() >= P.pedal_run) { pfl_down(); bt_start(P.bt_start_n); state = RUN; }
        break;
    case RUN:                                 /* 事件表在角度中断里逐针执行 */
        spindle_speed(pedal_to_rpm(pedal()));
        if (pedal() <= P.pedal_trim) { spindle_speed(P.n_trim); state = SLOW; }
        break;
    case SLOW:
        if (spindle_rpm() <= P.n_trim + 20 && enc_angle_x10() >= 1800) {
            rev_count = 0; state = TRIM;      /* 从这一针起 TRIM_REV0 为真 */
        }
        break;
    case TRIM:
        if (rev_count >= 1 && enc_angle_x10() >= P.pos_engage_x10) {   /* 第 1 转 25° */
            spindle_position(P.up_pos_x10); t0 = now_ms(); state = POSITION;
        }
        break;
    case POSITION:
        if (spindle_settled(5, 5)) { pfl_up_after(P.t_wipe_ms); state = IDLE; } /* ±0.5°，5 ms */
        else if (now_ms() - t0 > P.t_pos_max_ms) fault_raise(F_POS_TIMEOUT);
        break;
    case SAFE:
        if (fault_cleared() && pedal_neutral()) state = IDLE;
        break;
    }
}

19.6 先在电脑上“缝”：软件在环与硬件在环

样机装好以前，固件的大部分逻辑已经可以测试了。测试分三级，跑同一套测试用例，只换“被测对象”和“对象模型”（图 19-7）。

软件在环（SIL）　把工艺层、状态机和事件表编译成电脑上的程序，HAL 换成仿真驱动，接上机器模型。模型不必另写：本书的虚拟实验已经有了伺服停针（虚拟实验 13-1）、电磁铁吸合释放（13-2）、剪线时序（14-1）、花样机的 X–Y 与离布窗口（第 15 章）和横机选针（第 17 章）的模型，第 20 章的原型模型就是把这几个模型按同一组参数接起来。仿真按 50 μs 的步长推进，比实时快几十倍，每次提交代码都能自动跑一遍（持续集成），专查逻辑错误、时序表写错、参数越界。

硬件在环（HIL）　换上真的主控板和真的固件，对象仍是模型，但模型跑在一台实时仿真台上，用真实的电信号和主控板打交道。编码器仿真最考验功夫：5000 r/min 时主轴每秒 83.3 万个计数（A、B 两路方波各约 208 kHz），而模型 50 μs 走一步时主轴转过 1.5°、约 42 个计数；如果每一步一次性吐出 42 个脉冲，主控板看到的就是锯齿状的转角，事件会集中在某些时刻触发。所以仿真台要按模型给出的转速把计数均匀地插在两步之间，像数字频率合成那样输出，并在每转的固定计数处输出 Z 相。电磁铁可以接真线圈，也可以接 R–L 假负载（如 8 Ω、20–80 mH，第 13 章），仿真台测电流波形，由模型算出衔铁什么时候到位。伺服驱动器在 CAN FD 上用一个驱动器模型代替。HIL 最大的用处是故障注入：断编码器、过流、欠压、急停，这些在真机上很难复现或有危险，在台上可以每晚跑几千次，检查固件是否每次都进 SAFE、故障码是否正确。

整机测试台　最后是真机头、真伺服、真电磁铁，加转矩转速传感器、编码器记录和拍线迹的相机，验证机械和电控的配合：停针误差 ≤ ±1°、剪线 1000 次成功率 ≥ 99.5%、电磁铁折算转角 ≤ 20° 这些验收指标在这里测。三级测试的脚本都用 Python 和 pytest 写，通过网关的接口下发命令、读测量，每个用例对应一条需求（REQ-…），结果自动写成报告；第 22 章专讲这套测试体系。

19.8 从原型到工业级的路线

一台原型变成工业产品，一般要过五级：P0、P1、EVT、DVT、PVT，然后量产（图 19-8）。每一级的目标不同，退出条件都写成自动测试的通过率和测得的指标，而不是“大家觉得差不多了”。

P0 能动：一台样机，主轴能调速、停针，事件表能驱动电磁铁，软件在环全部通过；退出条件可以放宽，例如停针误差 ≤ ±3°、HIL 冒烟测试通过。P1 功能全：全部动作和联网都有了，每条需求都有测试用例，测试台能无人值守地跑；退出条件是用例通过率 ≥ 95%、停针 ≤ ±1°、剪线 1000 次成功率 ≥ 99.5%。实验室原型做到 P1 为止，第 20、21 章的两台原型都以 P1 为目标。

EVT 工程验证：把模块合成一块电控板、装进机箱，做 3–5 台，测热、电源和初步的 EMC，最高转速连续运转 4 h；退出条件是全部需求用例通过、温升合格。DVT 设计验证：设计冻结，做 10–20 台，做 EMC、电气安全、环境和寿命试验，送认证样机；退出条件是标准试验通过、寿命试验无关键故障。PVT 小批验证：用量产工装在产线上装几十到几百台，每台跑出厂测试 EOL 和老化，数据回流数字工厂；退出条件是 EOL 一次通过率达标（如 ≥ 98%，示意）、返修原因都已闭环。

从模块化的原型到产品，要补的工作主要有四类（表 19-11），大多在第 18 章讲过。要注意的是，这些工作不是到了 DVT 才开始：电源、接地和电缆屏蔽从 P1 起就要按产品的做法接，否则 EVT 的 EMC 预测试会推翻很多设计；需求表和测试用例从 P0 起就要有编号，否则到了 PVT 无法证明“全部需求都测过”。

19.9 设计要点与模型的边界

本章的要点是：四种原型共用一套五层架构，差别在主令和执行器的组合；动作以主轴转角（横机以机头位置）为时间基准，执行器的延迟按 6·n·t 折算成转角来检查；选型从写数字的需求表出发，按判据从零件库里挑最便宜的合格规格，BOM、接线表和固件配置由同一份数据生成；固件以事件表加状态机加 HAL 组织，换机头改参数、换模块换驱动文件；固件、参数、BOM 都有版本并随设备上报；测试按单元、SIL、HIL、测试台逐级做，每个用例对应一条需求；原型到产品分级推进，每级的退出条件写成指标。

本章的模型有明确的边界。主轴选型只算了从静止到最高转速的一次加速，没有算第 8 章讲的随转角周期变化的负载转矩，用 0.8 倍峰值的余量笼统地覆盖；间歇工况的起停次数和稳速负载是示意值，实际要用测功数据。步进电机的矩频曲线用“拐点以下恒转矩、以上按 1/n 下降”的折线近似，真实曲线与驱动电压、细分和共振有关，要查厂商的曲线；同步带的刚度按宽度比例取 EA，只检查了滑座在中间时的固有频率。电磁铁的吸合、释放时间是“模块 + 本平台驱动板”在额定电压下的值，电压偏低、线圈发热时会变长（第 13、14 章），选型时要用最坏情况。电源预算把强激磁按一半计入，是对电容分担的粗略估计。全部模块参数和价格都是示意值，建议编号尚未入库，入库时要按库的规则写明数据出处。

现场要点

  • 样机第一次急停就报过压，先核急停回馈能量和驱动器的制动能力，再看是否装了更重的手轮。
  • 剪线时好时坏，先查事件表的版本是不是改过、剪线转速是不是被调高，再查电磁铁电源电压；参数和固件版本要和测试报告对得上。
  • 换了机头，先改参数表里的事件角和停针角，在测试台上重新标定，不要改代码。
  • 主控 I/O 刚好用满时，留一两路备用或直接加扩展板；样机迭代总会多出一个传感器。
  • 选型助手说“库里没有”，不要自己编一个型号塞进 BOM；把它记成入库需求，按样本补全条目。

第 19 章 习题

  1. 平缝机原型换了一个更轻的手轮，负载折算惯量降到 4×10⁻⁴ kg·m²，同时要求 0.12 s 内从 0 加速到 5000 r/min。仍用 D-MOT-PMSM/400（转子 1×10⁻⁴ kg·m²、峰值 3.2 N·m），所需转矩、惯量比和急停回馈能量各是多少？是否满足 19.4 节的判据？
    参考答案所需转矩约 2.33 N·m ≤ 0.8 × 3.2 = 2.56 N·m，满足；惯量比 4；回馈能量 0.7 × ½ × 5×10⁻⁴ × 523.6² ≈ 48.0 J。
  2. 用 D-SOL-PUSH/L30（吸合 11 ms、释放 7 ms）做剪线电磁铁，剪线转速 300 r/min 时折算转角是多少？要满足 20° 的判据，剪线转速最高多少？换成 M15（吸合 6.9 ms）呢？
    参考答案吸合折算 19.8°，释放 12.6°，刚好满足；最高约 303 r/min。M15 最高约 483 r/min。
  3. 包缝机原型提速到 7000 r/min，主轴编码器每转 10000 个计数。每秒有多少个计数？0.1° 对应多少微秒？为什么事件调度要用编码器定时器的比较中断，而不是在 1 ms 的任务里检查角度？
    参考答案约 116.7 万个/秒；约 2.38 μs。1 ms 里主轴转过 42°，任务轮询的误差可达几十度，比较中断的误差只有一两个计数。
  4. 花样机原型的 Y 轴（运动质量 5 kg、阻力 15 N、加速度 25 m/s²、最高 0.5 m/s）改用 5M-20-25 带轮（节圆直径 31.831 mm），电机转速和所需转矩各是多少？配 D-MOT-STEP/34-45C（闭环，余量 0.8）是否满足？和 3M-24-15 方案比，为什么大带轮反而要更大的转矩？
    参考答案约 300 r/min；约 2.59 N·m（3M-24-15 方案约 2.01 N·m）。300 r/min 低于拐点，可用 0.8 × 4.5 = 3.6 N·m，满足。带轮半径大，同样的力需要的转矩与半径成正比；转速降低的好处只在高速段才体现。
  5. 给花样机原型加一根闭环步进驱动的电子中压脚轴。数字输入、输出和脉冲通道各增加几路？主控 S 加一块扩展板还够不够？
    参考答案DI 加 1（驱动报警），共 17 路；DO 加 1（方向），共 8 路；脉冲通道加 1，共 3 路。主控 S 有 12 路 DI、8 路 DO、8 路脉冲，加扩展板后 DI 28 路，够用，但 DO 已用满，没有余量。
  6. （讨论）有同学主张把剪线写成“松开脚踏后延时 180 ms 给剪线电磁铁通电”，理由是“测过几次都能剪断”。用本章和第 14 章的道理说明这样做的问题，并说明在事件表里应该怎样写。
  7. （讨论）你的原型在 P1 阶段剪线成功率 99.7%，固件 0.3.0、参数 LS-P1-001。同学改了拨线角度以后成功率降到 98%，却说不清改了什么。按 19.5、19.7 节的做法，你会怎样安排版本、测试和上报，使这类问题能被定位？
