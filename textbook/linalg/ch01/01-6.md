### 1.6.1 为什么要会编程

线性代数的手算只能处理很小的矩阵。三个未知数的方程组，手算要几分钟；三十个未知数，手算不再现实；而机器人控制器、图像处理和神经网络中的矩阵，动辄成百上千乃至上亿个元素。另一方面，计算机算得快，却会出一种手算不会出的错：舍入误差。本书的做法是“手算与程序并行”：小例子用整数和分数手算，弄清道理；同一个问题再用程序以浮点数计算，看清实际计算中会发生什么。书中每个算例的数据都由程序算出，程序可以在线运行和修改。

本书使用 Python 语言和它的 NumPy 库。Python 语法简单，是科学计算和人工智能领域用得最多的语言；NumPy 提供了数组和矩阵运算，底层调用 1.4.3 节所说的 LAPACK 和 BLAS，计算速度与专门的科学计算软件相当。本节从零开始介绍本书用到的最基本的语法；读者如果已经熟悉 Python，可以跳过 1.6.2 节。附录 F 是 NumPy 和 SciPy 的速查表。

### 1.6.2 第一行 Python

Python 程序由一行行语句组成，从上到下依次执行。最简单的语句是给变量赋值并做算术：

```python
a = 0.1 + 0.2
print(a)            # 打印变量的值；井号后面是注释，不执行
print(a == 0.3)     # 两个等号表示“比较是否相等”
```

运行它，得到的结果出乎许多人的意料：第一行打印 {{ex1_6.a}}，第二行打印 {{ex1_6.a_eq}}。原因是计算机用二进制存放小数，而 0.1 在二进制中是无限循环小数，只能存一个近似值；0.1 与 0.2 的近似值相加，与 0.3 的近似值差了大约 $5.6\times10^{-17}$。这不是 Python 的错误，所有使用二进制浮点数（IEEE 754 标准）的语言，如 C、Java、MATLAB、JavaScript，都是如此。由此得到一条重要的经验：**不要用“==”比较两个浮点数是否相等**，而要看它们的差是否足够小。NumPy 的 `np.isclose(a, 0.3)` 就是这样比较的，它返回 {{ex1_6.close}}。第 20 章将系统地讨论浮点数和舍入误差。

把一组数放在方括号中，就是一个**列表**。`for` 语句对列表中的每个元素重复执行缩进的几行：

```python
g = 9.80665                 # 标准重力加速度，m/s²
L = 0.817                   # UR5e 水平伸展时腕心到肩关节的距离，m
masses = [1.0, 2.0, 0.5]    # 三个零件的质量，kg
total = 0.0
for m in masses:            # 冒号结尾，下面缩进的语句是循环体
    total = total + m * g * L
print(total)
```

它计算三个零件一起吊在 UR5e 腕部时，在肩关节产生的总力矩（1.1 节），结果是 {{ex1_6.total:.3f}} N·m。Python 用缩进（通常是四个空格）表示哪些语句属于循环体，缩进错了程序的含义就变了。

经常要重复的计算可以写成**函数**：

```python
def torque(m, L=0.817, g=9.80665):
    """质量 m 的负载在力臂 L 处产生的力矩。"""
    return m * g * L

print(torque(2.0))          # 用默认的力臂
print(torque(2.0, L=0.4))   # 指定另一个力臂
```

`def` 定义函数，括号中是参数，`=` 后面是默认值，`return` 给出函数的结果。三引号中的文字是函数的说明。本书的程序大多就是由这样的几个小函数组成的。

### 1.6.3 NumPy 数组

Python 的列表可以存放任何东西，但不能直接做向量运算。NumPy 的**数组**专门存放数，并支持整体运算：

```python
import numpy as np                  # 载入 NumPy，约定简称 np

x = np.array([1.0, 2.0, 3.0])       # 一个有三个分量的向量
y = np.array([4.0, 5.0, 6.0])
print(x + y)        # 对应分量相加
print(2 * x)        # 每个分量乘以 2
print(x * y)        # 对应分量相乘（不是线性代数中的乘法）
print(x @ y)        # 内积：对应分量相乘再相加
```

`x * y` 给出 {{ex1_6.xy}}，是“逐元素相乘”；`x @ y` 给出 {{ex1_6.dot}}，即 $1\times4 + 2\times5 + 3\times6$，是第 2 章的内积（点积）。初学者最常犯的错误之一，就是把 `*` 当成矩阵乘法。本书约定：**线性代数中的乘法一律写 `@`**。

矩阵是二维数组，按行写出：

```python
A = np.array([[3.0, 2.0, 1.0],
              [2.0, 3.0, 1.0],
              [1.0, 2.0, 3.0]])
print(A.shape)      # 形状：几行几列
print(A[0, 1])      # 第 1 行第 2 列的元素（下标从 0 开始）
print(A[:, 0])      # 第 1 列
print(A @ x)        # 矩阵乘向量
```

`A.shape` 给出 {{ex1_6.shape}}；`A @ x` 给出 {{ex1_6.Ax}}，它的第一个分量是 $A$ 的第一行与 $\boldsymbol x$ 的内积 $3\times1 + 2\times2 + 1\times3$，其余类推（1.2 节、第 4 章）。注意 Python 的下标从 0 开始：数学上的第 1 行，在程序中是第 0 行。本书正文一律从 1 开始编号，程序中从 0 开始，读程序时要留意这个差别。

### 1.6.4 解线性方程组

上面的矩阵 $A$ 正是《九章算术》方程第一题（式 (1.4.1)）的系数矩阵。用 NumPy 解这个方程组只要一行：

```python
b = np.array([39.0, 34.0, 26.0])
sol = np.linalg.solve(A, b)
print(sol)
```

结果是 {{ex1_6.sol}}。与 1.4.1 节的精确解 $x = 37/4$、$y = 17/4$、$z = 11/4$ 相比，第二、三个数在小数点后十几位处有微小的差别：这又是舍入误差。对这个方程组，误差小到可以忽略；第 20 章将看到，对某些“病态”的方程组，同样大小的舍入误差会被放大成千上万倍。`np.linalg.solve` 内部做的是带主元的高斯消元，它比自己写的消元程序更快、更可靠（1.4 节工程师笔记）。

### 1.6.6 生活中的例子

电子表格（如 Excel 或 WPS 表格）其实也是一个矩阵计算器。把一列数乘以同一个数、两列对应相加，就是数乘和向量加法；Excel 的 `SUMPRODUCT` 函数计算的正是内积，`MMULT` 函数计算矩阵乘法，`MINVERSE` 计算逆矩阵。很多人每天都在用线性代数，只是没有意识到。

**工程师笔记**

- 浮点数比较一律用容差：`abs(a - b) < tol` 或 `np.isclose`、`np.allclose`。容差的大小要与问题的尺度相称：比较以米为单位的位置和以弧度为单位的角度，容差显然不同。
- NumPy 中尽量用整体的数组运算，少写逐个元素的 `for` 循环。整体运算由编译好的底层库执行，往往比 Python 循环快几十到几百倍。
- 程序中给物理量写上单位注释（如 `# m`、`# rad/s`），并在一个程序中统一单位。工程中有大量事故源于单位混乱。
- 一维数组 `np.array([1, 2, 3])` 既不是行向量也不是列向量，它的形状是 `(3,)`。需要明确区分时，写成形状为 `(3, 1)` 的二维数组。这一点在第 4 章讲矩阵乘法时还会提到。
