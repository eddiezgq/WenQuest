### 4.7.1 问题的提出

训练一个大语言模型，要做 $10^{24}$ 次量级的浮点运算，其中绝大部分是矩阵乘法；机器人的视觉网络处理一帧图像，也要做数十亿次乘加。按 (4.2.5)，两个 $n$ 阶方阵相乘要 $2n^3$ 次浮点运算，$n = 256$ 时是 {{ex4_7.flops256}} 次。运算次数由公式决定，可是不同的程序完成同样的运算，耗时却能相差几十倍甚至上千倍。差别从哪里来？还能不能少做一些运算？本节从两个方向回答：一是让每次运算更快，关键在内存；二是减少运算次数，代表是施特拉森算法。

### 4.7.2 内存才是瓶颈

现代处理器每纳秒能做几十次浮点运算，但从内存读一个数要几十到上百纳秒。为了弥补这个差距，处理器和内存之间有几级缓存：越靠近处理器，容量越小、速度越快（图 4.7.1 右）。数据从内存搬进缓存时，一次搬一整段（通常 64 字节，即 8 个双精度数）。所以：**连续访问内存很快，跳着访问很慢；读进缓存的数据要尽量多用几次**。

*循环次序*。按式 (4.2.3) 写成三重循环，有 6 种排列循环次序的方式，算的东西完全一样。NumPy 和 C 语言把矩阵按行存储：同一行的元素在内存中相邻。“ijk”次序的最内层循环让 $k$ 变化，读 $a_{ik}$ 是沿行连续读，读 $b_{kj}$ 却是沿列跳着读，每次跳过 $n$ 个数，几乎每读一次都要去内存取一段新数据。把次序换成“ikj”：

```python
for i in range(n):
    for k in range(n):
        a = A[i, k]
        C[i, :] += a * B[k, :]     # 最内层沿 B 和 C 的行连续访问
```

最内层沿行连续访问，这正是 4.2 节“行的组合”的看法：$C$ 的第 $i$ 行是 $B$ 的各行的组合。实验 4.7 中，$n$ 较大时 ikj 明显比 ijk 快，具体倍数因机器而异；用 C 语言编写时差距往往更大。

*分块*。$n$ 很大时，整个 $B$（$8n^2$ 字节）放不进缓存，ikj 对每个 $i$ 都要把 $B$ 从内存重新读一遍。分块乘法把矩阵切成 $b\times b$ 的小块，按 4.4 节的 (4.4.1) 逐块相乘累加：

$$
C_{IJ} \mathrel{+}= A_{IK}B_{KJ} . \tag{4.7.1}
$$

三个 $b\times b$ 块一起放进缓存后，做 $2b^3$ 次运算只需读写约 $3b^2$ 个数，每个数平均被用了约 $b$ 次。程序 4.7.1 用 $b = 32$ 的分块计算 $n = 256$ 的乘积，与直接相乘的最大差为 ${{ex4_7.block_tex}}$，那是加法次序不同引起的舍入差别。块的大小要与缓存匹配：$b = 64$ 时三个块占 $3\times 8\times 64^2$ 字节，约 96 KB，比一级缓存（通常几十 KB）大，比二级缓存（通常几百 KB 到几 MB）小。实际的程序库分好几层块，分别对应寄存器、一级、二级、三级缓存。

### 4.7.3 BLAS、GPU 与低精度

数值计算的基本运算早已标准化为 BLAS（基本线性代数子程序）：一级是向量运算（如 $\boldsymbol y\leftarrow a\boldsymbol x + \boldsymbol y$，运算量 $n$），二级是矩阵乘向量（运算量 $n^2$），三级是矩阵乘矩阵（运算量 $n^3$）。三级运算读写 $n^2$ 个数、做 $n^3$ 次运算，每个数能被反复使用，最能发挥处理器的能力，所以高性能的程序都设法把计算组织成三级运算。LAPACK 的消元、QR 分解等，都尽量把主要的计算组织成分块的矩阵乘法。OpenBLAS、英特尔 MKL 等程序库针对每种处理器手工调优了分块大小和指令，NumPy 的 `A @ B` 调用的就是它们，在普通计算机上能达到每秒 $10^{11}$ 次以上浮点运算，比实验 4.7 中浏览器里的 JavaScript 快几十倍。

GPU 有成千上万个简单的运算单元，矩阵乘法的 $n^2$ 个元素可以同时计算，天然适合它。专为深度学习设计的张量核心，一条指令就完成一个小矩阵块（如 $4\times4$ 或 $16\times16$）的乘加，并使用 16 位甚至 8 位的低精度数，速度可达每秒 $10^{15}$ 次运算的量级。低精度带来的舍入误差，在神经网络中通常可以容忍；在科学计算中则要用混合精度的技巧补救（第 20、22 章）。

### 4.7.4 施特拉森算法：7 次代替 8 次

另一个方向是减少运算次数。按 (4.4.2)，把 $A$、$B$ 各分成 4 个 $\frac n2\times\frac n2$ 块，乘积要做 8 次块乘法。1969 年，施特拉森发现 7 次就够了：

$$
\begin{aligned}
M_1 &= (A_{11} + A_{22})(B_{11} + B_{22}), & M_5 &= (A_{11} + A_{12})B_{22},\\
M_2 &= (A_{21} + A_{22})B_{11}, & M_6 &= (A_{21} - A_{11})(B_{11} + B_{12}),\\
M_3 &= A_{11}(B_{12} - B_{22}), & M_7 &= (A_{12} - A_{22})(B_{21} + B_{22}),\\
M_4 &= A_{22}(B_{21} - B_{11}),
\end{aligned} \tag{4.7.2}
$$

$$
C_{11} = M_1 + M_4 - M_5 + M_7,\quad C_{12} = M_3 + M_5,\quad C_{21} = M_2 + M_4,\quad C_{22} = M_1 - M_2 + M_3 + M_6 . \tag{4.7.3}
$$

以 $C_{12}$ 为例验证：$M_3 + M_5 = A_{11}B_{12} - A_{11}B_{22} + A_{11}B_{22} + A_{12}B_{22} = A_{11}B_{12} + A_{12}B_{22}$，正是 (4.4.2) 的结果。其余三个块留作习题。注意推导中没有交换任何乘积的次序，所以公式对矩阵块成立，而不只是对数成立。代价是加减法从 4 次增加到 18 次。

关键在于递归：7 次块乘法中的每一次，又可以用同样的方法再拆。设 $n = 2^k$，一直拆到 $1\times1$，乘法次数是 $7^k$，而普通算法是 $8^k = n^3$。由于 $7^k = 2^{k\log_27} = n^{\log_27}$，

$$
\text{施特拉森算法的乘法次数为 } n^{\log_2 7}\approx n^{ {{ex4_7.exp:.3f}} } . \tag{4.7.4}
$$

加减法的次数也是同样的量级。$n$ 越大，节省越多：

### 4.7.5 施特拉森算法的代价与后续

施特拉森算法在理论上意义重大：它第一次证明了矩阵乘法可以少于 $n^3$ 次运算，“消元必须 $n^3$”的直觉也随之破灭，施特拉森论文的标题就叫《高斯消元不是最优的》（求逆、解方程组都可以归结为矩阵乘法）。但在实际中它用得不多，原因有三：

1. 只数运算次数，拆一层在 $n\ge16$ 时就已经省了（习题 4.7.3）；但额外的加减法、临时存储和不规则的访存，使它按实际耗时通常要到数千阶以上才划算，而那时普通算法借助分块和 BLAS 已经接近处理器的峰值速度；
2. 它的数值稳定性比普通算法差：普通算法每个元素的误差与 $\sum_k |a_{ik}||b_{kj}|$ 成比例，施特拉森算法只能保证整体（范数意义下）的误差界，矩阵元素大小悬殊时个别元素的误差会大得多（第 20 章）；
3. 递归和不规则的访存不利于 GPU 等硬件发挥。

此后，数学家把矩阵乘法的指数 $\omega$（$n$ 阶乘法需要约 $n^\omega$ 次运算）不断压低：1990 年的科珀史密斯–威诺格拉德算法约为 2.38，2020 年代的一系列改进已降到约 2.37。这些算法的常数因子大得惊人，只有理论意义。$\omega$ 能否降到 2，是理论计算机科学的著名未解问题。2022 年，DeepMind 的 AlphaTensor 用强化学习搜索小矩阵的乘法公式，在模 2 运算下找到了只用 47 次乘法的 $4\times4$ 公式（把施特拉森公式用两层是 49 次），显示 AI 也能参与这类数学发现。

### 4.7.6 生活中的例子

在超市结账时，收银员把同一种商品“扫一次、输数量”，而不是一件一件地扫。这就是“读进来的数据多用几次”：少跑几趟货架（内存），多在手边（缓存）处理。分块乘法让处理器做的正是同一件事。

**工程师笔记**

- 永远不要在 Python 中用三重循环做矩阵乘法：它比 `A @ B` 慢上万倍。教学程序除外。
- 查看 NumPy 用的是哪个 BLAS：`np.show_config()`。在多核计算机上，BLAS 默认使用全部核心；与其他并行程序同时运行时，可用环境变量 `OMP_NUM_THREADS` 限制线程数，避免互相争抢。
- GPU 上做乘法前后，数据在内存与显存之间的拷贝往往比乘法本身还慢。尽量让数据留在显存里，把多次小乘法合并成一次批量乘法。
- 用低精度（float16、bfloat16）计算时，务必用双精度的结果抽查误差，尤其是要累加很多项的时候。
