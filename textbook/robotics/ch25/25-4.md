### 25.4.1 问题的提出：快多少

25.3 节证明了递推和拉格朗日方程算的是同一个方程。那么，为什么 1980 年前后工业控制器要从拉格朗日方法改用递推？本节数一数两种算法各要做多少次乘法和加法，再看实际用时。

先写出要比较的拉格朗日方法。20 世纪 60、70 年代通行的写法来自尤克（J. J. Uicker）1965 年和卡恩（M. E. Kahn）1969 年的博士论文：用 4×4 齐次变换矩阵表示各连杆的位姿 $T_{0j}(\theta)$，把动能写成矩阵的迹，按拉格朗日方程求导，得到

$$
\tau_i = \sum_{j=i}^{n}\Big[\sum_{k=1}^{j}\mathrm{tr}\big(U_{jk}\,\mathcal J_j\,U_{ji}^{\mathsf T}\big)\ddot\theta_k + \sum_{k=1}^{j}\sum_{l=1}^{j}\mathrm{tr}\big(U_{jkl}\,\mathcal J_j\,U_{ji}^{\mathsf T}\big)\dot\theta_k\dot\theta_l - m_j\,\bar{\mathfrak g}^{\mathsf T}U_{ji}\,\bar r_j\Big] , \tag{25.4.1}
$$

其中 $U_{jk} = \partial T_{0j}/\partial\theta_k = T_{0k}[\mathcal A_k]T_{kj}$（k ≤ j），$U_{jkl} = \partial^2T_{0j}/\partial\theta_k\partial\theta_l$，$\bar{\mathfrak g} = (0, 0, -\mathfrak g, 0)$，$\bar r_j = (c_j, 1)$ 是连杆 j 质心的齐次坐标，$\mathcal J_j$ 是连杆 j 的**伪惯量矩阵**

$$
\mathcal J_j = \begin{pmatrix} \frac12\mathrm{tr}(I_j)\,I_3 - I_j & m_jc_j \\ m_jc_j^{\mathsf T} & m_j \end{pmatrix} , \tag{25.4.2}
$$

$I_j$ 是连杆 j 对 {j} 原点的惯量张量（左上块就是 $\sum m\,rr^{\mathsf T}$）。式 (25.4.1) 是第 24 章 $M\ddot\theta + C\dot\theta + g$ 的一种显式写法：第一组和是 $M\ddot\theta$，第二组是速度项，第三组是重力项。它有三重、四重求和，每一项都是 4×4 矩阵的乘积再求迹，计算量随 n 的四次方增长。程序 25.4.1 用这个公式和算法 25.2.1 计算同一组数据，力矩相差 ${{ex25_4.err_le:sci1}}$ N·m。

### 25.4.2 数一数运算次数

为了公平，两种算法都按通用的程序来写：关节轴是任意的单位矢量，连杆参数任意，程序不跳过任何零元素；递推用三维矢量的写法（R、p、ω、v 分开算，思路与卢、沃克、保罗相同，但关节轴取任意方向、不利用 DH 参数的结构，也没有专门优化，所以次数比原论文的多），拉格朗日-欧拉用 4×4 矩阵（最后一行总是 (0, 0, 0, 1) 或 0，按 3×4 算，这是通常的做法）。三角函数两种算法都只对每个关节求一次，不计入。程序 25.4.1 让所有数据都带一个“计数器”，程序走一遍，就数出了它实际做的乘法和加法（减法算作加法）。

**命题 25.4.1** 算法 25.2.1 的运算次数是关节数 n 的一次式。

*证明*　前向、反向各有一个对 i 的循环。每一轮只用到本连杆和相邻连杆的量（$T_{i,i-1}$、$\mathcal V_{i-1}$、$\dot{\mathcal V}_{i-1}$、$\mathcal F_{i+1}$、$\mathcal A_i$、$\mathcal G_i$），做固定次数的 3×3 矩阵与三维矢量的乘法、叉积和加法，次数与 i、n 无关。所以总次数是 an + b。　∎

程序 25.4.1 数出的结果正是一次式：乘法 {{ex25_4.a_m}}n − {{ex25_4.nb_m}} 次，加法 {{ex25_4.a_a}}n − {{ex25_4.nb_a}} 次（n = 1～10 逐一核对）。常数项是负的，因为最后一个连杆没有下一级，反向递推的第一步不必把 $\mathcal F_{n+1}$ 换坐标。拉格朗日-欧拉的次数是 n 的四次式，首项系数（乘法）是 {{ex25_4.lead_m}}，加法是 {{ex25_4.lead_a}}。n = 6 时，拉格朗日-欧拉的乘法是递推的 {{ex25_4.ratio6:.0f}} 倍；n = 30（仿人机器人的量级）时，递推要 {{ex25_4.m30_rn}} 次乘法，拉格朗日-欧拉要约 {{ex25_4.m30_le}} 次，差一千多倍。图 25.4.1(a) 把它们画在对数坐标上：一次式是斜率为 1 的直线，四次式的斜率趋于 4。

正动力学（25.3.5 节）用 n + 1 次递推加一次楚列斯基分解，n = 6 时乘法 {{ex25_4.fd6_m}} 次、加法 {{ex25_4.fd6_a}} 次，主要花在 n + 1 次递推上，所以它随 n² 增长（图中斜率约为 2）；楚列斯基分解的 n³/6 次乘法要到 n 上千才占上风。

这些数还可以再小。针对一台具体的机器人，关节轴多半平行或垂直于坐标轴，$\mathcal A_i$ 和 $M_{i,i-1}$ 里有大量的 0 和 1；用符号计算预先展开、删掉乘零的项、合并相同的子式，生成专用的程序，运算次数还能减少很多。但无论怎样优化，递推是 O(n)、拉格朗日-欧拉是 O(n⁴)，这个差别改变不了。

### 25.4.3 实际用时

运算次数与机器无关，用时则与机器、语言、写法都有关。以下用时是在构建本书的计算机上测得的，换一台计算机会不同，但量级和比例差不多。

用 Python 写的算法，UR5e 算一次逆动力学：本书的 Chain.rnea（6×6 矩阵写法，每一步都调用 NumPy）约 {{ex25_4.t_np:.0f}} μs；三维矢量写法的递推约 {{ex25_4.t_sc:.0f}} μs；拉格朗日-欧拉写法约 {{ex25_4.t_le6:.1f}} ms，与 500 Hz 控制周期的 2 ms 是同一量级。MuJoCo（用 C 语言写成）的 mj_inverse 约 {{ex25_4.t_mj:.0f}} μs，其中大部分是 Python 调用和 MuJoCo 计算位置、速度相关量的开销。Python 解释执行，每次运算的开销比运算本身大得多，所以 Python 版本的用时并不与运算次数成比例；但在 C 语言或控制器的固件里，用时基本上就由运算次数决定：一千多次乘法，在今天的处理器上是微秒量级。

图 25.4.1(b) 是 MuJoCo 对 n 个连杆串成的链算一次逆动力学和正动力学的用时：n = 6 时约 {{ex25_4.t_inv6:.0f}} μs 和 {{ex25_4.t_fwd6:.0f}} μs，n = 96 时约 {{ex25_4.t_inv96:.0f}} μs 和 {{ex25_4.t_fwd96:.0f}} μs。两条线几乎重合，因为 MuJoCo 的这两个函数都先做“与位置有关”的一整套计算，包括用复合刚体算法求 M（随 n² 增长）和分解 M（随 n³ 增长），所以用时随 n 超线性地增长；在测到的范围内大致随 n² 增长。

再看 1980 年。卢、沃克、保罗用 PDP-11/45 小型计算机、浮点汇编语言写的递推，算斯坦福臂一次平均 4.5 ms；他们的论文指出，控制这台机械臂的采样频率不应低于 60 Hz，递推满足了这个要求，而计算量随连杆数四次方增长的拉格朗日方法做不到。今天的控制器要求 500 Hz 甚至更高，处理器也快了几个数量级，递推仍然是标准做法。

### 25.4.4 来龙去脉

20 世纪 70 年代末，机器人学界对“能不能实时算动力学”有过一场认真的讨论。拉格朗日-欧拉方程写起来系统，但计算量大，许多人认为实时控制只能用简化的模型（例如忽略速度项、只做重力补偿）。另一条路是查表：离线算好各种姿态下的 M、g，控制时插值，代价是巨大的存储量。1980 年，卢、沃克、保罗的递推牛顿-欧拉算法和霍勒巴赫的递推拉格朗日算法先后发表，霍勒巴赫还系统地比较了当时各种写法的运算量，结论是递推的写法都是 O(n)，其中递推牛顿-欧拉最省。从此，“动力学太慢、不能实时”不再是问题，计算力矩控制（第 44 章）也从论文走进了控制器。此后又有许多改进，例如巴拉福蒂斯（C. A. Balafoutis）等人 1988 年用笛卡儿张量的写法，按费瑟斯通和奥林的综述，六轴臂比早期的递推程序最多快到约 1.7 倍。

**工程师笔记**

- 比较算法的快慢先数运算次数，它与机器无关；用时要在目标平台上测，解释型语言的用时主要是调用开销，不能代表固件里的速度。
- 实时控制器里的动力学程序常由符号工具针对具体机器人生成，删掉乘零、乘一的项；通用程序（例如本书的 Chain.rnea）适合离线计算和检验。
- 计算量随关节数增长的速度决定了能做多大的系统：O(n) 的递推可以算几十个关节的仿人机器人、上百个连杆的绳索模型，O(n⁴) 的写法在 n = 10 时就已经要十几万次乘法。
