### 3.8.1 The problem

The conveyor comes in light-, medium- and heavy-duty versions, whose rollers use 6205, 6207 and 6209 bearings respectively, and each needs a pillow block. In CAD one can build a parametric model and generate the three sizes from a "design table". There is another way: write the design rules and the modeling steps as a program which, given a bearing designation, calculates all the dimensions, generates the 3D model and exports a STEP file. This is modeling in code.

### 3.8.2 Why model in code

Modeling in code (build123d, CadQuery, OpenSCAD and others) and modeling by clicking in a CAD interface produce the same kind of solid model. The advantages of code are:

- **The rules are spelled out**: how the wall thickness, center height and bolt size follow from the bearing designation is all in the program, where anyone can read and check it;
- **It can be compared and traced**: a program is text, so it can be managed with Git, and the difference between two versions is plain to see;
- **It can generate in batches**: one loop generates a whole product family, then produces drawings, calculates masses and exports STEP automatically;
- **It fits into automated workflows**: the online design bench of the digital factory (SH-301), the standard-part models of the parts library and the illustrations of this book are all generated by build123d programs.

The price is that for parts with complicated shapes that must be adjusted repeatedly by eye (such as styling surfaces), code is less convenient than interactive CAD. In engineering practice the two are often combined: code for the main bodies and for parts made in series, CAD for styling parts.

### 3.8.3 A parametric pillow block

**Example 3.8.1** Program 3.8.1 works in two steps: `params(bearing)` calculates all the dimensions by the design rules, and `model(params)` generates the solid in the order of its features. The design rules are:

- the bearing dimensions d, D and B are read from the standard tables of this book (GB/T 276);
- wall thickness = 0.12D + 3 (rounded), arc radius Ro = D/2 + wall thickness;
- the center height H is the R20 preferred number not less than Ro + 2 (Section 2.6), so that the center heights of one family fall on preferred numbers and the cross-members of the frame are easy to match;
- block width = bearing width + 14 (end-cover spigot 4 + shoulder 10), and the base is 12 wider than the block;
- anchor bolts: M8 for D ≤ 52, M10 for D ≤ 72, and M12 above that; hole spacing = 2(Ro + hole diameter + 2), base length = hole spacing + 3 hole diameters.

build123d code reads almost like plain language: `Box(L, Wb, tb)` is a box, `Pos(x, y, z) *` moves it somewhere, `+` is union and `−` difference, and `Cylinder(r, h)` is a cylinder. Without comments and blank lines the whole program is only {{ex3_8.n_lines}} lines long. The three sizes (Figure 3.8.1) are:

- 6205: center height {{ex3_8.H5}} mm, base length {{ex3_8.L5:.0f}} mm, {{ex3_8.bolt5}} anchor bolts, mass about {{ex3_8.m5:.2f}} kg;
- 6207: center height {{ex3_8.H7}} mm, base length {{ex3_8.L7:.0f}} mm, mass about {{ex3_8.m7:.2f}} kg;
- 6209: center height {{ex3_8.H9}} mm, base length {{ex3_8.L9:.0f}} mm, {{ex3_8.bolt9}} anchor bolts, mass about {{ex3_8.m9:.2f}} kg.

The masses are calculated for gray cast iron HT200 (7.2 g/cm³). The program also exports each size as a STEP file; the 6207 model has {{ex3_8.faces7}} faces, and its STEP file is about {{ex3_8.step7:.0f}} kB. STEP (ISO 10303) is the standard format for exchanging 3D models between CAD, CAE and CAM software: "Simulation & Analysis", NC programming and design release in the digital factory all read it.

### 3.8.4 Relation to the digital factory

The "Design & Process" page of the digital factory has an online design bench: the diameters and lengths of the segments of SH-301, its fillets and keyways are all parameters. Students change the parameters, the server regenerates the model and drawings with build123d, and the design is then submitted for release (Section 33.9). The 3D models of more than a thousand sizes in the parts library are generated in the same way: one generating program for each family of parts, and one model for each row of the size table. FreeCAD can run the same Python code; the WenQuest FreeCAD macro builds SH-301 in code.

**Engineer's notes**

- The coefficients in design rules (such as the wall thickness 0.12D + 3) must have a source: a standard, a handbook, company experience or a calculation. Rules without a source should be verified by test or analysis.
- Models generated by programs must be checked too: a single wrong symbol in the program makes the whole family wrong. Checking key values with assertions (`assert`) is the cheapest check there is.
- When handing a code model to someone else, hand over both the STEP file (the result) and the program (the intent).
