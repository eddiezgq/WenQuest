### 1.6.1 为什么要学计算

本书的每一个算例都有一段程序，书中计算得到的每一个数字都由程序算出。这样做有三个理由。第一，可以核对：读者手算的结果与程序不一致时，总有一方错了，找出错在哪里本身就是很好的练习。第二，可以探索：改一个参数、换一个函数，马上看到结果怎样变化，许多规律是这样“看出来”的，1.1 节的 $L_n$、$R_n$ 就是一例。第三，工程中的微积分问题绝大多数要靠计算机求数值解，会用计算工具本身就是工程师的基本功。

本书使用 Python 语言和三个免费的程序库：NumPy（数值数组与运算）、SymPy（符号运算，像人一样推导公式）、Matplotlib（画图）。读者可以在自己的电脑上安装 Python（例如 Anaconda 发行版，已包含这些库），也可以在问渠平台上直接阅读每个程序和它的运行结果。不要求读者事先会编程：本节只介绍本书最常用的几样东西，其余的在用到时再讲。

### 1.6.2 数和变量

Python 可以当作一个计算器用：

```python
>>> 0.25 * 2**2        # 乘方写作 **
1.0
>>> import math
>>> math.sqrt(2), math.pi, math.sin(math.pi / 6)
(1.4142135623730951, 3.141592653589793, 0.49999999999999994)
```

注意最后一个结果：$\sin\dfrac{\pi}{6}$ 应当是 0.5，计算机给出的却是 {{ex1_6.sin30}}。这不是程序错了，而是计算机用二进制的**浮点数**表示实数，只有约 16 位有效数字，大多数小数都只能近似地存储。再看一个更简单的例子：在计算机里，`0.1 + 0.2` 的结果是 {{ex1_6.f01}}，判断 `0.1 + 0.2 == 0.3` 得到 {{ex1_6.eq}}。比较两个浮点数是否相等，应当判断它们的差是否足够小，例如用 `numpy.isclose(0.1 + 0.2, 0.3)`，结果为 {{ex1_6.close}}。

这种微小的误差通常无关紧要，但在某些计算中会被放大，导致很大的错误。第 4 章、第 7 章将专门讨论这个问题：微积分里“$h$ 趋于零”的过程，在浮点数的世界里会遇到意想不到的麻烦。

### 1.6.3 NumPy：数组、相减与相加

NumPy 的核心是数组：一列（或一张表）数，可以整体运算。把 1.2 节 AGV 的位置函数 $x = 0.25\,t^2$ 在几个时刻的值算出来：

```python
import numpy as np
t = np.linspace(0, 2, 5)      # 从 0 到 2 等分取 5 个点
x = 0.25 * t**2               # 对每个元素平方、乘 0.25
```

得到 `t` = {{ex1_6.t}}，`x` = {{ex1_6.x}}。1.2 节的“相减”是 `np.diff(x)`，得到相邻读数之差 {{ex1_6.dx}}；再除以时间间隔 `np.diff(t)`，得到每一段的平均速度 {{ex1_6.v}}（m/s）。1.2 节的“相加”是 `np.cumsum`：把增量依次累加，恢复出位置。这两个函数在全书中反复出现，它们正是求导与积分在离散数据上的雏形。

### 1.6.4 SymPy：让计算机推导公式

NumPy 算的是数，SymPy 算的是式子。

```python
import sympy as sp
t = sp.symbols('t')
sp.limit(sp.sin(t) / t, t, 0)          # 极限
sp.diff(sp.Rational(1, 4) * t**2, t)   # 导数
sp.integrate(t**2, (t, 0, 1))          # 定积分
```

三行的结果分别是 {{ex1_6.lim}}、$ {{ex1_6.deriv}} $ 和 {{ex1_6.integral}}。第一个是第 4 章的重要极限；第二个说 $0.25\,t^2$ 的导数是 $t/2$，与 1.2.3 节的速度一致；第三个是 1.1 节曲线 $y = x^2$ 下方的面积，正是我们由 $L_n$、$R_n$ 猜出的 $\tfrac13$，而且是精确的分数，不是近似值。

SymPy 很有用，但不能代替自己的理解。它能告诉我们答案是 $\tfrac13$，却不能告诉我们为什么；有时它给出的结果形式很复杂，需要我们会化简、会检查；它也可能在特殊情形下给出不完整的答案。本书的做法是：手算推导，程序核对。

### 1.6.5 画图

把函数画出来，常常一眼就能看出许多性质。本书的插图都是用 Matplotlib 由程序画的。最简单的画图只需几行：

```python
import matplotlib.pyplot as plt
t = np.linspace(0, 4, 200)
plt.plot(t, 0.25 * t**2)
plt.xlabel('t / s'); plt.ylabel('x / m')
plt.show()
```

### 1.6.7 生活中的例子

很多人用手机计算器算 $0.1 + 0.2$，看到的是 0.3。原因因计算器而异：有的计算器用十进制运算，结果本来就是精确的 0.3；有的用二进制浮点数，只是在显示时把结果四舍五入到了十几位以内，内部的误差被藏起来了。电子表格软件多属后一种。所以“计算器上看着没问题”不代表内部没有误差；需要精确比较时，要像 1.6.2 节那样留出一个容许误差。

**工程师笔记**

- 程序中的角度一律用弧度，`math.sin`、`numpy.sin` 都以弧度为参数；从图纸、示教器读到的度数先乘 $\pi/180$。这是初学者最常见的错误之一。
- 判断浮点数是否相等，用 `numpy.isclose` 或 `math.isclose`，并明确容许误差；判断某个量是否为零，用“绝对值小于某个阈值”，阈值要根据问题的量级来定。
- SymPy 适合推导和核对公式，NumPy 适合大规模数值计算。工程中常见的做法是：用 SymPy 推出公式，再转换成 NumPy 函数（`sympy.lambdify`）高速计算。
