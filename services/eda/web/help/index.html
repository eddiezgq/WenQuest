起草台怎么用

起草台把一句话需求变成一份电路板设计描述。AI 只起草，判定都由代码做；草稿不存服务器，你确认后下载。

一、写需求

写清楚电压、电流、电机、接口。例如：“给 400 W、48 V 的机器人关节伺服电机做一块驱动板，额定相电流 8.5 A，峰值 30 A，带 2500 线增量编码器和 CAN。”需求框下面有三个示例可以点。

本版只做三相电机驱动板：九种功能单元（母线输入、辅助电源、半桥、栅极驱动、电流采样、MCU、增量编码器、SSI 编码器、CAN），拓扑固定。别的板子、别的接口会列在“目录里做不了的”里。

二、看草稿：每个数都有来源

  • 需求原文你写的需求里有这个数，下面是引用的原话。代码会核对：引用的话必须真在需求里，并且含有这个数。
  • 规则推出由需求里的数按规则算出来，下面写着用了哪些数。
  • AI 假设需求没说、AI 先提的，整行标成铜色，下面是要你回答的问题。请逐个看过。
  • 人填你在页面上改过的数。
  • 模板默认没人动过，沿用驱动板模板的值。

必须有的规格（母线电压、额定和峰值相电流）AI 不许假设：需求里没有，就留空、提问，页面上方会提示“缺必须有的规格”，你填上再重算。

“被代码退回的数”是 AI 给了、但没通过校验的数：不在目录里、超出范围、来源不成立。这些数没有进设计。

三、看结论、改数、重算

上方四个数是所有判定的结论：通过、不通过、待核对（用到的器件数据还没人对照规格书核对，不算通过）、未知（缺数据）。展开“计算书”能看到每个功能块怎么算的、仿真对照、出处。

在规格表和功能块参数里改数，点“按改过的数重算”。只列 AI 可以改的参数，范围以外的数会被拒绝并说明原因。

四、板子检查

计算书下面是“板子检查”：用驱动板模板已经布好线的板子，按你这份草稿的规格再查一遍。不重新布线（服务器上布一次线要几十分钟），所以规格改了、板子没跟着改的地方会在这里报出来。例如额定相电流改大，“大电流走线宽度”会变成不通过：电机线、母线要的线宽按 IPC-2221 跟着电流变。

  • 工艺：线宽、线距、孔、孔环、阻焊桥、铜到板边、器件外框、极性方向、器件到板边、ICT 测试点覆盖、大电流线宽。门槛来自示例贴片厂的工艺能力表（虚构）和设计描述里的设计规则。
  • 布局约束：功率回路面积、采样电阻的开尔文接法、去耦电容离芯片电源脚的距离、发热件离怕热件的距离、接插件在板边。限值是示例值，出处写在每一条后面。
  • 热：先算每个功率管的导通、开关损耗和采样电阻的损耗，再把板子当一块平板算温度，得出结温和上限比。这是布局阶段的保守估算，不替代样板实测；功率管导通电阻用的是 25 ℃ 的值，没超上限时只能判“未知”。

不通过、未知的项排在前面；通过的收在“通过的 N 项”里。完整的报告（带温度分布图）由工程师用 python3 -m wqeda.report 生成。

五、确认并下载

勾选“我已看过标成‘AI 假设’的数”，再点“下载设计描述（YAML）”。文件里 draft.provenance 记着每个数的来源。板子层（摆放、铺铜）本版沿用驱动板模板，按新规格重新布局在下一期做。

六、次数与记录

AI 起草要登录问渠账号，每人每天有次数上限。每次调用模型都有记录：谁、需求摘要、用的模型、是否通过代码校验。美国站用 Claude，国内站用已备案的 DeepSeek。

七、问渠贴片（工厂端）

起草台页头的“问渠贴片”是给贴片厂用的：上传客户的光绘、钻孔、物料清单和坐标（CSV），选按哪家工厂的工艺能力查，十几秒出检查结果、板图上的位置和数量统计（报价依据，只算量）。点“用演示资料包”可以直接试：驱动板 A 版，故意漏了一个物料编号。

  • 光绘里没有网表和器件外框，有几项查不了，判“未知”；有极性的元件列出来请人确认方向。
  • 列名、层认错了，在“列映射与层”里改，再查一次。
  • “AI 起草问题单”：AI 只拿到没通过的检查结果，拿不到文件；每条问题必须引用一条检查结果，编出来的会被退回。改完、勾选确认后下载：YAML 给设计端，Markdown 给客户。
  • 检查结果下面有“物料清单（到外部库查）”：同一物料编号、数值、封装合成一行，每行带搜索链接——芯片、功率管按型号查 SnapMagic、立创 LCSC、DigiKey；电阻、电容、电感、晶振按“封装尺寸 + 数值”、JST 插座按型号查 LCSC、DigiKey；认不出的行写“—（不猜）”。LCSC 是嘉立创贴片用的深圳现货库，点开能看有没有货、价格。链接只是方便查找，不参与任何检查；物料清单只回显给上传的人，不存。
  • 上传的文件算完就删，不存服务器，也不用来训练。演示工厂都是虚构的，工艺能力是示例值。

九、网页审图

起草台页头的“网页审图”：不装软件，在浏览器里看原理图和板子。

  • 选一块示例板子，右边列出它报告里没通过的项，点一条，板子上跳到那个器件（或那个位置）。
  • “打开自己的 KiCad 文件”：可以多选原理图、板子文件。文件只在浏览器里打开，不上传，所以这里不做检查；要检查，请用问渠贴片上传资料包，或在 KiCad 插件里跑。
  • 看图用的是开源的 KiCanvas（MIT 许可），滚轮缩放，拖动平移。

十、KiCad 插件（KiCad 9 起）

在 KiCad 的板子编辑器里，一键检查打开着的板子。判定和网页、工厂端是同一套确定性代码，不调 AI、不联网。

  1. 下载插件：wenquest-eda-kicad-plugin.zip。
  2. 解压，把里面的 wenquest-eda 文件夹放进 KiCad 的插件文件夹：Windows 是“文档\KiCad\9.0\plugins”，macOS 是“~/Documents/KiCad/9.0/plugins”，Linux 是“~/.local/share/kicad/9.0/plugins”。
  3. KiCad 里打开“首选项 → 插件”，勾选“启用 KiCad API”，重启 KiCad。第一次会自动给插件装它要的 Python 库（kicad-python、shapely、PyYAML），要等一会儿，装好后板子编辑器的工具栏上多一个绿色圆形按钮。
  4. 按下按钮，浏览器里开一个只在本机的结果页：每条结果点“定位”，KiCad 里选中那个器件并放大；“把摆放读回设计描述”在 design.yaml 旁边写一份 design.readback.yaml（原文件不动）；“出报告”写在工程文件夹的 wqeda-report/。

工艺能力表：工程文件夹里放 wqeda-factory.yaml 就按它查；没有就用插件自带的示例工厂（虚构，示例值）。KiCad 9 的插件还不能在编辑器侧边嵌面板，所以结果在浏览器里看。KiCad 7、8 用命令行：python3 -m wqeda.report、python3 -m wqeda.readback。

English, in brief

Write a requirement; AI drafts the specification and block parameters with a source for every number (requirement quote, derived rule, AI assumption, entered by you, template default). Code checks the draft, expands the circuit and runs the calculations and simulations; required values the requirement does not give are left empty with a question, never guessed. Edit, recalculate, tick the confirmation and download the design description. Board checks re-check the template's routed board against your specification (process, layout constraints, thermal estimate) without re-routing, so a larger current shows up as a failing trace width. This version covers one board family (three-phase motor drive). Example design, not for production.

Web review (/eda/view/): view schematics and boards in the browser with KiCanvas; click an open item from the report to jump to it; your own KiCad files are opened in the browser and never uploaded. KiCad 9 plugin: download the zip, put wenquest-eda in KiCad's plugins folder, enable the KiCad API under Preferences → Plugins; the toolbar button checks the open board and opens a local results page with jump-to, placement read-back and report. Short help videos above (AI answers in them are prepared examples).

WenQuest PCBA (factory side, /eda/factory/): upload a customer's Gerber, drill, BOM and placement files, pick a factory capability table and get the checks, locations on the board and quantities for quoting. AI drafts an engineering query from the open results only (never from your files); every item must cite a result. Below the results, “Bill of materials (look up outside)” merges rows by part number, value and package and gives search links (chips by part number on SnapMagic, LCSC and DigiKey; passives by package size + value on LCSC and DigiKey; rows it cannot read get “— (no guess)”). Links only; not part of any check. Files are deleted after the check. Demo factories are fictional.
