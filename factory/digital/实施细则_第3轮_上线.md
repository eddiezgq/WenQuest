## 一、目标

把第 1 轮做好的数字工厂放到网上，学生和老师用问渠账号登录就能进厂使用；以后每次推送 `factory/` 自动测试、构建、部署，边用边开发。

| 地址 | 内容 |
|---|---|
| `https://factory.wenquestrobotics.com` | 数字工厂工作台（首页运营看板、五个角色工作区、3D 车间、AI 工厂助手、实验 7） |
| `https://erp.wenquestrobotics.com` | ERPNext 减速器厂（老师和管理员直接登录用；学生通过工作台使用） |

## 二、现状与上线前必须解决的问题

第 1 轮按“自己电脑上用”设计，直接放上公网有四个问题：

| 问题 | 现在 | 上线后 |
|---|---|---|
| 登录 | 填个名字就能进，任何人都能选“厂长”、重置情景、制造故障 | 用问渠账号登录（见 D2） |
| 数据总线 | 匿名可读可写，端口直接开放 | 各服务用独立账号；浏览器只读，经 HTTPS 连接（D5） |
| ERPNext | 管理员和数据库密码都是 `admin` | 首次安装时自动生成强密码，只存服务器 |
| AI 工厂助手 | 不限次数，每次提问都调用 Claude | 每人限次（D7） |

## 三、决定（待确认）

| 编号 | 决定 | 说明 |
|---|---|---|
| D1 | **先和学习平台放在同一台 DigitalOcean 服务器上**（第 1 轮 F3 原定“另开一台”，改为以后需要时再分出去） | 现成的自动部署、HTTPS、每日备份都能直接用，你只需加两条域名解析。数字工厂单独一个目录 `/opt/wenquest-factory`、单独一组容器，经独立网络接到学习平台的 Caddy，做法与已在这台服务器上的 QMS 演示相同。部署时先检查空闲内存：服务器现为 4 核 8 GB，加上 ERPNext 约多用 3 GB；不够时部署会停下并提示，你在 DigitalOcean 控制台把服务器升到 16 GB（几分钟，数据不丢） |
| D2 | **用问渠账号登录**：在学习平台登录过的人打开工作台直接进入；没登录的看到“用问渠账号登录”按钮，跳到学习平台登录页，登录后回来 | 工作台服务器拿浏览器带来的全站登录凭证，向学习平台核对身份，并知道此人是否老师。不另建账号 |
| D3 | **权限**：学生只能用教学模式，可自选计划员、工艺员、操作工、质检员角色做实验 7；老师另可用厂长角色和生产模式，并可使用教师控制台（重置情景、改倍速、制造故障） | |
| D4 | **第一阶段只有一座公共工厂**：所有人进同一座工厂、看到同一份实时数据；实验评分按人分开记 | 每个班或每个学生一座独立工厂放到以后的轮次 |
| D5 | **数据总线加锁**：关闭匿名；枢纽、仿真、桥接各用一个账号，按附录 A.4 第 7 条按主题授权；浏览器经 `wss://factory.wenquestrobotics.com/mqtt` 连接，只能订阅、不能发布；1883 端口不对外 | 写操作本来就只经枢纽接口（F14），不影响现有功能 |
| D6 | **ERPNext 上线**：用官方 v16.34.1 镜像，首次安装自动建站、生成密码、导入减速器厂数据（`seed.py --opening-stock`）、给桥接生成 API 钥匙；管理员密码只存服务器 `.env`，部署日志里告诉你去哪里看 | 学生暂不开 ERPNext 账号，经工作台使用；以后按需给学生开只读账号 |
| D7 | **AI 工厂助手用 Claude**（服务器在美国，符合 F15）；密钥沿用学习平台服务器上已有的那把；每人每小时最多 30 次提问，超出时提示稍后再试 | 次数可在 `.env` 里改 |
| D8 | **Node-RED 不对外开放**，只在服务器内部运行；需要看数据流时用 SSH 隧道打开（帮助文件写步骤） | 避免数据流被人改动 |
| D9 | **仿真 24 小时运行**，倍速 20×；历史库只保留最近 30 天的总线消息，每天凌晨清理一次 | 防止数据库无限增长 |
| D10 | **自动部署**：新增工作流“数字工厂部署”，只在推送改动 `factory/` 时运行：自动测试（含完整闭环）→ 构建镜像推到 GitHub Packages → 登录服务器更新数字工厂 → 检查网址可以打开 | 学习平台的部署照旧忽略 `factory/`；两边互不影响 |
| D11 | **备份**：每天 03:30 的备份加上数字工厂历史库和 ERPNext 数据库，一起传到 Spaces 异地保存 | 与学习平台同一套备份和恢复方法 |
| D12 | **本地开发不变**：你 Windows 电脑上的 `docker compose up` 和 `update.ps1` 照常可用；上线只是另加一个“服务器配置”文件 | |

## 四、你需要做的（约 5 分钟）

在域名注册商的 DNS 设置里加两条 A 记录，都指向学习平台那台服务器的 IP（和 `learn` 同一个）：

| 类型 | 名称 | 值 |
|---|---|---|
| A | `factory` | 服务器 IP |
| A | `erp` | 服务器 IP |

其余全部由自动部署完成。GitHub 里已有的部署密钥（`DEPLOY_HOST`、`DEPLOY_SSH_KEY`）直接沿用，不用新加。

## 六、施工顺序

1. 服务器配置：数字工厂与 ERPNext 的服务器版容器配置、Mosquitto 账号授权、Caddy 增加两个网址。
2. 登录与权限：枢纽接问渠账号，按 D3 限权限，AI 限次；工作台登录页改为“用问渠账号登录”。
3. 部署脚本与工作流：安装（首次建站、生成密码、导入数据、生成 API 钥匙）、更新、状态、备份；内存检查。
4. 本地按服务器配置整体测试，完整闭环通过。
5. 推送上线（需要你先加好两条域名解析），跟踪部署结果。
6. 线上实测，写帮助文件，按实际结果更新本细则。
