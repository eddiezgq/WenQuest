## 一、起因

左侧“ERPNext”入口对所有人显示，但 ERPNext 有自己的账号体系，点进去要另外登录，学生没有账号，看起来像坏了。Eddie 选第 3 种：用问渠账号直接进 ERPNext，不另外登录。

## 二、决定

| 编号 | 决定 | 理由 |
|---|---|---|
| E1 | **数字工厂枢纽当“登录中转”（OAuth2 授权方）**，ERPNext 用自带的“社交登录”（Social Login Key，自定义提供方）接入。枢纽本来就会向学习平台核对问渠账号，加三个标准接口：授权 `/api/oauth/authorize`、换令牌 `/api/oauth/token`、用户信息 `/api/oauth/userinfo` | 不改 ERPNext 源码、不做自定义镜像；学习平台也不用改 |
| E2 | **自动登录**：没登录的人打开 ERPNext 会被送到登录页，登录页上的一小段网站脚本（Website Script）自动点“用问渠账号登录”。管理员要用密码登录时打开 `erp.<域名>/login?manual=1` | 做到“点进去就是登录状态” |
| E3 | **账号自动开**：每次通过问渠登录时，枢纽先用管理员钥匙在 ERPNext 里建好或更新这个人的账号（系统用户，邮箱为 `wq<问渠编号>@users.<域名>`，名字用问渠姓名），再交给 ERPNext 登录；ERPNext 里不允许“自助注册” | 账号由我们控制，权限一致 |
| E4 | **权限**：老师（能建课的账号）→ 工厂运营的各个经理角色（制造、库存、采购、销售、质量、物料），可直接在 ERPNext 里操作，**不给系统管理员**；学生 → 新建角色“问渠学生（只读）”，只能**查看**订单、工单、作业卡、物料、BOM、库存、请购、质检等单据，不能改。每次登录按当前身份重设角色 | 公共工厂里很多学生同时做实验，学生改动一律经工作台和桥接（有记录、可评分）；按第 3 轮 D6 的“只读账号” |
| E5 | **ERPNext 侧设置自动完成**：每次部署时 `seed.py` 用管理员钥匙检查并补齐“问渠”社交登录、网站脚本、只读角色及其查看权限；连接用的密钥首次部署自动生成，存服务器 `.env` | 不需要任何人手工进 ERPNext 配置 |
| E6 | **安全**：授权码 2 分钟有效且只能用一次；只接受回调到 `erp.<域名>` 的请求；换令牌必须带密钥；ERPNext 与枢纽之间换令牌走服务器内部网络 | 标准做法 |

## 三、规则

1. 登出 ERPNext 后会被自动重新登录（因为问渠账号仍在登录状态）；要彻底退出，请退出学习平台。帮助里写明。
2. 管理员 `Administrator` 的密码登录保留（`/login?manual=1`）。
3. 学生在 ERPNext 里看到的是同一座公共工厂的全部单据（与工作台一致），没有个人隐私数据。

## 四、交付物与验收

| 交付物 | 验收 |
|---|---|
| 枢纽 OAuth2 三个接口 | 单元测试：授权码一次性、过期、回调地址校验、密钥校验、老师/学生信息正确 |
| ERPNext 自动配置 | “服务器演练”（真 ERPNext）里：部署脚本配好后，用脚本走一遍完整登录（打开登录页 → 自动跳转 → 授权 → 回到 ERPNext），确认以该用户身份登录；学生账号读得到工单、改不了 |
| 线上 | 部署后线上检查 ERPNext 登录页带“用问渠账号登录”；**Eddie 用老师和学生账号各点一次左侧 ERPNext** |
| 帮助 | 使用说明、上线与维护帮助更新 |

## 五、施工顺序

1. 枢纽 OAuth2 接口 + 测试。
2. `seed.py --erp-sso`：社交登录、网站脚本、只读角色与权限；`install.sh`/`update.sh` 生成密钥并在每次部署时执行；服务器配置把密钥传给枢纽。
3. “服务器演练”里加完整登录测试。
4. 推送上线，跟踪部署；帮助；逐条验收写回本细则。
