# 问渠数字工厂 · 实施细则 · 第 18 轮 E7：经营与财务领域包

2026-10-08 · 依据：`docs/方案/厂情中枢架构与方案.md` 第九节“领域包”E7（经营目标与指标树、预算、应收应付、毛利、成本差异、经营周报）；承接第 17 轮工单成本（F1）、E1 合同条款（违约金）、E3 维修费用、E4 工时、E5 采购单与收货、E6 电费。

> 状态：**待确认**。第八节六个问题，Eddie 确认后施工。

## 一、目标

现在厂情中枢能算“工单多花了多少”（F1 成本差异）、每个方案“多花多少钱”，但工厂的账还没合上：
- 货做完了没有发货单、没有发票，客户什么时候付钱、欠了多久，都不知道（F2 应收逾期一直“待数据”）；
- 采购收了货，供应商的发票、什么时候付款也没有；
- 一张订单到底赚多少——料、工、电、废品、保修都算上——没有；
- 厂长定的经营目标（准时交付、毛利率、一次合格率、单件能耗……）和各领域的数没连起来，预算花了多少也看不到。

E7 把钱接进工厂主线：**订单 → 生产 → 发货 → 开票 → 收款**、**采购 → 收货 → 供应商发票 → 付款**，再把各领域的成本汇成**每张订单的毛利**，把各领域的指标挂到**经营目标的指标树**上，按月对**预算**。核心是三个取舍：
- 客户欠款逾期：催款、停止给他发货（信用冻结），还是先不管（他是大客户、订单还在做）；
- 一张订单毛利低：是料贵、工时超、废品多，还是报价低——下次报价怎么改；
- 预算超支：调预算，还是压某项开支（加班、急单、外协）。

按领域包的标准做齐六样：采集应用、教学模拟器、规则、动作、态势卡、帮助；再加 AI 代理的工具和评测题、一个新实验。E7 做完，十五个领域都接上，厂情中枢不再有“待数据”的规则。

这一轮结束时，三个验收故事要能在网页上完整走通：

**故事一：客户欠款逾期**
1. 东港码头的一张订单发货、开票（ERPNext 发货单、销售发票），付款条件 30 天；客户晚了 15 天还没付。
2. 厂情中枢开“应收逾期”：欠多少、逾期几天、这个客户还有哪些在做的订单、信用额度用了多少。
3. 右栏方案：发催款函 / 信用冻结（他的新订单要厂长批才能发货）/ 不处理（对照）。看现金流预测：不收回来，下个月哪一周现金不够付供应商。
4. 采纳“催款”：生成催款函（教学模式只记录，不发出）；客户（模拟器）几天后付款，ERPNext 收款单，应收清零。

**故事二：一张订单毛利低**
1. 一张 WQR-105 的订单做完：收入 $X；料（BOM × 采购价）、工（各工序实际工时 × 费率）、电（E6 单件电量 × 电价）、废品返工、急单和加班（推演采纳过的动作）都算上，毛利率 12%，目标 25%。
2. 厂情中枢开“订单毛利低于目标”，因果链连到花钱最多的几项：磨削工时超标、来料不合格后下的急单。
3. 学生按分解写改进：下次报价、工艺、供应商各改什么（不进推演，记进复盘）。

**故事三：本月能源预算超支**
1. 本月能源预算 $4,000，过半个月已花 $2,600（进度 50%，超 30%）。
2. 厂情中枢开“预算超支”：哪个成本中心、超多少、主要是哪几项（空转、峰时开炉）。
3. 方案：调整预算（厂长批）/ 不处理；并链到能源的节能方案。

## 二、决定（待确认）

| 编号 | 决定 | 理由 |
|---|---|---|
| E7-1 | **发货单、销售发票、收款，采购发票、付款以 ERPNext 为准**：Delivery Note、Sales Invoice、Payment Entry（收、付）、Purchase Invoice。平台经桥接写、轮询读回。**经营目标、指标树、预算、毛利分解、现金流预测在平台** | 账要进 ERPNext 的总账；目标和分析是平台的本事 |
| E7-2 | **教学模式自动开票**：订单的工单全部做完（最后一道检验完），平台按订单起草发货单 + 销售发票（教学模式自动提交；生产模式只起草提议，由会计确认）；E5 收货单提交后，起草采购发票（同样教学自动、生产提议） | 课堂上没有会计；生产模式不替会计做账 |
| E7-3 | **采集应用：新页“经营与财务”**（厂长、销售默认可见；“经营与成本”页并进来）。四个标签：<br>① **经营目标**：指标树（目标 → 指标 → 各领域的数），每个指标本月实际 vs 目标、红黄绿、趋势；<br>② **订单毛利**：每张订单 / 每个产品的收入、料、工、电、废品、急单加班外协、保修，毛利和毛利率；<br>③ **应收应付**：账龄（未到期 / 逾期 1–30 / 31–60 / 60 天以上）、每个客户的信用额度和余额、要付的供应商发票；现金流预测（未来 8 周，按到期日收付）；<br>④ **预算**：每个成本中心本月预算、实际、按进度应花、差额 | 方案“每个领域都有采集应用” |
| E7-4 | **毛利的口径**：收入 = 销售订单价；料 = BOM 用量 × 实际采购价（E5 批次的价格，期初按物料估价）；工 = 各工序实际加工 + 调整时间 × 工作中心费率（现有成本口径）；电 = E6 每件运行电量 × 当时电价；废品返工 = 不合格件的累计成本；急单、加班、外协、维修加急 = 推演采纳并执行的动作费用分摊到受益的订单；保修 = E1 服务工单费用记回原订单。都能点开看来源 | 一张订单从头到尾的钱；每一项都能追溯 |
| E7-5 | **指标树与预算**：经营目标（例如本年：准时交付 ≥ 95%、毛利率 ≥ 25%、一次合格率 ≥ 97%、单件能耗下降 10%、零重大安全事故、应收周转 ≤ 45 天）；每个目标挂几个指标，指标直接取各领域态势卡已有的数，不另算。预算按成本中心（生产人工、料、能源、维修、质量、服务、管理）按月；实际取 ERPNext 采购发票、平台工时、E6 电费、E3 维修、E1 服务。厂长在页面上改目标、预算 | 不重复造数，指标和态势卡一个口径 |
| E7-6 | **规则（7 条：F1 保留，F2 由“待数据”转为在跑，另加 5 条）**：<br>F2 应收逾期（逾期 > 0 天，超过 30 天为严重）；<br>F3 客户信用超限（应收余额 + 在做订单金额 > 信用额度）；<br>F4 供应商发票快到期、现金不够（未来 2 周应付 > 预测现金）；<br>F5 订单毛利低于目标（做完的订单毛利率 < 目标 − 5 个百分点）；<br>F6 预算超支（某成本中心本月实际 > 预算 × 时间进度 × 1.1）；<br>F7 经营指标偏离目标（指标树里某指标本月连续 2 周红） | 覆盖收、付、赚、花、目标 |
| E7-7 | **处理预案与新动作（4 种）**：<br>· 预案：F2 ——“催款 / 信用冻结 / 不处理（对照）”，看现金流预测怎么变；F3 ——“信用冻结 / 临时提额（厂长批）”；F4 ——“推迟付款（和供应商商量，影响评分卡）/ 加快催收 / 不处理”；F5、F7 —— 给分解和建议，不推演；F6 ——“调整预算 / 不处理”；<br>· 新动作：① **催款**（教学模式只记录；生产模式发邮件，沿用 E1 的客户通知）；② **信用冻结 / 放行**（这个客户的新发货要厂长批）；③ **付款**（ERPNext 付款单，厂长批）；④ **调整预算**（厂长批）；<br>· 审批：催款销售发起、厂长或销售主管批；冻结、付款、调预算厂长批 | 沿用 17C 的动作框架 |
| E7-8 | **教学模拟器（客户会晚付）**：开票后客户按自己的付款习惯付款（多数按时；个别客户常晚 10–30 天；催款后付款提前）；供应商发票按条件到期。时间压缩沿用 E5：客户的 1 天 = 真实 2 分钟。老师可以注入“某客户这张发票不付”。**教学模式默认开，载入实验 7 情景时关闭**，生产模式不模拟 | 和 E3–E6 同一个做法 |
| E7-9 | **经营周报**加“经营与财务”一节：本周收入、毛利率、收款、逾期应收、预算进度、偏离目标的指标；日报加一行现金与逾期 | 已有周报，补上钱 |
| E7-10 | **新实验 22“经营：订单毛利、应收与现金”**（4 学时）：在指标树里找偏离目标的指标 → 算一张订单的毛利（按分解表）→ 老师注入“某客户发票不付”→ 比较“催款 / 信用冻结 / 不处理”（比对模式，看现金流预测）→ 执行 → 写报价和成本的改进建议。自动评分 + 报告；指导书、报告模板、课程接口 | 每个领域包配一个实验；和实验 15 的成本差异、实验 20 的总拥有成本连起来 |

## 三、存储

平台新增 5 张表：

```
objective      (mode, code, name, metric, domain, target, direction, period, owner)   —— 经营目标与指标树
budget         (mode, month, center, amount, set_by, set_at)                             —— 每月各成本中心预算
order_margin   (mode, sales_order, item, qty, revenue, cost jsonb, margin, at)           —— 做完的订单的毛利分解（快照，可追溯来源）
credit         (mode, customer, limit_amt, hold, hold_by, hold_at)                       —— 信用额度与冻结
finance_sim    (mode, state jsonb)                                                       —— 模拟器开关、客户付款习惯、老师注入
```

ERPNext 侧：桥接新增写 Delivery Note、Sales Invoice、Payment Entry（收、付）、Purchase Invoice；轮询读回。本体里应收、应付转为“已有数据”，经营目标、预算转为“已有数据”。

1. 桥接与模拟 ERPNext：发货单、销售发票、收付款、采购发票（按 v16 字段）；订单做完自动开票（教学）、收货后采购发票。

6. 实验 22、帮助、方案；闭环测试第 19 段；服务器演练；上线。
