# 问渠数字工厂 · 实施细则 · 第 18 轮 E3：设备维护与资产领域包

2026-10-07 · 依据：`docs/方案/厂情中枢架构与方案.md` 第九节“领域包”E3；承接 E2（安全环保，已上线：挂牌上锁、虚拟维修工）、第 17 轮厂情中枢（推演、动作）、第 15 轮数字孪生（现场设备的寿命模型）。

> 状态：**已完成，已上线（2026-10-07）**。六个问题都按建议（2026-10-06，Eddie：“按建议”）。

## 一、目标

现在车间里的设备只会在老师注入故障时停机。它们没有台账、没有保养计划、没有点检、没有维修记录，也没有“该保养了”这回事。厂情中枢“设备维护与资产”一块只有“停机记录”有数据；规则 M2（预防性维护逾期）还是“待数据”。

E3 把设备的一生接进工厂：**台账 → 保养计划 → 点检 → 磨损和故障 → 维修 → 备件**。核心是一个取舍：保养要停机、花钱；不保养，设备迟早坏，坏的时候停得更久、更不是时候。按领域包的标准做齐六样：采集应用、教学模拟器、规则、动作、态势卡、帮助；再加 AI 代理的工具和评测题、一个新实验。

这一轮结束时，两个验收故事要能在网页上完整走通：

**故事一：保养逾期，磨床越来越容易坏**
1. 外圆磨床 GRD-01 的 500 小时保养（换液压油、查主轴轴承、校砂轮平衡）已经逾期 60 小时。厂情中枢开异常（预防性维护逾期），写出：按它的失效率，未来一周坏掉的概率从 5% 升到 22%，坏了平均要停 8 小时、修 $1,200。
2. 因果链：保养计划 → 这台设备 → 排在上面的工单 → 订单。
3. 右栏三个方案，用车间推演 + 失效风险算好：
   - 现在停 3 小时做保养；
   - 推到今天下班后（或周末）做；
   - 不做（对照）：按失效率算“预期停机”和“预期损失”，并推演“如果明天坏了”的交期。
4. 采纳“下班后保养”：生成保养工单（ERPNext 维护记录）；按时间自动开挂牌上锁许可（沿用 E2），设备停下 → 维修工做完 → 验收解锁 → 失效率回到起点。

**故事二：点检发现异常，备件不够**
1. 操作工开班前在手机上扫设备二维码点检：滚齿机 HOB-01 “润滑油位低、异响”。
2. 点检异常开维修单；维修要用的轴承库存低于最低库存，规则提示备件不足、建议紧急采购（沿用 17C 的紧急采购动作）。

## 二、决定（已确认）

| 编号 | 决定 | 理由 |
|---|---|---|
| E3-1 | **资产、保养计划、维修以 ERPNext 为准**：资产（Asset）、维护计划（Asset Maintenance，含保养任务和周期）、保养记录（Asset Maintenance Log）、维修（Asset Repair）。平台经桥接写、轮询读回。**点检、失效率模型、排程在平台**；备件就是 ERPNext 里的物料（已有） | 资产要进财务（折旧在 E7 经营与财务）；ERPNext 的资产维护模块现成 |
| E3-2 | **采集应用：新页“设备维护”**（维修工、厂长默认可见；手机好用）。四个标签：<br>① **设备台账**：每台设备的资产号、购置日期、原值、累计运行小时、距下次保养、失效率曲线、维修历史；<br>② **保养计划**：日历，每台设备的保养项目（周期按运行小时或天数）、下次到期、逾期标红；<br>③ **点检**：扫设备二维码（每台设备一张可打印的二维码）→ 按这台设备的点检表逐项打勾、异常拍照；<br>④ **维修与备件**：维修单（故障、原因、用时、用件、费用）、备件库存与最低库存 | 方案“每个领域都有采集应用” |
| E3-3 | **仿真车间加“会坏”**：每台设备一个失效率模型（威布尔分布，按自上次保养以来的运行小时计算），保养后复位；逾期越久越容易坏。坏了按故障种类停机（平均修复时间 MTTR），要备件的没备件就一直等。<br>· **教学模式默认开**，老师可以调“可靠性”（关 / 正常 / 加速 ×5，方便课堂上看到效果）；**生产模式默认关**（接真设备后故障来自设备本身）；<br>· 实验 7 情景不受影响（情景载入时关闭，开始实验后由老师打开） | 没有“会坏”，保养就没有意义；教学上要看得见取舍 |
| E3-4 | **保养和维修都要挂牌上锁**：开始保养 / 维修时自动开挂牌上锁许可（持证维修工，沿用 E2），设备停下；做完由另一人验收解锁。两个领域包在这里连起来 | 真实工厂的规矩；也是 E2 的自然延伸 |
| E3-5 | **规则（6 条，M2 由“待数据”转为在跑，另加 5 条）**：<br>M2 预防性维护逾期（按运行小时或天数）；<br>M3 点检异常未处理；<br>M4 失效风险高（未来 7 天故障概率超过阈值，默认 20%）；<br>M5 维修用备件低于最低库存；<br>M6 维修单超时没完成（超过平均修复时间的 2 倍）；<br>M7 平均故障间隔（MTBF）明显下降（近 30 天比之前低 30% 以上）。<br>原有 M1（同一设备反复停机）保留 | 覆盖计划、点检、预测、备件、维修时效、趋势 |
| E3-6 | **处理预案与新动作（3 种）**：<br>· 预案：M2 / M4 ——“现在保养 / 推到下班后（或周末）保养 / 不做（对照）”，用车间推演 + 失效风险（预期停机 = 概率 × MTTR，预期损失 = 预期停机的交期影响 + 维修费）；M3 ——“开维修单 / 先观察（下次点检复查）”；M5 ——沿用 17C 的紧急采购；<br>· 新动作：① **保养工单**（ERPNext 维护记录；到时间自动挂牌上锁）；② **维修工单**（ERPNext Asset Repair；挂牌上锁；用件出库）；③ **调整保养周期**（改维护计划的周期，要厂长批）；<br>· 审批：保养、维修要停机，厂长批；调整周期厂长批 | 沿用 17C 的动作框架 |
| E3-7 | **资产与点检表的初始数据**：车间 13 台设备各建一份资产（购置日期、原值按设备类型给）、1–3 个保养项目（例如磨床：日检 / 250 小时换砂轮修整器金刚笔 / 500 小时换液压油查主轴）、一张 5–8 项的点检表；部分保养设成“快到期”“已逾期”，教学一开始就有事可做 | 让台账和计划一开始就有内容 |
| E3-8 | **教学模拟器**：设备按失效率随机坏（教学模式、可靠性打开时）；点检每个班次由模拟器做一部分（偶尔报异常），其余留给学生；维修工按 MTTR 做完维修；老师可以注入“保养逾期”（把某台设备的保养往前拨）和“备件短缺” | 方案“每个领域包都有教学模拟器” |
| E3-9 | **新实验 18“设备维护策略：保养时机的决策”**（4 学时）：看台账和失效率曲线 → 手算某台设备未来一周的故障概率和预期损失 → 比较“现在保养 / 下班后 / 不做”（比对模式）→ 执行保养（挂牌上锁）→ 一周（仿真时间）后对比“做了”和“没做”的设备的停机记录；选做：用平台的故障数据估 MTBF、调整保养周期。自动评分 + 报告；指导书、报告模板、课程接口 | 每个领域包配一个实验；和实验 13（数字孪生的预测性维护）一里一外：一个管客户现场，一个管自家车间 |

## 三、存储

平台新增 5 张表：

```
reliability    (mode, unit, beta, eta_h, mttr_min, run_h_since_pm, last_pm, enabled)  —— 失效率模型参数和状态
checklist      (mode, unit, items jsonb)                                                —— 每台设备的点检表
inspection     (id, mode, unit, by_name, at, results jsonb, abnormal, photo_ids, repair_order)
failure        (id, mode, unit, kind, at, down_min, cause, parts jsonb, repair_order)    —— 故障记录（仿真车间发的 fault 事件 + 维修单补的原因）
maint_sim      (mode, state jsonb)
```

ERPNext 侧：桥接新增读写 Asset、Asset Maintenance、Asset Maintenance Log、Asset Repair（含用件），资产分类、维护团队首次使用时自动建。本体里资产、维护计划、维修单、点检、故障记录、备件从“ERPNext 可启用 / 待采集”转为“已有数据”。

- 教学：`POST /api/maint/reliability`（老师调可靠性）、`/api/lab18/*`

## 六、施工顺序

1. 失效率模型进仿真车间（默认关，现有测试不变）；可靠性开关；故障事件和故障记录。
2. 桥接读写 Asset / Asset Maintenance / Log / Repair；初始台账、保养计划、点检表；本体映射。
3. 保养与维修流程（挂牌上锁）、点检与二维码；规则 M2–M7。
4. 风险计算、处理预案、3 种新动作；“设备维护”页四个标签；态势卡、日报。
5. 教学模拟器、老师注入；AI 代理工具与评测题。
6. 实验 18、帮助、方案；闭环测试第 15 段；服务器演练；上线。

## 九、实施记录

### 1. 与细则的偏差（施工中定的，已按此实现）

| 条目 | 细则写的 | 实际做法 | 原因 |
|---|---|---|---|
| E3-2 页面 | 四个标签：台账 / 保养计划（日历）/ 点检 / 维修与备件 | 四个标签：设备台账（含距下次保养、失效率曲线、老师的可靠性开关、调整保养周期）/ 保养（保养单）/ 点检 / 维修与备件；没有做日历 | 保养按运行小时到期，日历上没有固定日期；“距下次保养”放进台账更直观 |
| E3-2 点检 | 异常拍照 | 逐项正常 / 异常 + 备注，暂不拍照（接口留了照片字段） | 先把流程做通；拍照沿用随手拍的上传，下期加 |
| E3-7 保养项目 | 每台 1–3 个保养项目，周期按运行小时或天数 | 每台一个保养任务（例如磨床“换液压油、查主轴轴承、校砂轮平衡”，500 运行小时）；周期以运行小时记在 ERPNext 维护任务的自定义字段 wq_interval_h，ERPNext 自带的周期填“每月”占位 | ERPNext 的保养周期只有日历周期；失效率按运行小时算，一台一个周期模型最清楚 |
| E3-5 M4 | 未来 7 天故障概率超过 20% | 未来 80 运行小时（单班约两周）超过 20%，超过 40% 为严重 | 运行小时和失效率模型同一单位；7 天在仿真倍速下太短，概率几乎都很小 |
| E3-5 M5 | 维修用备件低于最低库存 | 维修单要用的备件库存不够（等备件）；最低库存各 4 件只在页面上提示 | 真正卡住维修的是“不够用”，不是“低于最低库存” |
| E3-6 维修出库 | Asset Repair 带用件出库 | Asset Repair 只记维修（Pending → Completed，不提交）；用件走备件出库（Stock Entry，沿用 E1 的 ship_spares） | Asset Repair 提交会动资产价值（资本化），属于 E7；先不碰财务 |
| E3-6 预期损失 | 预期停机的交期影响 + 维修费 | 预期损失 = 概率 ×（修理费 + 平均修复时间 × 停机每小时少挣的毛利）；“不做”方案另外推演“如果现在就坏”订单晚几天。参数：人工 $45/小时，保养材料 $80，磨床修理 $1,200、停机 $200/小时（瓶颈），滚齿机 $900、$120/小时，其余 $400、$60/小时 | 交期影响单独显示，避免把“晚几天”和钱混在一个数里 |
| E3-7 初始状态 | 部分保养快到期、已逾期 | 情景开始时磨床已运行 620 小时（周期 500，逾期 120 小时），其余在周期内 | 一开始就有一条 M2，且磨床的经济账推荐“现在保养” |
| 角色 | — | 新角色“维修工”（maintenance），发起保养 / 维修 / 调整周期；厂长批准 | E3-6 需要有人发起 |
| E3-8 模拟器 | 维修工按 MTTR 做完；点检每班做一部分；老师注入“保养逾期”和“备件短缺” | 维修 / 保养按标准分钟 ÷ 30 的真实时间做完（至少 1 分钟），等人验收；故障维修单做完 3 分钟没人验收，班组长（模拟器）替验收解锁（车间不会一直锁着）；每 5 分钟（真实时间）点检一台，15% 报异响；老师注入“运行小时拨到逾期”和可靠性系数；“备件短缺”没有单独按钮（故障要用的轴承不够时自然出现） | 无人值守时车间也能自己恢复 |
