## 一、目标

厂情中枢的“安全、健康与环境”一块现在是灰的：本体里有危险源、隐患、事故、作业许可、培训、化学品、废弃物这些类型，但都是“待采集”；规则 E1–E4 都是“待数据”；全厂态势里这块卡片写着“待接入”。

E2 把安全接进工厂的主线：**一条隐患不是孤立的一张单子，它会让一台设备停下来，进而影响工单、订单和客户**。按领域包的标准做齐六样：采集应用、教学模拟器、规则、动作、态势卡、帮助；再加 AI 代理的工具和评测题、一个新实验。

这一轮结束时，两个验收故事要能在网页上完整走通：

**故事一：一张隐患照片，停一台磨床，算出对交期的影响**
1. 操作工在手机上“随手拍”：外圆磨床 GRD-01 的防护罩松脱、砂轮外露。选设备、选等级（重大）、拍照，提交。
2. 厂情中枢马上开异常（重大隐患未关闭），因果链连到：这台设备 → 排在它上面的工单 → 订单 → 客户。
3. 右栏三个方案，用 17C 的车间推演算好交期和花费：
   - 立即停机挂牌、整改（停几小时，按整改工时估）；
   - 限时整改：加临时防护、降速运行到下班后再停；
   - 停机整改，同时把能改派的工序改到同类设备、或加班补回。
4. 采纳“立即停机挂牌”：开一张挂牌上锁（LOTO）作业许可 → 车间里这台设备真的停下来（不能被派活）→ 维修整改 → 安全员验收、解锁 → 设备恢复。
5. 隐患关闭后，复盘对比“当时估的停机时长、交期影响”和实际。

**故事二：作业许可卡住没资质的人**
1. 维修工要给热处理炉做受限空间作业，申请作业许可。
2. 平台核对：这个人的“受限空间作业”培训已经过期 → 许可不能批（规则 E3），提示先安排复训或换有资质的人。
3. 安全培训快到期的人，提前 30 天出提醒（规则 E4）。

## 二、决定（待确认）

| 编号 | 决定 | 理由 |
|---|---|---|
| E2-1 | **数据放平台自己的表，不放 ERPNext**：ERPNext 没有像样的安全模块；隐患、作业许可、事故、培训、化学品、废弃物都由平台自建，同步进本体。整改要用的维修工单仍然走 ERPNext（和数字孪生的维修单一样，经桥接开 Issue / 维修单） | 不为了“以 ERPNext 为准”硬塞；整改花钱、用备件的部分仍进 ERPNext |
| E2-2 | **采集应用：新页“安全环保”**（所有角色可随手拍；安全员、厂长管理；手机上好用）。五个标签：<br>① **隐患**：随手拍（设备或区域、等级一般 / 重大、照片、一句话），整改人、期限、验收；<br>② **作业许可**：动火、高处、受限空间、挂牌上锁四种；申请 → 资质核对 → 批准 → 作业中 → 关闭；<br>③ **事故与未遂**：登记、5 Why 根因、纠正措施（3 级敏感：只有厂长和老师看得到详情，其他人只看到数量）；<br>④ **培训与资质**：每人每类培训的有效期，快到期、已过期标红；<br>⑤ **化学品与废弃物**：切削液、淬火油、润滑油的存量和安全数据表；废切削液、废油、含油抹布的产生和处置台账 | 方案“每个领域都有采集应用”；先做工厂里真有的几样 |
| E2-3 | **人员：先建 12 位虚拟员工**（操作工、维修工、安全员、班组长），各有岗位和培训记录，存平台的表；人员领域包（E4）上线后并入员工档案和技能矩阵。E1 的 6 位服务工程师不动 | 作业许可、培训都要“人”；现在没有人员数据 |
| E2-4 | **挂牌上锁真的让设备停下**：批准一张挂牌上锁许可 → 经车间（MES）把这台设备设为“不可用”（和老师注入停机同一个机制，原因写“挂牌上锁：许可证号”）；解锁 → 恢复。设备挂着锁时车间不会给它派活；推演、指挥台、3D 车间都显示“挂牌上锁” | 安全和生产在一张图里：这是 E2 最重要的连接 |
| E2-5 | **规则（7 条，E1–E4 由“待数据”转为在跑，另加 3 条）**：<br>E1 重大隐患未关闭（严重）；<br>E2 隐患整改逾期；<br>E3 作业许可缺资质（申请人相关培训过期或没有，严重）；<br>E4 安全培训 30 天内到期 / 已过期；<br>E5 挂牌上锁期间设备有运行信号（严重：可能有人违规解锁）；<br>E6 化学品存量超过限额 / 低于安全库存；<br>E7 危险废物暂存超过 90 天（按国内法规的常见期限，参数可改） | 覆盖隐患、许可、培训、LOTO、化学品、废物 |
| E2-6 | **处理预案与新动作（4 种）**：<br>· 预案：E1（重大隐患）——“立即停机挂牌整改 / 限时整改（临时措施，降速，下班后停）/ 停机整改 + 改派或加班”，**用 17C 的车间推演**算交期和花费（整改时长按隐患种类的标准工时估，可以改）；E2 ——“催办 / 改派整改人 / 延期（要写理由）”；E3 ——“换有资质的人 / 先安排复训”；<br>· 新动作：① **开挂牌上锁许可并停机**（车间设备不可用）；② **整改工单**（经桥接进 ERPNext 维修单，带工时和备件）；③ **解锁恢复**（安全员验收后）；④ **安排培训**（给一组人排一场培训，完成后更新有效期）；<br>· 审批：停机挂牌、整改工单要厂长批；解锁要安全员验收（不能是申请人自己）；安排培训安全员就能批 | 沿用 17C 的动作框架：试运行 → 审批 → 执行 → 写回本体 |
| E2-7 | **风险评估用最常见的“可能性 × 严重度”矩阵**（各 1–5 分，乘积 ≥ 15 为重大、8–14 为较大、其余一般）；危险源清单先给 12 条（每台主要设备 1–2 条），每条带控制措施；隐患登记时可以选关联的危险源 | 简单、教学常用、和课程里讲的一致 |
| E2-8 | **教学模拟器（教学模式）**：<br>· 每个班次按概率在各设备附近生成隐患（漏油、防护罩松动、地面有切屑、灭火器过期……），大多数是一般隐患；<br>· 少量“未遂事件”（例如切屑飞溅没伤人）；<br>· 虚拟员工的培训会陆续到期；<br>· 化学品按产量消耗、废弃物按产量产生；<br>· 老师在实验页可以注入“重大隐患”情景：指定设备，生成一条重大隐患 | 方案“每个领域包都有教学模拟器”；故事一可重复演示 |
| E2-9 | **新实验 17“安全隐患的识别、评估与停机决策”**（4 学时）：老师注入重大隐患 → 学生先做风险评估（可能性 × 严重度）→ 自己追影响（哪些工单、订单）→ 比较三个处理方案（比对模式，沿用实验 15）→ 选一个说明理由 → 走挂牌上锁许可 → 整改、验收、解锁 → 看复盘。自动评分 + 报告；指导书、报告模板、课程接口 | 每个领域包配一个实验；和实验 15（车间）、16（客户）连成一组 |

### 2. 和细则不一样的地方

1. **“开挂牌上锁许可并停机”这个动作，许可由动作执行时自动开好并批准**（持证人自动选有挂牌上锁资质的维修工），不用再走一遍许可审批——动作本身已经由厂长批过。手工在“作业许可”页申请的挂牌上锁许可，仍是申请 → 批准。
2. **隐患表多了“种类”和“整改标准工时”**（防护罩、急停、联锁、电线、漏油……），方案里的停机时长按它估；第三节表结构里没写。
3. **“限时整改”的延后时间**：按班次时到下班，24 小时连续运转时 4 小时；临时措施按 $150 算；整改人工按 $45/小时。这些参数写在代码里（`hub/ehs.py`、`hub/ont/plan.py`），帮助里写明了。
4. **E2（整改逾期）没有单独的“催办 / 改派 / 延期”方案**：在“安全环保”页上指派整改人即可改派；延期这一期没做。
