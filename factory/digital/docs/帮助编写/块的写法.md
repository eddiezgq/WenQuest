# 帮助正文里的块：怎么写

> 第 30 轮 §八（帮助改版：动画、视频、互动）8-1。给改写各章（8-3）的人看。
> 章节在 `web/src/help/teach/`、`web/src/help/enterprise/`，一章一个 `NN-名字.md`。块写成围栏代码块，块名紧跟三个反引号，
> 块里每行“键: 值”。写错了 `tests/test_help.py` 会指出是哪一章、哪一块。
> 一页看全部新块的样张：`tests/fixtures/help_blocks_demo.md`（只给测试和截图用，不放进帮助目录）。

## 一、每章的样子（细则 H-10）与检查

1. 开头一段**动画**（`anim`，或用 `lab` 嵌课程的动画页）；
2. 一段**视频**（`video`）——或者一个“做完打勾”的**带我去做**（`goto`，引导里有 `done` 条件）；
3. **互动至少两种**，其中至少一种在真工厂里动手：`try`（当场动手）或做完打勾的 `goto`；另一种可以是 `lab`（拖着玩）、`quiz`（你来选）；
   `ask`（问 AI）每章底部都放，但**不算**一种互动；
4. 一块本厂此刻的**实时数据**（`live`）。

文字只做旁白，每段不超过两三行；一章一屏到一屏半。

`tests/test_help.py::test_every_chapter_covered` 逐章数这几样，少一样就不通过（8-3 改写完各章后起强制）。教学版的 `17-course`、`18-faq` 不查。
动画可以是 `anim`，也可以是嵌课程动画页的 `lab`（例如设备维护嵌实验 6-1、经营嵌实验 10-1）。

### 正文和“查表”

一章分两部分，中间单独一行 `:::查表`：

- 上面是正文：一段动画、视频、动手、实时数据、你来选、问 AI，文字只做旁白；
- 下面是“查表”：页面各标签、谁做什么、中枢规则、处理方案、教学模式的细节——网页上收成一个折叠框“查表：页面、规则、谁做什么、处理方案”，点开才显示。

逐章检查**只数正文里的块**；“查表”里也可以放块（例如第二个视频、第二个带我去做），但不算数。
“你来选”的 `more` 可以链到“查表”里的小节，点了自动展开。

## 二、原有的五种

### goto 带我去做

````
```goto
tour: maint-pm
label: 带我走一遍保养单
```
````

`tour` 是 `web/src/help/tours.json` 里的引导名。按钮旁标“做完打勾”的，是带 `done` 条件的引导（见第四节）。

### anim 动画

````
```anim
name: causal
caption: 一次停机，因果链从设备一层层亮到客户
```
````

`name` 在 `web/src/components/help/anim/index.js` 里登记。

### video 视频

````
```video
name: teach-maint
caption: 保养工单、挂牌上锁
```
````

`name` 要在 `web/src/help/videos.json` 里，录制剧本在 `tools/help_videos.py`。

### live 本厂此刻

````
```live
kind: machines
```
````

`kind`：`machines`（每台设备此刻的状态）、`kpi`（关键指标）、`plant`（工厂、公司、币种、班次、车间大小）、`domain`（一个领域页上方那几个数，见下）。

````
```live
kind: domain
domain: maint
```
````

`domain`：`service` `supply` `maint` `people` `ehs` `energy` `finance`，各取哪几个数在 `web/src/lib/domainlive.js`；每 10 秒刷新，上面“当场动手”按了这里跟着变。
只在教学模式的演示工厂有（别处显示一句说明）。测试核对每个字段是接口真返回的。

### ask 问 AI

````
```ask
q: 我们厂现在哪台设备最该保养？
```
````

## 三、新加的三种

### lab 拖着玩：嵌课程的虚拟实验

````
```lab
id: pmopt
preset: after
height: 640
caption: 拖保养周期，找花费最低的那一点
```
````

| 键 | 说明 |
| --- | --- |
| `id` | 实验名，见下表 |
| `preset` | 可不写。实验页上的“预置”按钮，写了就替读者点上 |
| `height` | 可不写，缺省 640（像素，320–1200） |
| `caption` | 可不写，缺省写“课程《数字工厂实训》实验 x-y” |

页面滚到附近才装入（也可以点“打开实验”）；下面有“整页打开 ↗”。

| id | 实验 | preset 可写 |
| --- | --- | --- |
| `causal` | 一次停机的因果链（动画 3-1） | `book` `lab` `long` `rush` `fri` |
| `whatif` | 加班、加急还是外协（实验 3-2） | `book` `d30` `d40` `dec` |
| `weibull` | 威布尔可靠性：设备还能撑多久（实验 6-1） | `grd` `cnc` `ht` `exp` |
| `pmopt` | 保养周期怎样定（实验 6-2） | `after` `during` `exp` |
| `waterfall` | 订单毛利瀑布（实验 10-1） | `robot` `std` `cut` |
| `cashflow` | 未来 8 周的现金（实验 10-2） | `none` `dun` `hold` |

实验页的原件在课程里（`textbook/web-editions/dfactory/src/zh/labs/`），工作台用的是副本 `web/public/labs/`。
**只改原件**，改完运行 `python3 factory/digital/tools/sync_help_labs.py`；测试核对副本与原件一字不差。
要嵌新的实验：在 `tools/sync_help_labs.py` 的 `LABS` 和 `web/src/help/labs.js` 里各加一行，再同步。

### try 当场动手

````
```try
action: stop-grinder
label: 让磨床停机 2 小时
note: 按下去以后看下面的设备状态：GRD-01 几秒后变红。
```

```live
kind: machines
```
````

按钮在演示工厂里真做这件事，下面显示结果和“去某某页看 →”；紧跟一个 `live` 块，读者当场看到变化。

| action | 做什么 | 学生哪些岗位能按 | 做完去哪看 |
| --- | --- | --- | --- |
| `stop-grinder` | GRD-01 故障停机 2 小时（和教师控制台“注入一次故障”同一条路） | 维修工、操作工、班组长 | 3D 车间 |
| `rush-order` | 下一张急单 WQR-105 × 5、交期 5 天，提议自动确认（和两周情景第 1 幕同一条路） | 计划员 | 订单与计划 |
| `overdue-pm` | GRD-01 运行小时拨到保养周期的 1.4 倍（情景第 6 幕） | 维修工 | 设备维护 |
| `overdue-invoice` | 最近一张未收的应收发票逾期 15 天、不催不付（情景第 8 幕） | 计划员（销售、厂长只给老师） | 经营与财务 |
| `major-hazard` | 报一条重大隐患：GRD-01 防护门联锁被短接（情景第 5 幕） | 所有岗位（隐患谁都能报） | 安全环保 |
| `idle-saw` | 带锯床下班忘关、空转 4 小时（情景第 7 幕；同时打开能源模拟器） | 操作工、班组长、维修工、计划员 | 能源与环境 |

规矩（服务器 `hub/help_try.py` 管，网页只是照着显示）：

- 只在**演示工厂**、**教学模式**里显示和能用；企业工厂接口整组 404，生产模式不显示；
- 老师都能按；学生只能按自己岗位能做的，别的岗位按钮是灰的，旁边写“这一步要谁来做”；
- 每人 60 秒一次；老师 5 秒一次（只防连点两下）；按过以后同一页的几个按钮一起倒数；
- 复原：老师在“情景导演”里“重置实验 7 情景”或重新“开始两周情景”。

要加新动作：在 `hub/help_try.py` 的 `ACTIONS` 和 `_roles()` 里各加一项，复用现成的函数，`tests/test_help_try.py` 补测试。

### quiz 你来选

````
```quiz
q: 磨床逾期 120 小时，急单在赶：
options:
  - 现在保养 | wrong | 瓶颈停 3 小时少挣 $600，合计约 $817
  - 下班后保养 | right | 合计约 $235，不占生产时间
  - 不做 | wrong | 预期损失 $375，坏了急单要晚
more: 11-maint#保养：从异常到验收解锁
```
````

- `options:` 后面空着，下面每行“两个空格、减号、空格”一项：**文字 | right 或 wrong | 道理**。2–5 项，至少一项 right。
- 选完显示对错和这一项的道理，对的那项打勾；选错时给“回到那一段看看 →”。
- `more`：`章节文件名#小节标题`（`##` 或 `###` 的标题原文）；同一章写 `#小节标题`。测试会核对这一节真有。
- 数字要和平台、课程算出来的一致（从课程计算程序 `textbook/web-editions/dfactory/course/calc/` 或平台页面上取），不要估。

## 四、带我去做：做完打勾

`tours.json` 里引导的某一步加 `done`，系统检测到这一步真的做了就打勾、自动进下一步；带 `done` 的步骤都打了勾，最后显示“这一节完成 ✓”。
不带 `done` 的步骤照旧点“下一步”。三种写法（一步只写一种）：

```json
{ "help": "planner-calc", "text": "点“算料”……", "done": { "selector": "[data-help=\"planner-mrp\"]" } }
{ "help": "maint-tabs", "text": "打开“保养”标签……", "done": { "route": "/maint", "query": { "tab": "pm" } } }
{ "help": "ehs-report", "text": "随手拍……", "done": { "api": "/ehs/issues", "path": "issues.length", "grew": true } }
{ "help": "planner-proposals", "text": "点“提交”……", "done": { "api": "/proposals", "path": "0.proposal_id", "changed": true } }
```

| 写法 | 什么时候算做了 |
| --- | --- |
| `selector` | 页面上出现了这个元素（用 `data-help` 标记；要加在页面文件 `pages/X.vue` 里，测试只在页面文件里找） |
| `route`（可带 `query`） | 地址到了这一页（这几个查询参数也对上） |
| `api` + `path` + 比较 | 每 3 秒取一次这个接口（不写 `/api` 前缀，只能是 GET），按 `path` 取一个值（如 `issues.length`、`kpis.overdue`、`0.proposal_id`）；比较只写一种：`grew: true` 比这一步开始时多了；`changed: true` 和这一步开始时不一样了；或 `gt` / `gte` / `eq` 一个数 |

接口返回的列表有条数上限（如提议列表最多 50 条）时，`length` 到了上限就不再变，要用 `0.<编号字段>` + `changed`（最新一条换了）。
接口看的是全厂（同一模式）的数据：同一时间别人做了同样的事也会打勾。

现在带 `done` 的引导：`planner-order`（算料、提交）、`open-3d`（点一台设备）、`ehs-tour`（报一条隐患）；
8-3 加：`service-tour`（登记投诉）、`supply-inspect`（检验一批，看 `/supply/kpis` 的 `inspected_n` 变多）、`people-tour`（起草调班动作）、
`quality-chart`（开 8D）、`engineer-design`（发布新版本）、`ont-options`（采纳生成动作）、`labs-tour`（进实验 18）。

## 五、点哪看哪

3D 车间和首页“车间实况”上点一台设备，弹出名字、此刻状态（运行 / 停机 / 🔒 挂牌上锁 / 保养逾期 N 小时）、所属领域和对应的帮助：
停了、锁了、保养逾期 → “设备维护”一章；在跑或空闲 → “车间”一章；企业工厂 → 企业版“工厂清单”一章。
规则在 `web/src/lib/machinfo.js`。保养逾期：演示工厂取设备维护的 `/api/maint/risk/<设备>`（老师改过的保养周期以它为准，和“设备维护”页一致）；
取不到时按 `/api/layout` 里的标准保养周期 `pm_h` 与设备状态里的 `run_h_pm` 比。首页的设备卡片点一下弹出、再点一下（或 Esc）收起，“打开车间终端”在弹窗里。
