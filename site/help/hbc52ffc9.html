客户与服务

数字工厂工作台左侧“从订单到回款 → 客户与服务”。

它把“客户 → 商机 → 报价 → 合同 → 订单 → 交付 → 现场 → 投诉 → 追溯 → 服务 / 召回 → 回访”接成一条线： - 线索、商机、报价、合同、服务单都在 ERPNext 里有对应单据，平台经桥接写进去、再读回来； - 投诉、派工排班、回访打分、批次召回在平台里做； - 投诉和满意度下降会在厂情中枢变成异常，处理方案按工程师排班估算，批准后才执行。

谁能用： - 所有角色都能看； - 线索、商机、报价、合同、转订单：销售或厂长； - 登记投诉、派工、完工、回访打分：售后、销售或厂长（新角色“售后”在右上角“角色”里切换）； - 老师（教学模式）什么都能做。

页面上方五个数：满意度（近 30 天）、开着的投诉（平均响应小时）、待上门的服务（一次修复率）、保修成本（近 30 天）、漏斗金额（本月成交）。

右上角五个标签：销售漏斗、投诉、服务与排班、回访与满意度、客户 360。

一、销售漏斗

五列：线索 → 商机 → 报价 → 合同 → 订单，每张卡片下面是“下一步能做什么”。

  1. 加线索：最上面填公司名称和一句备注，点“添加”。几秒后出现在“线索”列（ERPNext 里是 Lead）。
  2. 转成商机：在线索卡片上填数量，点“转成商机”。金额 = 数量 × 标准售价（WQR-105 $1,650 / 台）。ERPNext 里建 Opportunity，线索状态改为 Opportunity。
  3. 出报价：在商机卡片上点“出报价”，ERPNext 里建 Quotation 并提交，有效期 14 天。报价快到期（3 天内）会出异常 C5。
  4. 签合同：在报价卡片上点“签合同…”，填三项条款：
  5. 延期违约金（$/天，没有就填 0）；
  6. 投诉响应时限（小时）；
  7. 保修期（月）。 点“签合同（写入 ERPNext）”。ERPNext 里建 Contract（已签、已提交），三项条款存在合同的自定义字段里。报价给的是线索的，签合同时自动建成 ERPNext 客户。
  8. 转订单：在合同卡片上填数量、选交期，点“转订单”，弹出和计划员一样的“接单并算料”预览（销售订单 + 工单 + 请购单）。确认后才写进 ERPNext；订单号回填到合同上。

合同条款在哪里用： - 推演的违约金：订单的客户合同有违约金，推演和复盘就按它算； - 投诉响应时限：超过时限没人回复，出异常 C3； - 保修期：服务方案里分“保修内由工厂承担”和“向客户收”。

教学模式里，模拟器隔一阵会来一条新线索（展会、官网询价），给销售同学练手。

二、投诉

登记投诉：填设备序列号（会自动带出客户）、现象、严重度（一般 / 严重 / 紧急）、渠道、联系人，点“登记”。同时在 ERPNext 开一张投诉单（Issue）。

厂情中枢下一轮检测（20 秒内）会开异常： - C1 客户投诉：开着的投诉都是异常。紧急的，或者客户合同有违约金（重点客户），为严重。 - C3 投诉超时：超过合同的响应时限还是“新投诉”。点“已联系客户”就算响应了。 - C4 同批多台投诉：两台以上投诉的设备，输出轴出自同一片砂轮或同一张工单。

追溯：投诉有序列号的，异常的因果链会一路追到出厂数据： 设备 → 出厂总成 → 装的输出轴 → 磨削它的砂轮 → 同一片砂轮磨的其他轴 → 装在哪些设备、哪些客户。 这就是排查范围。

投诉列表默认只看开着的；服务做完会自动关闭投诉。

三、厂情中枢的异常与处理方案（派工）

在厂情中枢指挥台打开投诉的异常，右栏有三个方案（按工程师排班估算，不进车间仿真）：

方案 做什么
A 只修出问题的 只上门修投诉的那台
B 修 + 高风险点检 再加上排查范围里的高风险设备（健康度红 / 黄，或最先到期的轴承已用 50% 以上）
C 整批排查 排查范围全部上门点检

每个方案都算好：派哪几位工程师、几天做完、几个人天、要几件备件、花多少钱（保修内 / 向客户收）、涉及几个客户、还有没有漏掉的高风险设备。推荐的是不漏高风险设备里最便宜的，再比天数。

派工规则： - 6 位服务工程师：东部（周海、陈蓝）、南部（林青、黄禾）、北部（赵岩、孙川）； - 现场所在区域：矿山 → 北部，港口 → 东部，食品厂 → 南部； - 同区域每人每天最多 2 单；去外区域一天只能做 1 单，人工按一整天算，加 $150 差旅； - 周末不排；21 天内排不进的会标出来； - 每单人工 $480 × 0.5 天（同区域）；换轴承一根轴两端一起换，带 2 件轴承。

采纳：点方案下的“采纳，生成动作”，会生成： - 服务派工：排进工程师日历，ERPNext 里每台开一张服务单（Issue，写明工程师和上门日）； - 备件出库：ERPNext 里一张出库单（Stock Entry，Material Issue）； - 客户通知（B、C 才有）：给排查范围里的其他客户发“预防性服务通知”。

谁批准： - 派工和备件出库要花钱，厂长批； - 只派一台、而且在保修期内的派工不算花钱，售后、销售也能批； - 客户通知由售后、销售或厂长批； - 不能批自己发起的（教学模式的老师除外）。

客户通知怎么发：生产模式下，批准后有邮箱的客户发邮件，没有邮箱的记录下来请人工联系；教学模式只记录、不发出。通知记录在“服务与排班”下方。

四、服务与排班

  • 排班表：6 位工程师未来 14 天，每天是休息、空闲还是已排几单；
  • 服务工单：每张单的设备、客户、做什么、工程师、上门日、保修内外、ERPNext 服务单号；
  • 完工：工程师做完点“完工”：
  • 数字孪生里那台设备的寿命复位、对应故障消失（点检时发现轴承已用 70% 以上会当场更换）；
  • ERPNext 服务单改为“已解决”；
  • 第二天生成回访任务。

教学模式里，模拟器会让工程师按排的日子自动完工。

五、回访与满意度

完工后第二个现场日要回访客户，打 1–5 分，写一句客户的话。教学模式由模拟器自动打分： - 从投诉到完工超过 3 天，扣 1 分； - 比计划上门日晚，扣 1 分； - 修完又投诉，扣 1.5 分。

某个客户最近 3 次回访平均低于 3.5 分，出异常 C2 满意度下降。

六、客户 360

选一个客户，一页看全：合同条款、订单、现场设备（健康度、报警、保修到哪天）、投诉、服务单、满意度。AI 助手回答“港口客户最近怎么了？”用的就是这一页的数据。

七、AI 助手能问什么

  • “港口客户最近怎么了？”“Summit 的合同违约金是多少？”（客户 360）
  • “CP-00003 这批轴还装在谁家？”（投诉追溯与排查范围）
  • “A-00012 怎么处理？”（投诉异常的三个服务方案）
  • “派工程师上门点检 WQR105-H2502-10 要几天？”（派工估算，只算不排）
  • “起草 A-00012 的方案 B”（起草动作草稿，要人提交、批准）

教学模式下，对学生只给提示、不直接说排查范围和该选哪个方案。

八、教学模式

  • 实验 16“客户投诉的追溯、召回与服务决策”：左侧“实验与任务 → 实验 16”。老师在页上注入批次投诉，学生追溯、标风险、选方案（比对模式）、起草派工和通知、看回访。指导书和报告模板在页面右上角。
  • 教学模拟器（只在教学模式）：现场设备健康度变红一定来电投诉，变黄每个现场日有 15% 的概率；工程师按日子完工；回访自动打分；隔一阵来一条新线索。
  • 老师“重置情景”时，投诉、服务单、回访、通知一起清空（工程师保留）。

两周情景：第 1 幕“客户下急单”用到这一页（订单从这里的销售漏斗走到下单），见两周情景。

九、常见问题

  • 点了“添加”，线索没出现？写进 ERPNext 后，桥接要几秒才把单据读回来。等 5 秒再看；还没有，到“数字工厂上线与维护”里查桥接日志。
  • 投诉没有异常？厂情中枢每 20 秒检测一次。没有序列号的投诉也会有异常，但追不到出厂数据，没有排查范围和方案。
  • 方案只有一个？排查范围里没有别的设备（同一片砂轮磨的轴没有装到别处），只能修出问题的那台。
  • 学生发起不了服务动作？要用“售后”角色（或“销售”）登录。
